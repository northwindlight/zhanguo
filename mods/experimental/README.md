# experimental 实验性发行版

`experimental` 是持续更新的实验性发行版；当前为 `0.15.0`。后续实验功能在此发行版继续演进，目前包括议会审核（默认使用该君主自己的模型，检查事实、承诺与失职）、库存反馈市场、Python 沙盒，以及仅供规则 AI 研究的战斗概率推演。

在当前 main 的 native 4.15.0 领域上替换政权模块，增加独立议会服务。默认 `mods.toml` 仍装配 native；选择 `mods.experimental.toml` 才启用这些实验。旧 World v4 代码保存在 legacy；本发行版不自动迁移旧存档。

配置顶层填写 `"mods":"mods.experimental.toml"`，用新的 save/journal 路径开局。议会默认使用该 LLM 玩家自己的模型与接入；只有单国条目显式写 `parliament.reviewer` 才另换。顶层 `parliament.reviewer` 只作为规则客户端的兜底，不再覆盖 LLM 玩家。示例见 [独立配置模板](../../mp_config.experimental.example.json)。用 `.venv/bin/python mp_run.py --config mp_config.experimental.example.json --new` 启动前填好接入参数，示例路径只用于新局。

## 保存的 Python 短脚本

[Python 沙盒](SCRIPTING.md)提供 `script(action=write/patch/check/status/run)`；脚本内部只调用 `api.call(capability, method, ...)`，不调用 LLM 工具名。保存一次，每回合手动执行一次；免费检查不运行。脚本操作标准玩家 API，国策审核、动作审计与控制权处理一致。支持递归与短序列插值，采用固定计算预算限制大型搜索；禁用导入、网络、文件、动态执行、反射和计时器。失败保留已成功动作，返回原错误信息，本回合不允许重试。源码和最近执行结果随档保存。

## 库存反馈市场

市场由 native 发行版提供：`market` 查询与玩家状态公开各商品 `inventory / reference`，君主和议长通过 `player_rules(topic="市场")` 获取当前规则。价格由库存与基准库存之比决定，基准库存随本期净流量逐步偏移（大买推高、大卖压低），同期内先后手同价，大单按扫过的深度加价或压价，市场只在开局发一次货，外部不回补。价格、库存、基准、参数、金币零头和全部成交记录随档保存；1.0 前不提供旧档适配。

金币结算沿用外部市场流动性，不引入市场金币储备限制；有限的是商品库存。整数金币采用买入向上支付、卖出向下收款，差额作为市场欠本账户的零头连续抵扣，避免反复小额买卖凭空套利；拆单和整单的支付一致。

离线验收：`.venv/bin/python -m unittest tests.test_experimental_market -v`。

## 审核与君主交替

每国每回合只能提交一次国策，包括罢免后的接任者。第一版国策直接生效，只告知君主本国设有议会，不调用议长模型、不进行审核或否决；同时保存第一版及提交时事实作为后续审核基线。这个首次豁免按国家整局计算，续档、国策过期或君主接任都不恢复。

从第一次修订起，草案提交不等于通过；议长先看[审核要求](requirements.md)、上一版国策、上一版提交后至此次修订前的全部行为及回执、地图和经济事实，再单独接收新版草案，决定批准或打回。

每次独立审核主要检查上一版及其后轨迹；跨审核事项表保留未解决的前提、承诺、风险和问题，沿稳定引用按需追查更早证据，不重新发送全部历史。提交时快照只提供事实，剔除其中残留的更早国策、历史小结及前次审核正文；独立档案原文保留。只有未通过时，审核对话及后续解释才延续到下次，直到通过后清空。

议长主要校核事实、情报以及经济、外交、军事承诺，并检查君主是否失职，协调君主，为国家负责。失职检查覆盖无威胁下 GDP 零增长、战争中总兵力占优却严重损兵、情报严重失真、丢首都、军队未动员、严重外交失误等；但只在失误本期可改变、君主未采取可行纠正时才打回，实力不对称、被迫防守战争和大国吞并不算失职。审核记录须写明检查结论（批准时也记录“已检查”）。主动检查必要评估与承诺是否完整，国策缩短或删掉承诺不会逃过审查；关键战略结论缺乏依据且未按未知情形处置时，可以打回，不必先证明隐藏事实相反。已确认事实直接沿用，不重复从头读取规则。不同风险偏好、合理调整战略和单次失败不是自动否决理由。

审核不得压低合理开战和推进游戏目标的意愿：无需必赢、完整全国情报或固定兵力倍数；目标有限、接触不利即退、损失有界且依据可推出的进攻可以通过，补情报可与备战并行。守势、种田和等待同样须说明目标推进、期限及转入行动的条件，不准靠无限等待逃避目标；不强制spy或某条战略，但可负担的目标国情报须实际使用。

目标推进独立审查，不以丢城、战损、违约或GDP下降为前提。长期养兵不用、反复续写中立守成，却缺少目标相关成果、明确期限或结束等待办法中的任一项时，直接打回要求解释，并在下期新版给出近期动作、阶段成果、期限和受阻后的替代路线。旧国策、历史小结、既往批准及自设禁令不是引擎规则；失效的禁令应明确撤销或替换，真实条约和承诺责任仍须核实。合理的有限休整和备战可以通过，不强制固定回合出兵或特定战争。

所有新增或沿用承诺均须明确可核验的适用/触发条件及完成期限；持续性承诺写起止期，确属无条件则须明示。任何承诺缺条件或期限直接打回，不必等到违约或停滞；不能用“长期、永久、择机”代替期限，也不能默认套用国策总期限。允许明确共用一组条件和期限，避免逐条重复；追踪时条件写入commitment正文、截止期写入due，到期复核，续期重新论证。真实引擎限制与既有条约义务按其来源核实，不因文案缺项擅自解除。

诚实约束同样适用于攻守判断：地图和任何他国的归属、兵力、经济、外交与意图须核来源、日期和覆盖范围，无支撑不采信、不作为批准依据；议会不能替原话补上“视野内/仅东翼”等限定圆场。声称能打或不能打均须核可投入兵力、兵种与HP、部署到达时间、地形城防、交战规则、后勤及援军；无据或严重失准应打回补证重算。全国军数、固定兵力倍数或一次败仗不能代替核算，最终路线可接受也不能豁免错误的战略依据。允许诚实注明未知，但诚实不是批准依据：条件化方案仍须给出敌情上界与最坏情形；不鼓励盲目进攻，也不要求完整情报才可行动。

审核按实质依据而不是文字合规裁决：如实标注未知、条件期限齐全、措辞精确都只说明君主没有隐瞒，不等于已经推出能打。批准进攻或宣战须从当期证据推出敌情总量或上界、增援到时、地形城防、后勤、己方兵力与HP、最坏情形损失与退路；总量未知且无上界时不得把主力投入敌国城堡、国祚或长期战线。可负担的目标国情报（20金已公布报表、当期视野）须实际取得，连目标国报表都没买、只买无关国家或写“必要时”算未处置未知；报表不含当前兵力，推断须写区间，需要兵种数量时用spy。引擎核对动作记录：本回合宣战目标在宣战前没有任何报表或谍报时，`council_approve` 会被拒绝，议会只能打回。

裁决按 [council_rating.md](council_rating.md) 的 R0—R3 评级：只有会改变结论或可执行性的 R0 能否决（一次至多3项，每项写清改变哪个结论/后果）；R1 记 tracking，R2/R3 只记录。措辞、笔误、±1、旧稿口径不构成打回理由；自设门槛与计划冲突时指出并允许修正。后续调整标准改评级条目，不再逐句改提示词。

批准回执：`议会通过了国策。` 此时草案成为有效国策，连续否决计数归零、议会审核对话清空；未解决事项与证据档案继续保留，批准不会自动关闭事项。批准之前，议会自己的完整对话、工具往返、审核与裁决持续保留，和君主记忆独立。

打回回执：`议会没有批准君主的国策，贵族们对这份国策不满：<原因>。要求君主解释，并在下回合给出新的国策。` 君主须调用 `explain_plan(text=...)` 后才能结束本回合；可以继续做其他行动，下一回合必须重提。解释不替代新版，也不构成本回合第二次审核。

连续三个实际相邻回合未通过：独立记录者处理开局以来全部行为、回执、地图、经济变化、完整君主对话、当前上下文及议会对话，生成交接摘要；大于单次窗口时逐段完整处理再合并，不静默截断历史。随后清空君主 replay、逐期小结、压缩块和递归记忆，撤销旧国策；独立审计档案和未获批准的议会对话保留。

新君主提示：`上一任君主被愤怒的贵族们罢免，你被推举为新的君主，全权接管这个国家，现在是你的回合。` 结合交接摘要重新组装上下文，在本回合继续行动。本回合已经提交一次，下一回合才可提新国策。旧君主触发罢免后，同一工具批次的剩余命令取消并补完整回执；新君主自己决定剩余行动。资源、军队、领土、外交条约与有效承诺均不凭空改变，旧君主的小结不会再通过政权面板回灌。

## 议长查询与接入

议长可调用 `player_rules(topic=...)` 查询当前模块规则，或 `read_manual(topic=...)` 取说明书汇总（公开规则、动作参数和建筑/兵种目录）或任一规则章节。策略讲义与游戏说明书由 `native:manuals` 按需读取，文档位于 `mods/native/docs/`，不作为规则章节注入系统提示。君主可用 `query(panel=manual, doc=basics/economics/war/strategy/manual)`；议长可用对应中文标题读手册。具体规则以当前模块规则、目录和回执为准。旧 World 手册不用于裁决当前模块规则。

议长可以查规则、手册及本国原始证据，维护本国追踪事项；不获得隐藏敌国库存或执行国家行动的权限。批准、否决、罢免由发行版授权服务写入政权模块，这些服务不在模型工具列表中。

`parliament.reviewer` 写在单国条目里才单独配置议长接入；未写时议长使用该玩家自己的模型与接入（同一种模型也有独立请求上下文和后端对象）。规则客户端没有模型，仍可用顶层 `parliament.reviewer` 作为兜底。`parliament.requirements` 可替换审核要求正文，或使用 `requirements_file`。路径相对启动目录；接入凭据不写入存档，审核要求随议会对话保存。已经开始、尚未批准的审核保留原要求，下一次清空后采用新要求。

原始完整审计材料独立于君主滚动窗口，随整局保存。事实采用开局完整快照、后续逐项变化和不重复的事件记录；每次审核独立提供本次事实和上一版提交快照；窗口不足时保留本次事实摘要、全区间动作/情报购买/现金统计和未解决事项，原文通过 `council_search` 定位、`council_read` 分页读取。`vision=false` 也有当前事实，不依赖图片或历史差分恢复现状。国策、失败计数、君主代数、议会对话、交接摘要和用量都可续档；两种发行版依赖不同，禁止混载。规则 AI 仍使用确定性君主客户端，但同样接受发行版议会审核，议长需要独立的 LLM 接入。

第一步由 `council_next_stage` 按钮结束；此前议长可核对事实、读取手册并保存追踪事项。每次请求均告知当前 `[x/10]` 轮，两阶段共用轮次；累计第 5 轮后每轮催办，第 10 轮仍未提交裁决则因审核未完成而打回，要求解释并在下期补齐重提；计入连续否决，绝不因超时自动批准。第二步结束时，议长必须在 `council_approve()` 与 `council_reject(reason)` 两个按钮中选择一个，作为本批次最后一个工具调用。完整输入、返回思考、正文、工具声明和往返、用量及裁决增量回写 journal，终端只显示进度。通过按钮不需要理由，君主只收到通过回执，不会收到议会建议或审核上下文；拒绝按钮必须给出简明、具体的核对依据。未调用按钮或参数错误时，系统把具体错误反馈到同一段议会对话，并额外调用一次让议长修正；仍然无效、审核调用失败、空答或交接总结失败会停止整局，保持最近完整结算存档。验收采用模拟模型，不新增付费调用。服务格式升级为 `council/2`，且发行版新增手册依赖，旧档不能直接混载；本次没有转换存档或替换正在运行的进程。

## 追踪与输入预算

`council_track` 记录关键前提、承诺、风险和问题，须附证据引用；关闭或替代须说明实际证据或合理调整。最多同时保留 24 条未解决事项，每条正文与关闭说明各限 600 字、引用限 8 个；满额会报错，不能静默挤掉未完成事项。系统自动将否决原因加入事项表；满额时仍保留否决原始记录。事项是议长判断，不是引擎事实，也不构成开战或批准的机械门槛。

`council_search(query, since, until, cursor)` 检索本国档案；`council_read(ref, section, offset)` 分页读取 `current`、`previous`、`tracking` 或稳定 `row/编号`。动态快照作为追踪证据时固定成档案行，保存续载后引用仍指向当时事实。未读完会返回 `next_offset`；未附内容不代表不存在。

每次模型请求先核对消息、工具、地图与输出预留预算。超限时依次减少历史明细、缩为快照摘要、合并区间统计及追踪摘要，并归档整组旧工具往返，保留配对和可检索原文；当前独立事实、未结事项清单、新草案受保护。极小窗口无法容纳这些必要材料时明确失败，不把超限请求送给提供者。固定回合记忆模式也有窗口上限，未配置时按 200k 窗口估算。原始档案保存在服务存档中，提示缩减不删除证据。

## UI 与图形地图

experimental 在 native 的领域与 UI 基础上增加议会审核与库存市场。与 native 一样装配独立 `ui:standard`，由宿主注入君主和议长客户端。顶层配置 `vision=true` 时，两者使用同一个 UI Mod 的可见地图；审核第一步使用提交新版之前的快照，第二步才展示新版。中英提示编排、语言覆盖与终端地图导出见 [UI Mod](../ui/README.md)。

## 发行版 API 提供层

议会审核与证据记录由 `Distribution.Session.Services.council` 装配，状态随发行版 Session 保存。LLM 走模型工具与 `submit()`，规则 AI 和脚本走 `call_api(capability, method)`，两者共享议会与审计行为；君主客户端只负责模型交互和界面。连续三次否决后，发行版立即更换控制权代次，旧玩家句柄后续动作失效，新句柄取得交接上下文。`enroll / decide / replace` 不开放为玩家工具。见 [发行版 Session API](../../docs/发行版Session.md)。

## 规则 AI 战斗概率研究

本发行版默认给 `client=rule` 注入 [概率研究能力](combat_research/README.md)，不向 LLM、议长或脚本注册概率工具。native 保留原策略与简化查询。研究算法按当前余伤转移规则计算；可选 C 扩展推荐编译，运行时优先使用。
