# experimental 实验性发行版

`experimental` 是持续更新的实验性发行版，采用 beta 版本号；当前为 `0.4.0-beta.1`。后续实验功能在此发行版继续演进，目前包括议会审核、库存反馈市场、Python 沙盒，以及仅供规则 AI 研究的战斗概率推演。

在当前 main（原正规化）的 native 4.1.0 领域上替换政权模块，增加独立议会服务。默认 `mods.toml` 仍装配 native；选择 `mods.experimental.toml` 才启用这些实验。旧 World v4 代码保存在 legacy；本发行版不迁移旧存档。

配置顶层填写 `"mods":"mods.experimental.toml"`，用新的 save/journal 路径开局。`parliament` 可放在顶层或单国条目；单国配置优先。示例见 [独立配置模板](../../mp_config.experimental.example.json)。用 `.venv/bin/python mp_run.py --config mp_config.experimental.example.json --new` 启动前填好接入参数，示例路径只用于新局。

## 保存的 Python 短脚本

[Python 沙盒](SCRIPTING.md)提供 `script_write / script_patch / script_check / script_status / script_run`。保存一次，每回合手动执行一次；免费检查不运行。脚本操作标准玩家 API，国策审核、动作审计与控制权处理一致。支持递归与短序列插值，采用固定计算预算限制大型搜索；禁用导入、网络、文件、动态执行、反射和计时器。失败保留已成功动作，返回原错误信息，本回合不允许重试。源码和最近执行结果随档保存。

## 库存反馈市场

采用库存缓冲（方案 3）与库存反馈报价（方案 4），不采用原先的基准价回归，也不直接积分全国生产与消费的差额。国家生产留在国家账户，只有真实市场交付才能改变市场库存。

- `I_next = I + 成功卖入市场的数量 - 成功从市场买走的数量`。报价只读；失败交易不改库存、行情、零头或流水。买单超过可用库存时整单拒绝，不部分成交，不自动补货。
- 回合结算 `p_next = p * exp(0.1 * (I_target - I_next) / I_target)`。目标库存时价格保持，即使当前价格已偏离开局基准；库存不足或过剩而没有新交易，仍然持续调价。
- 本回合按固定行情成交，买价上浮 5%，卖价下浮 5%；下回合才采用结算后的行情。没有额外叠加旧市场的逐笔价格冲击。
- 目标及开局库存：粮 192、木 192、矿 128、油 96、装备 64、补给 96，为现有深度的 8 倍。它们是显式外部开局缓冲，不属于任何国家，不随国家数量改变。市场所有商品库存与国家持有量在交易中守恒。
- `eta=0.1`：缺货到零时每期上涨约 10.5%，库存为目标两倍时每期下降约 9.5%。这是初始实验参数，尚未做真实长期对局校准。

参数在 [市场声明](market.toml)；[定价模块](market_pricing.toml)、[库存与查询实现](market.py)分别负责公式和状态。绝对数值边界为 `1e-6..1e9`，防止指数溢出或价格归零；它们不按基准价限制。目标偏差不是价格回归力，无交易并不保证行情稳定；响应过慢或持续囤货可导致长时间单向漂移。没有需求曲线时不能保证收敛。

市场由 native 发行版提供：`market` 查询与玩家状态公开各商品 `inventory / reference`，君主和议长通过 `player_rules(topic="市场")` 获取当前规则。价格由库存与基准库存之比决定，基准库存随本期净流量逐步偏移（大买推高、大卖压低），同期内先后手同价，大单按扫过的深度加价或压价，市场只在开局发一次货，外部不回补。价格、库存、基准、参数、金币零头和全部成交记录随档保存；1.0 前不提供旧档适配。

金币结算沿用外部市场流动性，不引入市场金币储备限制；有限的是商品库存。整数金币采用买入向上支付、卖出向下收款，差额作为市场欠本账户的零头连续抵扣，避免反复小额买卖凭空套利；拆单和整单的支付一致。

离线验收：`.venv/bin/python -m unittest tests.test_experimental_market -v`。

## 审核与君主交替

每国每回合只能提交一次国策，包括罢免后的接任者。第一版国策直接生效，只告知君主本国设有议会，不调用议长模型、不进行审核或否决；同时保存第一版及提交时事实作为后续审核基线。这个首次豁免按国家整局计算，续档、国策过期或君主接任都不恢复。

从第一次修订起，草案提交不等于通过；议长先看[审核要求](requirements.md)、上一版国策、上一版提交后至此次修订前的全部行为及回执、地图和经济事实，再单独接收新版草案，决定批准或打回。

议长主要校核事实、情报以及经济、外交、军事承诺，协调君主，为国家负责。符合战略应通过；严重反事实或无解释的反承诺须反复校核后说明依据再打回。不同风险偏好、合理调整战略和单次失败不是自动否决理由。

批准回执：`议会通过了国策。` 此时草案成为有效国策，连续否决计数归零、议会上下文清空。批准之前，议会自己的完整对话、工具往返、审核与裁决持续保留，和君主记忆独立。

打回回执：`议会没有批准君主的国策，贵族们对这份国策不满：<原因>。要求君主解释，并在下回合给出新的国策。` 君主须调用 `explain_plan(text=...)` 后才能结束本回合；可以继续做其他行动，下一回合必须重提。解释不替代新版，也不构成本回合第二次审核。

连续三个实际相邻回合未通过：独立记录者处理开局以来全部行为、回执、地图、经济变化、完整君主对话、当前上下文及议会对话，生成交接摘要；大于单次窗口时逐段完整处理再合并，不静默截断历史。随后清空君主 replay、逐期小结、压缩块和递归记忆，撤销旧国策；独立审计档案和未获批准的议会对话保留。

新君主提示：`上一任君主被愤怒的贵族们罢免，你被推举为新的君主，全权接管这个国家，现在是你的回合。` 结合交接摘要重新组装上下文，在本回合继续行动。本回合已经提交一次，下一回合才可提新国策。旧君主触发罢免后，同一工具批次的剩余命令取消并补完整回执；新君主自己决定剩余行动。资源、军队、领土、外交条约与有效承诺均不凭空改变，旧君主的小结不会再通过政权面板回灌。

## 议长查询与接入

议长可调用 `player_rules(topic=...)` 查询当前模块规则，或 `read_manual(topic=...)` 查询说明书、经济学手册、基础指南、战争手册、战略手册。说明书从当前发行版公开规则、动作参数和建筑/兵种目录生成；[手册](handbooks/)为本发行版策略参考，具体规则以说明书和回执为准。旧 World 手册不用于裁决当前模块规则。

议长只能查规则与手册，不获得隐藏敌国库存或执行国家行动的权限。批准、否决、罢免由发行版授权服务写入政权模块，这些服务不在模型工具列表中。

`parliament.reviewer` 独立配置模型接入，未指定的传输参数继承本国配置；即使使用同一种模型，它也有独立请求上下文和后端对象。`parliament.requirements` 可替换审核要求正文，或使用 `requirements_file`。路径相对启动目录；接入凭据不写入存档，审核要求随议会对话保存。已经开始、尚未批准的审核保留原要求，下一次清空后采用新要求。

原始完整审计材料独立于君主滚动窗口，随整局保存。事实采用开局完整快照、后续逐项变化和不重复的事件记录；每次审核附上一版提交时完整快照，便于复原地图与经济变化。国策、失败计数、君主代数、议会对话、交接摘要和用量都可续档；两种发行版依赖不同，禁止混载。规则 AI 仍使用确定性君主客户端，但同样接受发行版议会审核，议长需要独立的 LLM 接入。

审核调用失败、空答、非法裁决、查询步骤耗尽或交接总结失败会停止整局，保持最近完整结算存档。这里只做了模拟模型离线验收；未恢复任何付费联网跑局。真实旧版对局应继续使用 legacy 对应的历史提交。

```bash
.venv/bin/python -m unittest tests.test_parliament -v
.venv/bin/python -m unittest discover -s tests -q
```

## UI 与图形地图

experimental 在 native 的领域与 UI 基础上增加议会审核与库存市场。与 native 一样装配独立 `ui:standard`，由宿主注入君主和议长客户端。顶层配置 `vision=true` 时，两者使用同一个 UI Mod 的可见地图；审核第一步使用提交新版之前的快照，第二步才展示新版。中英提示编排、语言覆盖与终端地图导出见 [UI Mod](../ui/README.md)。

## 发行版 API 提供层

议会审核与证据记录由 `Distribution.Session.Services.council` 装配，状态随发行版 Session 保存。LLM、规则 AI 与直接调用 `host.player(actor).submit()` 的程序共享该行为；君主客户端只负责模型交互和界面。连续三次否决后，发行版立即更换控制权代次，旧玩家句柄后续动作失效，新句柄取得交接上下文。`enroll / decide / replace` 不开放为玩家工具。见 [发行版 Session API](../../docs/发行版Session.md)。

## 规则 AI 战斗概率研究

本发行版默认给 `client=rule` 注入 [概率研究能力](combat_research/README.md)，不向 LLM、议长或脚本注册概率工具。native 保留原策略与简化查询。研究算法按当前余伤转移规则计算；可选 C 扩展推荐编译，运行时优先使用。
