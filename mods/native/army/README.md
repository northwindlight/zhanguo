# 军队模块

`native:army` 2.9.0 按 [正式发行版模板](../README.md) 装配。`Unit / Units` 拥有部队、编号、守卫出生与行动状态；`Military` 拥有征召额度、军事经济回执、电网短缺事实、待发布事件和战斗随机状态。

兵种从内容注册表读取，原生 `native:infantry / cavalry / militia`，展示名与 ID 分离；动态征召 schema 使用同一注册表和国家政策配方。具体资源读取走 `native:gold / food / equipment / supply` 门面，扣款走原子资源兑换。建筑、地形、外交、视野和周期均通过声明接口获取，不读旧世界字典。

工具 `recruit / move / attack / retreat / disband / army / reachable`，面板 `army`。征召校验本国站点、兵营额度、民兵上限和电网，数量超额度或资源不足时减少到可负担数量，零支则拒绝；新兵当期不可行动。移动只变位置，异地进攻与撤退共用移动额度，原地进攻保留额度；联合进攻先整批校验，无效指令无部分修改。被围攻守军和交战部队不能遣散，批量遣散先完整校验。不可见阻塞按原规则消耗尝试额度，可见阻塞直接拒绝。

路径使用八方向与来源/目标地形较大代价。野地守卫在查询时为虚拟事实，成功进攻才物化，击杀后不重生。补给先于战斗，营内民兵免供，短缺等额扣HP；民兵独立免费回血，每件装备提供30HP总恢复量，由合格正规伤兵平均分配，单支至多回血30HP，按实际总回血量向上取整扣装备，HP小数保存。战斗同时结伤，使用持久随机状态；撤离部队当期继续参加战斗，战后才移动。占领由实际进攻部队裁决，同盟核心收复归还；和平遣返穿过中立地，不占地。

挂点为 `military.supply / battle / withdraw / claims / repatriate`，由发行版声明顺序。军事消耗发布资源事实供经济域汇总，不修改外域账本。显式保存包括单调交战序号和事件接收者快照，恢复校验国家、兵种、位置、计数器及随机种子。

当前联动验收 `tests.test_world_domains`；`tests.test_army_resources` 通过当前发行版验证资源读取权限、原子征召、补给回血、兵种扩展与存取。旧 ArmyLogic 与重复实现已删除；客户端仅使用 PlayerSession。

玩家查询提供 unit_catalog、army 和 tile；只有单格详情 tile 接受坐标。征召直接由 recruit 校验并返回成本和军队编号。native 规则 AI 在客户端用公开军队、地形与建筑事实估算战斗；experimental 研究客户端继续使用发行版注入的概率推演。reachable 玩家工具仅返回可见路径；内部行动裁决仍使用真实地形。

`frontier` 全国批量查询当前可及和可拓荒目的地；`logistics` 军需面板逐军队显示补给需求、免供、断粮损伤、回血装备需求/预计消耗、预计恢复HP和阻碍原因，最后统计补给与装备的需求、库存、消耗和缺口。面板、经济查询与AI资源简报共用领域预演，恢复计划与结算共用，不扣资源，也不假设后续生产。战报、断粮、回血、撤退、遣返均发布事实事件。遣返使用政策移速，以最近本国或盟国土地为目标贪心步进。

批量回执覆盖移动、进攻、撤退、遣散和可达查询。失败以 DomainRejection.details.items 逐支列拒绝原因及通过但未执行者；任何一支失败整批不执行。成功 MilitaryReceipt.items 逐支列位移与本次额度消耗；撤退列攻守角色与待结算状态。盲推实际失败则逐支说明未到达且额度已消耗。批量可达列当前行动状态，几何路线不代表尚有额度，已行动军队原地进攻的例外单独说明。
