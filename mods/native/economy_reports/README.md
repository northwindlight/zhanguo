# 独立经济报表层

当前进展（2026-10-13）：native 4.0.0 已接入其余领域，详见 [正式发行版](../README.md)。下文早期阶段的“未接线”描述保留为历史记录；旧客户端仍另做。

2026-10-12：`native:economy` 1.1.0 拥有一个 `economy` 对象，只汇总库存、生产、建造、交易和显式支出事实。它不拥有资源、市场、建筑或银行状态，不调用旧 `World.res / add_res / _ledger / _spend / alive`。可运行入口为 `mods/economy_acceptance/mod.toml`。

## 模块及接口

- `economy_reports`：事实去重、当周期流量、累计支出、库存与建筑资产、周期报表和增长率。
- `economy_valuation`：提供 `economy:valuation.quote`，从市场只读快照取完整价格，并通过资源域 `value` 调用具体子类的计价行为。
- 资源域 1.3.0 新增只读能力 `native:resource-inspection`：`owners / snapshot / value`。查看账户和估值不需要写库存权限。
- 建筑域 2.1.0 提供 `replacement_costs(owner)`：当前所有者的已落成建筑重置材料清单，不计地形、工程院或政策折扣。
- 市场域 1.1.0 和建筑域阶段适配器现在读取声明中的 `Requires / Before / After`，不再丢弃作者的阶段关系。

经济对象公开 `ingest(facts) / close(period) / settle(period, facts, liabilities=None) / turns / reports / snapshot`。跨域须声明 `native:economy` 的能力与具体方法，通过 `runtime.object_call` 使用。报表和快照均为不可变值；查询不会修改经济账本或其他域。

估值模块无状态，通过固定能力选择提供者；经济层不导入其具体实现。默认估值合同在 `contracts.Valuation`，其他实现仍须返回对应资源、数量与估值记录。

## 事实和计账

累计消费的评测口径用于研究与离线结算，不作为模型可读的游戏规则或策略讲义。结算按各历史国家已记录的建造、征召、军需（含回血装备）和行政四类总消费降序列成绩，亡国保留记录；历史估值不按终局价格重算。使用 `settlement.py --save 路径 --table` 查看，指标的论证和适用条件见[研究论文](../../../docs/research/消费总量评测指标论证.md)。

`EconomicFact` 字段是命名空间事件 ID、账户、周期、类别、投入、产出及实际成交金币。内置类别：`production / construction / import / export / recruit / military / administration`。

建筑生产记录转成逐实例生产事实；建造回执独立转成投资事实，不再把生产报告的汇总消费重复计成另一笔支出。市场实际成交记录转成进出口事实，金额采用整数金币实际支付/收入，不按事后市价重算成交额。

事件 ID 保持稳定：建筑生产使用周期与实例编号，建造使用实例编号，市场成交使用周期与当周期成交序号。相同 ID 与完全相同内容再次提交会被忽略；相同 ID 改内容、未知账户或资源、未来/已关闭周期的新事实均拒绝。事件去重状态随存档保存。

`ingest` 一批事实先完整估值、校验后提交。`settle` 将事实提交与关账视为一个操作：资产估值或关账失败时，不留下半笔新事实。关过的周期重放既有事实返回缓存报表，不重复计账，也不按新行情重估过去。

外域可在报告阶段前把额外的 `EconomicFact` 放入结算上下文 `economic_facts`。native 已接入征兵、军费、外交与通信及银行手续费事实。

## 估值规则及 tea

当前包声明 `ValuationAt = "report-stage"`，统一按经济阶段执行时的行情估值。市场默认在此之前已经完成库存定价结算，所以这里使用的是回归后的完整价格，不是一位小数的展示价格。

现有建筑记录没有保存下单或生产瞬间的价格，本轮不伪造这些历史价格。原混合经济域曾在生产/建造发生时估值；新合同明确采用报告阶段估值。已入账事实保存估值结果，后续行情变动和存档恢复都不重估它们。未来如需发生时估值，需要生产者提供相应价格凭据或在发生阶段捕获估值。

默认顺序：

1. 货币 `native:gold` 按资源子类的现金面值计价，库存透支按有符号面值计入资产。
2. 市场有行情的资源，使用市场快照价格。
3. 未上市资源若在估值模块 `mod.toml` 的 `[Prices]` 中明确声明价格，使用该估价。
4. 无行情且未声明估价，列为未估值。零库存不使账户产生未估值项。

例如茶园产出 `example:tea`，市场未声明它时不会生成行情。若包另外声明：

```toml
[Prices]
"example:tea" = 3
```

2 tea 可计为 6 金，仍不会变成市场商品。声明的估价只在市场没有该资源行情时使用；不能覆盖真实行情。

没有 tea 估价时，报表用 `Money(known=已知小计, unpriced=("example:tea",))` 表示覆盖不足，`total` 返回 `None`，`complete` 为假。GDP、库存资产、总资产及相关比率不会把缺失估价悄悄当成零。已知小计仍可查；未估值项目显式保留。

所有资源估值调用子类的 `value_of`，新资源重写计价行为会生效。未知资源、非有限数量或估价、货币/市场身份冲突拒绝，不回退到旧中文键。

## 流量、存量及报表口径

`TurnReport` 每周期按账户记录：

- 生产产值、生产投入和 GDP：`GDP = 生产产值 − 中间投入 − 能源燃料`。金币产出按现金面值计入，能源本身不是库存商品；实际只有投料的电厂可以产生负增加值，不强行截为零。
- 投资、征兵与军事消耗：独立估值。总支出另含外交、通信及借款手续费的行政消费，共四类；买入货物不混入这条既有累计消费口径，建造和贸易也不重复计入 GDP。
- 进出口额：来自真实成交金币。
- 库存资产：周期末账户资源存量，含金币及显式透支。
- 建筑资产：当前归属下已落成建筑的完整重置金木成本；在建不计入。城堡每级的金与木都计入，补正原混合资产函数遗漏城堡木材的情况。
- 总资产：库存资产加建筑资产。它不是 GDP，捕获/转让建筑影响资产所属，不增加生产流量。
- 当周期支出及从开局至今的累计支出；发布周期报表不清除累计支出。

`ReportEvery = 10` 在包中声明。对象周期从 0 开始，结束周期 9、19……发布一期 `PeriodReport`，记录实际覆盖的起止周期和跨度。新账户第一次报表可以少于完整窗口。

保留旧报告核心口径：GDP 与军事消耗取窗口最后一个周期的速率，投资、征兵、进出口金额按窗口累计，资产是发布时的存量。GDP、投资和资产增长率相对该账户上次发布报告计算；无上期、上期非正或任一估值不完整时为 `None`。

军事消耗占 GDP 的比率使用窗口最后周期的军费与 GDP；GDP 不正或任一估值不完整时为 `None`。

贸易比率为 `(窗口出口额 + 窗口进口额) / (窗口货物产值 + 窗口进口额)`，货币生产不进入这个分母。分母不正时为 0；货物产值未估全时为 `None`。比率没有强制限制在 1 以内。

## 阶段由包声明

默认独立发行版挂点：

```text
buildings.production
market.settlement
buildings.completion
economy.reports
```

经济模块声明消费条件 `buildings.produced / market.settled`，发布 `economy.reported`；阶段结果放在 `context['economy_turns'] / context['economy_publications']`。模块的阶段位置、`Before / After` 与条件依赖来自 `mod.toml`，引擎只进行通用调度与一致性校验。

把发行版的报表挂点移到施工落成之前是合法选择：当次报告中的建筑资产不包括仍在建的楼，但投资已经计入。把报表移到其必需的生产/市场条件之前会被引擎拒绝。另一个模块可以添加新挂点、提交额外事实，或在同一挂点用 `Before / After` 插入阶段，验收覆盖这些情况。

建筑 `produce()` 内部的采集、发电、工业和收入顺序目前仍由建筑模块实现，还没有拆成可插入的独立阶段。本轮没有宣称内部结算顺序完全开放；经济报告消费完整生产结果，不依赖这一拆分。

## 存档与边界

显式协议记录报告周期、货币、下一周期、已估值事实、每周期观察和已发布报表，使用 JSON 数组/映射。加载在候选对象里验证字段、周期、事件身份、资源、值、事实与流量总额、资产加总、窗口报表和发布完整性，成功后才替换现场经济对象。历史估值不按加载时价格重新计算。

旧混合 `mods/native/economy` 保留原路径，本轮经济报表实现位于 `mods/native/economy_reports`。原整局发行版没有接入新经济层，也没有兼容旧面板、排行榜或 RL 入口。央行及新经济工具现已独立落地，完整验收包见 [economic_system](../../economic_system/README.md)；较小的 `economy_acceptance` 继续只加载报表层。

## 经济层完成补充

发行包加载银行模块时，结算上下文传入 `bank_liabilities`，每周期记录与发布报表保存 `liabilities / net_assets`；不加载银行的包没有银行状态或工具，负债为 0。金融流水由银行持有，不伪造生产或消费事实。资源、建筑、市场和经济的模块 `After` 明确恢复次序，支持从空世界恢复合成存档。详见 [央行模块](../bank/README.md) 与 [经济查询](../economy_queries/README.md)。

## 1.3.0：滚动明细与累计检查点

事实按 `(period, owner)` 索引，累计消费从前一期延续，不全扫历史。逐期报告和事实保留最近两个完整报表窗口及当前窗口；滚出的事实与报告经 Session 写入历史分段。检查点分别保留四类消费及原始累计值，避免浮点重组改变历史对账。已发布十期报表永久保留，历史购买不依赖离线归档。

加载国家域时，仅对在世国家关账；亡国当期已经发生的消费事实仍记入累计消费。`spending(owner)` 返回检查点加保留明细，终局不得仅求保留明细的和。
