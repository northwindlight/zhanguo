# 独立 UI Mod

`ui:standard` 是独立、无持久状态的 Mod。native 和 experimental 都在发行版 Members 中装配它；引擎只负责注册，不认识地图或 LLM 提示。UI 不访问 World、native 对象或领域内部接口，消费 Player API 已过滤的 JSON 观察和发行版独立提供的观察者 JSON 快照。

UI Mod 只负责装配：语言目录、终端面板、文字/SVG/PNG 地图与客户端目录的接线。渲染原语位于 [`presentation/`](../../presentation/)，模型视图（system、回合状态、简报裁剪、工具本地化、回执）位于 [`clients/model_view.py`](../../clients/model_view.py)。客户端拥有对话记忆、模型调用和工具执行；`ui/terminal.py` 负责终端输入输出与 ANSI 处理。`ui/` 是装配入口，客户端使用宿主注入的 UI 对象，不再由 UI Mod 组装提示词。

## 配置

成功结束回合时，收到且本期可回应的外交提议若未回应，自动免费拒绝；本期开放的联盟表决若未表态，自动反对。回合结束回执列出自动处理的提议/投票编号，后续回合间通知相关国家，创盟失败通知全体。已提交回应、已接受的创盟邀请和已转内部表决的回应保留；显式弃权保留，新送达邀约等待收件国下一次行动。此行为由发行版统一处理，客户端不会各自猜测超时。

LLM 工具列表不提供 `player_state`；回合开局的战情总纲自动发送，批次之间不再追加上下文（模型本来就带着自己的对话历史与全部工具回执），旧上下文中继续调用该工具会收到未开放的拒绝回执。单独查询 `government` 时，模型收到的正文也不含全部 `summaries`，小结仍由客户端记忆、日志及底层 API 保存。

国策提交回执完整显示正文与最终审核结果；看海日志对同一动作只播报一次，玩家自己的行动历史仍保留。建筑站点回执同时展示已知地名与 0-based 坐标。

议会审核时，底部状态区显示当前国家、资料准备、旧国策核对或新国策审查，以及两阶段累计调用次数；每次模型请求前更新，结束后显示通过、打回或达到上限自动通过。非交互终端按行输出，日志保留完整进度；窄终端优先保证最新状态可见。

议长从第一次请求起收到当前审查 `[x/10]` 轮和所在阶段的提示，两阶段共用轮次；第 6 至第 10 轮每轮催办，告知包含本轮的剩余调用数。完整议会输入、工具声明、思考正文、发言、查询参数与回执、用量及最终裁决以 `📜` 记录写入同一份 journal，仅增量记录，不在终端滚屏，也不发送给君主。传输失败前的请求和错误类型仍会留下记录；配置与接入凭据不写入日志。

native 的 `build/recruit/move/attack/retreat/tile` 都接受 `site` 或 `place`，两者同义；同时填写须指向同一格，也可仅传 `x/y`。地点别名统一后再按原来的归属、迷雾、建筑、能源、资源和行动额度等规则裁决。

军队选择统一用于 `move/attack/retreat/disband/reachable`：`aid=4` 与 `ids=[4]` 等价，多支用 `ids=[4,5]`，双填仅允许 `ids=[aid]`。编号必须为正整数，列表非空且不重复。批量移动、进攻和撤退均先校验整批；移动/撤退的目标对整批相同。多支 `reachable` 返回按 `aid` 分组的 `destinations`，单支仍为坐标与代价列表。观察者每格显示地形，视野内已落成市政厅和城堡也标明数量或等级，仅从本国当前公开观察取数。军队工具声明变化遵循严格存档依赖校验，既有局不自动重启或迁移。

```json
{
  "language": "zh-CN",
  "vision": true,
  "map_max_px": 960,
  "map_estimated_tokens": 2048
}
```

这些配置可在顶层设置并由各国继承；单个国家可覆盖语言和视觉选项。`vision` 默认关闭，开启后给 LLM 发送图形地图。PNG 需要 `python -m pip install -r requirements-vision.txt`；缺少 Pillow 时发送文本地图。SVG 和文字地图不需要 Pillow。

终端：`map 秦` 显示文字地图，`map 秦 output/qin.png` 或 `map 秦 output/qin.svg` 导出图形地图。输出只含该国当时可见事实。命令中的文件路径有空格时用引号包住。

地图与 API 坐标均从 **0** 开始。地形 P/F/H/M/D、T 市政厅、C 城堡、国土颜色、I 步兵/C 骑兵/M 民兵各自支数的读法随图片一起发送；军队外圈绿为自己、蓝为同盟、红为交战方、灰为中立。事实与精确 ID 留在状态 JSON 中。迷雾格为黑色，绘制边界与军队不查询隐藏格。

单国文字地图和图片失败后的回退都有 0-based 坐标轴、归属与地形图例，并附按势力分段的逐格建筑与军队明细；`view` 查询复用同一份坐标明细。军队先列本国、再列他国，野人只给数量与逐格查询指引；逐军区分新兵、已行动、交战、可行动和待撤退。国土与建筑站点显示核心、城堡等级、驻军、当期是否已下单；分页明确本次条数与全国总数。

国祚警报由军队领域提供：仅对无人守卫的已落成市政厅，列出本期可行动、在本国视野内、且按真实路径可抵达的交战敌军。UI 不用距离近似判断安全。领土变更事件记录得失双方、地名、核心和市政厅；仅有实际归属变化才发事件，作为重大近讯优先保留，在回合间增量播报。

国策查询只展示当前战略及有效期，不附历史小结。银行和购买报表回执展示已购报表全文，`report(all=true)` 使用最新优先的一行一期趋势。历史通信与情报按到达顺序最新优先，迟到低编号情报也排在前面；历史查询不改变自动播报的去重游标。外交对象显示保障方向、共同防御、联盟及盟主。

OpenAI 与 Anthropic 共用同一快照和 PNG，只在传输层转换图片块结构。历史保存 `zhanguo.ui.map/1` 事实快照、图例和文字回退，不保存图片/base64；续档会用同一快照重绘，不会用当前世界改写旧图。语言切换也不翻译或重写旧回放、推理签名及玩家正文。

native/experimental 新增 UI 成员后，整局存档的严格模块依赖清单随之改变。1.0 之前不承诺旧档兼容，不做兼容适配或自动迁移；依赖清单不一致即拒绝加载。

## 语言键

`locales/zh-CN.json` 与 `en-US.json` 按相同键提供文案。`language=en-US` 或 CLI `--language en-US` 切换新生成的界面文字。`ui_catalog` 可为 JSON 对象或 JSON 文件路径，覆盖指定键；自定义语言目录未提供的键回退中文。已有界面键的替换须保留占位参数，否则启动时拒绝。

例如：

```json
{
  "ui_catalog": {
    "console.sent": "已发送至 {target}",
    "tools.build.description": "提交建筑施工；是否完成以回执及后续状态为准。"
  }
}
```

工具描述可用 `tools.<动作名>.description`，参数说明可用 `tools.<动作名>.parameters.properties.<参数名>.description` 覆盖；不会改动作名、参数键、枚举或命名空间 ID。UI 编排与 experimental 的审核、交接提示已键化。领域规则、内容展示名、业务回执、手册正文仍由所属领域提供；后续完整语言替换应由对应模块提供键与语言文案，不能翻译 API 身份或随意机器翻译玩家正文。

## 替换 UI Mod

模块声明能力 `ui:presentation`，通过 `presentations()` 注册 `ui:create(cfg)`。工厂返回 UI 接口：`text`、`console.board(rows)`、`console.overview(snapshot)`、`llm(cfg)`、`observer_map(snapshot)`、`map_text(observation)`、`map_snapshot(observation)`、`map_image(observation)`、`map_svg(observation)`、`expand_message(message, vision=...)`。LLM 编排器提供 `system`、`state`、`map_context`、`actions`、`context_plan` 和键值 `text`。

发行版可将标准 UI 成员换成其他提供方。也可在宿主顶层设置 `ui_mods`，指向独立的加载清单（格式同根目录 `ui.toml`）或带 `mod.toml` 的 Mod 目录，覆盖发行版的 UI。独立 UI 装配只用于展示，不改世界模块与存档状态。领域模块不反向导入 UI Mod，客户端不导入 UI 实现类。

## 中文看海控制台

启动时显示命令帮助和存档/日志位置。只在每回合开始自动显示一次全景：世界市场、各国当前七类库存、国土、各兵种军队数量、当前资产负债与有效关系；回合中间和结算后不自动重画表格。库存附上期生产与军队消耗净变化（绿色为增加、红色为减少，不含市场交易和赠礼），并明确标注口径。历史报表、信件和情报不再反复塞进“各国现状”；手动 `board` 仍可随时查看当前全景。

新战报、占领、外交、亡国和通信集中在回合间的“结算动态”增量播报一次，行动中只显示工具回执与调用进度。创盟有人拒绝、发起国撤回或条件失效时，关闭提议并向全体国家公告联盟创建失败及原因；仍在等待答复的提议保持待定。通信按实际到达的消息编号集合去重，迟到的旧编号间谍报告也能显示；续局不重放已有通信。情报、共享地图与赠送物资采用中文专用格式，保留采样回合与完整地块明细，不直接输出原始 JSON。主动查询 `intel` 展示本国收到的历史情报，`news` 按事件格式显示历史近讯；这些查询不改变底层结构化事实。

联盟、战争、亡国等重大公告在模型自动近讯中优先保留，不受普通动作最近十条窗口挤占；载荷仍受配置预算限制，筛选时明确提示通过 `news` 查看完整近讯。

模型每次调用后显示具体行动与实际结果：地点带地名及 `(x, y)`，军队带兵种编号，建造显示实际扣款，交易显示数量、金额和价格变化，国土每格一行，规则按章节显示。军队回执区分立即占领、交战和待撤退；外交区分提交、投票、等待其余创盟成员、拒绝关闭和生效。国策正文仅在提交或修订回执中完整显示。其余长回执和通信在终端约 600 字/10 行封顶，日志保留无颜色控制码的完整中文内容，原始数据由行动审计及领域记录保存。发言进入滚动区，思考默认收起，完整正文保存在日志；`thoughts` 查看最近思考，`thoughts on/off` 切换展开。底部状态区保留上下文计划、当前调用及重试进度。玩家和模型正文保留原文。

`map` 显示观察者全图，`map world.txt/world.svg/world.png` 导出全图；`map 秦 [文件]` 使用秦的过滤视野。每次结算自动更新日志同名的 `.map.txt`。地图渲染由 UI Mod 完成，发行版的 `observer_snapshot()` 仅提供脱离世界对象的事实，全图不会进入玩家工具或模型上下文。

控制台支持旧版公告、寄信别名及多行 `END`；`rate 5` 调整储蓄利率为 5%，`rate` 查看；`cheat 秦 金100 粮20 骑2` 为观察者补助；`add 国名 [政体ID]` 手动登场，新国家复用现有客户端接入设置，新增身份随存档续局。上述管理行为由发行版提供，不开放给玩家。

LLM 行动期间，命令在每次模型调用结束后处理；`quit` 完成当前整回合、保存后退出，`Ctrl-C` 中断并保留最近完整存档。`pause` 在完整回合保存后暂停，`resume` 继续。正在等待模型响应时，输入暂时排队。长命令水平滚动，完整输入仍会提交；终端缩放后按新宽度重画状态区。

## 精简模型表示

地块操作直接用 `x/y`，例如 `{"kind":"farm","x":3,"y":11}`；军队行动使用整数 `aid/ids`。模型状态和工具回执将站点路径表示为 `position:[x,y]`，库存表示为 `stocks:{资源键值:数量}`。军队公共事实移除内部全局编号、自动名称及交战排序编号；行动所需的整数编号、位置、HP和行动状态仍保留。

内容参数默认使用注册表中唯一的短键值，如 `farm`、`food`、`infantry`；多个模块定义同名内容时，使用完整命名空间键值。引擎工具用 `content_parameters=("kind",)` 或 `("resource",)` 声明需要解析的字段，普通正文不会当作内容键值解析。完整键值仍可直接调用。UI 使用发行版注册表提供的键值映射显示状态，不改写原始事实、审计、历史正文或地图快照。

建筑信息无参数调用 `building_economics {}` 一次返回全部类型的造价、配方与按当前市价算的净收益/回本，不接受地块参数；市政厅在给定座数外再加 3 座作乐观密度假设，工程院估算明确列出摊销假设。`building_catalog {}` 提供不依赖市价的各级基础成本、配方、能源、效果及门槛。真实施工须指定坐标；`build {kind,x,y}` 直接校验、扣款并返回施工回执。玩家查询仅 `tile {x,y}` 接受坐标，其余查询按全国或整类返回。默认 LLM UI 只按显式白名单注入决策事实及政体指引；完整规则与建筑/兵种/地形目录按需查询。模型侧的回合状态与工具回执都走观察者同一套中文渲染：状态是按紧迫度分节的战情总纲（威胁／交战／领土／国祚／国力／国策／国土视野／军队／外交／市场／央行／信箱／在途／近讯），坐标地图常驻，可及格数与可拓荒地并入军队节，成交回执末尾报余量。批次之间不再追加上下文，也不再发送结构化差分。历史小结只展示最近两条，完整日志和客户端历史保留。日志保存完整中文行动；原始参数及原始回执另入行动审计；终端截断只影响显示。当前优先完善中文叙述，新增叙述模板的完整国际化另行补齐。

公开规则仍由各模块的 `rule_sections()` 提供：`player_rules(topic="兵营")` 等主题按需查全文。四篇策略讲义与游戏说明书位于 `mods/native/docs/`，是手写文档，不注册为运行时模块，也不进入 `player_rules`。模型侧只常驻显式白名单的决策事实与政体指引；前 20 期的额外剧本背景由 `extra_prompt` 提供。

统一玩家 API 提供 `memory_search(query,limit)`，检索本国历史行动、发言与回执，排除思考。压缩上下文不清除检索源，历史随客户端状态保存；每次检索进入行动审计；非 LLM 客户端也可检索本国近期审计。`countries`、`threats`、`battle` 是不带坐标的整合查询，交战面板在盲战中只展示本国。行情展示买/卖单价，军队显示兵种与逐支HP，报表缺省最近一期，外交面板显示可操作提议和投票编号。

模型简报使用 `model_state_tokens` 预算（默认 12000，最小 1024，按本地估算器计数）：越界时从最不紧迫的节开始整节丢弃，并写明该用哪个工具查全文。地图与军队排在前列，不会是先被丢掉的那一节。近期事件最多 10 条且正文最多 320 字，情报只发最近 10 条索引；完整消息由 intel 查询。此预算不包含用户配置的额外背景、system、工具 schema 或图形 token；完整请求另由 ctx_window 与压缩预算管理。新模块面板不会自动进入模型常驻状态。
