# RL 观测 token 化设计

面向「带记忆的注意力策略」的观测布局。目标不是"更强的网络"，是**把游戏逻辑里
现在表达不了的运算（排序 / 取最近 / 成组）变成可表达的**，同时把成本钉在 CPU
训得动的量级上。

前置约束（用户口径）：**本分支 = main 减去外交；外交以后会加回来**
（会玩 → 外交 → 战争）。所以布局必须**一次定死**，加外交时只填预留位，
不换形状、不废 ckpt。

## 1. 窗口 token（self-attention 的对象）：固定 512

| 组 | 上限 | 字段（全数值，无字符串） |
|---|---|---|
| **G 全局** | 1 | 库存 7 `log1p`、现价 6、均衡价 6、消费 build/recruit/supply、回合/max、本回合步数 `log1p/3`、缺电、电量(有/需)、政体、领地数 `log1p/3`、建筑总数 16 `log1p/3`、军队(数/总HP/各兵种数)、**外交预留 8** |
| **M 地图 patch** | ≤64 | patch 内 `C×p×p` 拍平 → `Linear`；+ patch 中心 `(dx,dy)/POS_SCALE`；+ patch 内可见占比 |
| **A 军队** | ≤192 | 归属 3（自己/他国槽/野人）+ 兵种 3 + `hp/max` + `(dx,dy)/POS_SCALE` + 交战 + 本回合已动 + **情报年龄**（0=本回合可见，k=几回合前见的） |
| **N 势力**（预留） | ≤8 | 关系 6 one-hot + 盟槽 + 领地/军队/HP 估计 + 接壤 + 外交中心数 + 有无待议 |
| **E 事件**（预留） | ≤32 | 类型 emb + 年龄 + actor 槽 + target 槽 + 量级 |
| **R 记忆** | 8 | 每回合池化出 **2 个**，留最近 4 回合 |
| **K 关键节点**（可选） | ≤16 | 城堡/市政厅/瞭望塔/工程院 所在格 |
| **合计** | **393** | 预算 512，留 25% 余量 |

> ★**2026-09-11 实现时的两处偏离**（`rl/tokenize.py` 的 docstring 里有完整理由）：
>
> 1. **M 组不用自适应 patch 边长 `p ∈ {2,4,8,16}`，改成固定 8×8 = 64 格、块边长自适应。**
>    因为 `C×p×p` 拍平后**宽度随 p 变**——同一次训练里不同帧的 token 宽度就不一样，
>    拼批时错位，P4 还得为每个 p 备一个 `Linear`。改成「块内逐通道均值」后宽度恒为
>    `C+3`，与地图/帝国大小无关，分辨率等价。代价是块内布局丢了。
> 2. **A 组宽度 12，不设"情报年龄"那一维**：`World` 没有「这块地何时探明」的记录
>    （只有事件日志 `history`，没有逐格探明时间戳）。与其填一个恒 0 的假特征，不如先不设。
>
> 另：**M 组的地块通道直接取自 `env._obs()` 的网格**（36 通道、已按视野门控、已裁到外接框），
> 不在这里重建一份。所以下面的 `C = 45` 冻结布局是 **P4 的账**（那时 CNN 退场、
> 通道表要冻结）；P2 阶段宽度是 `len(env.obs_channels()) + 3`。

**地图通道 `C = 45`**（冻结）：

```
地形 5 + 地块资源 5 + 归属 11 + 建筑 16 + 每格标量 8
归属 11 = 自己 1 + 国槽 8 + 中立 1 + 野人 1
每格标量 8 = 已用位/20、在建、本回合已建、我方HP/100、敌方HP/100、野人HP/100、边境、曾经探明
```

两个决定在这里钉死：

- **归属用固定 8 国槽**（`vocab.NATION_SLOTS`，槽位由国家码绑定）。
  **加国家不改通道数**——否则观测形状随局内国家数变，ckpt 直接废。
  实测配置是 5 国（秦楚齐燕赵），8 槽留了余量。
- **自适应 patch 尺寸**：`p ∈ {2,4,8,16}`，取"能塞进 ≤64"里**最小**的那个
  （分辨率尽量高）。12×12 外接框 → p=2 → 36 token；30×30 → p=4 → 64；
  100×100 → p=16 → 49。**token 数恒定，分辨率自适应** —— 替换掉现在
  "外接框随帝国长大"的变长做法。

## 2. 位置编码：不用绝对 PE

地图 / 军队 / 事件 token 的位置**以特征形式进入**（相对家的偏移 ÷ `POS_SCALE`），
**不加 learned/rotary 绝对位置编码**。理由与 2026-09-11 那次改动同源：绝对 PE 会把
"我在图哪个位置"漏回去，而那是智能体不可能知道的（迷雾挡着、从未探索过边界）。
坐标进特征还顺带保证平移等变。

**顺序必须是状态的确定性函数**：军队按 `id`、地块按 `(x,y)`、事件按 `(turn,seq)`。
不许用 dict 遍历序——仓库里已经踩过一次（地块命名搬出共享 RNG）。

## 3. 候选 token：不进窗口，走 cross-attention

候选数实测 **中位 132 / p90 890 / 峰值 1376**，塞进窗口就是 O(C²)。

```
候选(Q, ≤1376) ──cross-attn──> 窗口 token(K/V, ≤512)
   → MLP(注意力输出 ⊕ 候选自身特征) → logits
```

- 候选自身特征 = 类型 emb + 子项 emb + 数量 emb + 落点 `(dx,dy)` + 被引用军队的
  `(dx,dy,hp,kind)`。
- 代价 `4·C·K·d` ≈ **0.74 GFLOP**（窗口那部分的 ~19%），可接受。
- 收益：候选**看得见全局，也能在上下文里定位**——"派最近的兵去 X"里的"最近"，
  现在算得出来了。这正是现有点积头在函数类上缺的那一块。
- **候选之间仍然互不可见**（O(C²) 不做）：单挑型策略不需要，这是明知的不做。

**为什么现在这个头表达不了集合级运算**：`logits = q(s)·c(a)` 是双线性形式，
每个候选独立打分。它表达不了 v9（规则 AI）逻辑里最常见的三类运算——

```python
targets.sort(key=lambda p: TROOPS_FOR[...] / max(tile_info(p)[1], 1), ...)   # 排序
def dist_to(p): return min(cheb(a, p) for a in armies)                        # 取最近
near = [a for a in armies if 距离 ≤ 1]; movers[:need_n - len(near)]           # 成组 / 配额
```

候选 "军7→X" 的编码里只有**这一支**军队（`ag` 是 gather 一支），它不知道军3 更近。
另有：卷积只有 2 层 3×3 → **感受野 5×5**，两格以外的东西在候选的地块特征里根本不存在
（连"这格离我家多远"都算不出来）。

## 5. 与 main 的一致性契约

**四条：**

1. **状态源唯一**：tokenizer 只读 `World` 的公开状态，不许有本分支私有的影子状态。
2. **信息集对齐**：能看到的东西 = main 里 LLM 玩家能看到的（`visible_to` + 自家面板）。
   **每个 token 组都必须能在 main 的面板里找到对应项**，找不到就是偷加了特权。
3. **动作集**：`KIND` = main 物理工具集（去掉只读 `query/report/rules/econ/countries`
   与 LLM 专属 `plan`）∪ 外交预留槽。
4. **枚举冻结**：见 `rl/vocab.py`。

**三条测试：**

| 测试 | 守什么 |
|---|---|
| `tests/test_vocab_main_parity.py` | 枚举表逐字逐序 = main；本分支与冻结表的差异**恰好只有外交**；main 的工具集被 KIND 恰好覆盖 |
| `tests/test_branch_behavior_parity.py` | **同一段动作流**（v9 录、两引擎回放）下，两个引擎逐回合逐字段相同 |
| （待写）`test_tokenizer.py` | 同状态两次 tokenize 逐位相等；token 数不超预算；纯函数 |

**★2026-09-12 已处理：G 组的累计消费停供（契约第 2 条）**

契约第 2 条要求"每个 token 组都必须能在 main 的面板里找到对应项"。核查结果：

| | LLM 玩家看得到累计消费吗 |
|---|---|
| `main` | **看不到** —— `mp_ai.py` 的 Observer 面板是「国库/储备/国土/军队/关系/通信」，全仓搜 `累计\|spend_total`，`main:mp_ai.py` **零命中** |
| `feat/rl` | **看得到** —— `mp_ai.py` 第 174 行（Observer 面板）、第 619 行（每回合提示） |

而 `rl/env.py:568-570` 把 `w.spend` 的 build/recruit/supply 喂进了 G 组 ——
**那就是 `spend_total` 拆成三份**（`_spend()` 的 docstring：「全期累计，不随报表清零」，
`spend_total = sum(这三项)`）。所以 G 组里确实是 reward 的原函数，且是**唯一
在 main 面板里找不到对应项的 token 组**。

**处理（方向 B：从 RL 侧去掉，保留形状）**：
- `env.glob_channels()` 新增 —— 逐位通道名，取维**按名字不按下标**
  （写死下标是本仓库反复出事的模式）。`_obs()` 里有断言盯着名字表与构建顺序对齐。
- `tokenize()` 把 `spend:*` 三栏**置零**、宽度照旧。权重留着 → 那几维变成死权重，
  旧 ckpt 不废、将来要加回来也不用改形状。
- 有测试盯着（`tests/test_tokenize.py::TestNoScoreInObservation`）。

> 未处理的一条（**不是 RL 轨的事**）：`feat/rl` 的 LLM 面板**多**了这一行，
> 而 `main` 没有。论证文档 §5.4 主张"给 LLM 也加仪表盘"，但它自己在
> `指标质疑与回应.md` §4 承认**"尚未验证"**，并提了对照实验（同模型同 seed，
> 显示/不显示）。要不要动 LLM 轨，是那边的决定。

**已知的观测层特权缺口**（与 main 无关，是老师/学生之间的）：

- ✅ **2026-09-11 已修：老师不再越权看。** `expand_rule_v9.py` 加了视野门控
  （`vis()` = `World.visible_to`），堵掉四处：`tile_info()` 的 `_new_tile` 开图偷看、
  目标/落点对迷雾格算 `owned_by`/`tile_terrain`、兜底目标取全图野人列表。
  口径 = **LLM 玩家面板的信息集**（`threats` 面板就是 `visible_to`；`land` 面板只给
  野地地形字符、不给资源）。其余规则 AI（v3/v4/v5/v6）**尚未加门控**。
- ~~⬜ `world.tiles` 的持久性 vs 观测只给当前视野~~ → **2026-09-12 核实：这条不成立，已撤回。**

  原文说"学生不会记住走过的地方，**老师却记得**"——**老师不记得**。
  `expand_rule_v9.py` 读 `world.tiles` 只有四处（`tiles()` / `cnt()` / `slots()` /
  建造与征兵循环），**`p` 全部来自 `own`（自家地块，永远可见）**；
  目标地块走 `tile_info()`（内含 `visible_to` 门控），野人走 `vis()` 过滤。
  **老师的信息集 = 当前可见，与学生完全相同。**

  → **对 BC/P4 而言「记忆」无事可做**：老师不用它，就没有可学的东西，也没有
  不对称要补。原文称它为"「记忆」最硬的理由"——**那条理由没了**。

  记忆仍可能是**PPO 阶段**的事（智能体自己探索时，记住走过的地形有没有用），
  但那是**能力问题**，得单独论证，**不是"补上学生与老师的差距"**。
  R 组的槽位照旧留着（形状已定死），填不填是 P5 之后的事。

## 6. 预算与成本

**训练机 = ECS（阿里云，1 物理核 / 3.3 GiB 可用）**，基准见 `训练机器性能简报.md`。
（原锚点「Windows 上一轮 PPO 8 局 10~15 分钟」随该机退出训练而作废；
按 Pi→ECS 的 fp32 训练比 5.9× 重锚。）

窗口 512 token、`d_model=192`、4 层 4 头、≈3M 参数：

| 项 | 值 |
|---|---|
| 窗口前向 | 参数 3.1 + 注意力 0.8 ≈ **3.9 GFLOP** |
| 候选 cross-attn | ≈ 0.74 GFLOP |
| 相对现状（0.13M 点积头，0.11 GFLOP/步） | **≈ 42×** |
| 一局 PPO 更新（现状 ≈ 1 分钟 @ECS） | ~~≈ 42 分钟~~ **实测 ≈ 8.9 分钟**（见下） |

> ★**2026-09-12 实测修正：上面那行"42 分钟"是拿 FLOP 比外推的，错了 7 倍。**
> 真实一局 BC @ECS = **531 s（8.9 min）**：19 s 采样+命中率 + 250 步 × **2.05 s**。
> 错在哪：122k 老模型跑 **batch 256**、候选补到批内最大（K≈400），**算力大半花在
> padding 上**；Transformer 跑 **batch 32**、GEMM 更大更高效。**FLOP 比 ≠ 秒数比。**
> 另：d192/4层实际 **2,083,986** 参数（不是本表估的 3M）。
>
> **真正的约束是内存**：窗口激活 ∝ `batch × token × d_model`，batch=256 时
> **自注意力掩码** `(B,H,T,T)` 一项就 422 MB —— 4 层合计把 ECS 压进 swap，
> 表现是"一步几分钟"，**看着像算力不够，其实是换页**。所以 batch 默认按主干定
> （tf 用 32），并打印粗估。

对照：3.4k 窗口 = 2,300×；16k = 26,000×。
**PPO 的更新侧是硬约束**——它必须对每个存下的 step 用新权重重算整窗前向，
KV cache 在这里无效。所以窗口大小由它定，不由采样定。

**★ 内存约束（ECS 3.3 GiB，硬）**：rollout 缓冲里**存帧、不存 token**。
512 token × d192 存 fp16 = 196 KB/步 × 1.2 万步 = **2.4 GB，装不下**；
存原始帧（bbox 网格 + 候选特征，~60 KB/步 ≈ 720 MB）则可行，
更新时**重建 token 窗口**。这条本来只是"更省"，在 ECS 上是"唯一可行"。

**★ bf16 / 线程数都要在真实模型上量过再定**：简报推荐 ECS 开 bf16，
但它自己那张表里 bf16（48,617 tok/s）**慢于** fp32（59,890），因为测的是 8.6 万参数的
玩具；我们的 3M + 512 序列矩阵大得多，bf16 大概率反超且省一半激活内存。
线程数同理（简报第 3 条：小模型多线程更慢）。别外推，量。

## 7. 落地顺序

1. `rl/vocab.py` + `test_vocab_main_parity` ✅ + `test_branch_behavior_parity` ✅
   （不动模型，先把"和 main 一致"钉死）
2. `rl/tokenize.py`：只出 token 张量 + mask，配纯函数级测试
3. 先接**现有点积头**跑通（tokenizer → 池化 → 原来的 q·c），验证 BC 命中不掉
4. 再换 Transformer 主干 + 候选 cross-attention，加记忆
5. 最后才开 PPO

第 3 步是故意的：**tokenizer 与主干分开验证**。否则换完分数掉了，
分不清是 tokenize 错了还是训练没上来。
