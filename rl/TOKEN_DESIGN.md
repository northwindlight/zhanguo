# RL 观测 token 化设计

面向「带记忆的注意力策略」的观测布局。目标不是"更强的网络"，是**把游戏逻辑里
现在表达不了的运算（排序 / 取最近 / 成组）变成可表达的**，同时把成本钉在 CPU
训得动的量级上。

前置约束（用户口径）：**引擎与 main 逐字相同；外交/战争在引擎里都在，
只是还没进 RL 的动作空间与观测**（会玩 → 外交 → 战争）。
（2026-09-12 之前的口径是「本分支 = main 减去外交」，那条已废弃 ——
砍外交对独局训练零收益，却要每次变基重做一遍手术。见 `rl/README.md`。）
所以布局必须**一次定死**，加外交时只填预留位，不换形状、不废 ckpt。

## 1. 窗口 token（self-attention 的对象）：固定 512

| 组 | 上限 | 字段（全数值，无字符串） |
|---|---|---|
| **G 全局** | 1 | 库存 7 `log1p`、现价 6、均衡价 6、消费 build/recruit/supply、回合/max、本回合步数 `log1p/3`、缺电、电量(有/需)、政体、领地数 `log1p/3`、建筑总数 16 `log1p/3`、军队(数/总HP/各兵种数)、**外交预留 8** |
| **M 地图 patch** | ≤64 | patch 内 `C×p×p` 拍平 → `Linear`；+ patch 中心 `(dx,dy)/POS_SCALE`；+ patch 内可见占比 |
| **A 军队** | ≤192 | 归属 3（自己/他国槽/野人）+ 兵种 3 + `hp/max` + `(dx,dy)/POS_SCALE` + 交战 + 本回合已动 + **情报年龄**（0=本回合可见，k=几回合前见的） |
| **N 势力** = **外交记忆** | ≤8 | 每国一个：关系 6 one-hot + 领土/军队/HP **现值 + 增量** + 接壤 + 上次观察回合 + 外交中心数 + 有无待议（见 §9.5） |
| **E 事件** = **事件记忆** | ≤32 | 按**回合**装填：类型 4 + 年龄 + actor 槽 2 + 落点 2 + 有落点 + 量级 + ok（见 §9.4） |
| **R 记忆** | 8 | ★**退役**（恒 mask、全零）—— 用户口径只有三类记忆，第 4 类"通用池化记忆"没有归属（见 §9.4 末） |
| **K 关键节点** → **地图记忆稀疏槽** | ≤16 | 原为"关键节点"，改作**值得单独钉住的格**：碰过壁的、曾属于我的、远处见过资源的（见 §9.3） |
| **合计** | **393** | 预算 512，留 25% 余量 |

> ★**2026-09-11 实现时的两处偏离**（`rl/tokenize.py` 的 docstring 里有完整理由）：
>
> 1. **M 组不用自适应 patch 边长 `p ∈ {2,4,8,16}`，改成固定 8×8 = 64 格、块边长自适应。**
>    因为 `C×p×p` 拍平后**宽度随 p 变**——同一次训练里不同帧的 token 宽度就不一样，
>    拼批时错位，P4 还得为每个 p 备一个 `Linear`。改成「块内逐通道均值」后宽度恒为
>    `C+3`，与地图/帝国大小无关，分辨率等价。代价是块内布局丢了。
> 2. **A 组宽度 12，不设"情报年龄"那一维**：`World` 没有「这块地何时探明」的记录
>    （只有事件日志 `history`，没有逐格探明时间戳）。与其填一个恒 0 的假特征，不如先不设。
>
> 另：**M 组的地块通道直接取自 `env._obs()` 的网格**（36 通道、已按视野门控、已裁到外接框），
> 不在这里重建一份。所以下面的 `C = 45` 冻结布局是 **P4 的账**（那时 CNN 退场、
> 通道表要冻结）；P2 阶段宽度是 `len(env.obs_channels()) + 3`。

**地图通道 `C = 45`**（冻结）：

```
地形 5 + 地块资源 5 + 归属 11 + 建筑 16 + 每格标量 8
归属 11 = 自己 1 + 国槽 8 + 中立 1 + 野人 1
每格标量 8 = 已用位/20、在建、本回合已建、我方HP/100、敌方HP/100、野人HP/100、边境、曾经探明
```

两个决定在这里钉死：

- **归属用固定 8 国槽**（`vocab.NATION_SLOTS`，槽位由国家码绑定）。
  **加国家不改通道数**——否则观测形状随局内国家数变，ckpt 直接废。
  实测配置是 5 国（秦楚齐燕赵），8 槽留了余量。
- **自适应 patch 尺寸**：`p ∈ {2,4,8,16}`，取"能塞进 ≤64"里**最小**的那个
  （分辨率尽量高）。12×12 外接框 → p=2 → 36 token；30×30 → p=4 → 64；
  100×100 → p=16 → 49。**token 数恒定，分辨率自适应** —— 替换掉现在
  "外接框随帝国长大"的变长做法。

## 2. 位置编码：不用绝对 PE

地图 / 军队 / 事件 token 的位置**以特征形式进入**（相对家的偏移 ÷ `POS_SCALE`），
**不加 learned/rotary 绝对位置编码**。理由与 2026-09-11 那次改动同源：绝对 PE 会把
"我在图哪个位置"漏回去，而那是智能体不可能知道的（迷雾挡着、从未探索过边界）。
坐标进特征还顺带保证平移等变。

**顺序必须是状态的确定性函数**：军队按 `id`、地块按 `(x,y)`、事件按 `(turn,seq)`。
不许用 dict 遍历序——仓库里已经踩过一次（地块命名搬出共享 RNG）。

## 3. 候选 token：不进窗口，走 cross-attention

候选数实测 **中位 132 / p90 890 / 峰值 1376**，塞进窗口就是 O(C²)。

```
候选(Q, ≤1376) ──cross-attn──> 窗口 token(K/V, ≤512)
   → MLP(注意力输出 ⊕ 候选自身特征) → logits
```

- 候选自身特征 = 类型 emb + 子项 emb + 数量 emb + 落点 `(dx,dy)` + 被引用军队的
  `(dx,dy,hp,kind)`。
- 代价 `4·C·K·d` ≈ **0.74 GFLOP**（窗口那部分的 ~19%），可接受。
- 收益：候选**看得见全局，也能在上下文里定位**——"派最近的兵去 X"里的"最近"，
  现在算得出来了。这正是现有点积头在函数类上缺的那一块。
- **候选之间仍然互不可见**（O(C²) 不做）：单挑型策略不需要，这是明知的不做。

**为什么现在这个头表达不了集合级运算**：`logits = q(s)·c(a)` 是双线性形式，
每个候选独立打分。它表达不了 v9（规则 AI）逻辑里最常见的三类运算——

```python
targets.sort(key=lambda p: TROOPS_FOR[...] / max(tile_info(p)[1], 1), ...)   # 排序
def dist_to(p): return min(cheb(a, p) for a in armies)                        # 取最近
near = [a for a in armies if 距离 ≤ 1]; movers[:need_n - len(near)]           # 成组 / 配额
```

候选 "军7→X" 的编码里只有**这一支**军队（`ag` 是 gather 一支），它不知道军3 更近。
另有：卷积只有 2 层 3×3 → **感受野 5×5**，两格以外的东西在候选的地块特征里根本不存在
（连"这格离我家多远"都算不出来）。

## 5. 与 main 的一致性契约

**四条：**

1. **状态源唯一**：tokenizer 只读 `World` 的公开状态，不许有本分支私有的影子状态。
2. **信息集对齐**：能看到的东西 = main 里 LLM 玩家能看到的（`visible_to` + 自家面板）。
   **每个 token 组都必须能在 main 的面板里找到对应项**，找不到就是偷加了特权。
3. **动作集**：`KIND` = main 物理工具集（去掉只读 `query/report/rules/econ/countries`
   与 LLM 专属 `plan`）∪ 外交预留槽。
4. **枚举冻结**：见 `rl/vocab.py`。

**三条测试：**

| 测试 | 守什么 |
|---|---|
| `tests/test_vocab_main_parity.py` | 枚举表逐字逐序 = main；**RL 观测子表 = 冻结表 − MAIN_ONLY**；main 的工具集被 KIND 恰好覆盖 |
| `tests/test_branch_behavior_parity.py` | 引擎文件与 main **逐字节相同**；同一段动作流（v9 录、两引擎回放）下逐回合逐字段相同 |
| （待写）`test_tokenizer.py` | 同状态两次 tokenize 逐位相等；token 数不超预算；纯函数 |

**★2026-09-12 已处理：G 组的累计消费停供（契约第 2 条）**

契约第 2 条要求"每个 token 组都必须能在 main 的面板里找到对应项"。核查结果：

| | LLM 玩家看得到累计消费吗 |
|---|---|
| `main` | **看不到** —— `mp_ai.py` 的 Observer 面板是「国库/储备/国土/军队/关系/通信」，全仓搜 `累计\|spend_total`，`main:mp_ai.py` **零命中** |
| `feat/rl` | **看得到** —— `mp_ai.py` 第 174 行（Observer 面板）、第 619 行（每回合提示） |

而 `rl/env.py:568-570` 把 `w.spend` 的 build/recruit/supply 喂进了 G 组 ——
**那就是 `spend_total` 拆成三份**（`_spend()` 的 docstring：「全期累计，不随报表清零」，
`spend_total = sum(这三项)`）。所以 G 组里确实是 reward 的原函数，且是**唯一
在 main 面板里找不到对应项的 token 组**。

**处理（方向 B：从 RL 侧去掉，保留形状）**：
- `env.glob_channels()` 新增 —— 逐位通道名，取维**按名字不按下标**
  （写死下标是本仓库反复出事的模式）。`_obs()` 里有断言盯着名字表与构建顺序对齐。
- `tokenize()` 把 `spend:*` 三栏**置零**、宽度照旧。权重留着 → 那几维变成死权重，
  旧 ckpt 不废、将来要加回来也不用改形状。
- 有测试盯着（`tests/test_tokenize.py::TestNoScoreInObservation`）。

> 未处理的一条（**不是 RL 轨的事**）：`feat/rl` 的 LLM 面板**多**了这一行，
> 而 `main` 没有。论证文档 §5.4 主张"给 LLM 也加仪表盘"，但它自己在
> `指标质疑与回应.md` §4 承认**"尚未验证"**，并提了对照实验（同模型同 seed，
> 显示/不显示）。要不要动 LLM 轨，是那边的决定。

**已知的观测层特权缺口**（与 main 无关，是老师/学生之间的）：

- ✅ **2026-09-11 已修：老师不再越权看。** `expand_rule_v9.py` 加了视野门控

  目标/落点对迷雾格算 `owned_by`/`tile_terrain`、兜底目标取全图野人列表。
  口径 = **LLM 玩家面板的信息集**（`threats` 面板就是 `visible_to`；`land` 面板只给
  野地地形字符、不给资源）。其余规则 AI（v3/v4/v5/v6）**尚未加门控**。
- ~~⬜ `world.tiles` 的持久性 vs 观测只给当前视野~~ → **2026-09-12 核实：这条不成立，已撤回。**

  原文说"学生不会记住走过的地方，**老师却记得**"——**老师不记得**。
  `expand_rule_v9.py` 读 `world.tiles` 只有四处（`tiles()` / `cnt()` / `slots()` /
  建造与征兵循环），**`p` 全部来自 `own`（自家地块，永远可见）**；
  目标地块走 `tile_info()`（内含 `visible_to` 门控），野人走 `vis()` 过滤。
  **老师的信息集 = 当前可见，与学生完全相同。**

  → **对 BC/P4 而言「记忆」无事可做**：老师不用它，就没有可学的东西，也没有
  不对称要补。原文称它为"「记忆」最硬的理由"——**那条理由没了**。

  记忆仍可能是**PPO 阶段**的事（智能体自己探索时，记住走过的地形有没有用），
  但那是**能力问题**，得单独论证，**不是"补上学生与老师的差距"**。
  记忆的定稿见 **§9**（2026-09-12 用户定：只限外交/事件/地图三类）。

## 6. 预算与成本

**训练机 = ECS（阿里云，1 物理核 / 3.3 GiB 可用）**，基准见 `训练机器性能简报.md`。
（原锚点「Windows 上一轮 PPO 8 局 10~15 分钟」随该机退出训练而作废；
按 Pi→ECS 的 fp32 训练比 5.9× 重锚。）

窗口 512 token、`d_model=192`、4 层 4 头、≈3M 参数：

| 项 | 值 |
|---|---|
| 窗口前向 | 参数 3.1 + 注意力 0.8 ≈ **3.9 GFLOP** |
| 候选 cross-attn | ≈ 0.74 GFLOP |
| 相对现状（0.13M 点积头，0.11 GFLOP/步） | **≈ 42×** |
| 一局 PPO 更新（现状 ≈ 1 分钟 @ECS） | ~~≈ 42 分钟~~ **实测 ≈ 8.9 分钟**（见下） |

> ★**2026-09-12 实测修正：上面那行"42 分钟"是拿 FLOP 比外推的，错了 7 倍。**
> 真实一局 BC @ECS = **531 s（8.9 min）**：19 s 采样+命中率 + 250 步 × **2.05 s**。
> 错在哪：122k 老模型跑 **batch 256**、候选补到批内最大（K≈400），**算力大半花在
> padding 上**；Transformer 跑 **batch 32**、GEMM 更大更高效。**FLOP 比 ≠ 秒数比。**
> 另：d192/4层实际 **2,083,986** 参数（不是本表估的 3M）。
>
> **真正的约束是内存**：窗口激活 ∝ `batch × token × d_model`，batch=256 时
> **自注意力掩码** `(B,H,T,T)` 一项就 422 MB —— 4 层合计把 ECS 压进 swap，
> 表现是"一步几分钟"，**看着像算力不够，其实是换页**。所以 batch 默认按主干定
> （tf 用 32），并打印粗估。

对照：3.4k 窗口 = 2,300×；16k = 26,000×。
**PPO 的更新侧是硬约束**——它必须对每个存下的 step 用新权重重算整窗前向，
KV cache 在这里无效。所以窗口大小由它定，不由采样定。

**★ 内存约束（ECS 3.3 GiB，硬）**：rollout 缓冲里**存帧、不存 token**。
512 token × d192 存 fp16 = 196 KB/步 × 1.2 万步 = **2.4 GB，装不下**；
存原始帧（bbox 网格 + 候选特征，~60 KB/步 ≈ 720 MB）则可行，
更新时**重建 token 窗口**。这条本来只是"更省"，在 ECS 上是"唯一可行"。

**★ bf16 / 线程数都要在真实模型上量过再定**：简报推荐 ECS 开 bf16，
但它自己那张表里 bf16（48,617 tok/s）**慢于** fp32（59,890），因为测的是 8.6 万参数的
玩具；我们的 3M + 512 序列矩阵大得多，bf16 大概率反超且省一半激活内存。
线程数同理（简报第 3 条：小模型多线程更慢）。别外推，量。

## 7. 落地顺序

1. `rl/vocab.py` + `test_vocab_main_parity` ✅ + `test_branch_behavior_parity` ✅
   （不动模型，先把"和 main 一致"钉死）
2. `rl/tokenize.py`：只出 token 张量 + mask，配纯函数级测试
3. 先接**现有点积头**跑通（tokenizer → 池化 → 原来的 q·c），验证 BC 命中不掉
4. 再换 Transformer 主干 + 候选 cross-attention，加记忆
5. 最后才开 PPO

第 3 步是故意的：**tokenizer 与主干分开验证**。否则换完分数掉了，
分不清是 tokenize 错了还是训练没上来。

## 9. 记忆（2026-09-12 用户定稿）

用户口径原话：

> 要有记忆，不过**只限外交记忆，事件记忆和地图记忆**，同时**地图记忆可能需要的东西更多**，
> 包含**曾经占有的地块，视野内曾发现敌军，盲行军得到的报错信息**。

### 9.0 地基：记忆是 **agent 侧的**，不是世界侧的

这一条同时解释了「为什么它不违反契约 §1（状态源唯一）」，以及「为什么它必须这么做」：

| | 记忆存在哪 |
|---|---|
| LLM 玩家 | **它的上下文里**：`mp_ai.py:1321` 把工具返回值原样 append 进 messages；`_store_turn_memory`（`mp_ai.py:1040-1053`）**整回合完整存**，滑出后再由 LLM 压成 ≤800 字摘要（`mp_ai.py:1087`） |
| RL agent | `rl/memory.py` 里一个**agent 侧缓冲** —— 不改 `World` 一个字节 |

契约 §1 说的「不许有本分支私有的影子状态」指的是**世界状态**（不许自己维护第二份 `tiles`）。
记忆不是世界状态 —— **世界没有"玩家记得什么"这回事**，记得什么的是玩家。

**写入规则只有一条**：

> **记忆只能由「agent 当回合合法观测到的东西」写入。**
> 合法观测 = `env._obs()` 给的东西 ∪ 该回合动作的返回文本（`info["msg"]`；
> LLM 从工具返回值拿到的是同一句话）。

这条规则是**可测的**：每个记忆条目都必须能追到「第几回合、哪次观测 / 哪次动作」。
也正因为它可以测，它才挡得住"记忆悄悄变成偷看"——`_place_crosses`
（`mp.py:409-415`）把各国开局地块都建进 `world.tiles` 那件事就是这么被堵住的。

### 9.1 三类记忆各自的信息集锚点（每一类都能在 main 里找到对应项 ← 契约 §2）

| 记忆 | 引擎里已有的对应实现 | 现状 |
|---|---|---|
| **事件记忆** | `World.events_for(name, limit)`（`mp.py:366-378`）—— 已按 `visible_to` 门控：`h["nation"]==name` 无条件给，其余看**落点是否可见**。LLM 的【近讯】面板就是它（`mp_ai.py:379`→`_fmt_news`，limit=10） | **RL 侧一个字都没用**（E 组恒 mask） |
| **外交记忆** | `mp_ai` 的 Observer 面板的各国**国土/军队/关系**（`main:mp_ai.py:355`、`feat/rl:mp_ai.py:173`） | G 组已有**现值**（`rival_tiles/armies/hp`，`rl/env.py:619-625`）；**记忆补的是"上回合是多少"** |
| **地图记忆** | `World.visible_to`（`mp.py:334-348`）的**逐格历史** | 完全没有 |

### 9.2 ★先读这一条：独局下地图记忆的信息增量 ≈ 0（已实测）

**训练制式是单国独局**：`ZhanguoEnv` 的 `rivals` 默认 `()`（`rl/env.py:111`），
`bc.py` / `train.py` / `compare.py` **没有一个传 rivals**。所以地图上只有你 + 野人。

而 `_vision_mask`（`rl/env.py:412-435`）= 自家格 ∪ 八邻 ∪ 瞭望塔圆，
**自家领土在独局里只增不减**（没有对手能夺地；野人只防守不进攻，`mp.py:428-448`），
于是**视野是单调递增的**：今天看得见的 ⊇ 曾经看得见的。
野人还是**静态**的（`mp.py:431-433` 注释原话「野人是地图的静态属性」），
瞭望塔也不会被拆 —— 没有任何一条路径能让一个格子"看过又看不见"。

实测（v9 跑满 70 回合，`map ∈ {16,32}` × `seed ∈ {3,11}`）：

| map | seed | 曾见过 | 当前可见 | **曾见但当前不可见** |
|---|---|---|---|---|
| 16 | 3 | 55 | 57 | **0** |
| 16 | 11 | 52 | 55 | **0** |
| 32 | 3 | 83 | 85 | **0** |
| 32 | 11 | 81 | 81 | **0** |

→ **「把网格裁到探明外接框」在独局里与现在的可见外接框完全等价**（探明 bbox 11×11 vs
可见 bbox 11×12，逐格算过，没有一个"见过但现在看不见"的格）。
PLAN 里那条「很多地方要改」的担心（网格变大 → mlp 路 CNN 成本涨）**在独局里不存在**。

**它什么时候才有内容**：等**加对手**（`rivals≠()`）。那时领土会易主、他国军队会进出视野、
你在边境外看见过的东西会被忘掉 —— 这正是它的设计目标（路线图：会玩 → 外交 → 战争）。
**在那之前它是死权重**，和 G 组停供的累计消费三栏一样。

**独局下仍然真实存在、且只有一块**：**盲行军的遭遇**。因为

- 军队**不提供视野**（`visible_to` 只看领土与瞭望塔，`mp.py:334-348`）——
  这是"盲行军"的成因，不是 bug；
- 孤军在外时它脚下那格在观测里 `vis=0`、地形全 0（`_obs` 的 `chans[i] *= vis`，`rl/env.py:510-513`）；
- 你对那格发起 `atk`，引擎回的文本（`mp.py:807-819`："与野人交战" / "敌人为 0，拓疆「地块名」地形"）
  **只存在于动作返回值里**，观测里一个字都没有 —— 而 LLM 从工具返回值拿到了它。

最典型的一例：**同归于尽**（`mp.py:1010` 那一支）—— 你的军队和守军一起死光，
野地维持无主。观测里你只知道"军队没了"，**不知道那格现在空了**，
而下一回合你本可以零代价走进去。这条信息现在**两边都只存在于动作返回值里**：
LLM 留在上下文，RL 直接丢（`rl/env.py:183` 的 `info["msg"]` 谁都没接）。

### 9.3 地图记忆：逐格「最后已知 + 我的遭遇」

**新增 `rl/memory.py`**（agent 侧，随 episode 重建，不被 `World` 引用）：

```python
tile[(x, y)] = {
    "seen_turn": int,          # 最后一次看见它的回合；-1 = 从没看见过
    "terrain": str | None, "resources": dict,
    "owner": str | None, "buildings": dict,
    "probe": None | {"turn": int, "kind": ProbeKind, "note": str},
}
foes[key] = {"owner", "kind", "x", "y", "hp", "seen_turn"}
```

- **`probe`（★盲行军得到的报错信息）** —— `kind` 是个小冻结表：
  `atk_lost`（同归于尽/打输，那格现在是空的/仍有守军）、`blocked`（不可进入）、
  `atk_ok`（打赢了/无守军，进驻）。
  来源就是 `_apply` 的返回值 `(ok, msg)`。
- **写入时机只有一处**：每回合末（`_run_round_end` 之后）按该回合的 `_vision_mask()`
  刷新 `tile`，并把本回合拿到的带落点动作结果写进 `probe`；把当前可见敌军刷进 `foes`。
  **别分散写** —— 分散写就没人能证明"每条都来自合法观测"。

**读出（`tokenize`）**：

- **网格**：bbox 从「可见外接框」扩到「`tile` 里出现过的格的外接框」。独局下二者相同（§9.2），
  加对手后才有差别。非当前可见但见过的格**填最后已知值**；新增两个通道：
  `remembered`（1 = 这格我有记忆；与 `visible` 正交，解决"零值和没记忆分不清"）、
  `probe`（1 = 我在这格碰过壁）。→ **通道数 36 → 38**（一次加完，之后不再动）。
- **A 组**：自家（原样，**必须在前的顺序不变** —— `army_idx` 指着它）
  + 当前可见敌军（原样）+ **曾见但当前不可见的敌军**
  （按 `(age, owner, x, y)` 确定性排序，接在可见段之后）。
  → `F_A` 第 12 维**"情报年龄"终于能填**（`age = turn - seen_turn`，当前可见的填 0）。
  `rl/tokenize.py` 的「偏离说明 2」就是为它留的位。
  **截断规则**：超 192 时从最旧丢，丢了多少记进 `meta`。
- **K 组**（16 槽，原本"关键节点"、倾向不设）**改作地图记忆的稀疏槽**：
  值得单独钉住的格（碰过壁的、曾属于我的、远处见过资源的），带 `(dx,dy)` + 类型 + 年龄。
  **为什么需要它**：M 组恒 ≤64 patch、块边长随外接框自适应 ——
  外接框一大，**丢的恰恰是"哪一格特殊"**（`rl/tokenize.py` docstring 已记这条代价）。

### 9.4 事件记忆（E 组，32 槽）

**两个来源，都是 LLM 上下文里本来就有的东西**：

1. **引擎日志**，口径直接用 `World.events_for`（`mp.py:366-378`）—— **别自己写第二份过滤**
   （契约 §1）。它只读、不碰 `history_seen`，可以放心调。
2. **自己的动作与结果**（`info["msg"]`）—— `rl/env.py` **现在完全不记**，
   也**不写 `world.history`**（与 `mp_ai.py:816` 的 `log_tool` 不同）。所以这块现在是纯丢弃。

**★容量问题（先解决它）**：PPO 下一回合 ~70 步，32 槽连本回合都装不下；
而**本回合的动作本来就还在状态里**（`turn_actions`、国库、地块…），逐条记它没有意义。
所以 E 组**按回合装填**：

- 每次 `end_turn` 时，把本回合的动作结果**压成 ≤2 条摘要**入池
  （"本回合：3 次进攻，占 2 格，1 支阵亡"），**逐条不入池**；
- 引擎日志（`events_for` 口径）**按条**入池；
- 池满丢最旧，`age = turn - 事件回合`。

**这是对原 R 组（"每回合池化 2 个 × 近 4 回合"）的收编**：机制留着，但**只服务事件记忆**。
→ **R 组退役**（恒 mask、全零）：用户口径只有三类记忆，第 4 类"通用记忆"没有归属。

**宽度 `F_E = 12`**：类型 4（one-hot：行动 / 战报 / 领土 / 内政）+ 年龄 1 + actor 槽 2
+ 落点 `(dx,dy)` 2 + 有落点 1 + 量级 1 + ok 1 = 12。
（`tokenize.py` 里 `F_E` 现值 12 —— **宽度不用改**，只把语义定死。
actor 槽沿用 `NATION_SLOTS` 的槽位口径，野人单占一槽。）

### 9.5 外交记忆（N 组，8 槽）

**单国独局下无外交**：`rivals=()` → 一个对手都没有（引擎只建 `["秦"]`）。
所以 N 组**现在恒空**，与 `tests/test_tokenize.py::TestDiploReserved` 的断言一致 ——
**这一条不用改**。（引擎那侧的外交代码在，但独局里没有对象可用。）

定死的是**加对手 / 外交回来时填什么**：每国一个 token ——
关系 6 one-hot + **领土现值/增量** + **军队现值/增量** + **HP 现值/增量** + 接壤
+ **上次观察回合** + 外交中心数 + 有无待议。

**现值来自面板、增量来自记忆**：LLM 的上下文里有它每回合读过的面板，所以它算得出增量；
RL 若只有现值就算不出。**这是这条记忆补的唯一一处不对称** —— 也正因如此，
它和 G 组的 `rival_*` 现值**不重复**（现值照旧在 G，N 只放"变化"）。

### 9.7 ★盲行军是**探测手段**，不是 bug（用户 2026-09-12 追加口径）

> 原话：「迷雾泄露很有价值，因为**盲行军可以探索敌国位置**」。

**口径定死**：`move`/`attack` 被拒时那句「不可入境：(x,y) 是「楚」的领土」**不是要修的洞，
是游戏给的探测传感器**。玩家花一步（军队本回合的移动额度）换一条情报，这是**代价换信息**的
正常设计，与"偷看"的区别恰恰在于**你要付出动作**。所以：

- **不堵**。不改成"前方情况不明"之类的模糊回话 —— 那是**换规则**（用户口径：别换规则）。
- **要记**。拒绝消息落进 §9.3 的 `tile[(x,y)]["probe"]`（`kind="blocked"`，记下 `owner`）。
  于是「曾经占有的地块 / 曾见敌军 / 盲行军报错」三件事在**同一个结构**里闭环。

**★★ 但有个前提必须先拆掉：RL 的候选枚举现在用真值过滤，等于把这份情报白送。**

`rl/env.py` 有三处拿 `World` 的**真值**做筛选，Agent 从"**哪个候选不在表里**"就能反推出
情报 —— 不用花动作、不用探测，而且**一次覆盖整个速度半径**，比那句拒绝消息**强得多**：

| 位置 | 现状 | 后果 |
|---|---|---|
| `rl/env.py:337-341` | `o = w.owned_by(x,y)`；`if o is not None and o != me: continue` | **速度半径内少了哪个候选 = 那格是他国领土**（"不可入境"的信息白拿） |
| `rl/env.py:342-343` | `busy = any(d["owner"] not in ("野人", me) and d.get("engaged") and ...)` 扫**全图** `w.armies` | 候选被压掉 = 那格有看不见的他国军队在打野 |
| `rl/env.py:232-234` | `_retreat_legal` 用 `owned_by` 真值判八邻 | 撤退候选的形状泄露四周 8 格的归属 |

**改法：把这三处的判据从「世界真值」换成「agent 的记忆」**（§9.3 的 `tile`）：

- 记忆里**已知是他国** → 不生成（探测过了，别重复付代价）；
- 记忆里**不知道** → **照生成**，让它去撞、去被拒、把结果记回来。

这样就形成一个干净的自限循环：**探测一次 → 记住 → 候选里消失 → 不会再付第二次代价。**
（独局下这三处本来就一次都不触发 —— `rivals=()` 时 `owned_by` 只可能返回自己或 `None`，
所以这条改动**在独局里是 no-op**，可以安心先落代码、等加对手自动生效。）

**⚠ 但要说清 PPO 会不会自己发现它**：`feat/rl` 里**没有战争也没有外交**
（`mp.py:7-8`：他国领土不可进入、不可攻击），而 reward = **自己的总消费** ——
知道楚在哪，**当前分支里没有任何可兑换的收益**。所以：

- 独局 + 无外交 ⇒ **PPO 学不出探测**（探测花一步、收益 0），别指望；
- 战争/外交回来之后 ⇒ 探测才有价（找到敌国城池去打），那时 PPO 才可能自己发现它。

→ 所以 9.7 的正确落地时机和 §9.6 的 2/3 步**完全一致：跟着加对手 / 外交一起上**。
**在那之前，它是一条"设计上留着、行为上禁用"的规则** —— 写在这里是为了
**别在将来看到"候选里有注定失败的动作"时把它当 bug 删掉**。
