# 诊断报告：BC 学生「市场空转、从不建兵营、零扩张」

> 2026-09-12 · 战国（`northwindlight/zhanguo`）RL 训练线 · 供外部讨论

## 0. 系统是什么

一个 4X 策略游戏（`~/projects/python/zhanguo`，Python 引擎 `mp.py`）。
我们训一个 RL agent 玩**单国独局**（地图上只有自己 + 野人守卫），
框架是 **BC（行为克隆）→ 之后才 PPO**，老师是一支手写规则 AI（`expand_rule_v10`）。

- **目标函数 / 奖励 = 终局「总消费」**（支出法：建造 + 征兵 + 军费，按当时市价折金）。
  市场买卖**不计入**消费（买来的物资只有在真正被消耗时才入账）。
- 观测：可见区网格 + 全局向量 + token 窗口（352 token，自注意力主干 + 候选 cross-attention）。
- 训练期**域随机化**：每局按 seed 重采样一整族规则数值（建筑造价/产出/市场价/兵种属性/
  地形属性/建筑效果，±20% 对数均匀），目的是让模型学「给定这组数值该怎么打」而不是背下标。
- 训练局长 **70 回合**（用户口径：70 回合覆盖的是**开荒**；后期是"复制模式"，不专门学）。
- 评估：**真值表**（不抖动）、固定 seed、多图、与规则基线比**终局消费**与**领地**。

## 1. 现象

同一份学生权重，在 3 张图（seed 500000~500002）、真值表、70 回合下：

| | 消费 | 相对老师 v10 | 领地 | 动作/回合 |
|---|---|---|---|---|
| 老师 v10 | 3,842 | ×1.00 | **28.0** | **5~6** |
| 学生·贪心 | 2,722 | ×0.71 | **5.0** | — |
| 学生·采样 | 2,423 | ×0.63 | **5.0** | **18.5** |

（领地 5 = 开局十字，**一格没占**。）

### 1.1 学生一局的动作分布（采样）

步数 1,213（70 回合）：`sell` 650、`buy` 468、`end_turn` 70、`build` 25，
**`recruit` / `move` / `attack` 各 0 次**。

### 1.2 学生一局建了什么

场上建筑：林场 10、农场 6、矿场 3、石油厂 3、木材能源厂 **1**、补给厂 1。
**兵营 0、军屯 0、市政厅 0、工程院 0、瞭望塔 0、黄金矿场 0、石油能源厂 0。**

（同一份权重的前一版：木材能源厂 8、补给厂 3、总建造 30 —— 能源厂从 8 掉到 1。）

## 2. 因果链（每一步都有实测）

1. **没建兵营/军屯**（场上 0 座）⇒ 征兵候选**根本不存在**（引擎只允许在有兵营/军屯的格子征兵）
   ⇒ `recruit` 恒 0 ⇒ 无军队 ⇒ `move`/`attack` 恒 0 ⇒ 领地恒 5。
   *所以"不征兵"不是策略偏好，是候选集里没有这一项。*
2. **大件买不起**：兵营 350 金 + 20 木、木材能源厂 120 金 + 15 木，
   而它建的全是 45~70 金的便宜货（林场/农场/矿场）。
3. **为什么攒不下钱**：BC 监督的是「每一步选哪个动作」——**"省着不花"不是动作，是"少做动作"**。
   老师的标签里交易占约八成（它每回合都卖余量换现金、买缺的那种投料），
   学生的边际策略就是"交易" ⇒ 预算全花在买卖上 ⇒ 现金永远到不了 350。
4. **而它连"停手"都没学会**：老师每回合 **5~6** 个动作，学生 **18.5** 个。
   疑点：DAgger 的 `endturn_cap=1`（每回合最多 1 条 `end_turn` 标签，
   当初为治"九成标签都是 end_turn"而加）可能**矫枉过正** ——
   1 条 stop 标签被 5 条交易标签稀释 ⇒ 策略的停止概率被压低 ⇒ 推理时不停 ⇒ 空转。

## 3. 一个关键旁证：消费这个指标能被"资本开支"套出来

同一批图，**起点权重**（只训过 4 局）：**5 格 / 0 征兵 / 0 进攻 / 30 次建造**，
消费却到老师的 **×0.95**。老师是 **28 格**打出同样的数。

⇒ **同样的消费，两种完全不同的打法。** 只看消费会把"空转刷分"误读成"学会了开荒"；
评估前期**必须看领地**（本文所有表都带这一列）。

## 4. 候选修法（含代价）

### 修法 A：给动作空间封顶「每回合 ≤5 次 sell、≤2 次 buy」

- **为什么这个数**：实测老师**从没有一回合卖超过 5 次**（0/210 回合），买超过 2 次只 1.9%
  ⇒ 封顶**几乎不碰老师**（不会造成标签失配），却把学生的 18.5 动作/回合砍到 ≤7。
- **机制**：不是"逼它干别的"，而是**逼它攒钱**（买被封 → 现金留在账上 → 大件买得起）。
- **抗辩**：「买卖用完了它就结束回合」——**在这个机制下恰恰是想要的**（结束回合 = 留着钱）。
- **代价/风险**：
  - 实现在 RL 环境的候选枚举里（引擎不动）；老师/基线不走候选集，**不受影响**（对比仍公平），
    但约 1.9% 的回合里老师的第 3 次买会被 `match()` 降级成同类别兜底标签 ⇒ 少量标签失真。
  - 它治的是**症状**（预算被买卖吃掉），不是根因（没学会停手/攒钱）。
  - 封顶是**永久的设计约束**：它会把"多回合分批卖货"这种策略也一起禁掉。

### 修法 B：调 `endturn_cap`（1 → 2 或 3）

- **机制**：直接治第 2.4 条的根因（学生没学会停手）。停止概率上去 ⇒ 动作/回合回落到老师的 5~6
  ⇒ 交易自然少 ⇒ 现金自然留 ⇒ 大件买得起。
- **代价**：这个 cap 当初就是为治"标签被 end_turn 淹没"而加的（加到 90%），
  往上调有**回退到旧病**的风险（策略退化成"什么都不做"）。需要扫 1/2/3 三档看行为。
- **好处**：只改一个已有开关，不引入新的游戏规则约束。

### 修法 C（不改数据/环境）：先验证"给钱它会不会建兵营"

**未验证的关键假设**：封顶/攒钱之后，模型**愿不愿意**建兵营？
它现在 25 次建造里 0 次兵营 —— 可能是"没钱"，也可能是"标签里兵营太少、模型不偏好它"。

**可做的实验**（很便宜）：造一个局面，开局直接把国库塞到 400 金 + 40 木、
给一块合法地块，看模型在**有购买力**时会不会下兵营。
- 会 → 根因是"攒钱"，修法 A/B 都对症。
- 不会 → 根因在**标签分布**（`兵营`/`recruit` 是稀疏类，被高频的交易类淹没），
  需要类权重/课程（从老师的中局状态起手）之类的办法。
