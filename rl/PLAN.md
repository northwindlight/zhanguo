## 一、为什么换线

**旧线**：**一个**模型吃全观测 → 吐引擎动作空间里的**任意动作**（建造/征兵/买卖和移动/攻击
混在同一空间），目标挂**终局总消费**。病根已量化（`--grad-diag`）：`coh(pg)=0.0635`，
噪声底 `1/√230=0.0659` ⇒ **回报信号对更新方向没有系统贡献**；`cos:pg:bc=−0.778`（与 BC 锚互相拆台）。

**新线**：**每个目标单独炼一个模型**，问题切小 ⇒ 动作空间小、判据清楚、每个模型都小到能快跑。

### 国祚（市政厅）的口径 —— 2026-09-21 起，`2d66417`

- **国祚 = 市政厅**：`has_townhall` = 名下有**已落成**的厅（在建不算）；
  `_eliminate_if_dead` **厅尽失即亡，领土还在也照亡**。
- **开局白送**：`_place_crosses` 在十字开局**中心格**送一座（不花钱、不受 `min_slots≥6` 约束），
  中心格**强制平原**。⇒ **每个国家开局就有一座厅**，场景天然有目标。
- **亡国余土成无主废墟**：`owner`/`core` 置 None、**建筑原样留着**、**不补野人守卫** ⇒ 废墟**白捡**。
- ★ **市政厅对他国公开**（`_public_buildings`：视野内的他国地**只公开城堡与市政厅**）——
  原话「**看不见就打不着**，不公开这条规则就是死的」。

## 三、★ 首个沙盒：攻取国祚（8×8 自对弈）

**用户 2026-09-24 原话**：「直接 ppo 对抗，例如一个 8x8 的地图，放两个国家，开局每人 5 个步兵，
每五个回合补一支，**奖励是拿下对手的市政厅**，**开局告诉模型自己市政厅和敌人市政厅的位置**，
**稀疏奖励**。类似 alpha zero 那样训练。」

### 3.1 规格

| 项 | 值 |
|---|---|
| 地图 | **8×8**，两国（甲 / 乙） |
| 开局 | 每国 **5 个步兵**，摆在**自己的核心格** |
| 补员 | **上限 = 5 + 本国国土数 // 10**（开局 5 格 ⇒ 上限 **5**，与"开局 5 步兵"自洽；8×8 最多 32 格 ⇒ 上限 8）。**每 5 回合触发一次**：把军队**补足到上限**（★不是"每次 +1"、**不无限加兵**）。补在核心格，规则白给、**不经经济层** |
| 国祚 | 每国核心一座市政厅（`_place_crosses` 白送） |
| **终局** | **一方拿到对手的市政厅** ⇒ 本局立即结束（**不设固定回合数**） |
| **兜底** | **T_max = 200 回合**（只防僵局；用户 2026-09-24：「40 回合不够」）⇒ 到时判平 |
| **奖励** | **赢 ⇒ `1 − turns / T_max`**（★用户：「时间越短奖励越高」）；**输 ⇒ −1**；**平 ⇒ 0** |
| **观测** | **完全信息**：开局即知**双方市政厅位置**；军队/地块位置可见（8×8 不用迷雾） |
| 野人 | **清空**（`guard_once` 填满全图防重生）——本沙盒里没有野人 |

### 3.2 实测过的可行性（2026-09-24）

```
World(size=8, seed=0, nations=['甲','乙'])
  → tiles = 10（两国各 5 格十字）
  → 甲 市政厅 (4,2)   乙 市政厅 (4,6)      ← 自动送的，不用手搓
  → 开局军队 = 0（要自己摆）；野人 = 54（要清）
```
- ✅ `w.armies` 过滤 + `w.guard_once` 填满全图 ⇒ 野人剩 **0**
- ✅ `_new_army(owner)` + append ⇒ 摆得出 5 步兵
- ✅ `resolve_turn()` 跑通
- ⚠ **坑**：军队别摆在 `own_tiles[0]`（字典序第一格，实测落在 `(3,2)`，**不是核心 `(4,2)`**）
  ⇒ 用**市政厅所在格**当出生点。
- ⚠ **待查**：`w.turn` 在 `resolve_turn()` 之后没递增 —— 回合计数的口径要单独确认。

### 3.3 动作（军事子集）

每回合**逐军决策**（一支军一次）：`move(army_id → 格)` · `attack(army_ids → 格)` ·
（`retreat` 可选）· 全部动完即 `end_turn`。
**砍掉** `build`/`recruit`/`buy`/`sell`（本沙盒里兵是白给的，经济层整个不进）。

---

### 3.4 脚本老师 + BC（用户 2026-09-24：「也可以弄个 bc」）

**手写一个小脚本老师**：简单启发式 —— **朝最近的对手市政厅推进，路上遇敌就打**。
它不需要像 v11plus 那样完整（不需要经济层、不需要编组求解器），只要能**把对手市政厅
当目标**就行 —— 而这恰恰是 v11plus **不会**的（它的军事层不知道"市政厅=国祚"）。
用它跑对局 → **BC 学它的动作** ⇒ 得到**起点策略**。

- **BC 是起点，不是终点**：自对弈的两份网络从 BC 权重出发，再靠 PPO + MCTS 提升。
- 它同时是一条**对照线**：PPO+MCTS 必须**能超过 BC 起点**才算有用。

★ 这条也顺带修正了 plan 早先那句"没有老师"：**没有的是 v11plus 这种现成老师**，
手写一个"只认市政厅"的**小**老师是可行的（而且便宜）。

## 四、训练方法：PPO + MCTS + 自对弈（用户 2026-09-24 定）

| 决策 | 选择 | 说明 |
|---|---|---|
| 自对弈 | **两份独立网络**（`W_甲` vs `W_乙`） | 互相当对手；对手在动（非平稳），但能防"自己克自己" |
| 搜索 | **PPO + MCTS** | 每步跑 MCTS（网络当先验），**用搜索得到的访问分布当策略目标** —— 稀疏奖励的中间信号就从这里来 |
| 奖励 | **稀疏**（终局 ±1） | 不加势函数塑形（用户明确要稀疏）；**判据看胜负曲线** |

★ **为什么 MCTS 是关键**：AlphaZero 能在稀疏奖励下work，靠的就是搜索把终局信号反传成
中间状态的访问分布 —— 等于一份**免费的中间信号**。纯 PPO 没有这一层，值函数要从零学
"当前局面二十回合后会不会赢"，而 PPO 的优势估计又依赖值函数，会互相拖。

★ **奖励里的时间项与补员规则是咬合的**（值得记住）：每 5 回合补员 ⇒ 拖久了双方都补满、
更难突破 ⇒ **速攻本身就是更优解**；而"时间越短奖励越高"正好把这个压力灌进梯度里。
两个设计互相强化，不是两条独立的规则。

★ **便宜且强的技巧**：两国**完全对称** ⇒「甲视角」与「乙视角」是同一批样本的两份
（视角互换做数据增强）——样本翻倍，且**强制策略对称**。

## 七、路线（一版一 commit）

**阶段①（本沙盒，先跑通）**

1. **沙盒跑通**：能用一个**随机策略**打完一整局并正确判定胜负
   （同时查清 `w.turn` 的口径、补员时机、`attack` 的原子性）。
2. **网络**：局面 → (策略 logits, 价值)。
3. **脚本老师 + BC**：手写"只认市政厅"的小老师 → 跑局 → BC ⇒ **起点权重 + 对照线**。
4. **MCTS**：PUCT + 网络先验（8×8 上搜索几乎免费）。
5. **自对弈回路**：两份独立网络（**从 BC 权重出发**）对打，落库（局面/搜索分布/结果）。
6. **PPO + MCTS 训练**：用搜索分布当策略目标 + 终局 z 当价值目标。
7. **评估**：胜负曲线（对随机 / 对 BC 起点 / 对上一版自己）；★ 报数说清覆盖到哪一段。

**阶段②**：换真对手（v11plus）验"学会了能不能打真对手"。
**阶段③**：其余 6 个任务，以及同局多模型协同（**独立课题，阶段① 不背**）。
