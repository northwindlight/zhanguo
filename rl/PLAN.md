## 一、为什么换线

**旧线**：**一个**模型吃全观测 → 吐引擎动作空间里的**任意动作**（建造/征兵/买卖和移动/攻击
混在同一空间），目标挂**终局总消费**。病根已量化（`--grad-diag`）：`coh(pg)=0.0635`，
噪声底 `1/√230=0.0659` ⇒ **回报信号对更新方向没有系统贡献**；`cos:pg:bc=−0.778`（与 BC 锚互相拆台）。

**新线**：**每个目标单独炼一个模型**，问题切小 ⇒ 动作空间小、判据清楚、每个模型都小到能快跑。

### 国祚（市政厅）的口径 —— 2026-09-21 起，`2d66417`

- **国祚 = 市政厅**：`has_townhall` = 名下有**已落成**的厅（在建不算）；
  `_eliminate_if_dead` **厅尽失即亡，领土还在也照亡**。
- **开局白送**：`_place_crosses` 在十字开局**中心格**送一座（不花钱、不受 `min_slots≥6` 约束），
  中心格**强制平原**。⇒ **每个国家开局就有一座厅**，场景天然有目标。
- **亡国余土成无主废墟**：`owner`/`core` 置 None、**建筑原样留着**、**不补野人守卫** ⇒ 废墟**白捡**。
- ★ **市政厅对他国公开**（`_public_buildings`：视野内的他国地**只公开城堡与市政厅**）——
  原话「**看不见就打不着**，不公开这条规则就是死的」。

## 三、★ 首个沙盒：攻取国祚（8×8 自对弈）

**用户 2026-09-24 原话**：「直接 ppo 对抗，例如一个 8x8 的地图，放两个国家，开局每人 5 个步兵，
每五个回合补一支，**奖励是拿下对手的市政厅**，**开局告诉模型自己市政厅和敌人市政厅的位置**，
**稀疏奖励**。类似 alpha zero 那样训练。」

### 3.1 规格

| 项 | 值 |
|---|---|
| 地图 | **8×8**，两国（甲 / 乙） |
| 开局 | 每国 **5 个步兵**，摆在**自己的核心格** |
| 补员 | **上限 = 5 + 本国国土数 // 10**（开局 5 格 ⇒ 上限 **5**，与"开局 5 步兵"自洽；8×8 最多 32 格 ⇒ 上限 8）。**每 5 回合触发一次**：把军队**补足到上限**（★不是"每次 +1"、**不无限加兵**）。补在核心格，规则白给、**不经经济层** |
| 国祚 | 每国核心一座市政厅（`_place_crosses` 白送） |
| **终局** | **一方拿到对手的市政厅** ⇒ 本局立即结束（**不设固定回合数**） |
| **兜底** | **T_max = 200 回合**（只防僵局；用户 2026-09-24：「40 回合不够」）⇒ 到时判平 |
| **奖励** | **赢 ⇒ `1 − turns / T_max`**（★用户：「时间越短奖励越高」）；**输 ⇒ −1**；**平 ⇒ 0** |
| **观测** | ★ **POMDP**：**市政厅位置公开**（引擎 `_public_buildings` 口径 —— 视野内的他国地**只公开城堡与市政厅**，"看不见就打不着"）+ **其余一律按视野 `visible_to`**（军队 / 资源 / 其它建筑都是内政底细，得靠侦察）。⇒ **目标已知、守军未知** |
| 野人 | **清空**（`guard_once` 填满全图防重生）——本沙盒里没有野人 |

★ **迷雾的战略含义**（用户 2026-09-24 纠正后补）：守军未知 ⇒ "偷家"必须先知道**对方家里空着**，
**侦察（推进视野）本身就有价值**；反过来，"先手必败"那个观察（8/8 乙赢）在迷雾下**要重新审**
—— 后手"看到空档"这件事本身就受视野限制。
另：嫁接 v11plus 军事层**天然带这个口径** —— `targeting.candidates` 的**每一源**都要过
`cell in mask`（`pathfind.vision_mask`），它从不读视野外的军队与资源（v9 当年堵掉的四处越权之一）。

### 3.2 实测过的可行性（2026-09-24）

```
World(size=8, seed=0, nations=['甲','乙'])
  → tiles = 10（两国各 5 格十字）
  → 甲 市政厅 (4,2)   乙 市政厅 (4,6)      ← 自动送的，不用手搓
  → 开局军队 = 0（要自己摆）；野人 = 54（要清）
```
- ✅ `w.armies` 过滤 + `w.guard_once` 填满全图 ⇒ 野人剩 **0**
- ✅ `_new_army(owner)` + append ⇒ 摆得出 5 步兵
- ✅ `resolve_turn()` 跑通
- ⚠ **坑**：军队别摆在 `own_tiles[0]`（字典序第一格，实测落在 `(3,2)`，**不是核心 `(4,2)`**）
  ⇒ 用**市政厅所在格**当出生点。
- ⚠ **待查**：`w.turn` 在 `resolve_turn()` 之后没递增 —— 回合计数的口径要单独确认。

### 3.3 动作（军事子集）与 **候选集屏蔽**

每回合**逐军决策**（一支军一次）：`move(army_id → 格)` · `attack(army_id → 格)` ·
全部动完即 `end_turn`。**砍掉** `build`/`recruit`/`buy`/`sell`（沙盒里兵是白给的，经济层整个不进）。

★★ **候选集屏蔽**（用户 2026-09-24：「这次要做候选集屏蔽，**无法移动的位置屏蔽，
已经使用过的军队屏蔽**」）—— 在 `sandbox.legal()` 里做，**进模型之前**：

| 屏蔽什么 | 判据 |
|---|---|
| **走不到的位置** | 落点只从 `world._reachable` 取 ⇒ 根本不给 |
| **已经使用过的军队** | `a["moved_turn"] == world.turn` ⇒ **整支屏蔽**（一个动作都不给） |
| **交战中的军** | `a["engaged"]` ⇒ 同上（它动不了、也不能改攻） |
| **撞墙的 mv** | 结构上不存在（落点来自引擎合法集，不会触发 `_blind_cost` 烧额度） |

★ **这与旧线是反着来的**，值得记牢：旧线的候选是「引擎合法动作**全部**、不限额不预过滤」，
实测 **~49% 点不动**，靠一个 `exec_head`（可执行性头）去学"这个候选点不点得动"。
**屏蔽之后那个头就不需要了** —— 候选集小一个量级、**无废动作**、学习信号不被稀释
（旧线 `coh(pg) ≈ 噪声底` 的病根之一，正是大量废候选在稀释梯度）。

### 3.4 **打分器**（替代 BC，也替代 MCTS —— 用户 2026-09-24 定）

> 用户原话：「要是搜索也写不好就**纯打分**，越近敌方分越高，越多地分越高，丢地扣小分，
> 损兵扣大分，丢家直接输」＋「消灭敌军也要加分」＋「每多一支军队也加分，鼓励占地盘加兵」
> ＋「**有打分器的话就不用 bc 了，直接 ppo 对抗**」

`rl/evaluate.py` 给一个**静态局面**打分（正 = 我占优）。逐条落地：

| 项 | 权重 | 用户口径 |
|---|---|---|
| 丢家（国祚尽失） | `±INF` | 「丢家**直接输**」 |
| 国土 | 每格 `±1` | 「越多地分越高、丢地扣**小**分」 |
| **我的兵** | 每支 `+10` | 「损兵扣**大**分」＋「每多一支军队也加分」 |
| **敌的兵** | 每支 `−6` | 「**消灭敌军也要加分**」 |
| hp | 每点 `±0.02` | 伤而不死只是小账 |
| 逼近 | 每近一格 `±1.5` | 「**越近敌方分越高**」 |

★★ **两条设计要点**：
· **兵分两项写、不合成"兵力差"** —— 合成的话 1 换 1 会抵消成 0 分，"消灭敌军"就白干了。
· **权重与引擎规则天然对齐**：引擎是「每 10 格国土 ⇒ 补员上限 +1」，而这里是
  「10 格地（10 分）= 1 支兵（10 分）」⇒ **"占地 → 上限涨 → 兵多"这条链已经是通的**。

★ **它一物两用**：① PPO 的**势函数**（奖励取它的差分）；② 将来价值网络的**老师/对照**。

（~~纯打分贪心基线~~ **已删** —— 用户 2026-09-24：「那玩意**证明不了真正的对抗**」：
贪心 vs 贪心是**同一个确定性策略对打自己**，既不对抗、也不学习，拿来当"基线"什么也说明不了。）

## 四、训练方法：**PPO + 自对弈 + 打分器**（用户 2026-09-24 定）

| 决策 | 选择 | 说明 |
|---|---|---|
| 自对弈 | **两份独立网络**（`W_甲` vs `W_乙`） | 互相当对手；对手在动（非平稳），但能防"自己克自己" |
| 搜索 | ~~MCTS~~ **不用** | ★ 用户：「有打分器的话就不用 bc 了，**直接 ppo 对抗**」—— 打分器已经把中间信号给足 |
| BC | ~~不要~~ | 同上：不需要老师带起步 |
| 奖励 | **打分器的差分** | `reward_t = score(s_{t+1}) − score(s_t)`；终局 = ±1（丢家直接输） |

★★ **为什么打分器能把 BC 和 MCTS 一起省掉**：稀疏奖励的真问题是"值函数要从零学
二十回合后会不会赢"，而 PPO 的优势估计又依赖值函数，两者会互相拖。打分器把这个死结
**从根上消掉** —— 它给每一步一个密集信号，等于把终局判据**提前铺到每一步**。

★ 而且它是**势函数差分**（potential-based shaping）：与旧线的
`reward = Δspend_total × 0.01`（`feat/rl` 的 `rl/env.py:336`）**同形** ——
理论上**不改变最优策略**，所以既不引入 reward hacking，也不必担心"塑形把策略带偏"。

★ **奖励的时间项与补员规则是咬合的**：每 5 回合补员 ⇒ 拖久双方都补满、更难突破
⇒ 速攻本就更优，而「时间越短奖励越高」正好把这个压力灌进梯度。

★ **便宜且强的技巧**：两国**完全对称** ⇒「甲视角」与「乙视角」是同一批样本的两份
（视角互换做数据增强）—— 样本翻倍，且**强制策略对称**。
