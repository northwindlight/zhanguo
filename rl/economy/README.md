# 经济 BC 独立实验分支

分支 `codex/rl-economy-bc`，基于当前 main 的正常 native 规则。先以改进 v13
采集行为克隆示范；当前投资网络决定建设和征兵，采购与出售由完整项目的执行器处理，军事仍实际调用
v11plus 进行移动、战斗和扩张。先完成 BC 开局验收；夜间训练可按能力切换 BC／DAgger／PPO，不替换默认 v13。

2026-11-07 连续续训入口为 `python -m rl.economy.ppo_cycle`：实验 PPO 链与
独立验收分开运行，未通过晋级仍继续训练，不据此推断模型上限。每轮默认
8 个 150 回合新世界；运行、备份及正式验收见
[连续 PPO 记录](../../docs/reviews/经济RL连续PPO续训-20261107.md)。
11-08 已由 Kaggle 私有 GPU 任务接管；本地 `scripts/econ_kaggle_watch.py` 接回每轮结果并继续提交，旧 Colab 监控已停。

目标是最大化论文 S：当期价累计实际消费 `S = 征召 + 军需 + 行政`（`settlement.settle`
的三类消费代理）。建造是固定资本形成，单列投资，不计入 S。S 是唯一主指标；
BC 学习教师动作，并不凭训练损失证明这个目标已经达到。奖励 = 每回合 ΔS，
`gamma=lambda=1`：单个回合的 ΔS 在完整回报中不被折扣掉，所以逐回合奖励不短视。
GDP、现金、生产、缺料、军需短缺、领土和军队只作诊断，不参与奖励/晋级。
固定初始价格净生产只是数量参考，不是利润。

2026-11-09 用户新增：准备无效动作惩罚，先保持关闭，到总计 20 轮后再考虑启用。
`ppo_cycle --invalid-action-penalty` 默认 `0`；正值时仅在 PPO 更新副本上，对每次
实际执行失败的建设/征兵尝试扣分。落盘原始轨迹、游戏账本和验收仍使用实际 S，
仅 padding 掩码保持；非零配置须用独立实验目录，不能混入原来的零惩罚续训。

用户进一步明确：征兵在长期经营决策中通过扩张取得新土地、资源容量和后续产能；
但在论文 S 口径里，粮/装备变成兵是“用掉”，计入消费，建造设施才是固定资本形成。
正式账本分类保持原规则，学习决策不能把征兵仅当需要压低的费用。
BC 首先须通过正常零兵开局的供电→兵营→材料→征兵→实际扩张链路；不能仅凭
已经可征兵的样本分类准确率验收，也不以固定赠兵／教师代操作冒充模型学会。

## 教师与训练环境

`ruleai/v13plus` 保留 v13 五种持久经营偏好及市场竞争情景。修复原流程中
先卖材料、选中新投资后又禁止买回的冲突：推迟一般清仓；只为完整投资／运营配方
按需出售可用余量；候选验资和真实筹资共用同一套整单正式报价。新征部队的军需
进入随后投资预算。正式 `planning` 提供建设成本、施工额度和容量。

教师仍是启发式策略，不是全局最优解；工程院的长期回报尚未建模。改进首先解决
已确认的资金与材料流程冲突，不能把更多投资／军队直接当成更高经济收益。

每局至少四国，默认八国，混合 v11plus、v13、v13plus 和五种偏好；地图种子、
地形、尺寸均可变化。市场随所有国家实际成交和生产变化。没有战术分支的无限
资源或自动送兵。按完整世界种子切分训练、验证和最终对局评估。

非战争下 4 个候选席的经济决策互不依赖，但这属于 main 计划中的动态回合（和平
并行行动、战争有序行动、回合末统一结算），不在本轮训练侧自造。当前保持
`GameHost` 的顺序回合；等 main 实现动态回合后，RL 线合并/变基到 main 并复用其
路径。训练分支不改引擎，也不在训练侧另做并发/两阶段批量。

## 当前：完整投资项目与无硬合法掩码

使用 `--projects` 采集与训练。网络在自有地点的建设／征兵项目和结束之间选择，

## 原子动作基线（前两轮未通过开局验收）

复用 `feat/rl-tactics` 的 `c650a82` 中 FastLinear／Attn／Block，保持训练梯度
和 Pi 推理优化；沿用候选读取观测、候选互相注意、保留候选原始身份的结构。
旧分支的战术环境、规则副本和旧权重不适用于当前经济任务，未混入。

输入只有绑定玩家可见的市场、库存、运营需要、地块、建筑、军需和历史市场记忆，
显式提供经营偏好。不同国家的私有库存和教师的选择／评分／内部阶段均不输入。
该历史基线候选来自正式规划与报价；买不起的项目仍可被注意力看到，执行掩码阻止非法提交。
交易数量用连续 `log(1+数量)` 头监督，执行时按正式可购／可售上限取整；没有
训练时临时添加正确数量候选的泄漏。相同资源当期不反向交易。

约一百万参数的网络独立决定经济结束；每期最多 96 个经济动作，触顶次数必须
在评估中报告，不用教师回退掩盖网络失误。军事层与正常结束回合流程保持原样。
目前只通过实验 runner 加载 checkpoint，尚不支持将学习客户端的游戏存档恢复到
正式 GUI；教师 v13plus 已有独立版本和正常保存恢复。

## 复现

使用已有 PyTorch CPU 与 NumPy 虚拟环境；普通游戏不依赖 PyTorch。

```bash
# 数据只落入忽略目录；已有同名世界不会被覆盖。
python -m rl.economy.collect --seeds 101 102 103 104 105 106 201 202 \
  --turns 150 --sizes 20 24 28 --out rl/runs/economy-bc/data
python -m rl.economy.train --data rl/runs/economy-bc/data \
  --valid-seeds 201 202 --epochs 12 --threads 2 --batch 24 \
  --out rl/runs/economy-bc/model
# 最终留出种子不得出现在训练或验证中；实际对局与教师使用同样的席位与对手。
python -m rl.economy.evaluate --seeds 301 302 --turns 150 \
  --checkpoint rl/runs/economy-bc/model/best.pt \
  --out rl/runs/economy-bc/holdout.json
python -m unittest tests.test_economy_bc tests.test_rule_market tests.test_player_clients -q
# 求解器 C 快路径对账（扩展未编译时只跑回退检查）
python -m unittest tests.test_econ_fast -q
```

`world-*.npz` 按世界压缩存储，包含源码指纹；`world-*.json` 保留场景与结果。
`run.json` 保存参数量、完整种子划分、数据哈希和配置；`metrics.jsonl` 同时报告
动作分类、各动作准确率和交易数量的对数误差。`best.pt` 只按验证世界损失选择；
`last.pt` 带优化器和随机状态，可用 `--resume .../last.pt` 续训。训练准确率不是
经济成绩；必须另外查看实际 rollout、失败和动作预算触顶。

多环境实局筛选使用 `python -m rl.economy.benchmark --baseline 对照.pt
--checkpoint 候选1.pt 候选2.pt --cache 教师缓存目录 --out 评测目录`。
默认完整跑完 8101 不换位与 8102 换位两个 150 回合环境；`--formal` 扩为原有六个
150/200/250 回合环境。缓存核对模型、场景、教师与运行时，支持中断后续跑；
逐席位累计 S 与尾段 S 回退会阻止候选入选。该入口只报告筛选，不生成 accepted.pt；
最终门槛仍为教师总 S 的 150%，并须通过独立新种子确认。当前 14 世界 T4 复训见
[接手记录](../../docs/reviews/经济BC接手与14世界T4复训-20261107.md)。

一次项目编码内默认缓存正式报价与单位目录查询，返回值隔离，任何其他 API 调用都会清空缓存，
编码结束后不再复用。诊断时可用 `ZHANGUO_ECON_QUERY_CACHE=0` 退回原路径。
两个完整 150 回合世界的输入、回执、S 和最终游戏状态对账通过，整局耗时分别减少 19.93% / 2.50%。
旧数据通过精确版本等价登记继续使用，未放宽对未知观测、奖励或缓存修改的检查；评测缓存另用
实际推理实现指纹，训练超参数变化不再使实局结果失效。详见
[缓存验证](../../docs/reviews/经济RL编码查询缓存验证-20261107.md)。

当前课程对零兵状态使用 4 倍权重，对兵营、征兵、零兵时的发电和征兵材料样本再
使用 3 倍权重；仅改变监督损失，不改推理动作／规则掩码。可用 `--init best.pt`
更换课程后初始化，`--resume` 要求课程权重一致。评估另记录首次兵营、征兵、
扩张的实际期数。祖先模型见过的种子也继承到 `seen_seeds`，不能伪装成最终留出局。

第一轮第 4 epoch 开局探针中，四个国家 16 期仍零兵：三个建了兵营，但扩建后的
电力缺口使正式征兵停摆。为覆盖这种学生失误状态，可在采集中使用
`--student-checkpoint ... --teacher-probability .5`，逐个国家／回合随机由学生或
教师经营；只收教师动作标签，军事仍全部真实执行。它是混合轨迹上的纠错 BC，
不是每步 DAgger，也没有 PPO。`pipeline` 自动让验证种子保持纯教师数据。
最终评估只运行模型经济层，不带这些教师干预。

纠错轨迹还暴露了 v13 旧征兵流程不检查上期电网的边界。v13plus 现逐次读取正式
征兵规划，先核电网、设施和剩余额度，再筹集可购买的材料；缺材料不会被误当成
不可投资，断电时则先让后续投资环节修复供电。捕获到的非法教师动作会终止该世界，
不会写成标签。

采集中断后可用新的输出目录和 `pipeline --reuse-data 原目录/data` 继续：仅复用
配置、特征指纹、学生检查点和教师比例一致的完整世界，保留它们原来的源码记录。
不同教师修订混用须显式 `--allow-mixed-teachers`（恢复 pipeline 会传入），训练
清单列出全部源码哈希，不伪装成单一版本重新生成。失败世界重新采集。

## 训练设备与候选规模

- `--device cpu|cuda`（`train` 与 `overnight`）：只决定 BC／PPO **更新**在哪个设备
  算；对局 rollout 与能力门是引擎模拟，始终在 CPU。默认 `cpu`，有 CUDA 时才需要显式指定。
- `--max-candidates N`（默认 `0` = 不截断）：每行训练候选上限，开启时保留教师选中项
  加 `N-1` 个随机负样本，并随 epoch 换一批。它改变监督语义（模型看不到全部负样本），
  只在候选规模大到训练不可行时显式打开；150 回合的局每行候选中位数 685、上限约 2000，
  不截断时单 epoch 在 ECS 上约 22 分钟，截断到 384 约 4 分钟。
- `--no-length-bucketing`（默认开启长度分桶）：`collate` 把一批补齐到批内最长候选，
  随机组批时一条约 2000 候选的尾段行会把整批短行一起撑到 2000，而候选自注意力是
  O(n²)。按候选长度分桶让每批长度接近，**只改组批、不改行/标签/损失权重**；同批内
  仍随机，每个 epoch 重排。实测 ECS 上单 epoch 1355 s → 454 s。
- `--family-aux`（默认关闭）：加一个 finish／build／recruit 三分类的动作族辅助头，
  推理时把族对数概率并入候选分数（等价于 P(候选)=P(族)·P(候选|族) 的分解）。
  动机是实测的族级混淆：教师选建设的 1364 行里，模型 37.8% 选了征兵、23.4% 选了
  finish——候选集里 build 有「地块×建筑种」上千个、recruit 每地块一个，直接对候选
  做交叉熵时族级判断被负样本淹没。`--family-weight` 控制推理权重，
  `--family-loss-weight` 控制辅助损失系数。
- 以上都只影响训练侧，不改变观测契约、教师动作和采集数据的内容。

## 求解器快路径（可选 C 扩展）

经济求解器的纯算术有可选的 C 快路径：`ruleai/v13/_econ_fast.c`，实现稳态物料
平衡、运营物料目标、现金储备与市场情景估值四项。引擎调用（规划、报价、成交）
仍在 Python 里走正式 API；扩展不读世界、不改世界、不碰随机数。

```bash
.venv/bin/python -m ruleai.v13.build
.venv/bin/python -m unittest tests.test_econ_fast -q
```

- **逐位一致**是硬要求：扩展保留 `Counter` 的插入顺序与每个值的 int／float 类型，
  并复刻 CPython 3.12 起 `sum()` 的两种路径（整数精确累加、浮点 Neumaier 补偿）。
  `tests/test_econ_fast.py` 对真实教师局势逐次对账，并比较开启／关闭扩展两局
  的完整世界状态与训练数据，必须完全相同。编译固定 `-O2 -ffp-contract=off`。
- **失败即回退**：扩展缺失、编译产物比 `_econ_fast.c` 旧（编译时写入 SHA-256，
  加载时校验）、或任何调用异常，都退回 Python 参考实现，行为不变；回退原因记录在
  `ruleai.v13.econ_fast.FALLBACKS`。`ZHANGUO_ECON_FAST=0` 强制走 Python。
- 编译产物 `.so` 不入库、不进发行包，缺失时一切照常。v13 与 v13plus 共用同一套
  求解器算术，两者同时受益；`rl/economy/projects.py` 的投资打包同样走这条路径。
- 编码期内同一地块的规划结果只询问一次（`memo_planning`）：一次编码期间没有建造、
  征兵或交易，重复询问与复用等价，教师每执行一个项目重编整局时省下重复查询。

## 夜间持续训练（2026-11-01 用户授权）

`python -m rl.economy.overnight` 从通过本地留出对局的项目 BC 检查点起步。
以 ECS 用户 systemd 服务运行，到指定带时区的 `--until` 自动保存结束。

阶段依据完整对局能力决定，而非固定 epoch：

- 开局没有全员在第 8 期前征兵、第 12 期前扩张：BC，沿教师动作采新世界。
- 开局通过但学生局面上的教师项目种类一致率不足 90%，或有执行／补给问题，
  或长期经济指标未达到教师门槛：DAgger。每个学生决策状态直接询问教师下一项目，
  教师查询不交易、不建造、不征兵；学生继续自己行动，再聚合标签训练。
- 开局、补给、动作上限稳定，项目失败率不超过 0.2%，项目种类一致率达到 90%，
  逐席位 S 中位数达到教师 95%、总 S 达到教师 95%、末 50 回合 S 增量中位数达到
  教师 90%：PPO。资产/领土只作诊断。

能力对局固定使用验证种子 7101/7102、24/28 地图、相反席位，前 3 轮 150 期，
第 4–7 轮 200 期，之后 250 期。它们参与阶段／模型选择，**不是最终留出样本**。
训练每轮另取两个新种子、20/24/28 地图，保持八国、多种经营偏好和 v11plus 军事。

PPO 借鉴旧 `feat/rl` 5260224 的约定：采样与更新共用可执行性预测软权重，只
mask padding；保存实际采样的 float32 观察、旧 log probability；逐国家、逐世界
计算 `gamma=lambda=1` 的完整回报，避免把国家轨迹串在一起或按原子动作把长期投资的回报截断。使用全批优势归一化、0.2 clip、0.5 梯度裁剪，
开局前 12 期有初始 BC 分布的软 KL 约束。独立价值头从 0 输出开始，价值损失
按回报标准差缩放，避免其量纲淹没策略梯度。PPO 学习率 3e-5，每轮至多 2 次更新遍历。

2026-11-03 修复后，正常 PPO 用 8 行微批累积成 128 行有效批次，再做一次参数更新。
KL 惩罚初始系数 0.1，每 8 个有效批次按实际行数加权统计（通常 1024 行），
以 0.03 为目标自适应调整系数；不再因某个 8 行批次超标而终止整轮。
日志记录实际处理行数、独立行数、覆盖率、完成 epoch 数和每个 KL 窗口。
显式更新预算、截止时间和数值错误仍可结束更新。`kl_mode='legacy'` 仅用于复现旧实验。

奖励 = `ΔS / 1000`，S = 征召+军需+行政（当期价累计实际消费）；建造是固定资本
形成，不计入 S。无效项目只作失败率诊断，不加虚拟惩罚，不改变 S 奖励或
游戏账本。在线报告单列成功项目数、总 S / 成功项目数、成功项目所在期的 S / 项目数，
以及无成功项目期的 S；这些是描述比值，不代表单个项目的因果收益。
GDP 只作诊断，不参与奖励/晋级——它不是论文 S（见
`docs/research/消费总量评测指标论证.md` 与实现附录：GDP 是增加值代理，不能代替
三类消费）。

每轮候选必须通过相同世界的逐席位 S 对照才能替换 `current.pt`：开局不能退化；
失败率、军需短缺和触顶不恶化；每席位 S ≥ 当前模型 95%，总 S 不低于当前模型；
末 50 回合 S 增量逐席位 ≥95%。资产/领土只作诊断，不作为单一指标。未通过的候选
保留诊断，但不覆盖当前模型。数据保留初始 BC 示范和最近四个在线世界，只有本任务
目录的旧 replay NPZ 会清理；空闲磁盘、单局样本量和结束时间均有限制。模型、状态、

`best.pt / current.pt / accepted.pt / candidate.pt / state.json / summary.json / events.jsonl / round-*/`。
