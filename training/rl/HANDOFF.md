## 训练口径

- Python 规则和示范采集使用 `d32c340331a66c2a81db436438b26020742f257f`。`python/` 是从 rpi3 拉回的仓库，`from-rpi3/` 保存 Claude 的启动脚本和历史检查点。
- `cpp/` 基于交接的 C++ W3，补上同版本 Python 对已完成城堡最高层的拆除规则，并把对应候选标为可执行。采样器在 Colab L4 上重新编译。模型使用 `N_DIM=40`、`T_DIM=72`、`F_DIM=80`。
- BC 使用 `results/cpu-demo-manifest.json` 冻结的 386 局 W3 镜像胜局，每局收录获胜座位，合计 445,277 个决策。验证按整局切分，每轮统计验证集前 6,000 个决策。训练跑 8 个 epoch，候选交叉注意力两层，启用候选自注意力。
- PPO 从 BC 起步，并固定 BC 为 KL 参考。每次更新采样 96 局，学习者对 C++ W3，地图尺寸 13、上限 150 回合。更新端使用 BF16 autocast、回合 GAE λ=0.95、γ=1、学习率 `2e-5`、KL 阈值 `0.05`、无效动作扣分 `0`。
- BC 和最终 PPO 分别对 W3、rule 评估 192 局，起始种子 `90000`。PPO 训练种子从 `120000` 开始，每轮连续 96 个。胜率按全部对局计，达到回合上限且未灭国的局计为平局。

## 文件

| 路径 | 内容 |
| --- | --- |
| `demos/w3tC/`、`demos/w3tE/` | CPU Colab、ECS 的示范数据与采集记录 |
| `results/` | BC 训练日志、采样评估、数据清单、模型权重 |
| `results/ppo/` | 每轮指标、阶段权重、最终权重和评估 |
| `run_ppo.py` | L4 上的 PPO 驱动，验证每轮轨迹和检查点，支持在现有运行目录续跑 |

PPO 的 `ck*.pt` 包含训练权重和 AdamW 状态。`ppo-native.pt` 供 LibTorch `sample` 加载。`bcT1.log` 显示每轮 BC 的训练与验证交叉熵和动作命中率。

L4 上的 BC 和 PPO 进程独立于交互 SSH。PPO 等待 BC 完成对局评估后自动启动，计划跑 30 次更新。本机 `sync_run.py` 定期回传日志、BC 权重、PPO 第 1 次和每 5 次更新的检查点及最终导出。若 Colab 回收运行时，需用本机已回传的检查点恢复。

按用户指令，L4 已恢复原 PPO 队列。价值头与策略从 PPO 第一次更新开始联合训练。

本机示范已校验完毕。`demos/w3tC/` 中的 386 份训练文件与 `results/cpu-demo-manifest.json` 的 SHA-256 全部一致。

高内存 CPU 会话已于北京时间 16:09 释放。采集结束前获得的另外 125 局已逐份校验并转存到 L4。`sync_cpu_archive.py` 回传 `results/cpu-extras.tar` 及对应清单，该批数据未加入本轮训练。
