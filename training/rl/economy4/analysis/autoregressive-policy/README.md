# 战国自回归策略原型与设计审查

本地 CPU 与 Vulkan 运行入口见[推理说明](INFERENCE.md)。

本原型实现了一个 **18,180,507 参数**的 PyTorch 策略。局面编码复用现有 RL 观测和候选结构。历史层宽 384，使用三层 Gated DeltaNet 和一层 Qwen Sparse Attention。另有三层独立因果解码器，直接读取局面、历史和四槽内存图。GDN 接手循环状态。

## 执行契约

1. **每席有自己的持久历史。** 每个新的可见快照都有修订号和一条观测事件。每个已选择的思考操作记录操作、写入后的图、快照修订号及策略 log 概率。模型先决策，已选择的操作随后入历史。其他国家的私有思想和训练折算 GDP 不进入该席输入。
2. **快照完整可恢复。** 同一可见修订只记录一次。CPU 归档每 32 份留一个完整快照，中间用按字段、按行的差分。思考期间地图只编码一次，交叉注意力重用其 K/V。视图改变时重新编码，此前的思考仍引用原来的快照。
3. **每回合思考 8–30 步。** 只能向未满的槽追加 4 种符号，或清空一槽。完成 8 次后可以主动结束。第 30 次仍是策略选择，随后的强制切换由引擎记录。完成时释放解码器本回合的临时自注意力缓存，已写入 GDN/QSA 的想法和观测继续保留，内存图也带入下一回合。行动阶段从引擎给出的候选里选择，沿用游戏的独立 60 次预算。
4. **未来的信件是完整的内存图。** 先选收件国，再用同格式草稿写四槽，构造完即提交整图。草稿与本国工作内存分开。原型可构造包含发件人、收件人和回合的不可变信件。落地时的提交、费用、送达及可见权限由 main 的外交规则决定。 [游戏说明书](../../../../../mods/native/docs/游戏说明书.md:90)

QSA 用 4 token 一块，每次取 16 个相关完整块与当前未满块。每个决策都可重新查询。索引器实现了密集教师 KL 与稀疏模式下的块内目标。GDN 的衰减在初始化时按头覆盖约 8–2048 个事件的半衰期，实际衰减仍可按事件内容学习。这个初始化是本项目选择。 [Qwen 技术报告](https://arxiv.org/html/2608.30320v1#S2.SS1)

## CPU 验证

使用本机树莓派 5、PyTorch 2.6.0、2 线程。真实样本为种子 550100 的 24×24 脚本示范，首帧有 587 个局面 token 和 180 个候选。

| 检查 | 结果 |
| --- | --- |
| 历史整段与分块更新、解码器整段与逐步缓存 | 最大输出差分别为 1.74×10⁻⁶ 和 8.34×10⁻⁷ |
| 扰动未来事件或未来思考输入 | 先前输出差为 0 |
| QSA 稀疏筛选 | 21 个历史块中选 16 个，短前缀全选时和密集注意力最大差为 4.77×10⁻⁷ |
| 完整尺寸反传 | 局面编码、GDN、索引器、因果解码器和价值头都有有限非零梯度 |
| 回合边界与可恢复历史 | 第 8 步后可停，第 30 步强制切换。重放 39 个思考操作，所选操作的 log 概率差为 0 |
| 快照归档 | 一局 78 份真实示范观测逐项恢复一致，张量 16.09 MB 降到 2.40 MB，不含 Python 对象开销 |
| 单样本延迟 | 首版测得一次局面编码约 218 ms，8 步思考和历史写入约 146 ms，从已有局面缓存评分游戏候选约 46 ms |

这些延迟来自本地参考实现的一次检查。完整自对弈吞吐依赖动作数量、缓存失效率和 GPU 批量调度。

## 审查结论

**思考阶段是模型自学的隐式搜索。** 模型自行决定写什么符号、如何回读和什么时候停止。BC 的监督范围是游戏动作。思考操作由模型在对局中采样，使用后续结算回报训练。用同一权重和同一批留出对局比较不同思考预算，以实际行动和结算评价搜索是否带来收益。

| 优先级 | 发现与落地条件 |
| --- | --- |
| 高 | **BC 只监督游戏动作。** 按地图和本国时间顺序重放观察与动作，补齐可见回执、版本和阶段事件。自对弈采集模型自己的思考轨迹。同局面分支可用于回测燃料、建厂和补给等动作链。 |
| 高 | **原始观测和模型可检索表示的粒度不同。** 原型保留可逐项恢复的上一刻视图，QSA 读取观测编码及思考内容。历史某地块库存或单支军队 HP 等精确事实如出现回忆失败，可以根据命中的事件修订号按需展开该历史快照。逐实体历史回读还需要接到解码器。 |
| 高 | **PPO 必须从参与者当时所见重放。** 轨迹需保存阶段、候选、合法掩码和版本。主动结束与写槽都计策略概率，强制切换只记事件。思考步在同回合内按折扣 1 接入游戏回报。权重更新后需重建活跃片段的循环状态和 K/V。小型因果验证通过，跨地图分段回放、PPO 和游戏奖励尚待接线。 |
| 高 | **批量吞吐主要取决于缓存实现。** 参考 QSA 通过拼接追加 KV、稳定排序选块，GDN 用可读的逐步循环。长局多席应改为预分配或分块追加，并在目标 GPU 验证索引、GDN 扫描和历史重放。训练用密集索引教师须按窗口限制中间张量，直接覆盖整局会产生二次开销。 |
| 中 | **通信的意义要靠对局验证。** 信件格式已经确定。首次联训应把发送开关与游戏任务绑定，并跨种子、跨版本互测，观察消息是否会改变可验证的合作结果。 |

原型覆盖神经网络、观测归档和单席思考回放。后续接入的 C++ 动态回合训练入口见下文。

## 思考步数对照和价值头热身

回测使用 C++ 四国动态回合。一席由模型控制，另外三席固定 W3。每个模式复用地图种子、学习座位和游戏动作随机数流，思考用独立随机数流。

| 模式 | 计算 |
| --- | --- |
| `0` | 直接行动，保留 BC 中的观测／动作事件格式 |
| `8` / `30` | 固定生成 8 / 30 次内存操作，结束时记录引擎强制切换 |
| `8-kv` | 生成 8 步，游戏动作继续读该回合的思考 K/V，下回合重新开始 |

四组共用策略检查点。对照报告真实名义 GDP、土地、征兵、进攻、断供、伤亡相关指标、非法动作率与耗时。本国统一结算用于价值头的训练目标。默认在额外的 0 步对局上拟合价值头，用互斥种子的 0 步对照评估 MSE。目标沿用全局 PPO 的实际名义 GDP 加持地奖励，除以 3000。只有留出 MSE 改善时才导出独立的价值热身检查点。

## PPO 回放契约

`SeatTrace.header`（`TraceHeader`）记录轨迹格式、思考预算和是否保留思考 K/V。回放必须按轨迹头重建。`records` 按发生顺序交错保存以下三类条目：

- 历史事件 `Record`。思考记录带采样时的 logp 和动作前的 V。强制切换 `THOUGHT_LIMIT` 只记事件，不带概率。
- 游戏决策 `GameRecord`，保存修订号、候选下标、采样时的 logp 和动作前的 V。它后面紧跟 BC 格式的 ACTION 事件。
- 回合边界 `TurnBoundary`，标记思考状态和解码器缓存在此重置。

`replay.py` 提供两条回放路径。

- `replay_stepwise` 逐条重走采样时的代码。
- `replay_batched` 用于 PPO 训练，保留梯度。历史事件整段编码。同回合的思考步沿时间维解码，只在快照修订号变化处分段。同回合的游戏 token 放在 batch 维，每条只读三样东西：同一份思考 K/V（轨迹头保留时）、自己的 token、自己修订号的棋盘 K/V。所以每条游戏 token 的 RoPE 位置都等于思考缓存长度，游戏动作之间互不可见。
- `require_adaptive` 是自适应 PPO 的入口校验，固定预算轨迹和 K/V 设置不一致的轨迹都会被拒绝。

`verify_replay.py` 只用合成观测，不需要示范数据和引擎。它覆盖 `0`、`8`、`30`、`8-kv`、自适应主动 STOP（含思考中途刷新观测）、自适应撞 30 步上限，以及保留 K/V 的自适应 STOP。每个场景都要求两条回放路径的 logp 和 V 与记录误差在 2×10⁻⁵ 以内。它还检查错误轨迹头必然报错或明显不一致，以及各模块梯度有限且非零。

```bash
PYTHONPATH=../dynamic-turn-dual-ppo-20261124/reference/python \
  OPENBLAS_NUM_THREADS=1 python3 -B verify_replay.py --threads 2
```

## 自适应思考 PPO

从通过热身的 `value-warm.pt` 起跑。每张 24×24 地图由同一份策略控制四席，每席独立保留内存图、观测历史和采样随机流。C++ 动态调度沿用建造／征兵的预付提交、同一行动波的观测和统一结算。默认两张 GPU 并行采图，汇总后由一张 GPU 更新共享权重。正式地图上限 100 回合，起步思考预算为 8–30 步，游戏动作沿用 60 次预算。

四席思考、游戏动作和统一结算按发生顺序进入全局时间线。各国回报累计本国名义 GDP 和持地折算，γ 与 λ 均为 1，用动作前的 V 作基线。每个实际行动的席位回合、每个采样思考操作和每个游戏动作都参加两轮 PPO；第一轮更新被拒时终止该批。强制思考切换只作为历史事件。游戏动作依次划分为不重叠的 2–4 步组合，余下的单步独立计分。每个组合使用起点优势与联合概率比，每个思考操作单独裁剪，两类策略损失各占一半。

地皮奖励的系数由真实期末名义 GDP 决定。每个 PPO 批次完成后，先对每局四席的期末名义 GDP 取均值，再对最近 16 局等权取均值。首次达到 60 的批次仍用原奖励，从下一批开始，在随后 200 局内把持地折算系数从 1 线性降到 0。每 4 局一批时，每批降低 2 个百分点。触发后即使 GDP 回落也继续退坡，归零后各回合只按本国名义 GDP 计奖。系数在每批采样前确定。它只参与回报计算，模型看到的仍是真实名义 GDP。

同一 GDP 门槛也控制每个国家回合的思考预算。首次达标的批次仍用 30 次上限，从下一批起永久放宽到 100 次写入或清槽。两阶段都允许写满 8 次后主动结束，游戏动作预算始终为 60。切换时沿用第 0–30 步的位置嵌入和 Adam 状态，为第 31–100 步各增加一个可训练位置，使用旧第 30 步的向量初始化，新行的两组 Adam 动量从零开始。回放从轨迹头读取当时的上限，批次报告中的 `thought_limit` 是采样的实际值。`verify_thought_limit.py` 覆盖达标切换、主动停止、100 次强制停止、梯度以及检查点续训。

批次报告记录本批系数 `land_reward_weight`、最近 16 局期末均值 `rolling_final_gdp` 和触发局数 `land_reward.triggered_at`。检查点保存滚动窗口和触发局数。首次从旧检查点续跑会从同目录已完成的连续批次报告恢复窗口；只有权重文件时从新采样的局数累积窗口。

反传窗口以席位回合为边界，每满 8 个游戏动作另开一段。每个窗口从行为策略的真实 GDN 状态、QSA 历史和私有内存图继续。一个席位的全部窗口共享追加式历史的 CPU 副本，窗口保留各自的因果前缀长度。每轮检查回放决策 ID，全局覆盖数须与 C++ 采样结果一致。首轮更新前检查 logp 与 V 的误差上限 2×10⁻⁵，必要时逐步重放。学习率仍按思考与游戏的 KL 折半回试。

全回合训练使用独立任务名和结果目录，从第 10 轮 BC 策略及单独预热的价值头开始。策略和价值优化器从零创建，契约会拒绝旧的抽样 PPO 检查点。

`watch_thought_ppo.py --warmup <回测结果目录> --output <PPO 结果目录>` 提交私有 Kaggle 任务。首段在同一会话做独立 CUDA 检查，验证思考头、游戏头和价值头实际更新，随后从原预热检查点开始正式采样。每段回拉末尾检查点和两套 Adam 状态；通过 `--segment` 指定每段局数。每个后续任务使用上段核验过的哈希和总局数。实时进度在 `live.json`，本地已校验进度在 `verified.json`。

批量重算超过误差门槛的回合片段改用采样时的逐步张量形状重算，对选中动作和价值继续施加同一校验。校验通过的片段在这一批的更新和 KL 检查中沿用逐步重算。若云端中途退出，保留已更新的最后一批检查点，回传校验后暂停该段续训。

此前抽样训练只为选中回合归档观测与动作概率，当时所有回合都更新本席模型历史。动作、logp 和 V 一次回传，四席结算统计仅在期末读取。双 T4 的同种子 12 回合短测中，这组改动让采样用时从 69.16 秒降至 66.39 秒。单卡双流在同种子短测中进一步提速，两组各两局的用时合计从 154.68 秒降至 141.80 秒。每组的动作与思考选择、观测和奖励目标均逐项核对。

完整 100 回合的第 41–48 局使用双流，4 局一批采样约 28 分钟，上一段每批约 13 分钟，游戏与思考决策数相近。从第 56 局检查点恢复每卡一局和 2 个 PyTorch CPU 线程，保留已验证的同步和归档优化。双流仍可通过本地命令的 `--rollouts-per-device 2` 选项复测。

### 跨局推理与双卡 PPO 更新

在 `thought_ppo.py` 上可以独立启用两项优化。

- `--device cuda --workers 2 --distributed-update` 在每张卡上各运行一个进程。每局的回放窗口留在负责采样的进程。两边用整批的优势均值、方差和损失分母，梯度求和后才裁剪。两张卡用同一批 KL 样本决定接受或回退步长，各自更新同一策略。主进程写模型和两套 Adam 状态。
- `--batch-inference --rollouts-per-device 2` 将同一卡上两局当前可执行的决策放入同一次局面编码、解码和候选评分。思考进度重叠的步骤也能合批。每席的 GDN、稀疏历史、内存图与两个随机数流保持独立。回放记录采样时的批次行和各实体区长度，必要时按原形状重算 logp 和 V。两项开关可以组合。

使用同一个父检查点比较时，给各次运行指定各自的输出目录，固定 `--seed`、`--turns`、`--batch-games` 和 `--stop-games`。日志中的 `ppo_coverage` 标记采样结束，`ppo_batch_complete` 标记两轮更新与存盘结束。`batched_games` 和 `batched_thoughts` 计数实际与其他世界合批的游戏、思考决策。

Kaggle 续跑入口 `watch_thought_ppo.py` 接受上述相同开关。选项在新提交的分段生效，调度器会封存带地皮退坡规则的源码包，采样与更新方式可分别配置。遇到并发 GPU 会话已满时，`live.json` 标记 `waiting_for_gpu_slot`，有空位后自动重试。

`verify_batched_rollout.py --library <评估桥> --checkpoint <检查点> --check-actions` 用 C++ 局面对照串行与合批的每个选择，并检查两条回放路径和梯度。`verify_parallel_ppo.py` 用两个 CPU 进程测试分片不均及一个分片为空时的梯度、覆盖和两轮更新。

### 单事件 CUDA Graph 与回放计时

实体机的 `thought_ppo.py --cuda-graph-history` 在每个 GPU 的采样副本上录制三层 Gated DeltaNet 的单事件前向。每次重放前写入该席位的历史状态，输出保存为独立张量。PPO 的反传走可微分的常规前向。双卡实例同时启用 `--workers 2 --distributed-update --batch-inference --rollouts-per-device 2`。一张卡运行多个独立采样线程时使用原有逐步实现。

第 84 局快照在 5060 Ti 上的同种子测试使用两局、每局三回合、共 1,099 次决策。按原版、新版、新版、原版交替运行，采样平均耗时由 16.15 秒降至 11.99 秒，全部动作、采样 logp、V 和结算一致。可用 `verify_cuda_graph.py --checkpoint <检查点> --library <评估桥>` 重跑；它还验证更新后的权重和跨席历史快照。

PPO 将同一窗口的事件嵌入、裁剪损失以及 logp 和 V 的校验按组计算。在固定的 98 个真实窗口上，包含回放、损失和反传的一轮平均由 18.01 秒降至 16.59 秒。相对梯度误差小于 8×10⁻⁷，未触发逐步回放。测试与生产训练共用 GPU，时间适用于该短测。

PPO 对每个训练窗口按实体类型补齐同一批棋盘，并一起计算局面编码、候选动作分数和解码器棋盘 K/V。每个游戏决策仍使用自己修订号对应的局面与合法掩码。包含额外观测或同一观测多次行动的窗口沿用逐局面编码。首次更新时继续逐窗口核对采样 logp 和 V，超过 2×10⁻⁵ 的窗口用采样时的张量形状重算。
