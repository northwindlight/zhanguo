## 训练方式

- 每世界四国共享一个真实市场及战场。A/B 各控制两席，按种子轮换 AABB、ABAB、ABBA、BAAB、BABA、BBAA；各国库存、视野和 GRU 隐状态独立。
- GPU0 控制 A 的就绪国家，GPU1 控制 B。C++ 按军队行动包络形成冲突组，组内有序，组间的待推理请求一起凑批；只有 CPU 协调器执行世界动作。
- 两组策略快照在一批采样期间固定。采完后两个 Python 进程分别在 cuda:0 / cuda:1 更新，使用本组轨迹、优势归一化、价值头和 Adam。权重与梯度不平均。
- 当前学习率 1e-4、FP32、γ1、GAE λ0.99、24×24、100 回合。每批最多 8 个世界。每组 minibatch32、subsample .25、最多384次更新；数据分组后实际次数可能少于上限。
- 每回合奖励仍是实际名义 GDP 加持有新增土地的虚拟 GDP。新增 1/2/3/4/5 地累计 +10/+15/+18/+20/+21，其后每地 +1；丢地回退。实际 GDP、市场账目不加入这笔奖励。

两份 checkpoint 由已核实的同一个 BC 权重原样复制初始化。BC 文件没有 PPO 优化器，两组各自新建 AdamW，随后因各自轨迹自然分化。每批先完成并校验两份新权重，再发布一个 pair manifest，最后清理上一对；单边成功不能投入下一批。

## 正式执行与 legacy 观测

C++ 动态路径启用延后生产订单，旧单策略路径保持原模式。模型的原有特征维度、网络和权重格式不变。

- 建造提交时预付、预占容量，模型立即看到 `pending`；已落成建筑通道保持不变。统一结算边界开始施工，生产之后才落成，因此新电厂不会提前供电。
- 征兵提交时预付并预占额度，真实军队在结算边界生成。模型只在本国观测中看到计划单位；计划单位不能参与真实移动、进攻、战斗、补给或冲突包络计算。计划单位的取消映射为订单取消并全退未生成部分。
- 被占领/取消的未开工订单释放预占并退款；已开工建筑遵循原施工/落成顺序。农场与民兵营共同占耕地容量。
- 逐国 `end_turn` 只推进调度器，外交默认收尾在全部国家行动结束后按轮换次序处理。世界每回合只结算一次。
- 仍使用现有 legacy 候选接口：建造动作代表本格当期的一项建造意图，未新增 main 的批量多期队列工具。执行、费用和模型观测使用同一预占；不能把“只改变画面”当作规则迁移。

## 自动部署与恢复

旧训练服务保持停止。新服务 `zhanguo-ab-dynamic-ppo-watch.service` 执行根目录 `watch_ab_ppo.py`，读取本次明确重启入口 `restart-ready.json` 及绑定已测试源码 SHA 的 `validated-code.json`。启动时发现源码变化会停止。`prepare_ab.py` 校验原始 BC 检查点，生成两份输入、私有代码/状态数据集和初始化记录 `migration.json`。根目录原停训闸门在本次明确授权后归档。

私有 Kaggle 任务 `northwindlight/zhanguo-dynamic-ab-ppo` 的每段流程：

1. 校验预期累计局数和 A/B 输入 SHA，拒绝旧数据集版本。
2. 编译原生双模型采样器，检查确有两张 GPU。
3. 做独立的 2 世界×3 回合 CUDA 采样及两组短 PPO 检查；验证原始生产权重未改，测试权重丢弃。
4. 执行最多一个 200 世界任务段，退出并释放 GPU。
5. 本机下载、校验 pair/native 两组 SHA，再上传并提交下一段。

累计 2000 世界后停训，新 24 张同种子地图上用相同动态运行方式比较 BC 原始基座与最终 A/B，输出总体与各组 GDP、土地、征兵、进攻、断供等；最终自动回拉并生成 ZIP。CUDA 检查或训练失败会记录失败并结束远端任务，不留后台空转进程。

```bash
systemctl --user status zhanguo-ab-dynamic-ppo-watch.service --no-pager
cat ab-dynamic-ppo-results/live.json
tail -n 10 ab-dynamic-watch.log
```

`verified_games` 是本机校验完成的累计世界数；`last_completed_batch.games` 是远端已提交新权重的进度。`segments/NNN/verified.json` 是每段交付证据，最终 `verified.json` 是全部训练、回测和回拉完成标记。

## 验证与记录

`../analysis/ab-dynamic-tests/` 保存实际验证：

- 原生动态调度的单次结算、冲突分组、建造占位与全退、计划新兵本国投影/不可行动/期末生成、共享耕地容量。
- 与 main 直接对拍的 5 个提交/取消/出兵状态，资源和队列一致。
- 完整原生采样 → A/B 两个 PPO 更新 → pair 提交 → 重启续跑 → 有限回测的 CPU 小模型链路。
- 单边更新失败时保留原 pair；200 局迁移至 2000 局的全段调度；父 checkpoint 的字节一致复制及幂等迁移。
- 旧路径同种子 8 席终局记录逐字一致。

采样日志保留逐回合六商品报价，成功建设/征兵/军令等动作及其资源余额，期末真实军队数、HP和待出兵数。巨大原始轨迹在更新成功后清理，避免磁盘持续增长。
