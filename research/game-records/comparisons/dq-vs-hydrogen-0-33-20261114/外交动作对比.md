## 两封求援信与三次宣战

Hydrogen仅有的两封信都出自燕，第29回合分别送给齐和周：

> 致齐：赵军四步兵倾巢侵燕，意在独霸东海。唇亡齿寒，燕破则齐北疆难安。燕已备足军资死守绥井，望齐国严阵牵制或伺机取利，燕愿与齐守望相助。

> 致周：赵国四支主力步兵尽数东犯燕国，其曦城(15,5)与本土空虚。若赵吞燕，周北境必危；燕已死守绥井，邀周趁势牵制或共扼强赵，战后西线愿与周分利互安。

两封信都成功送达。内容有具体兵力、共同威胁、敌方后方空虚与利益交换，不能说它不会写外交信；实际差别在于通信只出现在遭到进攻之后，而且没有促成条约。齐和周没有发回信，齐第33回合还向燕宣战。

三次生效的主动宣战为：第13回合秦→魏，第28回合赵→燕，第33回合齐→燕。魏第14回合尝试向周称臣，被战时规则拒绝；第17回合改向秦提出称臣和平邀约，但同回合亡国，未形成和约。不能把后一件事写成秦看过提议后拒绝谈判。

## 新版提示与两步宣战

旧版没有当前的[随机tips](../../../../presentation/tips.py)，宣战也没有当前工具约定的自检、`confirm=true`确认两步流程。当前tips直接建议了解邻国、购入20金报表；[宣战工具](../../../../mods/native/tools/diplomacy.py)自检也会要求核对情报、兵力、条约和退路。这些都是本次比较的规则与提示差异。旧局另有Qwen议会审核，本局native没有议会，种子也不同。

Hydrogen的原始宣战调用共8次，拆开是：

- 4次只返回宣战自检，没有提交外交命令；
- 4次带确认的真实提交尝试，其中1次缺钱被拒绝，3次提交并最终生效。

因此表中是3次生效宣战，不是8次。以下额外只读查询也与外交命令分开：

| 主动调用的只读面板 | 旧局 | Hydrogen |
| --- | ---: | ---: |
| 外交 `foreign` | 9 | 21 |
| 近讯 `news` | 6 | 67 |
| 宣战推演 `war` | 0 | 3 |
| 收件情报 `intel` | 0 | 2 |
| 报表 `report` | 0 | 9 |
| 可购地图 `map_offers` | 旧版无 | 11 |
| 历史地图知识 `map_knowledge` | 旧版无 | 1 |

开局与每回合自动展示的事实不计为这些主动查询；不能把0次额外查询等同于没看到自动简报。

65次购报中，13次发生在全局第一次宣战自检之前；36次来自从未触发宣战自检的国家，另16次早于购买国自己的首次宣战自检。情报购买的增加不能全部解释成收到宣战自检后才补做，但随机tips的影响仍无法从这两局中单独剥离。

本局的外交手段确实比旧局单薄，情报获取则更积极。旧局的关系经营主要形成共防网络，Hydrogen更多通过单边获取资料和直接开战推进局势；这与前面“军队更多、列国战争更早，但八国总领土未增长更快”的结果相符。

共防网络还有实际军事含义：旧局向赵宣战，会面对赵与其燕、韩、魏、齐四个直接共防伙伴的防守义务；Hydrogen本局没有这组条约。这里按规则说明潜在参战成本，不把未发生的战争当成实测结果。

## 资料核对与复算

旧局按议会保存的正式行动记录统计，回退后废弃的后缀不计；Hydrogen按已提交存档的审计流逐ID去重，包含保存的末尾记录，没有重复ID内容冲突。两局均排除第34回合及以后、自动收尾回执、观察者来信、模型思考和历史查询中重复展示的动作。

提交后的外交命令逐项与存档/领域归档中的最终状态核对；信件、谍报与共享地图核对正式派送结果，而不只看最终消息列表（旧版只保留每国最后2份谍报，早期报告会从列表淘汰）。边界34的共防/联盟状态从旧局议会保存的原始外交状态差分、Hydrogen正式世界存档读取。

复算需要解压旧局原档与审计，Hydrogen使用与经济比较相同的边界34原档；不推进游戏，不调用模型：

```bash
python3 diplomacy.py --dq /path/to/dq/session.json \
  --hydrogen /path/to/hydrogen/session.json --output /tmp/diplomacy-comparison
```
