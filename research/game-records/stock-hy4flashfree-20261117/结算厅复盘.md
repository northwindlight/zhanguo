## 2. 本局主策略：v16 持有型消息驱动双向交易

最终保存并实际运行的是槽1的 **v16**。核心逻辑不是动量，而是新闻里的 `cashflow_change_pct` 对短期价格的预测性。

主要规则：

- 只处理本回合新闻，窗口 **2500 tick**。
- 新闻权重：
  - earnings：1.2
  - wire：1.0
  - market：0.3
  - shock：0
- 信号强度 `s` 上限 ±8。
- 新鲜信号 `fresh` 只统计 **800 tick** 内新闻。
- `fresh > 1.5` 做多，`fresh < -1.5` 做空，且方向要和 `s` 一致。
- 仓位：
  - `tv = s * 1800`
  - 多头单股上限 12000
  - 空头单股上限 8000
- 多头约按85%可用现金约束，空头约按40%现金价值约束，并检查借券。
- 持有型：空仓才建仓；持有后等信号衰减或反转才平，不做反复再平衡。
- 尾盘 `tick > 18500` 强制平仓。
- 第57回合起，即 `rnd >= final - 3`，只平仓不建仓。
- 200 tick 回调一次。
- 用 `if/elif/else` 保证每股每回调只做一个动作，避免同股多空委托混合。
- 不调用 `orders()`。
- 股票池动态读取 `quotes()`，不硬编码。

这套策略的优势在于：**抓消息公布后的短周期反应，而不是预测长期价值。**

## 3. 关键转折

### 第一次转折：从动量转向消息

最早我写过横截面动量策略，但因为历史不足没交易。后来研究发现，新闻现金流变化对短期价格反应明显强于动量，于是转向消息驱动。这是本局最根本的方向选择。

### 第二次转折：从纯做多到双向交易

早期纯做多会错失利空下跌行情。后来加入做空，并检查借券和保证金，才真正适应了市场。

### 第三次转折：修复技术事故

第4、5回合附近，我遇到过两个关键问题：

- 同股多空委托混合；
- `orders()` 返回逐日累积委托，导致计算量超限。

修复方式是移除 `orders()`，改用 `if/elif/else` 单向结构，并把评分与交易合并成单遍循环。这一步让策略从“想法”变成“能稳定跑的脚本”。

### 第四次转折：从衰减再平衡改为持有型

第10回合前后，信号方向其实对，但反复按衰减信号再平衡，导致高买低卖，手续费吃掉收益。第11回合改成持有型后，效果明显改善。这是策略收益曲线真正稳定向上的核心转折。

### 第五次转折：v16 加大仓位

第14回合我把仓位系数和单股上限提高，形成 v16。之后第15、16、17回合验证有效，尤其第17回合大丰收，说明在强信号日提高资金利用率是对的。

### 终局转折：清仓模式

第48回合我实际读了脚本，确认第57回合起清仓逻辑真实存在。第57、58回合回执也验证了清仓模式下空仓无交易、免费1档算力足够，所以最后没有再买算力池，省下120现金。

## 4. 风险和暴露出来的问题

### 宏观消息翻转会打脸

云度、星海这类股票多次出现宏观消息正负快速切换，策略会来回被打。这是消息策略的固有风险，不是脚本 bug。单日小回撤时不能轻易推翻框架。

### 固定成本会吞掉弱信号日利润

有些交易日交易毛利为正，但手续费加算力池后净值几乎不涨甚至小跌。比如第43、第51附近就是这种情况。教训是：弱信号日不要幻想靠交易覆盖固定成本，长期靠强信号日拉开收益。

### 算力档位不能乱买

第12回合多买算力导致本来盈利的一天转亏。后来坚持交易日只买2档池，14只股票下约610多万步，2档足够。终局清仓模式更不需要买池。

### 技术风险比策略风险更致命

`orders()`、多空委托混合、算力超限、隔夜仓位，这些都不是收益问题，而是生存问题。每回合检查 effective、回执、持仓、费用，是必须的流程。

### 我自己的流程教训

我前面多次凭记忆说“清仓保险已就位”，但直到第48回合才真正读脚本验证。结果是对的，但流程不够严谨。终局前关键逻辑应该更早实读，而不是只靠记忆。

### 研究费用口径

早期我确实做过研究尝试，长期记录里曾把研究费列为拖累；但最终结算里 `intelligence_expenses = 0.0`。具体口径差异我记不清，以最终结算为准。实战上后来停止付费研究、只在必要时只读检查，是正确的。

## 5. 经验教训总结

1. **消息信号强于动量信号**，尤其 earnings 和 wire；market 只能降权；shock 多次反常，应该剔除。
2. **最新消息比累加信号更重要**，但不能用最新信号反复再平衡，否则手续费会吃掉优势。
3. **持有型比频繁调仓更适合这个市场机制**。
4. **双向交易是必要的**，否则利空行情只能旁观。
5. **资金利用率要够，但不能无脑放大**；v16 的仓位上限和现金约束是平衡点和风险点。
6. **成本控制很关键**：2档算力池足够，终局免费档足够，不买多余池。
7. **脚本稳定性优先于策略复杂度**：不调用 `orders()`、单遍循环、单向动作、动态股票池，这些简单结构反而最可靠。
8. **终局纪律要提前验证**：第57起清仓、尾盘强平、空仓现金化，最终才能把账面收益变成结算现金。
9. **不要因单日回撤推翻已验证框架**；但要因技术错误、费用失控、逻辑不一致及时修正。

## 2. 策略主线：从找 edge 到被迫收尾

我大致走过几条线：

### 早期：消息驱动和趋势跟随，基本失败

最早试过现金流消息、market 消息、wire 消息、宏观入场+wire出场、趋势做空等。

教训是：

- `cashflow_change_pct` 早期看似有效，后来发现是单边趋势日假象；

- wire 消息胜率不稳定，而且入场太晚；
- 趋势做空在第10回合市场反弹时被挤压止损约1400。

这些方向都没有形成稳定 edge，反而贡献了大量试错成本。

### 中期：锚价回归，是真正发现过的 edge

后来发现锚价回归才是我这局最接近有效机制的东西：

- `ratio < 0.75` 历史回测 5/5 胜，5日平均约 +23.8%；
- `ratio < 0.82` 回测 13/18 胜，平均约 +13.6%；
- v21 精确规则回测 19笔12胜，平均 +4.03%。

第16、17回合锚价回归实盘确实见效，账户从约90350升到91209，持仓浮盈一度接近+979。那是我这局少数真正“策略有效”的阶段。

### 后期：市场机制切换，转向 REC，再转收尾

第25回合研究发现：早期均值回归有效，但近期纯回归失效，REC信号（低于锚价且正在回升）相对更稳。

于是做了 v22：

- 买入：`ratio < 0.95` 且 5日动量 > 2%
- 出场：+12% / -12% / 6日 / 动量转负超过 -8%

但 v22 实盘结论很残酷：

- 第26-29回合免费档：账户 89249→89318，微赚；
- 第30-35回合买池2，累计720费用后：89318→88531，亏787。

也就是说，**v22交易本身基本持平，账户下降几乎全由每回合120元算力费造成。**

最后我改成 v23 精简收尾策略：

- 不再开新仓；
- 只管理遗留持仓；
- +12%止盈、-12%止损、动量<-8%出场；
- 第50回合强制清仓。

最终保存的 v24 不是盈利策略，而是清仓修复版：无条件对持仓用限价卖单清仓。它是执行补丁，不是 alpha 策略。

## 4. 风险和暴露的问题

### 技术风险非常致命

我这局出现过一串脚本问题：

- `**0.5` 非整数指数报错；

这些都说明：**语法检查通过不等于能跑，能跑不等于能成交。必须看 effective、回执、成交笔数和持仓变化。**

### 成本风险比策略风险更大

最终算力费用7120，已实现交易亏损4277。也就是说，即使交易端少亏一些，费用也足以吞掉大量净值。

- 过度研究；
- 过度工程；
- 频繁改版；
- 在收益基本持平时仍买池2。

### 策略风险：价值陷阱和机制切换

hongfan、zhongli 这类“低于锚价但还在下跌”的股票，是典型价值陷阱。后来 REC 信号就是为了避开这种刀。

## 5. 经验教训

1. **先算成本，再谈策略。** 弱 edge 策略一旦叠加每回合固定费用，就会从微赚变微亏，再变大亏。
2. **策略复杂度必须匹配收益。** v22 交易本身基本持平，却用了复杂遍历和池2，结果费用吞掉净值。
3. **不要频繁改版。** 我多次因为短期回撤或单日现象重写策略，最终证明是主要亏损来源之一。
4. **止损后反弹不代表止损错了。** zhongli 止损后反弹约24%，taiping 止损后账户反而回升，这些都应视为机制正常代价。
5. **终局纪律要提前验证成交，不只是验证逻辑。** 第50回合清仓失败就是教训。
6. **空仓也是策略。** 第51回合清仓完成后，后面完全空仓现金化，这是后期最稳的处理。
7. **动态股票池、读取 holdings 成本、检查 available_quantity，都是硬要求。**
8. **研究要克制。** 研究确实帮我发现过机制切换和技术问题，但费用与反复工程化也拖累了净值。

## 2. 最终策略：槽1 v45，宽基等权方向篮子

最终保存并实际运行的是槽1 **第45版**：

核心逻辑：

- 用宏观新闻方向决定市场方向，不押注个股强弱。
- 开盘 `tick < 500` 时，根据上一交易日 `last_macro` 建仓：
  - `last_macro > 0.3` 做多宽基篮子；
  - `last_macro < -0.3` 做空宽基篮子；
  - 方向未变则不动，降低换手。
- `tick7000` 只读取当天 market 新闻均值，记录为下一交易日用的 `last_macro`，不再追高建仓。
- 篮子构建：动态遍历 `quotes`，每只约2500名义，等权做多或做空。
- 宏观变号时，翻转必须分两个回调：
  1. 先 `close_all()` 并设 pending；
  2. 等持仓清空后，再 `open_basket()` 开反向仓。
- 财富低于78000时全平并停止开仓。
- 终局前3回合，即 `rnd >= final - 3`，强制清仓、不再开仓。

### 2. 最终策略：v23 极低换手持有策略

最终保存并实际运行的是槽1第25版，也就是我称为 **v23** 的低换手策略。

核心规则：

- `day >= 56`：进入清仓模式，遍历所有持仓，多头 `sell`、空头 `cover`，清仓后直接 `return`，不再开新仓。

  - `trend = (price / ma20 - 1) * 100`

`final_close_count = 0` 不是风控强平，也不是漏平。第57回合我已经主动清仓，3笔卖出委托全部成交，卖出600股 / 39922元，手续费39.92元，之后空仓到终局。终局没有正常平仓笔数，是因为已经提前现金化。

### 2. 最终策略：v23 是止血工具，不是 alpha

最终保存的是槽1第25版，也就是 v23。

核心规则：

- `day >= 56` 清仓，多头 `sell`、空头 `cover`，清仓后直接 `return`；
- 每日最多检查一次，用 `state["day"]` 防重复；
- `trend = (price / ma20 - 1) * 100`；
- `score = trend + momentum_5 * 100`；
- 严格买入：`trend > 2` 且 `score > 5`；
- 宽止损：跌破 `0.9 × ma20` 才卖；
- 持仓上限2只只限制新开仓，不砍历史超配持仓；
- 极低换手，宁可零交易。

最终轮我要更明确地说：

**v23不是盈利策略，它是止血策略。**

它做对的是：

- 停止频繁换手；
- 停止追涨杀跌；
- 让已有盈利持仓自然修复；
- 按规则止损，不人工抢跑；
- 终局按时现金化。

但它没有做到：

- 持续产生新的交易毛利；
- 形成足够厚的 edge；
- 覆盖算力和摩擦成本；
- 把峰值浮盈转化为最终盈利。

最终交易端 **-5033.19** 就是证据。  
低换手减少了我继续犯错的速度，但没有替我赚钱。

### 3. 关键转折

#### 第一，早期频繁换策略，是费用失控的根源

我前后改了二十多版：动量轮动、消息高频、日内多空、做空最弱、tick7000消息交易等。

很多方向未必完全错，但我换得太快，很多判断基于短期噪声。再加上技术事故：

- 100 tick轮询耗尽算力；
- 同股多空委托混合导致脚本失败；
- `quotes()` 超限；
- 历史对齐误用 `h[R+3]`、`h[R+2]`；
- 曾把当日消息验证误当成次日预测，存在前视偏差。

这些共同推高了算力费用。  
**17640算力费不是某一天炸出来的，是长期试错一点点扣出来的。**

#### 第二，v21/v22让我发现换手损耗是核心问题

第15-19回合附近，我用过长线动量 v21/v22。选股方向有时是对的，但每日再平衡不断吃手续费和滑点。

当时关键诊断是：  
`realized_pnl` 大幅为负，而持仓浮盈并不大，说明亏损主要来自换手，不是选股。

于是转向 v23：严格买入、宽止损、极低换手。这个方向是对的。

#### 第三，我后来把“零交易”过度解读成了策略有效

第22、23回合开始，v23连续零交易，净值从低点74643反弹到77479，再到后续修复。那段时间我确实看到低换手减少了失血。

但我后来犯了一个认知错误：  
把“零交易”和“持仓反弹”过度解读成策略有稳定 edge。

更准确的说法应该是：

> 零交易只是停止继续失血；持仓反弹主要来自市场均值回归，不等于我的策略有稳定预测能力。

#### 第四，止损事件让我学会不抢跑

第37回合云度跌破 `0.9 × ma20`，脚本按规则止损，卖出126股，损失有限。之后净值反弹，说明规则止损本身没有错。

后来我多次误判山海、金晖是否触发止损。有些回合我判断可能止损，但实际脚本没有触发，事后继续反弹。  
教训是：**让脚本按实时数据判断，不要人工抢跑。**

#### 第五，终局清仓成功，但这只是保全

第57回合清仓分支正常触发：

- 委托3笔；
- 成交3笔；
- 成交7笔；
- 卖出600股 / 39922元；
- 手续费39.92元；
- 持仓归零。

第58回合脚本 effective、动作0笔，符合空仓预期。第58、59回合没有再买算力池，避免新增不必要费用。

但这只能说明：  
**终局执行成功，把剩余现金安全落袋。**

甲的终局现金化是保住利润；我的终局现金化是固定亏损。两者不能混为一谈。

### 6. 最终经验教训

1. **交易端必须足够厚。** 交易端打平或小亏，费用就会决定失败。
2. **算力费是硬成本。** 弱edge叠加高算力，必然从微亏变大亏。
3. **少改版比多优化重要。** 我早期最大损耗就是反复推翻策略。
4. **区分 alpha 和风控。** v23是风控有效，不是盈利有效。
5. **零交易不是edge。** 它只是避免继续犯错，不能替代盈利能力。
6. **止损按规则执行。** 不要因人工误判抢跑，也不要因止损后反弹否定规则。
7. **技术执行是底线。** effective、回执、成交笔数、持仓变化、费用都要看。
8. **终局现金化要提前验证。** 清仓逻辑、成交方式、盘口深度、空仓后不买算力，都要提前确认。
9. **研究必须防前视偏差。** 历史对齐错误会得出完全错误的结论。
