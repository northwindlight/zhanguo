## 消费分类、数学与需求价格复核（2026-10-19）

[实现与复现附录](../../docs/research/消费指标实现与复现.md)区分现行三类消费、四类支出、当期价格金额和固定价格数量指数。以下三项已实际完成，不执行模型调用或读取真实存档：

- `theory_checks.py` / `theory_check_results.json`：资本积累平衡、常数投资率、有限期最优递推与穷举、衰减反例、需求弹性与名义金额分解的独立数值复算。
- `market_value_checks.py` / `market_value_results.json`：竞争价格支持宏观用途价值的数值例子、20个有理数投入产出模型的消费资源价值等式、国家/消费投资分解、残差界及劳动价值联系；不加载游戏。
- `strict_consumption_probe.py` / `strict_consumption_results.json`：六组同初始世界，各实际消耗60补给、无投资。动态无交易/买入/卖出组的三类消费金额为360、551.991815、223.055993；固定报价三组均为360。逐期独立核对库存扣减、部队状态和使用事实，最终取正式结算 consumption。

成对差异说明当期价消费不具备共同价格数量指数的路径不变性。额外买卖确实改变了市场需求和供给，不能只凭差异判定价格没有经济意义。2026-10-15 的价格探针只包含建造，不能用其百分比代替三类消费的结果；两组材料分别保留。

## 已完成范围

- 合成事件：200 笔木材往返交易；固定估值下三种资源来源的同一建设；中间生产；默认银行参数的一次完整借还周期。
- 初步账本运行：双国、12×12、8 个种子、各 40 周期。种子 0、1 做过连续运行与保存恢复后逐期状态比较。此项不作国家能力比较。
- 多国检查点：八国、24×24、种子 0、30 周期，均为 v11plus，通用宿主初始化，没有正式八国剧本的特殊外交安排。该区间经济事实 3464 条，各国累计消费与事件估值加总残差均为 0。
- 八国续算检查：从同一第 30 周期合成存档独立载入两份状态，分别推进至第 31 周期，完整状态相同。这是重复载入后的确定性核对，不是未中断运行与恢复运行的完整对照。
- **价格通道成对实测（2026-10-15 新增）**：六个体积相同、物理实现逐项相同（金 360、木 180）的合成世界，处理组只增加合法市场交易。现行字段 `cumulative_spending` 比对照高 42.9%（每期买入 300 木）或低 25.9%（每期卖出 300 木），按基准价复算则六臂全部相等（720）。**这证伪了论文中的命题 H₂**：现行字段不是交易路径不变的。原始结果见 `price_channel_results.json`。

原计划八国 4 种子 × 60 周期已停止，只有种子 0 的前 30 周期进入记录。不得把计划规模写成完成规模。30 周期内木材买入 1701、卖出 0、市场期末库存 219，不能据此认定长期内部供给成立。

八国工作记录共 1284 条宿主行动，其中 24 条领域拒绝；失败记录全部保留。主结果采用当期估值，固定价格下的不变性结论不能无条件套到动态价格总额。

## 复核已保存材料

在匹配源码的仓库根目录、现有 Python 环境中执行：

```bash
.venv/bin/python experiments/consumption_metric/audit_checkpoint.py
```

脚本先校验源码与此前已完成核对的指纹相同，再读取本目录的合成检查点；两个载入实例各推进一周期，重新运行四组小型事件核对，最后写入 `results_eight_country.json`。本机一次核对约数分钟。它不会连接模型服务或读取真实对局。

`audit()` 从已生成的经济事实重新累加建设、征募、军事及行政使用估值，并与报表比较。它不是逐项独立验证底层资源扣除，也不能发现所有“资源已扣除但事件未生成”的漏记。未定价资源会导致核对失败，不按零处理。

市场来源实验使用固定报价模块；转移例子是合成账户划拨，不包含外交服务费。银行核对采用当前默认存款 0、借款每周期 2%、5 周期期限与整数利息规则。详细序列保存在 JSON 中。

## 运行成本（2026-10-15 实测，Raspberry Pi 5 / 4 核）

长局慢的原因已定位，不在机器。八国 24×24、v11plus、一个周期约 41→54→64 秒（**随局面增长**），单次 `to_save()` 仅 0.018 秒，建局 0.38 秒。cProfile 显示一个周期里 **98% 的时间在 `observe()`**，链如下：

```
observe → vision.tiles(actor)            # 每周期约 160 次
        → 逐格调用 vision.visible(x,y)    # 每次约 581 格
        → territory.owned(owner)         # 每格都重建全领土列表：约 93,000 次/周期
        → territory.snapshot() → get()   # 每块地一次 get()，内部还有一次跨模块 buildings.site 调用
```

一个周期合计约 **370 万次** `get()`、**470 万次** `object_call`。三点结论：

1. **瓶颈在引擎**（`mods/native/vision` 与 `mods/native/territory` 的组合：无每周期缓存），不在 ruleai 的决策算法。
2. **ruleai 是放大器**：一个回合调用 `observe()` 四次（`entry.py`、`military.py`、`combat.py`），把引擎的常数乘了四倍。
3. **换机器解决不了**：这是单线程纯 Python，ECS 单核与 Pi 5 同级或略快。性价比最高的是多种子并行（4 核 = 4×，零代码改动），其次是给 vision/territory 加每周期缓存（把 160 次 `tiles()` 与 93,000 次 `owned()` 压到每国每周期一次，预期一个数量级），再次是让 ruleai 复用同一份 observation。

正式长局实验开展前应先处理第 2、3 点，否则"大地图、多种子、长周期"的规模会被这个常数直接吃掉。

## 后置的正式实验

正式研究应重新设计大地图、长周期、多种子与角色轮换，检查逐资源供给、初始库存贡献、地理路径依赖、建设成熟和完整债务周期。扩大地图与延长时间不自动保证地理影响消失。

后续若研究“需求承接者盘活经济”，需要明确策略干预与对照，记录产出、库存、成交、价格、实际用途与负债；现有同策略短局不承担这个因果结论。当前没有后台长局继续运行。
