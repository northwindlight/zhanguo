# 地图图片渲染（玩家 UI 层改造）

2026-10-12 起。**方向是用户定的**：原生多模态模型越来越多，用图片而非文字展示地图更合适。
渲染器本体是仓库根目录的 `render.py`（**尚未接进回合循环**，见文末）。

跑法（都要 Pillow，见「依赖」）：

```bash
python render_sim.py    # 造一局八国 24×24、规则 AI 跑到 T60，出一张玩家视角图
python pack.py          # 出一张世界地图 + 八国视角图，打包成 zip
python readoff.py       # 让模型读图报"某坐标是谁的地"，对答案（含三种对照）
python variance.py      # 同一张图连测三次：**先量抖动，再谈差异**
python palette_search.py  # OKLab 网格搜索：8 国色离四色兵牌最远能到多少
```

## 为什么该改（实测）

`_fmt_atlas`（常驻面板）是**每格一行的坐标列表**——不是地图，是带坐标的数据库导出，
几何形状（地图唯一不可替代的东西）在列表里没了。八国局、规则 AI 驱动，韩：

| 回合 | 视野格 | 国土 | 取景框 | 框里无效格 | atlas | 整个 state | atlas 占比 |
|---|---|---|---|---|---|---|---|
| 1 | 21 | 5 | 5×5 | 16% | 334 tok | 1789 | 19% |
| 40 | 102 | 23 | 21×21 | **77%** | 1111 | 2603 | 43% |
| 110 | 202 | 81 | 21×21 | 54% | 2056 | 4553 | 45% |

取景框 = 视野包围盒；领土长成条状时框被撑成大方块、**四分之三是 `?.`**（图像里"看不见"
本该只是没有像素）。而且它**线性增长**——越强越花钱读自己的地。ASCII 网格版（`panel=grid`）
同样浪费，还要两行列头 + 图例才能解码。

## 图有多贵（实测，经 qoder-flash 网关打上游）

| 尺寸 | 图净耗 token |
|---|---|
| 400² | 184 |
| 800² | 422 |
| **1024²** | **652** |
| 1280² | 994 |

渐近 ≈1600 px²/token。★ 与 DeepSeek 官方文档「大图缩到总像素≈1300×1300、
**每张图封顶 1024 token**」独立对上（1300²→1024 ⇒ 1650 px²/token）。
★ `detail:"low"`（文档说缩到 512×512）在本路上**被静默忽略**（实测 491 vs 491）——
省 token 只能靠少画像素，不能指望它。

线上剧本 `map_size: 24` ⇒ 36px/格 = 864px，**全世界一屏装得下**，不用取景框/小地图内嵌。

# ★★ 最贵的一条：颜色这条件通道不够用（全部实测）

## 1. 8 国色不可能互相分清 —— 这是几何问题

配色验证器（all-pairs，calibration 是"颜色为唯一识别通道且无标签"的统计图）：

```
3 slots → PASS
4 slots → FAIL   (黄↔橙 CVD ΔE 4.8 / 常视 10.6)
8 slots → FAIL   (CVD 1.6 / 常视 7.1)
```

用户 2026-10-12 要求「各国都不要使用友敌军颜色作为国土颜色」（兵牌固定
自己绿/友军蓝/敌人红/中立灰）。OKLab 网格搜索的结果（`palette_search.py`）：

| 约束 | 离兵牌色的最近距离（最优） | 门槛 |
|---|---|---|
| 四色全在 | **9.3** | 15 |
| 只留自己绿/敌人红 | **12.3** | 15 |

⇒ **做不到满分，卡住的是"8 个国家"本身，跟兵牌用什么颜色无关。**

## 2. 但真正的瓶颈不是颜色 —— 是**对照表画错了地方**

同一张图、同一个模型，只换「国名↔颜色对照表」的位置：

| 变体 | 命中 |
|---|---|
| 斜纹开 · 对照表**画在图里** | 3/12 |
| 斜纹关 · 对照表画在图里 | 7/12 |
| **斜纹开 · 对照表在文本里** | **9/12** |

⇒ 模型读地图上的色块没问题，**读不出画在图里那排小色卡**。
国名↔颜色是张查找表，本来就该是文字（`render.legend_text()`，与"图给形状、文给精确"同一条口径）。

## 3. ★ 先量抖动，再谈差异（这一步差点让我报了个假结论）

同一张图**连测三次：7 / 8 / 5** ⇒ 模型在这个任务上的自身抖动就有 **3 题**。

- 我以为的"满格覆盖从 9 掉到 6"——**差 3 题 ≈ 抖动，无结论，已撤回**。
- "对照表在图里 vs 在文本"差 6 题 > 抖动 3 ⇒ 方向可信。

逐题稳定性才是有用的：自己国土 3/3 稳对；**(8,9) 韩→楚 稳错**；**(11,8) 周 稳错**；其余全摇摆。

## 4. 稳错那题最有价值

韩＝品红 `#cd00cd`、楚＝亮品红 `#ff00ff`——**同一色相的两个明暗档，模型 3/3 全错**。
⇒ ANSI「同色相 + 明暗两档」那套方案**不能用于国别**：明暗差在模型眼里不是"两个颜色"。

## 5. 结论

> **单靠颜色在 44px 的格子上辨国，本来就不稳（5~8/12 且晃）。**
> 这不是配色问题，是「颜色这一条通道不够用」。

**HOI4 怎么解的**（对照）：省份 ID 网格是权威数据、颜色是运行时着色；**地图模式**各一张
（政治/地形/补给…），压根不试图一张图塞完；兵牌一个省一张带堆叠数字；
★而"认不出是谁"**不在颜色层解决**——靠**重描国界线 + 悬浮 tooltip + 国家名标注 + outliner**。

我们的处境：**重边框**可以抄；**悬浮抄不了**（模型没有 hover）⇒ 那一路只能用文本补。

### 待定（用户拍板中）

- **A** 恢复第二通道（每国一种斜纹角度，纯图案不动颜色）
- **B** 把格子做大（44 → 70px+）
- **C** 地图只回答「我的 / 别人的 / 无主」，具体国名交给文本
- 倾向 **C + A**

# 渲染器的设计（现状）

**图层**：地形（格角字母 P/F/H/M/D，与文本面板同一套）→ 迷雾（近黑，"看不见"就是没有像素）
→ 归属（**整格铺满国色**；有地标/军队=平涂，其余=压在国色上的粗暗斜纹）
→ 地标（房子=市政厅=国祚、城垛楼=城堡+等级）→ 军队兵牌 → 可及虚线框 → 四边坐标。

**兵牌**（用户给的结构，**两层嵌套长方体**，由外到内）：
`黑描边 → 阵营色一圈(自己绿/友军蓝/敌人红/中立灰) → 白色内框 → 暗底 + 兵种符号(用国家色)`
牌右数字=几支，牌下血条=该阵营在这格的**总血量**；同阵营合并，一格最多四种。
野人=空心圆（不属阵营）。★ **这个框不是装饰**：符号能在任何底色上读出来靠的就是它，
而不是靠"国土色跟阵营色不一样"（后者几何上做不到，见上）。

**世界地图**（`render_world()`）：观察者视角，不裁、无迷雾、所有军队，兵牌外圈=国家色。

## 踩过的坑（都会静默）

1. **`bool(buildings(x,y))` 恒为真** —— 那个 dict **16 个键恒在**、没建的值是 0。
   于是每格都判成"核心"，斜纹一次没画过，**症状还是"看起来正常"**（满屏实色）。查了两轮。
2. **`d.polygon` 要的是点对列表** —— 传扁平 `[x0,y0,x1,y1]` 会被当成"两个点"，画出来是
   一条斜线。自家军队整整一轮在图上显示为一道白杠。
3. **变量遮蔽** —— 兵牌那段把 `cw`（网格宽）复用成"兵牌宽"，冲掉了网格宽。
   网格照样画对（`grid_w` 早算好了），**只有标题的"全世界 vs 取景"判断错**，
   一直到世界地图把"取景 x1-24"印在标题上才露出来。
4. **斜纹密度是三轮试出来的**：交错+step6 → 糊成实色；单向 step13 → 线太细；
   光加粗（step20/宽2）→ 国色只占一成、读不出是谁的地。定稿 **step15/宽5 + 淡国色底**。

## 依赖

`render.py` **不需要 Pillow 也能 import**（lazy import，`available()` 只探不抛）；
真画时才用。缺 Pillow/字体 ⇒ `render()` 返回 `None` 并**大声说一次**，调用方退回文本面板。
**画图永远不许弄死一局。**
