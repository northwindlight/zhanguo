# experiments/

游戏机制统计实验，独立目录，**不 import 游戏运行时（mp.py）、不改游戏任何文件**；
只复用 `game.py` 里的纯函数权重表抽法。

## gold_uniformity.py — 金矿均匀度

随机种子 + 随机地图边长（默认 30..100）生成 N 张图，统计每格黄金资源
（0/1/2，权重随地形，山地最富）的分布均匀度。

```bash
~/.venv/bin/python gold_uniformity.py                # 200 张图，约 20s
~/.venv/bin/python gold_uniformity.py --trials 500 --size-min 40 --size-max 80
```

明细写 `out/gold_uniformity.csv`，汇总打 stdout。指标：

| 指标 | 含义 |
|------|------|
| density | 有矿格占比（黄金≥1） |
| total | 全图金量（=可建黄金矿场上限之和） |
| sector_cv | 4×4 分区金量的变异系数，↓越小越均匀 |
| sector_max_ratio | 最富分区/平均分区（某角独肥程度），↓ |
| gini | 逐格基尼（绝大多数格为 0，天然≈0.9，看相对变化） |
| near_mean / near_max | 每格到最近金矿格的距离（8 邻域 BFS）：平均/最远，↓ |

与真实对局的差异：游戏里资源从世界 RNG 顺序抽（依赖占地顺序），实验改为
每格独立抽——分布相同，逐格具体值不对应某次对局，对均匀度统计无影响。

## gold_uniformity2.py — 生成方案对比（A 现状 iid / B 分区配额 / C 蓝噪声）

回答两个问题：①"MT19937 理论很均匀，为什么还一地金子？"②"能不能更均匀？"

① 数列均匀 ≠ 空间均匀。逐格独立抽样是泊松点过程，天然成簇——实测分区 CV
恰等于泊松预测 1/√λ（大图 0.128 vs 0.124），随机数没毛病。12% 密度下开荒
几十格见到连片金矿是 iid 的正常表现。

② 同种子同图三方案对比（100 张，边长 50..100）：

| 指标 | A 现状 iid | B 4×4配额 | C 蓝噪声(间距≥2) |
|------|-----------|----------|----------------|
| 分区CV↓ | 0.152 | **0.093** | 0.102 |
| 最富/均↓ | 1.285 | **1.177** | 1.195 |
| 距矿最远↓ | 4.5 | **3.0** | 3.2 |
| 矿贴矿比↓ | 0.638 | 0.547 | **0.000** |
| 最大矿簇↓ | 10.6 | 5.9 | **1.0** |

- **B（分区配额）**：区域公平最好——每 4×4 块金点数只差 ±1，"最富分区"
  p90 从 1.45 降到 1.30；但块内随机落点仍 55% 贴矿，"一地金子"减而不除。
- **C（蓝噪声，任意两矿间距≥2）**：直接消灭连片金矿（矿簇恒为 1 格），
  距矿均值也最低；区域公平略逊 B。
- 两者都需把金矿与地形解耦（游戏里黄金矿场只看资源值不看地形，解耦不影响玩法）。
- 落地改法（若要做）：World 初始化时按 B/C 铺一张金矿表，`_new_tile` 查表
  代替 `roll_resources` 抽黄金（其余资源照旧）；改动集中在 mp.py 一处。

## 一次 200 张的结果（2026-09-09，种子 1486468087）

- 有矿格占比稳定在 **12%** 左右（几乎不随地图大小变）。
- 分区 CV 随边长增大而降（小图 0.28 → 大图 0.13），主要是分区期望金量变大的
  泊松效应（CV≈1/√λ），并非"大图机制上更公平"。
- 最富分区平均是均值的 1.37 倍（p90≈1.6）——开局选边时可能碰到明显的肥角。
- 全图任意格距最近金矿平均 1.26 格，最远 rarely 超过 5 格——金矿在可达性上
  相当均匀，不存在"大片无矿区"。

## march_probe.py — 行军/编队/目标选择探针（v10 vs v11）

同种子同尺寸、单国（秦）跑两个规则 AI，量**行军效率与编组质量**。
仓库里原先**没有**能复现"行军/进攻"那类数字的工具（v10 文件头引的那几个数
是当年手工跑出来的），这个探针就是补这个缺口。

```bash
PYTHONUTF8=1 .venv311/python.exe experiments/march_probe.py
PYTHONUTF8=1 .venv311/python.exe experiments/march_probe.py --seeds 0,1,2 --size 30 --turns 150
```

指标：行军/进攻次数、首次进攻回合、**停滞军队·回合**（满血未交战却没动）、
**倒退次数与倒退率**（某军回到两回合前的格 = 抖动）、每动一格走了几格、
领土与"到 10/20/30 格"的回合（曲线指标，抗方差）、消费（中位）。

**实测（锚定提交 `0f7cc3c`，40×40 · 300 回合 · 6 种子，中位）**：v11 领土 279 → 400.5
（6/6 种子全胜）、倒退次数 198 → **0**、行军 1223 → 406、消费 29.9k → 28.7k。
设计与推导见 `docs/v11编组模型.md`。

## probe_spend_v10_v11.py — v10 vs v11plus 的单国消费对比（2026-09-16）

一图一国（用户口径：多国对战会把"谁先动手、谁背刺"的运气混进消费里），16×16 或 40×40 × 300 回合，
逐图配对报**终局总消费 / 领土 / 剩余金 / 余货折金**，另附消费构成（建造 / 征兵 / 军费）与国库金曲线。
口径与 `rl/train.py:teacher_baseline`（`feat/rl`）逐条对齐：图种子 = 局种子 = `900000+i`、
老师 rng `0xB4BE`、`max_actions` 无上限、每局开跑前清编组状态。

```bash
python3 experiments/probe_spend_v10_v11.py                          # 16x16 × 300 回合 × 8 图
python3 experiments/probe_spend_v10_v11.py --size 40 --maps 8       # 40x40（不饱和，区分度更好）
python3 experiments/probe_spend_v10_v11.py --shares 0.15,0.30,0.60   # v11plus 的 MIL_SHARE 扫描
python3 experiments/probe_spend_v10_v11.py --gold-trace             # 另打国库金曲线
```

**一条读数的坑**：16×16 在 300 回合会**打满**（256 格全占）⇒ 指标被压平，看不出差别；
要区分得用 40×40（不饱和）或更短的回合数（`teacher_baseline` 只用前 100 回合就是这个道理）。

**首轮结果（2026-09-16，单国 300 回合，逐图配对 + 对地图 bootstrap）**

| 图档 | 消费中位 v10 → v11plus | 领土中位 | 剩余金中位 | 军费占比 |
|---|---|---|---|---|
| 16×16 × 8 图（**300 回合已打满**） | 49,747 → 48,816（差 −1,911，CI 跨 0） | 249 → 256 | 228 → 308 | 39.6% / 39.7% |
| 40×40 × 8 图（不饱和） | 69,936 → 66,426（差 −5,071，CI [−8,582, −2,001]） | 352 → **660** | 396 → 248 | 38.7% / 38.9% |

读法：**v11plus 拿近两倍的地、花少 7.6% 的钱**（消费是终局口径，300 回合时那些地还没转成消费
—— 按"地是消费的期权"的口径，这不一定是坏事）。两边军费占总消费都 ~39%，与 `MIL_SHARE`
不是一回事（那个闸管的是 `军费 / 收入`）。

MIL_SHARE 扫描（v11plus，300 回合 × 每档 8 图，现状 0.30）：

| 图档 | 0.10 | 0.15 | 0.20 | 0.30（现状） | 0.45 | 0.60 |
|---|---|---|---|---|---|---|
| 16×16（300 回合已打满）消费中位 | 49,509 | **51,437** | 51,244 | 48,816 | 38,319 | 20,747 |
| 16×16 军费 / 建造 | 9.3k / 38.9k | 12.8k / 36.5k | 15.9k / 33.1k | 19.3k / 26.4k | 19.2k / 16.7k | 13.1k / 6.6k |
| 40×40（不饱和）消费中位 | — | 61,356 | — | **66,426** | — | 53,845 |
| 40×40 领土中位 | — | 540.5 | — | **659.5** | — | 648.0 |

⇒ **最优值跟图档走，别拿小图的结论去定大图**：

- **16×16**（300 回合会打满）：峰值在 **0.15~0.20**，0.30 比峰值低约 5%
  —— 与 `feat/rl` 那句「MIL_SHARE 拐点 ≈ 0.15（200 回合）」对上（那个也是在 16×16 上量的）。
- **40×40**（不饱和）：**0.30 反而更好** —— 比 0.15 多 8% 消费、+22% 领土；地多就要更多兵去占/守。
- **0.60 开始出现塌局**：40×40 的 8 张里有 2 张消费只有 0.9~1.0 万、领土停在 5 / 217 格
  （军费 21k 吃掉建造 6.6k ⇒ 断粮崩盘）⇒ 上界别超过 0.45。

所以现状 0.30 **不是"借错了"，只是没在 40×40 上量过**；要拍板就按"目标图档"重跑一档。

国库金（8 图中位）：全程 30~60（中段）→ 240（终局），**"堆着不用"是脉冲而非堆积** ——
300 回合里只有 2~4 回合 >500、2 回合 >1000，1,500 那个峰值是卖货换现的过路钱；v10/v11plus 同款。

## probe_econ_coverage.py — 地开发到哪一步了（2026-09-16）

逐回合记 `领土 / 真·未建格 / 国库金 / 国库木 / 本回合建造数 / 建筑总数` + 集中度。
用来回答"为什么 v11plus 拿两倍的地、消费却少 7.6%"：两个 AI 都是**塔式**发展
（建筑扎堆在少数按 ROI 挑出的格子），而 v11plus 抢地快一倍 ⇒ 开发到的格反而更少（29 vs 49）
⇒ 产出上不去。中段国库金只有 30~120 ⇒ **钱是紧的**，建造速度 ~1~2 座/回合。

★ 一个坑：`t["buildings"]` 是**全键字典**（`{'林场': 4, '农场': 0, …}`），
`if not t["buildings"]` 恒为 False —— 真·未建要判"所有键的值都是 0"。

**木头工作库存（2026-09-16，用户：「木不是按金折算了吗，保证不屯木头」）**

病根：`need["木头"]` 被"**想要**的兵营数"（`n_barr`，兵营 350 金/座、往往买不起）灌成
20 木/座 —— 实测末期 `need木 ≈ 493`（`n_barr=24 × 20 = 480` 全来自它）⇒ 清仓只卖
「库存 − 493」⇒ 木堆到 500~900，而那块价值**不计入 `_budget`** ⇒ 既锁死资金又不产生购买力。
改法：`economy.WOOD_KEEP = 60`（木头只留工作库存，其余按市价卖掉）。

| 40×40 × 300 回合 × 8 图（中位） | 消费中位 | 领土中位 | 余货折金 | 军费占比 |
|---|---|---|---|---|
| v10 | 69,936 | 352.0 | 2,216 | 38.7% |
| v11plus（改前） | 66,426 | 659.5 | 1,924 | 38.9% |
| **v11plus（改后）** | **68,339** | **681.5** | **930** | 38.5% |

配对差 v11plus − v10：**−5,071 [−8,582, −2,001] → −2,481 [−6,596, +1,113]（CI 跨 0）**，
领土 +347.9 → +340.9 ⇒ 木头不再屯、消费补回约 2,900（+4.4%），领土还略增。

**建造顺序的坑（2026-09-16，用户：「有难地你完全可以不建」）**

v11plus 的 ROI 建造原是**逐格按坐标序发钱**（`for p in free_tiles` → 每格建它回本最快的那个），
而 `roi` 那张按回本期排好的表只用来算"该留多少木"。后果：**排在前面的难地先动工**
（森林/丘陵/山地施工惩罚 +15~50%），回本更快的平地反而等不到钱。实测 t=200（seed 900000）：
v11plus 在惩罚地上建了 **70** 座，而"有资源、回本达标"的平地还空着 **53** 格。

改成按 `roi`（回本期升序）逐格建、失败即跳过（⚠ **不能**改成"只建 `planned` 那几条"：
那张表按预算裁过、而且被 ①②③ 花掉的钱会让它失效 —— 实测那样建筑从 219 掉到 72）。

| 40×40 × 300 回合（单图） | 领土 | 建筑 | 均/座 | 地形惩罚 | 建在平原 | 消费 |
|---|---|---|---|---|---|---|
| v11plus 改前（seed 900000） | 514 | 219 | 118 | +20% | 26% | 46,934 |
| **v11plus 改后** | 630 | **323** | 151 | **+7%** | **76%** | **81,459** |
| v10 同图 | 308 | 319 | 105 | +10% | 60% | 60,769 |
| v11plus 改前（seed 900002） | 524 | 227 | 116 | +19% | 41% | 45,888 |
| **v11plus 改后** | 550 | **271** | 146 | **+6%** | **83%** | **68,261** |
| v10 同图 | 325 | 255 | 102 | +8% | 77% | 48,116 |

⇒ 两图上都**反超 v10**（+34% / +42%），而地仍是 1.9 倍。副作用：后期国库金开始堆（t=300 余金 5,694）
—— 那时"回本期 ≤ 剩余回合"那条闸把大多数建筑挡住了，是下一个可动的旋钮。
