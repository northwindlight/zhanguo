# 自修订轨迹：模型改自己的交易脚本，算不算一次「发布」

stock 里模型唯一的动作是写脚本，所以每一次行为改变都是一次有版本、有检查、有计量、有审计的代码发布。
本目录从已归档的五局审计里还原每席的脚本版本，把交易槽失败与当回合修订对应起来，
为 Trust4RSI-Agent @ AAAI 2027 投稿草稿（「每次自我更新都是一次发布」）提供全部第二张表的数字。

```bash
python experiments/self_revision/analyze.py
```

只读 `research/game-records/` 的审计压缩包，不调用模型；输出 `results/self_revision.json`，几秒跑完。
口径（修订回合、失败日、诱发失败、版本重放、失败分类）写在 `analyze.py` 文件头。

边界：五局都是同模型四席自博弈，只有两个种子，三个模型都是 flash 级；修订与失败是相关不是因果
（模型也会因为出错才去改）。hy4-flash-free 三局共 12 次回退：3 次是同一回合内撤销刚做的 patch，
另外 9 次恢复更早的版本，没有一次发生在失败的交易日之后，更像在已保存的策略之间切换，不是事故回滚。
r1、r2 同模型同种子，两局之差只来自模型侧采样。Hydrogen 局休市日的交易槽运行已排除在外。

口径：诱发失败指失败日当回合有修订、且上一个交易日没有失败。失败原因取自结算回执正文里每个失败槽的报错原文。
H、F 两局审计压缩包里有同一 id 的重复记录，脚本按 id 去重；早先未去重的版本把重复的 write 算成了
「逐字节相同的重部署」（H 2 次、F 64 次），也多算了编辑次数和研究槽次数，现已更正。
