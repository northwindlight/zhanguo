# 统一玩家接口与客户端

2026-10-13：引擎提供 Player API v1，native 4.1.0 提供领域事实与规则，LLM 和 v11plus 均通过绑定国家身份的 `PlayerSession` 行动。宿主负责装配、剧本、轮转、结算与整局存档。

| 层 | 责任 | 入口 |
| --- | --- | --- |
| engine | 身份绑定、权限检查、工具分发、JSON 回执、模块生命周期 | `engine/player.py`、`engine/runtime.py` |
| native | 国家、经济、外交、军事等事实和业务规则；玩家公开查询 | `mods/native/` |
| host | 初始落位、国家登场、客户端选择、整局结算与存档 | `host.py`、`mp_run.py` |
| LLM | 模型调用、提示、工具往返、记忆压缩、用量 | `clients/llm.py` |
| rule AI | 经济与军事决策、路径和分组策略、跨期目标 | `ruleai/v11plus/` |

客户端不导入 game、native 或 World，不保存世界对象，不直接修改领域状态。模块替换沿用同一公开契约；内容类型和实例都使用稳定命名空间 ID，显示名称仅用于展示。当前为可信进程内调用接口；不提供 HTTP 服务或隔离恶意 Python 的沙箱。

## 玩家契约

```python
from host import GameHost
host = GameHost.new({'map_size':16, 'seed':73,
                     'nations':[{'id':'scenario:qin','name':'秦','client':'rule'}]})
player = host.player('scenario:qin')
facts = player.observe()
schemas = player.actions()
quote = player.query('build_quote', {'site':'scenario:qin/land-8-8', 'kind':'native:farm'})
receipt = player.submit('plan', {'text':'发展生产，积蓄军力'})
# 整局由宿主调用 host.cycle()；客户端不调用 resolve_turn。
```

| 方法 | 返回与约束 |
| --- | --- |
| `observe()` | `{api, actor, period, can_act, facts}`；facts 由发行版 PlayerState 的只读工具组装 |
| `actions()` | 当前身份可用的工具 JSON Schema，包括三个通用查询工具 |
| `query(name, arguments)` | 只读查询；不能调用写工具或覆盖行动者 |
| `submit(action, arguments)` | 结构化回执；行动者由宿主绑定 |
| `events(cursor=0)` | `{cursor, items}`；只包含当前国家可见事件，客户端持久化自己的游标 |
| `rules(topic='')` | 当前国家作用域中模块公开的规则章节 |

`player_state`、`player_events`、`player_rules` 与直接方法等价。其余工具由模块声明，当前 native 56 个，加三个通用工具共 59 个。结束行动后查询仍有效，写工具拒绝；被淘汰国家不能继续请求。返回值是脱离领域对象的 JSON 数据，修改返回值不影响游戏。

回执字段固定为 `api / actor / action / period / ok / status / code / message / data`。`submitted` 仅说明进入待结算队列，`effective` 才是该次调用完成；外交的最终结果需在后续状态或事件中读取。失败回执保留领域消息与结果，不凭文字判断成功。

错误码：`inactive_actor`、`unknown_action`、`unavailable_action`、`invalid_arguments`、`domain_rejected`、`action_failed`。参数绑定错误有稳定回执；模块内部程序错误向宿主传播并停止运行，便于发现缺陷。

建筑和征召报价调用 native 的真实成本逻辑；客户端按报价安排资金。兵种和建筑目录均为公开数据。战斗预估只使用自军和目标格可见敌军，未知目标返回未知；采用期望骰值，不包含补给、治疗或第三方增援，因此是决策参考。可达路径查询按玩家可见地块过滤。隐藏世界不能通过客户端预估或路径查询泄露。

API v1 内保留现有方法、回执字段与错误码；新增可选字段或工具可兼容，移除或改变必填参数需要升级玩家 API。模块状态 API 3、模块版本与整局格式独立版本化。未来跨进程适配器应复用本契约。

## 策略退役与客户端状态

规则 AI 默认且唯一受支持版本为 v11plus。v11plus 以前所有版本和旧 v11 分支旁支 v12 已从运行代码和注册表移除，显式配置这些版本会失败。历史源码可从 Git 历史找回，不保留运行兼容层。

v11plus 保留全局分组目标和有界求解；计算预算耗尽时完成全部指派并保存 `exact=false`。经济决策比较各站点真实报价与收益；所有策略参数留在客户端。它只保存部队目标与求解标志，各国状态独立。

LLM 保持真实 assistant/tool 往返、推理签名、滚动上下文与递归摘要；一个批次中每个工具调用都有回执。记忆、摘要、用量、事件游标由客户端保存。模型仅口头说结束不算结束，必须成功调用 end_turn。调用失败或耗尽步骤直接停局，不代替玩家自动结束。独立 `ui:standard` Mod 编排提示、上下文展示和地图；native 与 experimental 均显式装配。`vision=true` 时将玩家可见事实快照附到本回合消息，发送边界渲染 PNG 并转换成协议图片格式。回放保存 JSON 快照，不保存 base64；终端 `map 国名 文件.png` / `文件.svg` 走同一个 UI Mod。语言配置与接口见 [UI Mod](../mods/ui/README.md)。旧提示词检索工具未接入。

## 整局存档与开局

`zhanguo.session/1` 保存模块依赖清单、模块状态、宿主 roster 与剧本常驻文案、按国家 ID 索引的客户端状态。API key 和接入配置不写入存档，续局需外部配置。只在整局行动边界原子保存；半局状态不能写为可续档。失败保留最近完整结算存档。

旧整局存档与旧 World 构造器不兼容，不自动迁移、不自动覆盖或重开；旧存档用历史提交续局，新局使用新路径。相同国家 ID 续局不能静默改变客户端类型；需要显式客户端状态迁移。

配置推荐填写 `id / name / client`。普通国家默认初始登场；政体默认按模块声明定时登场，`appearance=manual` 可手动加入。`enable_turn` 与 `enable_turn_max` 采用种子和国家 ID 决定登场周期。`add` 仅接受配置声明的国家。银行是否启用和利率来自发行版模块，不再读取 world_bank。旧 opening_guide 开关由模块公开规则查询替代。

八国生成器返回 GameHost，用外交模块的行政初始化方法写入七条保障，常驻文案随档保存；不会作为玩家工具绕过外交费用。默认仅读取示例配置，`--template` 才指定其他配置。已有目标文件要求 `--force`，检查在写入任何产物之前进行。地图尺寸、固定种子、手摆位置与原目标文案保留。
