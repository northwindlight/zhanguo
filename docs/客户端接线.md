# 统一玩家接口与客户端

2026-10-13：引擎提供 Player API v1，native 4.4.1 提供领域事实与规则，LLM 和 v11plus 均通过发行版绑定身份的玩家 API 行动。发行版提供场景、管理接口和 Session；host 加载声明的入口。

| 层 | 责任 | 入口 |
| --- | --- | --- |
| engine | 身份绑定、权限检查、工具分发、JSON 回执、模块生命周期 | `engine/player.py`、`engine/runtime.py` |
| native | 国家、经济、外交、军事等事实和业务规则；玩家公开查询 | `mods/native/` |
| 发行版 Session | 配置、开局、登场、管理 API、玩家 API 与服务装配 | `mods/native/session.py`、`mods/examples/minigame/session.py` |
| host / 通用 Session | 加载入口；客户端轮转、单次提交、审计、控制权与存档机制 | `host.py`、`engine/session.py`、`engine/api.py` |
| LLM | 模型调用、提示、工具往返、记忆压缩、用量 | `clients/llm.py` |
| rule AI | 经济与军事决策、路径和分组策略、跨期目标 | `ruleai/v11plus/` |

客户端不导入 game、native 或 World，不保存世界对象，不直接修改领域状态。模块替换沿用同一公开契约；内容类型和实例都使用稳定命名空间 ID，显示名称仅用于展示。当前为可信进程内调用接口；不提供 HTTP 服务或隔离恶意 Python 的沙箱。

## 玩家契约

```python
from host import GameHost
host = GameHost.new({'map_size':16, 'seed':73,
                     'nations':[{'id':'scenario:qin','name':'秦','client':'rule'}]})
player = host.player('scenario:qin')
facts = player.observe()
schemas = player.actions()
catalog = player.query('building_catalog')  # 全部类型资料，无需地点
receipt = player.submit('plan', {'text':'发展生产，积蓄军力'})
# 整局由宿主调用 host.cycle()；客户端不调用 resolve_turn。
```

| 方法 | 返回与约束 |
| --- | --- |
| `observe()` | `{api, actor, period, can_act, facts, action_state}`；facts 由发行版 PlayerState 的只读工具组装；native 把本国、各国与外交关系合并为一个 `foreign` 事实 |
| `actions()` | 当前身份可用的工具 JSON Schema，包括四个通用查询工具 |
| `query(name, arguments)` | 只读查询；不能调用写工具或覆盖行动者 |
| `submit(action, arguments)` | 结构化回执；行动者由宿主绑定 |
| `events(cursor=0)` | `{cursor, items}`；只包含当前国家可见事件，客户端持久化自己的游标 |
| `rules(topic='')` | 当前国家作用域中模块公开的规则章节 |
| `action_state()` | `{generation, current_generation, active, can_act, context}`；判断当前句柄是否仍拥有行动控制权 |

`player_state`、`player_events`、`player_rules` 与直接方法等价；`memory_search` 免费检索本国记录并进入行动审计。其余工具由发行版 tool 层注册：native 模型可见 8 个（`build`/`economy`/`end_turn`/`intelligence`/`military`/`plan`/`query`/`relations`），加四个通用工具共 12 个；动作工具用 `military(...)` 这类命令伞的 `action` 参数选动作；旧动作名只是 tool 层内部适配器，不进模型工具表。脚本与规则 AI 不走工具名，统一用 `call_api(capability, method, arguments)`：能力名对应模块 `[PlayerAPI]`，读方法返回数据，写方法返回与 `submit` 同形的回执，并经过阶段、行动门与政体检查。结束行动后查询仍有效，写工具拒绝；被淘汰国家不能继续请求。返回值是脱离领域对象的 JSON 数据，修改返回值不影响游戏。

回执字段固定为 `api / actor / action / period / ok / status / code / message / data`。`submitted` 仅说明进入待结算队列，`effective` 才是该次调用完成；外交的最终结果需在后续状态或事件中读取。失败回执保留领域消息与结果，不凭文字判断成功。

错误码：`inactive_actor`、`unknown_action`、`unavailable_action`、`invalid_arguments`、`domain_rejected`、`action_failed`、`internal_fault`。工具内部错误记录故障并返回 failed，序列化失败明确提示动作已执行；不承诺隐式回滚。结算或行动模型调用无法继续时停止运行。

实际建造和征召由领域校验与扣款，回执报告真实成本。建筑回本表是显式假设的批量估算。兵种和建筑目录均为公开数据。战斗预估只使用自军和目标格可见敌军，未知目标返回未知；采用期望骰值，不包含补给、治疗或第三方增援，因此是决策参考。可达路径查询按玩家可见地块过滤。隐藏世界不能通过客户端预估或路径查询泄露。

1.0 前接口、模块状态与整局格式可以调整，不承诺旧档或旧接口兼容；不提供兼容适配或迁移。

## 策略退役与客户端状态

规则 AI 默认且唯一受支持版本为 v11plus。v11plus 以前所有版本和旧 v11 分支旁支 v12 已从运行代码和注册表移除，显式配置这些版本会失败。历史源码可从 Git 历史找回，不保留运行兼容层。

v11plus 保留全局分组目标和有界求解；计算预算耗尽时完成全部指派并保存 `exact=false`。经济决策比较各站点真实报价与收益；所有策略参数留在客户端。它只保存部队目标与求解标志，各国状态独立。

LLM 保持真实 assistant/tool 往返、推理签名、滚动上下文与递归摘要；一个批次中每个工具调用都有回执。记忆、摘要、用量、事件游标由客户端保存。模型仅口头说结束不算结束，必须成功调用 end_turn。行动模型调用失败停局；步骤耗尽时通过正常 end_turn 闸门补写事实小结，合法结束后保存回放，国策等前置条件不满足仍拒绝结束。记忆压缩返回空正文或不足 20 字时继续尝试，每次提示压缩进度，最多调用 10 次；得到有效摘要后立即结束。10 次均无有效结果或调用异常时，保留原长期记忆，归档退回逐回合小结并通知观察者，继续对局。独立 `ui:standard` Mod 编排提示、上下文展示和地图；native 与 experimental 均显式装配。`vision=true` 时将玩家可见事实快照附到本回合消息，发送边界渲染 PNG 并转换成协议图片格式。回放保存 JSON 快照，不保存 base64；终端 `map 国名 文件.png` / `文件.svg` 走同一个 UI Mod。语言配置与接口见 [UI Mod](../mods/ui/README.md)。客户端提供 memory_search 检索自己的行动、发言与回执正文，排除思考；检索索引保存模型看到的回执散文而不是 JSON，旧档的历史行在检索时用同一套 UI 渲染成散文；检索源独立于上下文压缩并随档保存，通过统一玩家 API 暴露，LLM 检索有界客户端正文，规则客户端检索近期审计。

## 发行版提供 Session 和 API

```toml
[Distribution.Session]
Entry = "mods.native.session:NativeSession"

[Distribution.Session.Services.council]
Entry = "mods.experimental.council:CouncilService"
[Distribution.Session.Services.council.Services.government]
Capability = "native:government"
Methods = ["enroll", "decide", "replace"]
```

Session 工厂签名为 `(runtime, cfg, client_factory)`，可继承通用 `engine.session.Session`；具体契约和完整独立示例见 [发行版 Session API](发行版Session.md)。场景、内容 ID、初始资源与管理 API 由发行版定义。客户端类型可由 `Distribution.ClientFactories.<kind>` 声明；无工厂的未知类型拒绝启动。

`host.player(actor)` 返回绑定当前控制权代次的 API。所有 `submit()` 都经过发行版服务，再由引擎检查权限和参数、执行领域动作。服务的 `next_submit()` 对同一次请求只能调用一次，最终回执和失败轨迹进入 `host.audit`。嵌套脚本只要调用同一绑定 API，其内部动作逐次记录，观察者回调也从此处发出。`runtime.player()` 是底层领域传输，发行版行为应通过 Session 提供的入口调用。

experimental 的国策审核、证据归档和罢免属于发行版服务，适用于 LLM、规则 AI 和直接调用 API 的程序。`enroll / decide / replace` 是声明授权的内部服务，不出现在玩家动作中。罢免立即增加控制权代次；旧句柄后续提交得到失败回执，新句柄取得交接上下文。客户端按 `action_state()` 停止旧控制者行动；通用轮转取得新句柄继续当前回合。

LLM 使用 `record_dialogue(messages)` 把当前上下文和工具对话交给发行版记录。该方法不执行国家行动，也不赋予领域写权限；完整行动审计不依赖客户端提供这份对话。

## 整局存档与开局

`zhanguo.session/4` 保存模块依赖清单、模块状态、roster、剧本开局文案与 opening_guide 开关、最近 2048 条逐次行动审计及递增序号、控制权代次及交接上下文、发行版服务状态、按玩家 ID 索引的客户端状态。API key 和接入配置不写入存档，续局需外部配置。只在整局行动边界原子保存；半局状态不能写为可续档。失败保留最近完整结算存档。

动作审计和滚出窗口的经济/外交/事件历史写入 `<save>.audit/<stream>/` 不可变分段，Session 文件保留续局必需状态。经济事实和逐期账本保留近两个完整报表窗口及当前窗口，累计消费以检查点续算；已公布报表和市场成交历史仍全量保存，因此整份存档并非固定大小。

旧整局存档与旧 World 构造器不兼容，不自动迁移、不自动覆盖或重开；旧存档用历史提交续局，新局使用新路径。相同国家 ID 续局不能静默改变客户端类型；类型不同直接拒绝加载。

配置推荐填写 `id / name / client`。普通国家默认初始登场；政体默认按模块声明定时登场，`appearance=manual` 可手动加入。`enable_turn` 与 `enable_turn_max` 采用种子和国家 ID 决定登场周期。`add` 仅接受配置声明的国家。银行是否启用和利率来自发行版模块，不再读取 world_bank。四篇策略指南由公开 handbooks 目录与 player_rules 提供，UI 只常驻显式登记的决策事实与政体指引；指南按需查询。opening_guide 控制前 20 周期的额外剧本背景，存档保存全局开关。

八国生成器返回 GameHost，用外交模块的行政初始化方法写入七条保障，开局文案随档保存；不会作为玩家工具绕过外交费用。默认仅读取示例配置，`--template` 才指定其他配置。已有目标文件要求 `--force`，检查在写入任何产物之前进行。地图尺寸、固定种子、手摆位置与原目标文案保留。

## 实现入口

- `clients/llm.py`：LLM 玩家与逐动作工具循环。
- `clients/memory.py`：本客户端历史正文检索，排除思考，独立于上下文压缩并随档保存。
- `clients/context.py`：上下文预算、回放、压缩与用量统计。
- `clients/provider.py`：OpenAI 兼容和 Anthropic 接入。
- `ruleai/`：规则客户端注册与配置；`ruleai/v11plus/`：现役策略。
- `ui/terminal.py`：终端输入输出；`mods/ui/`：可替换的显示和地图实现。

根目录只保留 `host.py` 和 `mp_run.py` 两个 Python 装配及启动入口，不再保留旧导入路径的转口。
