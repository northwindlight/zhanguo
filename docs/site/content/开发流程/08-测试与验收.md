# 测试与验收

测试用 `unittest`，放在 `tests/` 下，一律用合成配置和临时目录，不读写真实对局存档，不调用付费模型。

```bash
.venv/bin/python -m unittest tests.test_example_mods -v      # 单个文件
.venv/bin/python -m unittest tests.test_x.TestY.test_z       # 单个用例
.venv/bin/python -m unittest discover -s tests -q            # 全量
```

全量回归有一千多项。本机慢时，先跑改动相关的文件，全量交给 CI：推送分支并开 PR，`离线回归` 任务会在干净环境里跑完。

## 每个模块要覆盖的五项

| 覆盖 | 断言什么 |
| --- | --- |
| 装得上 | `Runtime.load(发行版)` 不报错，模块顺序与阶段顺序（`runtime.stage_order`）符合预期 |
| 工具可用 | 工具在玩家的工具表里，schema 正确；非法参数被拒绝，并说清原因 |
| 结算生效 | 跑一轮结算，检查写进 `context` 的数据，并把数量对平：库存变化等于声明的产出或消耗 |
| 存档往返 | `save → load → save` 完全相同；模块版本变了，旧档被拒绝 |
| 摘得掉 | 去掉一个模块，装载期报出 `state 无主`、`缺少依赖` 或 `所需能力无提供者`，而不是 `ImportError` |

```python
class TestHelloMod(unittest.TestCase):
    def setUp(self):
        self.runtime = Runtime.load(ROOT / 'mods/examples/hello')
        self.world = self.runtime.world_class()()

    def test_add_accumulates(self):
        self.runtime.call(self.world, 'a', 'hello_add', {'amount': 3})
        self.runtime.call(self.world, 'a', 'hello_add', {'amount': 4})
        self.assertEqual(self.runtime.call(self.world, 'a', 'hello_total', {})['total'], 7)

    def test_bad_argument_is_rejected(self):
        with self.assertRaises(ValueError):
            self.runtime.call(self.world, 'a', 'hello_add', {'amount': 0})
```

完整样板见 `tests/test_example_mods.py`，配方巡礼本身也有测试（`tests/test_examples_tour.py`）。

## 模型客户端用假后端测

模型客户端最容易“跑起来才炸”。给它装一个假后端，不发任何网络请求：

```python
class FakeBackend:
    def __init__(self, responses=None):
        self.responses = list(responses or [])
        self.requests = []

    def chat_turn(self, messages, tools, cfg, on_retry=None, on_delta=None):
        self.requests.append({'messages': messages, 'tools': tools})
        message = self.responses.pop(0) if self.responses else {'content': ''}
        return message, {'hit': 10, 'miss': 2}

    def complete_text(self, messages, cfg, max_tokens=None, tools=None):
        return '…', {'hit': 8, 'miss': 1}
```

至少断言三样：工具表里有你的工具；模型的调用全部成功（没有未知工具、参数不合法）；`end_turn` 的回执里有 `text`。`tests/test_model_view_contract.py` 是这套做法的样板，它同时守住“模型面向层与发行版无关”和“minigame 能被模型驱动”两件事。现成的假后端见 `tests/test_player_clients.py` 的 `FakeBackend`。

## 行为变更要核对引擎结果

规则改动不能只验证“能跑完”。用独立的离线合成局，检查引擎写出的结果（库存、部队、领土、回执）与预期一致；涉及桌面版的，再核对界面呈现与引擎结果一致。

## 提交前

| 改动 | 要做 |
| --- | --- |
| 改了模块声明、工具或字段 | `python3 scripts/api_doc.py` 重新生成 API 参考；CI 用 `--check` 核对 |
| 改了文档站内容 | `python3 docs/site/build.py`，确认能生成；`--serve` 可本地预览 |
| 新增示例 | 在[示例索引](附录/01-示例索引.html)登记，必要时给 `mods/examples/tour.py` 加一步 |
| 改了存档相关的东西 | 提升 `[Mod] Version`，补往返与旧档拒绝的测试 |
