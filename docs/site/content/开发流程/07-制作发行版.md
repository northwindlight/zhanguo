# 制作发行版

发行版是装配清单，不写规则逻辑。它由两份文件组成：

| 文件 | 内容 |
| --- | --- |
| 入口：仓库根的 `mods.toml`、`mods.<名字>.toml` | `[Load] Packages = ["<目录>"]`，每条指向一个含 `mod.toml` 的目录 |
| 清单：那个目录里的 `mod.toml` | `[Distribution]`、`Members`、`[[Hooks]]` 以及会话、配置、工具层、客户端声明 |

`Runtime.load(路径)`：路径是文件时按入口解析；是目录时收集目录下所有 `*.toml`，其中带 `[Distribution]` 的作为清单，其余作为模块声明。一次只能装一个发行版，否则报 `同时加载多个发行版`。

玩家在配置顶层用 `"mods": "mods.<名字>.toml"` 选择发行版，缺省 `mods.toml`（native）。

## 成员：引用别处，只替换要改的那一条

`Members` 的路径相对清单文件所在目录。新增内容就追加一条；替换实现就把对应的那一条换成自己的，并**保持原来的 `Id` 和 `[Capabilities] Provides` 不变**，因为别的模块按它们引用你。`mods/examples/tea_dist/mod.toml` 就是这样做的：

```toml
[Distribution]
Id = "example:tea-dist"
Version = "1.0.0"
Members = [
  "../../native/resources/mod.toml",
  "../../native/buildings/mod.toml",
  "../tea/market.toml",                 # 替换：多上市一种商品，Id 仍是 native:market
  "...",
  "../tea/mod.toml",                    # 追加：注册新资源
]
RequiredState = ["resources", "buildings", "market", "..."]
```

## 挂点

挂点是结算骨架上的时机，写在清单**顶层**（不在 `[Distribution]` 段里），顺序即执行顺序：

```toml
[[Hooks]]
Id = "buildings.production"
Name = "建筑生产"
Description = "采集、燃料发电、电网和工业按实际投入结算。"
```

`Id` 只能用 `[a-zA-Z0-9_.:-]` 且全局唯一；`Name` 用于规则正文里的结算顺序表。没有阶段挂在上面的空挂点是允许的。模块的阶段用 `hook=` 指向挂点，同一挂点内的先后由 `needs`／`provides` 条件决定，见[跨模块协作](开发流程/05-跨模块协作.html)。

## 会话

```toml
[Distribution.Session]
Entry = "mods.native.session:NativeSession"
Observer = { Capability = "native:intelligence", Records = "records", Announce = "announce", Send = "send" }
```

会话类是发行版自己的开局与回合管理：投放初始资源与建筑、落位、登场、轮转与结算前后的钩子、管理 API、整局存取。`Services` 可以挂议会、脚本等发行版服务；`Observer` 声明观察者用哪个能力记录、公告和送信。宿主不要求任何固定的领域对象名或 native 内容 ID，所以 minigame 的 `MiniSession` 可以投放完全不同的资源与建筑。

完整契约见[发行版 Session 与剧本](宿主与会话/01-发行版Session.html)。

## 玩家时钟、行动门与行动者集合

```toml
ActorCollection = "nation_actors"
ActionGate = {Capability = "native:government", Method = "can_act"}
PlayerClock = {Capability = "native:government", Method = "period"}
PlayerEvents = "news"
```

`ActionGate` 判断某国本回合还能不能行动，`PlayerClock` 给玩家 API 提供当前期数，`PlayerEvents` 指定事件流来自哪个只读工具。引用的能力、方法和工具都必须存在，否则装载时报错。

## 工具层与事实

小型发行版用 `PlayerState` 列出每回合发给玩家的只读工具。native 系发行版用工具层：

```toml
[Distribution.Tools]
Entry = "mods.native.tools:build"
```

工具层封装各模块的 `[PlayerAPI]`，事实取 `fact=True` 的工具。两条路径的区别见[暴露给玩家](开发流程/03-暴露给模型.html)。

## 配置

```toml
[Distribution.Configuration]
Entry = "mods.native.config:normalize"       # 归一化并校验整份配置
Preflight = "mods.native.config:require_ready"   # 开局前只读检查，不创建会话、不调用模型
```

`[Distribution.Assembly]` 可以在装配前按配置选择模块、服务和客户端（experimental 用它实现议会、脚本、战斗研究三个开关）。实际装配结果记在 `Features` 里，随依赖清单一起校验。配置层的完整说明见[配置层](宿主与会话/02-配置层.html)。

## 客户端工厂

配置里每个国家的 `"client"` 字段选择由谁来行动：

```toml
[Distribution.ClientFactories.mini]
Entry = "mods.examples.minigame.client:MinigameClient"

[Distribution.ClientFactories.llm]
Entry = "clients.llm:LLMClient"
Configuration = "clients.config:normalize"
```

- `Entry`：客户端类，`模块:类名`；不写就用宿主的缺省实现（native 只写了 `Configuration`）；
- `Configuration`：该客户端的配置归一化函数；
- `Services`：显式授予该客户端的对象能力。

自己写客户端的方法见[配方：提供一个客户端](配方/05-提供客户端.html)，接线细节见[客户端接线](宿主与会话/03-客户端接线.html)。同一个发行版可以同时接模型、规则 AI 和真人：它们之间只靠工具面和事实形状这份契约联系，见[模型面向契约](reference/模型面向契约.html)。

## 剧本

```toml
[Distribution.Scenarios.eight_nations]
Mod = "scenario:eight-nations"
```

剧本是一个普通模块（`mods/scenarios/eight_nations/`），声明开局国家、地图与可选的胜负钩子。配置选用发行版没声明的剧本会被拒绝。

## 装配检查清单

1. 每个模块 `Id` 唯一，`Requires` 都已装载。
2. 每个状态键恰有一个所有者，`RequiredState` 里的键都有主。
3. 每个能力只有一个提供方，所有 `Needs` 都有提供者。
4. 工具名与别名全局唯一，不占用 `player_state`、`player_rules`、`player_events`、`memory_search`。
5. 阶段名唯一；每个 `hook` 都在挂点表里；`needs` 的条件都有提供者，且位于同一或更早挂点；阶段依赖无环。
6. 事实与面板都指向存在的只读工具；`[PlayerAPI]` 的每个方法都被工具层封装。

任何一条不满足，都在 `Runtime.load()` 或世界构造时抛 `ModError`，不会拖到对局中途。

## 发布一个新发行版

1. 建目录：清单 `mod.toml` 加上本发行版自有的模块。
2. 仓库根加入口 `mods.<名字>.toml`。
3. 写测试：装配成功、离线跑几回合、存档往返、至少一种客户端能驱动整局。
4. 在[示例索引](附录/01-示例索引.html)登记；对外发布的发行版加进 `scripts/api_doc.py` 的 `DISTRIBUTIONS`，参考页会自动生成它的清单。
