# 开发流程总览

## 1. 先判断：模块、发行版，还是只改呈现

- 加一条规则、一种资源、一种建筑或兵种 → 写或替换**模块**。
- 换掉整套规则（另一套资源、另一个时代、另一种胜利条件） → 写**发行版**。
- 只改工具描述、回执措辞或简报 → 改发行版的**工具层与语言目录**，不动规则模块。

判断方法：改动能不能独立成一个目录加一份 `mod.toml`？能，就是模块。

## 2. 划边界

动手前先写下三行：

```
这个模块独占：<状态键>
这个模块提供：<能力名>（对象上的哪些方法）
这个模块需要：<别人的能力>.<方法名>
```

它们分别对应 `mod.toml` 的 `[State]`、`[Capabilities]` 和 `[Interfaces]`。先定接口再写实现，否则写到一半才发现要改别人的状态，或者能力名和别人撞了。

命名约定：模块 ID 和能力名用自己的命名空间（`example:hello`、`yourname:tea`），不要占用 `native:`；状态键短而具体（`bank`、`territory`）；方法名用动词短语（`exchange`、`owner`、`transfer`）。

## 3. 写声明

见[写一个模块](开发流程/02-写一个模块.html)，全部字段见[模块声明](reference/模块声明.html)。

## 4. 写实现

继承 `GameMod`，只实现需要的方法，其余用基类的空实现。`mixins()` 是唯一的抽象方法。可覆写的方法见[引擎 API](reference/引擎.html)。

## 5. 暴露给玩家

选一条接入路径：小型发行版由模块直接返回 `Tool`；native 系发行版由模块声明 `[PlayerAPI]`，再由发行版工具层封装成工具。描述、参数、内容键值和只读事实的写法见[暴露给玩家](开发流程/03-暴露给模型.html)。

## 6. 写规则正文

用 `rule_sections()` 写，数字用 `{{number:…}}` 引用参数，不要写死。见[规则与手册](开发流程/04-规则与手册.html)。

## 7. 跨模块协作

读别人走能力（`runtime.object_call`），写别人的状态要申请（`[State] Requests`），结算顺序用挂点条件声明。见[跨模块协作](开发流程/05-跨模块协作.html)。

## 8. 存档

有状态就实现 `save_state`／`load_state`；对外接口变了就提升 `[Mod] Version`。见[状态与存档](开发流程/06-状态与存档.html)。

## 9. 验收

至少覆盖装载、工具、结算、存档往返、摘除报错这五项，并用离线合成局核对引擎结果。见[测试与验收](开发流程/08-测试与验收.html)。
