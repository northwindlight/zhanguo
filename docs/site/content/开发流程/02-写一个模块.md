# 写一个模块

## 目录

小模块两份文件就够；领域模块按 native 的习惯拆开：

```
mods/<你的命名空间>/<模块>/
  mod.toml      声明：身份、依赖、状态、能力、模块自己的参数表
  mod.py        GameMod 子类：装配、结算阶段、存取
  objects.py    领域对象：状态与规则本身（native 习惯）
  api.py        玩家 API：给工具层调用的薄封装（声明了 [PlayerAPI] 才需要）
```

各层目录不需要 `__init__.py`；`Entry` 按仓库根解析。

## 声明

以 `mods/examples/harvest/` 为例：它在发行版新增的「秋收」挂点给每个存活国家发粮。

```toml
[Harvest]                                # 模块自己的参数表：引擎不解释，原样放在 self.declaration
Yield = 4

[Mod]
Id = "example:harvest"
Version = "1.0.0"
Entry = "mods.examples.harvest.mod:HarvestMod"
Requires = ["native:resources", "native:nations"]   # 必须同时装载的模块
After = ["native:nations"]                          # 模块顺序：排在这些之后

[State]
Owns = []                                # 本模块独占的状态键；要写别人的状态用 Requests 申请

[Capabilities]
Needs = ["native:nation-inspection", "native:resource-exchange"]   # 用到的能力
Provides = []                            # 本模块对外提供的能力；Optional 写可选依赖

[Interfaces]                             # 每个用到的能力都要列出具体方法名
"native:nation-inspection" = ["ids"]
"native:resource-exchange" = ["exchange_batch"]
```

全部字段见[模块声明](reference/模块声明.html)。

## 实现

```python
from engine.runtime import GameMod, RuleSection, Stage


class HarvestMod(GameMod):
    def mixins(self):
        return ()

    def stages(self):
        return (Stage('example:harvest.reap', self._reap,
                      hook='example.harvest', provides=('harvest.reaped',)),)

    def _reap(self, world, context):
        amount = self.declaration['Harvest']['Yield']
        actors = world.runtime.object_call(world, 'native:nation-inspection', 'ids')
        operations = [{'owner': actor, 'debits': {}, 'credits': {'native:food': amount}}
                      for actor in actors]
        if operations:   # 一批原子提交
            world.runtime.object_call(world, 'native:resource-exchange', 'exchange_batch', operations)
        context['harvest'] = {'yield': amount, 'nations': list(actors)}

    def rule_sections(self, world=None):
        return (RuleSection('秋收', f'每个行动期在「秋收」挂点按国发放 '
                            f'{self.declaration["Harvest"]["Yield"]} 单位粮食。', ('秋收', 'harvest')),)
```

`state_keys()`、`needs()`、`provides()` 缺省读声明里的对应字段；示例里显式覆写只是为了说明，不覆写也一样。

常用的可覆写方法：

| 方法 | 何时调用、返回什么 |
| --- | --- |
| `mixins()` | 必填。返回混进 `World` 类的类；不需要就返回 `()` |
| `configure(declaration, path)` | 装载时调用；覆写时先调 `super()`，再读自己的参数表 |
| `initialize_world(world)` | 世界构造完成后调用一次，放置本模块的状态 |
| `objects(world)` | 返回 `{能力名: 对象}`；别的模块通过 `object_call` 调用这些对象的公开方法 |
| `content_definitions()` | 注册内容：资源、建筑、兵种、地形 |
| `tools()` | 直接返回给玩家的 `Tool`（与 `[PlayerAPI]` 二选一） |
| `player_api(world)` | 声明了 `[PlayerAPI]` 时返回玩家 API 对象 |
| `stages()` | 结算阶段 |
| `rule_sections(world=None)` | 规则正文 |
| `numbers()` | 本模块的数值表，供规则正文与文档引用 |
| `save_state(world)`／`load_state(world, state)` | 存取本模块的状态 |
| `before_tool`／`after_tool` | 工具调用前后的钩子 |

`self.runtime` 在装载后可用，`world.runtime` 在世界上也能拿到同一个对象。

## 工具签名

工具处理函数的前两个参数固定是 `(world, actor)`，其余参数由类型标注生成 JSON Schema，调用时自动转换类型（字符串 `"3"` 转成整数 `3`）：

```python
def _add(world, actor, amount: int): ...                     # 必填整数
def _note(world, actor, text: str = ''): ...                 # 有默认值即可选
def _buy(world, actor, target: str, turn: int | None = None): ...   # 可空
```

需要更细的约束（枚举、最小值），就手写 `parameters`。写了 `additionalProperties: false`，引擎会真的拒收多余参数，并在回执里列出可用参数：

```python
Tool('build', self._build,
     parameters={'type': 'object', 'properties': {
         'x': {'type': 'integer', 'minimum': 0}, 'y': {'type': 'integer', 'minimum': 0},
         'kind': {'type': 'string', 'enum': ['farm', 'mine']}},
         'required': ['x', 'y', 'kind'], 'additionalProperties': False},
     content_parameters=('kind',),
     description='在本国地块动工……')
```

处理函数里拒绝非法输入时抛 `ValueError`，引擎会把它变成失败回执交给玩家，不会中断对局。

## 装载期的硬性检查

声明与实现不一致时，`Runtime.load()` 或世界构造阶段直接抛 `ModError`，不会拖到运行中途：

| 检查 | 典型报错 |
| --- | --- |
| 模块 ID 唯一 | `重复的 Mod ID` |
| `Requires` 都已装载 | `<模块> 缺少依赖 <模块>` |
| 每个 `Needs` 都有提供者 | `<模块> 所需能力无提供者：<能力>` |
| 每个状态键恰有一个所有者 | `state 有多个写入所有者`、`state 无主` |
| 工具名与别名全局唯一，不占保留名 | `工具名称/别名冲突`、`模块工具不能占用玩家 API 保留名称` |
| 阶段挂点与条件可解 | `<阶段> 挂点条件无人提供：<条件>`、`依赖存在环` |
| `[PlayerAPI]` 与实现一致 | `声明了 [PlayerAPI] 但未实现 player_api`、`[PlayerAPI] 方法未封装` |
| 发行版事实与面板存在且只读 | `玩家状态必须声明唯一的只读工具` |

运行期调用别人没声明的方法，报 `<模块> 未声明对象接口调用：<能力>.<方法>`。更多见[报错速查](开发流程/09-报错速查.html)。

## 装起来试

先单独装，再放进发行版：

```python
from engine.runtime import Runtime
runtime = Runtime.load('mods/examples/harvest')     # 目录：收集目录下全部 *.toml
print(runtime.order)                                 # 模块顺序
```

依赖 native 领域的模块，单独装会因为缺依赖失败，这是预期行为。这时用一个只列必要成员的小发行版来试，写法见[制作发行版](开发流程/07-制作发行版.html)。
