# 跨模块协作

模块之间**不互相 import**。要别人的数据走能力，要写别人的状态先申请，结算先后用挂点条件声明。

## 读：对象接口

提供方在 `objects()` 里把能力名映射到一个对象：

```python
def objects(self, world):
    return {'native:buildings': world.buildings}
```

调用方声明能力和方法，缺一不可：

```toml
[Capabilities]
Needs = ["native:buildings"]

[Interfaces]
"native:buildings" = ["count", "snapshot"]
```

```python
world.runtime.object_call(world, 'native:buildings', 'count', actor, kind)
```

`object_call` 在调用时核对：能力有提供者、调用方在 `Needs` 或 `Optional` 里声明了它、方法列在 `[Interfaces]` 里、方法名不以下划线开头。不满足就报 `未声明对象接口调用`、`对象接口无提供者` 或 `对象接口不能调用私有方法`。被调用的方法在提供方的上下文里执行，由所有者负责校验与写入。

`Optional` 是可选依赖：能力在就能调（方法同样要列进 `[Interfaces]`），不在也不拦装载，调用时才报无提供者。适合“有更好、没有也能跑”的路径，例如装了地图就能按地名找地块，没装就只认坐标。

minigame 的模块自己包了一个 `self._call(能力, 方法, *参数)`，内部就是 `runtime.object_call`，不是引擎提供的方法。

## 写：状态申请

每个状态键只有一个所有者。别的模块要写它，先在自己的声明里申请：

```toml
[State]
Requests = ["polity"]
```

写入通过 `runtime.write_state(world, key, operation)`，最终由所有者的 `apply_state_change` 决定是否放行；没申请就写会报 `未声明向 <所有者> 请求写入 state`。`polity` 与 `phase` 两个系统状态归引擎所有（记为 `$engine`）。

多数情况下不需要写别人的状态：调用所有者提供的写方法（例如 `native:resource-exchange` 的 `exchange_batch`）就够了，而且校验留在所有者那里。

## 顺序：模块顺序与阶段顺序

```toml
[Mod]
Requires = ["native:resources"]   # 装配期：缺了直接拒绝装载
After = ["native:territory"]      # 模块顺序：排在它之后
Before = []
```

结算阶段的先后不靠模块顺序，而靠**挂点与条件**：

```python
Stage('example:elephants.upkeep', self._upkeep,
      hook='military.supply',            # 挂在发行版声明的挂点上
      needs=('military.supplied',),      # 在提供该条件的阶段之后跑
      provides=('elephants.fed',))       # 发布自己的条件，供后续阶段消费
```

`needs` 的条件必须由同一挂点或更早挂点上的某个阶段 `provides`，否则报 `挂点条件无人提供`；形成环则报 `依赖存在环`。全部阶段共享一个 `context` 字典，这是阶段之间传数据的唯一途径，处理函数的返回值会被忽略。

`scope='actor'` 的阶段对每个行动者各调用一次，签名是 `(world, actor, context)`。这里的行动者是 `ActorCollection` 里的国家，不是兵种；“只对某个兵种生效”应写成 `scope='world'`，在处理函数里按 `unit.kind` 过滤。

## 数值

`numbers()` 返回本模块的数值表，供规则正文的 `{{number:…}}` 和文档枚举。政体可以覆盖若干通用数值，规则代码统一这样读：

```python
world.runtime.parameter(world, actor, 'build_cost_pct', 100)
```

它先检查 `number.<键>` 是否被该国政体禁用，再取政体 `[Policy.Overrides]` 里的值，都没有就用默认值。`parameter()` 和 `numbers()` 是两套独立机制。

## 政体

政体是作用域限定在单个国家上的模块，声明里多一个 `Kind = "actor"`：

```toml
[Mod]
Id = "native:huns"
Kind = "actor"
Aliases = ["huns", "匈奴"]

[Policy]
Tag = "native:huns"
Rejection = "该政体不允许此外交动作"
Appearance = "scheduled"
Disable = ["tool.guarantee", "action.guarantee", "communication.gift"]

[Policy.Overrides]
build_cost_pct = 130
```

| 键 | 作用 |
| --- | --- |
| `Tag`／`Aliases` | 配置里国家 `polity` 字段的取值 |
| `Enable`／`Disable` | 显式启停：`tool.<工具>`、`action.<动作>`、`stage.<阶段>`、`hook.<挂点>`、`panel.<面板>`、`number.<数值键>` 等 |
| `Overrides` | 数值覆盖，由 `runtime.parameter()` 读取 |
| `Appearance` | `initial`（开局在场）、`scheduled`（按配置登场）、`manual` |
| `Rejection` | 被禁用时返回给玩家的文案 |

裁决集中在引擎：`runtime.in_scope(world, actor, unit)` 判断模块是否作用于该国，`runtime.permits(world, actor, capability)` 判断能力是否被禁用。政体还可以实现 `activate_actor`（登场时的一次性动作）、`parameter_overrides()`（动态覆盖）和 `prompt(world, actor)`（给该国的额外提示）。

新增政体不用改引擎或其他模块：写一个模块，加进发行版 `Members`，在场景配置里给国家填 `polity`。摘掉政体模块，标准局照常开局，只是那个国家不在。
