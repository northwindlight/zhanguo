# 提供一个客户端

示例：`mods/examples/idle_client/client.py`。

## 声明工厂

发行版可以声明新的客户端类型，也可以覆盖已有的 `llm`、`rule`：

```toml
[Distribution.ClientFactories.llm]
Entry = "mods.examples.idle_client.client:IdleClient"
```

这样配置里照旧写 `"client": "llm"`，实际用的是 `IdleClient`。minigame 则声明了自己的 `ClientFactories.mini`，配置写 `"client": "mini"`。native 的缺省选择是：配置了 API key 用 `llm`，否则用 `rule`。

## 客户端接口

| 成员 | 说明 |
| --- | --- |
| `kind` | 字符串，与配置的 `client` 一致；用于存档类型校验与轮转分支 |
| `__init__(cfg, *, record=None, services=None)` | `record` 是存档里的 `{'kind', 'version', 'state'}`，新局为 `None` |
| `play(player, *, emit, head, on_call, on_result)` | 用绑定的玩家 API 行动，返回回执列表 |
| `to_save()` | 返回恰好含 `kind`、`version`、`state` 三个键的字典 |
| `on_settlement(player)` | 可选，结算后调用 |

回执项的形状与 `player.submit()` 的返回值相同，至少有 `ok`、`status`、`code`、`message`、`data`。返回值经 `engine.player.wire()` 处理，允许的类型见 `engine/player.py`。

## 服务授权

客户端缺省只拿到 `services['ui']`。要额外的对象能力，由工厂显式授权：

```toml
[Distribution.ClientFactories.llm.Services.<别名>]
Capability = "native:government"
Methods = ["enroll", "decide"]
```

宿主据此生成 `services[别名](方法名, *参数)`；没列在 `Methods` 里的方法不存在。国策审核这类发行版行为由 `[Distribution.Session] Services` 装配，不放在客户端里，直接调用和客户端调用走同一套玩家 API。

完整的接线方式见[客户端接线](宿主与会话/03-客户端接线.html)和[发行版 Session 与剧本](宿主与会话/01-发行版Session.html)。
