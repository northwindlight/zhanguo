# 替换已有内容

示例：`mods/examples/no_power/`（替换后的建筑模块）与 `mods/examples/no_power_dist/`（发行版）。

## 做法：换掉拥有它的模块

添加和替换都走 `content_definitions()`：注册一个**同 ID** 的定义把原来的顶掉。内容表是累加的，同一 ID 注册两次会被拒绝，所以替换的前提是原来那份不再被注册，也就是换掉拥有它的模块：

```python
from mods.native.buildings.mod import BuildingsMod
from mods.native.buildings.types import BUILDING_TYPES

POWER_PLANTS = ('native:wood-power-plant', 'native:oil-power-plant')

def _without_energy(cls):
    return type(cls.__name__, (cls,), {'ENERGY_USE': 0})

class NoPowerBuildingsMod(BuildingsMod):
    def content_definitions(self):
        return {cls.TYPE_ID: _without_energy(cls)
                for cls in BUILDING_TYPES if cls.TYPE_ID not in POWER_PLANTS}
```

配套的 `buildings.toml` 与 native 的逐字相同，只改 `Version` 和 `Entry` 两行；`Id` 和 `[Capabilities] Provides` 保持不变，因为别的模块按它们引用建筑模块。发行版里把 `native/buildings/mod.toml` 换成这一份即可。

## 为什么要把所有建筑的耗电归零

单个建筑只在自身 `ENERGY_USE` 非零、且本国电网短缺时停摆；**征兵**看的却是全国电网（`army.grid_short`），国内任何一个耗电建筑缺电，征兵就会被拦。所以去掉电力系统，必须把所有建筑的 `ENERGY_USE` 归零并删掉电厂，只改兵营不够。

## 建筑角色

建筑类除了 `TYPE_ID`、`GOLD_COSTS`、`EFFECTS`，还可以声明 `ROLES`。消费方按角色查询，不写死建筑 ID：

| 角色 | 含义 | 消费方 |
| --- | --- | --- |
| `capital` | 全部失去即亡国 | succession、army 驻守与占领事件、地图 |
| `recruiter` | 征兵建筑（每座每回合 1 支） | army |
| `militia` | 民兵驻屯（编制与免补给） | army |
| `castle` | 防守减伤 | army、地图 |
| `vision` | 开阔视野 | vision |
| `academy` | 建造折价 | 经济估算 |
| `power` | 电网基准燃料 | 经济估算 |

查询方法是 `native:buildings` 的 `kinds_with_role`、`kind_with_role`、`has_role`、`count_role`、`effect_role`。新增一座同角色的建筑，只改建筑模块。地形定义带 `glyph`，兵种映射也可以带 `glyph`，地图字形来自公开目录，而不是写在界面里的常量。
