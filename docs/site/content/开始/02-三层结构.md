# 三层结构

| 层 | 是什么 | 在哪 |
| --- | --- | --- |
| 引擎 | 机制：装载与依赖解析、状态所有权、能力调用裁决、工具通道、结算调度、存档核对 | `engine/` |
| 模块 | 一个领域：它独占的状态、它提供的能力、它的结算阶段、它的规则正文 | `mods/native/<领域>/`、`mods/examples/<名字>/` 等 |
| 发行版 | 一份装配清单：成员模块、结算挂点、工具层、会话、客户端工厂 | 入口 `mods*.toml`，清单 `mods/<发行版>/mod.toml` |

## 依赖方向

**引擎 ← 模块 ← 发行版**。模块不 import 发行版，也不 import 别的模块，要用别人的东西只能通过声明过的能力。这带来两个后果：

1. 模块可以单独装载、单独测试，不必先跑起整个发行版。
2. 引擎里没有「建筑」「补给」「市场」这类游戏词汇。换掉整套规则不用改引擎，`mods/examples/minigame` 就是这样从零写出来的。

## 引擎管什么

- **装载**：读声明，解析 `Requires`、`After`／`Before` 与挂点条件，算出模块和阶段的顺序，核对声明与实现是否一致。
- **裁决**：谁能写哪个状态（`[State]`），谁能调用哪个能力的哪个方法（`[Capabilities]`＋`[Interfaces]`），某个工具或能力是否被某国的政体禁用。
- **调度**：按挂点顺序跑结算阶段，阶段之间只通过共享的 `context` 字典传数据。
- **通道**：把工具变成模型能调用的 JSON Schema，归一化参数（类型转换、内容键值、别名），把回执交给呈现层。
- **存档**：保存时记下完整的依赖清单，读档时严格核对，不一致就拒绝装载。

接口清单见[引擎 API](reference/引擎.html)。

## 模块管什么

一个模块负责一个领域，并且**显式声明**它和别人的关系：

- 它独占哪些**状态键**，别人要写必须申请；
- 它提供哪些**能力**，也就是别人能调用的对象；
- 它需要哪些能力，以及要调用对方的哪些**方法**；
- 它在哪些**挂点**上跑结算阶段；
- 它注册哪些**内容**（资源、建筑、兵种、地形）；
- 它给玩家的**规则正文**（玩家用 `player_rules` 按主题查）；
- 它给玩家开放哪些动作和查询。

模块内部怎么组织是自由的：minigame 的九个模块写在同一个 `game.py` 里，native 则一个领域一个目录（`api.py`、`objects.py`、`mod.py`、`mod.toml`）。

## 玩家动作的两条接入路径

| 路径 | 写法 | 谁在用 |
| --- | --- | --- |
| 模块直接返回工具 | 模块的 `tools()` 返回 `Tool`；工具名、参数和描述都写在模块里 | `hello`、minigame 等小型发行版 |
| 玩家 API＋发行版工具层 | 模块在 `[PlayerAPI]` 声明方法并实现 `player_api()`；工具名、参数结构、回执文案由发行版的工具层（`[Distribution.Tools]`）统一提供 | native、experimental |

两条路径不能混用：模块一旦声明了 `[PlayerAPI]`，`tools()` 就必须返回空，否则装载时报 `声明了 [PlayerAPI] 但仍在 tools() 返回工具`。工具层还必须封装 `[PlayerAPI]` 里的每一个方法，漏了会报 `[PlayerAPI] 方法未封装`。详见[暴露给玩家](开发流程/03-暴露给模型.html)。

## 发行版管什么

发行版是**装配清单**，不写规则逻辑。入口文件只说装哪个清单：

```toml
# mods.toml（缺省发行版：native）
[Load]
Packages = ["mods/native"]
```

清单写在那个目录的 `mod.toml` 里（节选自 `mods/native/mod.toml`）：

```toml
[Distribution]
Id = "native"
Version = "4.22.0"
Members = ["../ui/mod.toml", "resources/mod.toml", "buildings/mod.toml", "...", "../scenarios/eight_nations/mod.toml"]
RequiredState = ["resources", "buildings", "market", "economy", "..."]
ActorCollection = "nation_actors"
ActionGate = {Capability = "native:government", Method = "can_act"}
PlayerClock = {Capability = "native:government", Method = "period"}
PlayerEvents = "news"
ReadOnlyPanel = "query"

[Distribution.Tools]
Entry = "mods.native.tools:build"

[[Hooks]]
Id = "buildings.production"
Name = "建筑生产"
```

发行版决定：装哪些模块；结算挂点有哪些、什么顺序；玩家看到哪些工具、每回合自动收到哪些事实；用什么会话类开局、存档、管理回合；配置里的 `client` 对应哪个客户端类。

仓库里现有的入口：

| 入口 | 发行版 |
| --- | --- |
| `mods.toml` | native：标准八国局 |
| `mods.experimental.toml` | experimental：在 native 模块上加议会、脚本、战斗研究 |
| `mods.stock.toml` | stock：模拟炒股 |
| `mods.minigame.toml` | minigame：从零写的九模块小游戏 |
| `mods.playable.toml` | playable_min：在 native 上做减法的最小可玩局 |

玩家在配置顶层用 `"mods": "<入口文件>"` 选择发行版，缺省是 `mods.toml`。

## 换掉一整套规则要改什么

只改两样：发行版清单（`Members` 换成另一批模块声明），以及新模块的实现。引擎、模型客户端、呈现层、存档格式都不用动。
