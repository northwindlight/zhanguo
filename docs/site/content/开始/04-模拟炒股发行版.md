# 模拟炒股发行版

`mods/stock` 是一套独立的发行版：**LLM 玩家只能通过 Python 脚本量化炒股**。
沙盒沿用原版 `experimental:python`，发行版换掉了全部玩法。

```bash
cp mp_config.stock.example.json mp_config.json   # 填 api_key
python3 mp_run.py --config mp_config.json

# 不想接模型：离线配置，自带 sim 客户端，不需要密钥
python3 mp_run.py --config mp_config.stock.offline.example.json
```

## 一个回合

| 阶段 | 玩家看到什么 | 玩家能做什么 |
| --- | --- | --- |
| **盘前** | 上回合脚本的**打印输出与报错**（类型、行列、出错那行）、持仓、现金、负债、总财富、**昨收**与均线指标 | 打磨脚本、借贷、思考 |
| **开盘** | — | **所有脚本在开盘那一刻一起执行**，按开盘价挂单 |
| **开盘窗口（20 分钟）** | — | 行情按时间片**连续变动**，脚本能看见盘口随自己的进度往前挪 |
| **闭市** | — | 引擎统一撮合、收盘记账、计息、追保、强平、破产判定 |

盘前今天还没开盘，玩家只看得到昨收与日线指标；今天的价格要到开盘才揭晓。

**回合结束的标准是所有玩家都结束行动**：一个玩家 `end_turn` 只是收掉自己的回合，
不触发结算。

额度按模型侧工具调用计数，是墙钟之外的确定性口径；墙钟耗时也会报给模型。
**每 5 个交易日休市 2 天**：休市日不能买卖，但可以改脚本、规划、借贷。

## 脚本是并发跑的

脚本不在你的回合里执行。等所有玩家都结束行动，市场开盘，所有脚本在那一刻一起开始执行，
下单一律进**同一本挂单簿**、闭市时**单线程统一撮合**——
对局结果与真并发一致：谁也影响不了谁的报价与决策，也没人能抢先看到别人的下单。

Python 的 GIL 让沙盒跑不出真并行，所以实现上给了两种等价写法（模块参数 `Concurrency`）：
`timeslice`（默认，时间片轮转，结果完全确定）与 `threads`（每个脚本一个线程，GIL 自己切碎字节码，
挂单簿的取号与入簿有锁）。两者给出**相同的对局结果**。

模型工具面里没有「运行脚本」动作：脚本什么时候跑由引擎决定，模型只负责把脚本写好。

## 价格是逐步走出来的

市场状态按 tick 拆开，开盘窗口 20 分钟切成 4 片（每片 5 分钟），窗口里行情**连续变动**。
脚本消耗的计算量就是它走过的开盘时间，所以脚本永远不会被提前掐断——它最多走到自己预算用尽的那一片，
窗口剩下的时间照走，闭市才结算。收盘价落在最后一片上，**没有人能提前看到它**；
下一回合的开盘价还会被玩家自己的订单流推开一点。

## 买卖只能在脚本里

模型能调用的工具只有：脚本伞工具（写/改/查/跑）、四份只读事实（持仓与财富、行情、
上回合脚本结果、回合日历）、借贷伞工具、结束回合。
**买卖没有工具**：发行版注册了一个不出现在模型工具表里的封堵工具，
真被按名字调用会直接回执拒绝，并说明正确路径。

```python
# 脚本里（沙盒：无导入、无文件、无网络、无随机、无 try/except）
quotes  = api.call('stock:market', 'quotes')
history = api.call('stock:market', 'history', symbol='shanhai', limit=30)
order   = api.call('stock:market', 'buy', symbol='shanhai', quantity=100)
book    = api.call('stock:portfolio', 'holdings')
print('已挂单：' + order['data']['symbol'])
```

单次运行预算 800000 计算单位、2000 次 API 调用（一次 API 调用计 100 步），
够跑横截面选股、组合再平衡这类多步策略。

写方法的 `api.call` 返回回执（订单在 `receipt["data"]` 里）；被拒绝时脚本直接终止并带回原因，
回合开局就能看到。

## 行情与账户口径

价格引擎借鉴开源 [TraderSim](https://github.com/Sad-Sun678/TraderSim) 的分层做法：
均值回归 + 动量 + 波动率 + 订单流冲击 + 板块情绪 + 大盘情绪；滑点用固定比例冲击成本近似
（参考 [tliesnham/quant](https://github.com/tliesnham/quant) 的 `SlippageModel` 思路）。
同一个 `seed` 的行情路径完全可复现。

净值 = 现金 + 持仓市值 − 负债。授信额度 = 基础授信 + 追保比例 × 持仓市值。
负债击穿追保线时**银行强制平仓**：按市价（同样吃冲击成本）从最大的持仓开始砍仓；
砍完仍资不抵债、净值跌破零，账户破产退市。

参数都在模块的 `[Parameters]` 里：交易日历与窗口额度在 `mods/stock/mods/clock.toml`，
费率与冲击成本在 `market.toml`，初始资金、利率与追保线在 `portfolio.toml`。
