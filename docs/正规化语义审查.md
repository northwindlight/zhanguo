# 正规化：说明书语义审查

- 审查日期：2026-10-12（Asia/Shanghai）
- 对照基线：`main@e2c4e7ace8d759be60d1a10ba4d8e2b2007721f5`
- 主文档：[游戏说明书](游戏说明书.md)
- 总计划：[PLAN.md](../PLAN.md)
- 本文记录 **25 项**冲突或语义缺口；不修改游戏行为、不自行替用户决定新规则。
- “代码现状”是核对结果，不意味着偶然实现必须成为规则。“待正规化”必须形成明确契约与可复现案例。

## 审查结论

说明书已经覆盖主要玩法，但存在章与章互相冲突、生成块携带旧语义、代码边界没有写清、策略建议混进硬规则四类问题。

`python3 docs/sync_manual.py --check` 当前通过：13 个说明书 AUTO 块及四本手册均与生成器一致。**同步检查通过只说明文本与生成器一致，不能证明生成器文案或手写段落的语义正确。**

用户已确定“全部国家间外交回合末生效”。**外交在回合末内部的位置仍须特别核对**：说明书 §九已有“外交在补给/战争之前”的契约，助手此前建议的“战斗/亡国之后”与之不同，不能作为用户已经定案的规则。

## 优先级

- P0：结算、外交、亡国与指令生效时刻。先定契约，再实施。
- P1：战斗、移动、生产、信息、计价等会改变玩家决策的边界。
- P2：文案、入口、存档与策略说明的结构化整理。
- 类型：“冲突”已有相互不一致的证据；“缺口”是目前说明不充分，需要明确规则。

## 25 项清单

### R01 · P0 · 冲突：说明书两份结算顺序不同

- 位置：§一“一局游戏”、§九“回合末的结算顺序”。
- §一仍为战争→撤退→补给，且没有单列亡国与央行；§九为补给→战争→亡国。当前 `World.resolve_turn` 先补给/回血，后战斗。
- 待正规化：只维护一份阶段契约，其他章节引用它；阶段应覆盖生产、撤退、占领、亡国、投票、市场、建设、银行与报表。
- 验收案例：残血军本轮断粮死亡，不能先打出一轮伤害；在建工厂不参与本轮生产。

### R02 · P0 · 待定冲突：外交放在回合末的哪个位置

- 位置：§九；此前助手在 PLAN 中的候选顺序。
- 说明书明确约定未来外交先于补给与战争，允许当轮议和取消当轮战斗；助手建议过战斗/亡国后处理，后果相反。
- 用户已经确定的是“外交回合末生效”，未明确改掉既有阶段先后契约。
- 待正规化：以已有书面契约为基线核对，记录最后选择及理由；全工具的回执、队列与文档一致。
- 验收案例：已进入交战格后本轮议和；最后一座厅被攻时提出议和；同轮宣战、入盟、保障、退盟的冲突。

### R03 · P0 · 冲突：不投票是否等于立即弃权

- 位置：§五“联盟投票与弃权”；`cast_vote/_tally/_expire_votes`，`mp_ai._exec(end_turn)`。
- 说明书称结束本国回合即等于弃权；当前 end_turn 不写弃权，未投仍计入 pending，直到期限届满才作为弃权计票。
- “可改票”也受议案是否已提前通过/否决限制，提前结束后不能再改。
- 待正规化：明确发起轮、截止轮、谁有机会表态、提前通过与盟主否决、改票截止点。
- 验收案例：议案在某成员行动完后才出现；赞成1/未投1；盟主尚未投票前是否能提前通过。

### R04 · P0 · 冲突与缺口：休战的实体归属和到期边界

- 位置：§五休战、§六盟主；`set_truce/active_truce/bloc_transfer`。
- 说明书“盟外和约不受影响”没有说明成员私约与联盟约分离。代码按外交实体保存休战；成员私约在盟内暂停，退出按原日期恢复；换盟主不改变联盟约。
- `active_truce` 在 turn≥until 时认定到期。“至第N回合”容易被读成第N回合仍禁止宣战。
- 待正规化：定义独立国与联盟的休战归属、个人私约暂停/恢复、到期区间、普通和约与强制休战叠加。
- 验收案例：T10签10轮到底在哪轮可宣战；移交盟主；退盟时私约已过期；全球休战与更长普通和约并存。

### R05 · P1 · 冲突：撤退参数把100写成免伤

- 位置：§四 AUTO:combat“防御方撤退时受到的伤害”。
- 表写“50%（上限100＝免伤）”，但代码 `retreat_cover` 是**实际承受比例**，按 share×cover/100 扣血；100表示全额，0才是免伤。
- 待正规化：区分“伤害减免比例”与“承受伤害比例”，生成器和字段名称一并审查。
- 验收案例：承受比例0/50/100，各自的实际扣血。

### R06 · P1 · 冲突：伤害溢出转嫁并非所有路径都一样

- 位置：§九“伤害均摊，但溢出转嫁”；`_spread/_resolve_battles`。
- 普通路径使用 _spread 转嫁致死后的剩余伤害；有撤退减伤军时，当前代码改走按人数均摊后逐军减免的分支，不调用 _spread。
- 说明书没有说明这个例外；减免掉的伤害不转嫁，与“低血量吞掉过量伤害”是不同问题。
- 待正规化：决定撤退混编时先均摊、先减免、死亡溢出的顺序，不能靠不同代码分支暗中决定。
- 验收案例：20/90HP军混编，总伤害100，其中一支防御撤退；检查实际伤害与减免的区别。

### R07 · P2 · 冲突：亡国者是否参加结算厅

- 位置：§十二手写段落及 AUTO:settle；`settlement.hall_roster/_game_context`。
- 说明书两处称亡国者不参加、上下文清空；当前代码邀请含亡国者的完整 roster，并用保留的小结/归档/长期记忆重建上下文。
- 待正规化：说明留下哪些记忆、缺 API 时如何处理；同步生成器，不只是手改 AUTO 块。
- 验收案例：七国已亡、燕独存；亡国者有/无 API、有/无近期回放。

### R08 · P1 · 冲突：别国经济报表摘要是否全世界公开

- 位置：§五情报、§七央行、§八报表；`_close_report_period`。
- 说明书多处称报表生成时全世界收到 GDP/军费/资产摘要；当前生成公告用 log(nation=n)，没有 broadcast/全体 parties。
- 待正规化：选择摘要公开还是仅本国可见，明细购买是获取什么信息；避免“公开账”与“实际未广播”矛盾。
- 验收案例：秦出报表时，燕不开间谍、不买表，究竟能看到什么。

### R09 · P2 · 冲突：规则入口和命令预算的说明不准确

- 位置：§十一命令表与“max_steps决定能发多少条命令”；`rules_text/run_openai_turn`。
- 命令表称 rules 无主题返回全文；代码及 schema 实际返回目录。
- max_steps 是 LLM 调用循环上限，一次响应可包含多个工具，不等于命令数量；规则 AI 的 max_actions 又是另一口径。
- 待正规化：区分查询、工具执行、模型请求与世界回合的额度。
- 验收案例：一次模型响应带3个命令；无主题/未知主题 rules；模型只说话不调工具。

### R10 · P1 · 缺口：统一胜利与消费排名不是同一概念

- 位置：§一、§十二，八国剧本志向；`mp_run` 终止条件、`settlement.settle`。
- 运行器以现存国家少于2或回合上限终止；成绩按总消费排名。剧本中的统一、尊王/入盟等目标不应被默认理解为都已是引擎胜利条件。
- 待正规化：区分游戏结束原因、剧本胜负、测评得分、观海者手动终止；明确全员俱亡和限时局的结果。
- 验收案例：统一者消费不是第一；到时限仍多国；全员亡国；剧本目标达成但国家数未变。

### R11 · P1 · 缺口：移动几何与“穿不过去”不够精确

- 位置：§四移动表与散文；`neighbors/_reachable`。
- 地图按八邻域，相邻斜步与直步都要明确；代码没有普通路径的“禁止切角”条件，可斜绕山地。每步取出发/到达格更贵者，不是仅看目标。
- “骑兵穿不过山林”容易被误读成不能进入/不能从山林出来。
- 待正规化：坐标基准、距离、邻接、逐步成本、通行关系、中间格与目标格规则。
- 验收案例：骑兵两次斜步绕山；从森林到平原；目标两格但中间受阻。

### R12 · P1 · 缺口：移动/进攻/撤退额度与新兵可行动

- 位置：§四征召/移动/攻击；`recruit/move/attack/retreat`。
- 新兵立即出现，moved_turn=-1，本轮可行动并吃补给。三种军事命令共享一次行动额度。
- attack 对“已在目标格”的军与从别格冲入的军存在条件差异；多人命令也有整批校验。
- 待正规化：定义一次移动与移动力、同格参战、反复 attack、部分军不可达时的整队结果。
- 验收案例：征兵后立即进攻；move后attack；同格补入战斗；一支军不能到达的混编命令。

### R13 · P1 · 缺口：失败是否有副作用/费用

- 位置：§一迷雾、§十一失败说明；`_blind_cost/execute/_charge`。
- 有些失败会耗移动额度，有些只返回错误；费用也有成功后扣与任务发出即扣等口径。
- “异常不炸整局”不等于事务回滚。队列化后还必须区分提交成功、执行失败、结果作废。
- 待正规化：错误类型、已扣资源、预留、额度、重复执行/重试与补偿。
- 验收案例：视野外目标墙、仅路径不通、多军参数错误、目标执行前亡国、异常发生在部分状态写入后。

### R14 · P1 · 缺口：完整战斗公式与多方混战

- 位置：§四战斗；`faction_atk/battle_sides/_combat_power/_round_damage/_resolve_battles`。
- 需要明确伤兵是否仍满额输出、双方同时出手、骰子/地形/城堡/撤退的乘算与取整、最低伤害。
- 多方混战按敌对阵营分配输出，再按军队分摊；总HP之比不足以单独预测胜负。
- 待正规化：用公式和例子把算法完整写出，并区分算法规则与建议兵力比。
- 验收案例：11支低血军对3支满血军；三方各自的敌人不同；混编民兵；同归于尽。

### R15 · P1 · 缺口：索取顺序、撤退兜底和强制遣返

- 位置：§四占领/撤退、§六退盟；`_claim_winner/_withdraw_illegal`。
- 索取按在场且未撤退的存活方、敌对关系、engage_seq决定，不只是笼统“第一个攻击者/其盟友”。
- 撤退点失效可改撤或留守；遣返是逐回合自动移动，不是瞬移。forced路径允许中立地，不按普通地形移动代价走，也不检查普通本轮移动额度。
- 待正规化：替代点选择、无合法本土、并列最近目标、是否跨山/穿越他国部队、取消交战与取消撤退标记的关系。
- 验收案例：首次进攻方全部撤退；两个互不敌对且不同盟进攻方；退盟后本轮已移动；所有本土丢失但尚未亡国。

### R16 · P1 · 缺口：生产投料优先级与电网状态采样

- 位置：§二、§三；`resolve_turn/recruit`。
- 全国资源不足供全部电厂/工厂时，当前按 tiles/buildings 迭代顺序分配，说明书没有把这个优先级说清。
- 正规军征召检查 grid_short（上次结算的派生状态），不是动作发生时重新运行整个电网。
- 待正规化：确定稀缺燃料/原料如何分配；说明查询额定/实际产量，夺厂/失厂/买燃料后何时改变可征兵状态。
- 验收案例：两类电厂争燃料、两座工厂争最后一份矿；刚买燃料、刚失电厂后征兵。

### R17 · P0 · 缺口：在建建筑、占领与亡国的交叉

- 位置：§一/三/九；`build/_conquer/_settle_deaths/resolve_turn`。
- 已落成厅在亡国判定中有效；pending建筑晚于判定落成。占领后在建项目与建造/征兵配额的归属也应明确。
- 表中“市政厅被毁”没有对应普通玩家拆毁命令；“没被拔走的厅仍留在亡国遗土”也与厅尽失定义容易混淆。
- 待正规化：抢回旧厅与本轮新建厅区别；夺取在建工程是否继承、是否退材料、是否成为废墟；拆毁是存在能力还是文字残留。
- 验收案例：最后旧厅被拔，同轮另一厅在建；攻占敌方工地；亡国后pending项目落成。

### R18 · P1 · 缺口：军屯编制减少与免供名单

- 位置：§三/四军屯与民兵；`recruit/_supply_fed`。
- 全国编制限制新征召；失去军屯后现存超编民兵如何处理没有明确写出。
- 驻同格超过免供覆盖时，哪几支免供、哪几支扣血依赖稳定军队顺序；“免供”也不代表国家断供时一定仍能回血。
- 待正规化：编制与免供分别定义，选择免供军的规则明确且可预测。
- 验收案例：失去唯一军屯、夺取新军屯、同格3支民兵而覆盖2支、正规军断粮时免供民兵回血。

### R19 · P0 · 缺口：战时冻结、在途条约与战争传导冲突

- 位置：§五/六；`_void_pending_treaties/_declare_war_internal`。
- 说明书没有完整定义冻结按国家/实体/全世界哪个范围判断，也未覆盖战争爆发时已有提议/投票。
- 多条共同防御/保障可能有相互敌对的候选，需把“防守优先”“已有战争不重复收编”的排除规则和顺序写清。
- 待正规化：有效条约、未完成请求、跟随方身份、多个已有战线的匹配优先级及通知对象。
- 验收案例：缔约已发起但接受前宣战；两个候选援军互为敌人；一国同轮收到多份宣战。

### R20 · P1 · 缺口：通信/馈赠/情报的采样与失败

- 位置：§五情报/信箱；`send_mail/gift/share_map/spy/begin_turn`。
- 分享地图保存发送时快照；间谍获取回报时情报，二者不能混用。“换图”实际是单向发送，没有自动交换。

- 待正规化：外交队列化后计时起点、送达顺序、目标亡国/改盟后身份、重复购买与情报保留数量。
- 验收案例：发图后扩张；spy途中失地；赠送双方先后亡国；同期开局到信/到物资/到情报。

### R21 · P1 · 缺口：玩家可见信息矩阵

- 盲战是否能知道城堡，文案与查询可能使用不同过滤；地块查询动作是否能被别国看见，需要明确是否泄露侦察意图。
- 丢地通知、结盟后历史事件、离盟后保留情报、无主废墟资源/建筑公开度均需统一。
- 待正规化：为事件/查询/回执/快照/公开公告各列“谁知道什么、何时知道”。
- 验收案例：盟友视野、瞭望塔远格、视野外攻击、楚查坐标被周观察、退出联盟后查询旧信息。

### R22 · P1 · 缺口与不严谨表述：市场拆单、取整与流动性

- 位置：§七；`market_walk/_settle_gold/buy/sell/_update_market`。
- “分批慢卖更划算”需区分同回合拆单和跨回合等待；线性曲线内同回合同方向拆单不应自动省钱。
- 零钱余额与整数金结算、地板/天花板处的路径、国家数变化后的深度下限需要明确。
- 市场是否无限供货/接货、买不起是否自动缩单、同商品买卖能否因其他国家推动价格而盈利，不能用“套利必亏”取代精确条件。
- 验收案例：单笔与十笔等量买卖、价格贴边、剩1国、余额不足、其他国家插入交易。

### R23 · P1 · 缺口：经济指标的时点、单位与命名

- 位置：§八/十二；`_close_report_period/nation_assets/spend_total/settlement`。
- 国家资产是期末存量，不是“整期值”；生产流按发生时市价计价，而报表军费在市场回归后用价格折算，消费军费又在实际吃补给时入账。
- GDP−军费不是实际国库现金流；外贸比率的分子分母定义可能产生超过100%的值，不能自然叫“其余＝内循环”。
- 总消费没有把所有耗料都计入（例如回血装备），要用明确账本定义而非“所有真实消耗”的泛称。
- 待正规化：指标公式、采样时点、折价基准、0/负分母、首次增长率；区分局内市价报表与终局基准价展示。
- 验收案例：本轮市场价格大变、出售旧库存、GDP为0、回血耗装、刚占领建筑、期号错位比较。
