# 军队选择与鼠标军令

2026-10-28 用户设计，现已接入v0.7.0开发代码，尚未随完整版本发布。承接[下一轮计划](../plans/GUI下一轮试玩改进-20261027.md)和[规则复用审计](../reviews/GUI规则复用审计-20261028.md)。实现与验证见[鼠标军令验收](../reviews/鼠标军令与持续路线-20261028.md)。

## 操作对应

| 输入／状态 | 目标行为 |
| --- | --- |
| 右侧军队面板左键选择／勾选 | 选择本国军队，地图显示选中光环，并立即显示可选移动范围 |
| 已选军队，地图右键 | 向点击的格子下达移动指令 |
| 按住 Ctrl | 范围与鼠标提示切换为可选攻击目标；松开恢复移动范围 |
| Ctrl＋右键 | 向点击的格子下达攻击指令 |
| Shift＋右键 | 安排长距离移动，向路径末尾追加移动节点；重复点击可手工标多个节点 |
| Shift＋Ctrl＋右键 | 安排长距离攻击，向队列末尾追加攻击目标节点 |

地图上的移动／攻击成为日常操作主入口，现有按钮可保留为辅助入口。快捷操作直接接同一套正式军令 API。鼠标在面板控件上时，由控件接收输入，避免同时向底下地图发军令。

## 跨地块选择与可见反馈

- 取消当前“只能选择同一驻地，换格即清空”的 GUI 限制。右侧列表中的勾选可跨驻地累加，切换地图关注格或滚动面板保持选择；取消勾选与清空选择应明确可操作。
- 选择集合绑定本国真实军队编号。不同出发格、不同兵种与不同移动力分别按引擎结果处理。
- 右侧面板固定显示“已选 N 支／M 处驻地”及兵种摘要；提供清空、仅看已选和完整已选清单。主列表变长或滚动时，此摘要仍可见。
- 少量选择直接列出编号与驻地；数量较多时明确显示还有多少支，可展开完整清单并逐项取消。不能让面板外的勾选变成玩家不知道的隐含选择。
- 候选范围按各军队的引擎结果组合。目标只对部分部队可用时，显示“可执行 k/N”、参与编号以及留在原地者的原因；执行范围与预览一致，未执行部队仍保持勾选。

该设计覆盖 v0.6.2 为避免跨格残留而引入的“同驻地选择”限制；历史实现记录保持原样，新一轮以明确的全局选择和持续反馈解决问题。

## 脚底选中光环

- 被选中的军队脚底显示清楚的光环，取消选择时消失；移动和战斗演出中跟随对应军队。
- 光环属于选中状态，须与国色、攻击目标圈和路径节点区分；常用缩放下保持辨识度，不遮住脚下位置、血条或数量。
- 光环按实际军队编号关联。同格未选部队不应一起显示选中效果；多个军队合并绘制时须区分选中与未选中，并明确标注部分选择，例如“已选2/5”。
- 右侧勾选、固定已选清单和地图光环保持一致。军队阵亡或不再属于本国时更新选择，并给出变更提示。

## 范围、路径线与多节点

- 选军后立即显示本期可移动目标，按住 Ctrl 立即切为可攻击目标，不必先点移动／攻击按钮。鼠标移动到目标格时显示该格的可执行部队和原因。
- Shift 指令支持超过本期行动范围的长距离计划，由军队在合法行动时机逐步推进；保留此前低于30生命时停下回血、恢复后续行的开关设计。
- 用户已确定恢复门槛：低于绝对30生命后锁定等待，直到正常补给恢复满血才继续；各军队单独暂停，其他军队继续。不会额外治疗、补给或强制撤退，交战中无法正常回血时明确等待。
- 手动节点按 1、2、3 顺序标记，移动与攻击节点使用不同符号；地图持续显示节点间的路径线，攻击终点显示方向。
- 区分本期可执行、后续回合计划和未确认通路。未知通路使用明确的不确定样式；路径不包含玩家无权获知的地形。
- 跨驻地部队显示各自出发点与路径。路径拥挤时可聚焦单支查看，始终能对照已选清单确认归属。
- 提供查看节点、修改／删除后续节点和取消剩余路径的入口；已执行节点随进度更新，阻塞或等待回血的位置明确标注。
- 路径预览、节点合法性、实际逐步军令和演出依据同一套引擎规则；GUI 不再另算移动代价和目标合法性。

## 输入优先级

地图上已有军队选中时，右键及其 Ctrl／Shift 组合优先作为军令，不触发此前计划中的“右键返回上次操作”。没有军队选择且不在编辑路径时，才按该设置处理右键返回。

路径编辑与临时军令的取消保留清楚的 Esc／取消入口；设置页须说明上述条件，避免一个右键同时返回面板和下达指令。具体取消层次在实现交互时核对。

## 引擎能力核对与实施边界

先查引擎 API 再做增删：现有 `native:army.move / attack` 接受军队 `ids` 与目标格，`reachable` 支持逐支／批量可达查询，军队领域已具备逐支行动状态和原地攻击例外。跨驻地选择首先调整 GUI 的选择限制，不为它另创一套军令规则。

接入前先处理审计中已证实的候选／按钮误拦截。单支和批量 `reachable` 的返回契约不同，移动、攻击、撤退也各有语义，不能用一条布尔判断代替。

长距离多节点、跨回合推进和暂停续行先核对引擎已有队列／路径能力；只把真实缺口列入规则侧设计，继续复用正式军令执行。玩家信息权限、单机单人和原结算阶段顺序保持。

验收覆盖：跨驻地与混合兵种选择；长面板滚动后仍明确已选；选中光环与编号一致；Ctrl按下／松开立即切范围；四种右键组合；部分可执行的明确反馈；多节点、跨回合与存读档；低血暂停续行；右键返回设置冲突；路径与实际执行一致。

## 当前实施决定

- `native:army.queue_orders / orders / cancel_orders`统一提供追加／替换节点、全国路线查询与取消（可删除指定剩余节点）。模型工具归入military；读面板为`march_orders`，不新增按地图坐标查询。每支最多64个节点，路线不预扣资源，原军需与行动额度不变。
- 追加后当前可执行部分开始，其后在轮到该国的行动前推进；引擎只新增通用`Session.before_actor`扩展点，战国规则仍在军队域。每支每期最多一次自动军令，每支实际移动后立即记录演出快照，避免提前执行其他国家军令或把多支军队拍成瞬移。
- 长距离攻击可规划穿越敌地，但实际停在第一个需要进攻的地块，交战期间等待；目的地已归己方／盟方时使用普通移动。普通移动／攻击／撤退成功提交会替换该批军队的剩余路线；失败校验不会清掉原路线。删节点、取消路线不撤销已经发生的移动或交战。
- 行进规划与可执行目标均复用`army/navigation.py`。预览仅使用绑定玩家事实；未知段用虚线示意且不输出隐藏经过格，不依据历史归属作当前阻挡。可见高山／海洋不可作为新节点；外交或路径变化可使既有路线等待。
- 中键拖动地图；有军队选择时右键优先军令，控件区域不会向底下地图传军令。Esc取消临时选点或重画模式，已提交路线须用取消按钮明确停止。右键返回设置仍待后续设置组接线。
