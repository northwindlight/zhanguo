# 正式生产队列（v0.7.0开发）

按[第二版计划](../plans/GUI两版实施-20261028.md)实现。用户已确定：未开工取消全额退回；建设已开工拆除50%，完工拆除0%。军队已生成部分不退款，取消只返还剩余未生成单位的预付费用。

## 规则与价格

- 建筑队列由建筑域拥有，征兵队列由军队域拥有；GUI提交正式操作、显示回执，不独立计算扣款或资格。
- 入队立即扣全部金币与材料，按入队时已生效的政策、地形、工程院折扣与等级锁价；开工不再扣款。原直接建设／征兵API保留，已有规则AI不强制改为排队。
- 建筑队列预占建筑位、共享耕地／其他资源位、同格同类上限和全国自建限额。建设按同地块FIFO，每地每期仍只动工一次；城堡按等级顺序，取消不能留下中间缺级。
- 征兵需本格已有已落成设施；不让缺设施的地块通过排队绕过门槛。兵营与军屯各按现有额度执行，多单位条目可分期生成，正规／民兵两条设施生产线分别使用原额度。民兵待生成数预占全国编制。
- 每次实际开工仍用正式规则重验；停电或前提变化使队列等待并说明原因。失去地块或亡国取消未开始部分，全额退回原付款，不把队列送给新领主。

## 推进和账目

- 入队后若本期可执行则立即开始；后续由native Session在新一轮行动前推进。沿用原18阶段结算顺序，不在GUI计时器里生产，不新增按国结算。
- 预付款是待消耗的本国资产，单列预付资源；库存显示可花余额，总资产包含未开工预付款。建设／征兵消费在实际开工／生成时记一次，取消未开工只将预付款退回库存，避免重复消费或凭空损失资产。
- 原有在建撤销与实际成本回执继续复用。批量征兵取消只退尚未生成部分，已经生成军队仍按原军需／新兵禁行动规则处理。
- 新队列数据、部分完成数、价格、编号及暂停原因随存档保存；演出只使用真实开工结果。只读查询不能推进队列。

## API与兼容

优先扩展现有建筑／军队API：排队、取消、全国队列查询及内部推进，定价和校验仍复用quote/planning/build/recruit。普通查询不新增按坐标入口。

引擎会严格比较完整依赖／工具契约。队列API与状态会改变此契约，不能因旧JSON字段有默认值就声称旧档兼容。已加入0.6.3 native／experimental合成旧档及固定清单指纹；`scripts/upgrade_native_save.py`校验已知旧格式，生成新文件并复制相邻audit历史，未知依赖和混用发行版仍拒绝，真实运行局不自动迁移。当前为源码命令入口，桌面升级入口待后续发行版选择一起接线。

## 当前实现

规则、真人接口、模型工具、桌面队列模式和全国生产管理已接入。原直接操作保留，桌面可关闭队列开关使用。全国面板显示预付资源、位置、待建／在建、征兵完成量、等待原因与实际退款；取消前确认。界面待提交指令另行标注尚未扣款。

离线验证与实际窗口记录见[生产队列验收](../reviews/正式生产队列-20261028.md)。这只完成第二版中的生产队列一步，不代表整个v0.7.0已完成或已发布。
