# 模型面向层与发行版解耦（改造说明）

日期：2026-10-20。提交：`4844b00`。
触发：用户指出 **minigame 本身没坏**，坏的是「模型与 native 不兼容」。

## 一、症状与根因

症状：minigame（`mods/examples/minigame`，从零写的一套九模块小规则）能跑、能过测试，
但**接不上真实模型**——发行版里根本没有 `llm` 客户端工厂。

根因不在 minigame，在**模型面向层**：`clients/model_view.py`、`presentation/briefing.py`、
`presentation/locales/` 这些**共用**代码里写死了 native 的词汇。发行版一换，模型面对的东西就自相矛盾：

- 系统提示让模型去调 `query(panel=market)`，可这个发行版根本没有 `query` 工具；
- 简报催模型「须提交国策」，可这个发行版没有国策这个概念；
- 仪表盘读 `diplomacy.wars[].attackers`，换个形状的交战事实就崩。

一句话：**发行版换了，模型看到的说明书没换。**

## 二、六处耦合与改法

| # | 耦合点 | 原状 | 改法 |
| --- | --- | --- | --- |
| 1 | `clients/model_view.py` 的系统提示 | 硬编码 native 的面板清单与伞工具名 | 按**实际工具表**生成：面板枚举取自 `query` 工具自己的 schema，命令工具取自带 `action` 参数的工具；发行版没有 `query` 时只说明读法 |
| 2 | `presentation/locales/*.json` | 基础语言包写着「你是战国的一国玩家」 | native 专属文案搬到 `mods/native/tools/locales/`（发行版工具层语言包会覆盖基础包），基础包改通用文案 |
| 3 | 规则正文进系统提示 | `model_view.py` 硬编码标题「匈奴政体」 | 新增 `RuleSection.system`：哪一节常驻提示由**发行版自己声明** |
| 4 | `presentation/briefing.py` 简报 | 假定 native 事实齐全 | 发行版没有的概念就不出那一节；`stocks_of` 兼容 `econ` 与 `stock` 两种事实形状 |
| 5 | 交战事实 | 只认 `{'attackers','defenders'}` | `presentation/facts.py:war_sides` 兼容三种写法，认不出就当没交战，绝不抛异常 |
| 6 | `clients/llm.py` 客户端工厂 | `LLMClient.__init__` 签名与宿主工厂契约不符 | 接受 `record` / `services`，发行版可在自己的清单里复用模型客户端 |

## 三、模型面向契约（正典）

解耦之后，「发行版与模型客户端之间」的约定要显式写下来：

- **工具**：动作工具 `read_only=False`，只读工具 `read_only=True`。
- **事实**：`PlayerState` 里的只读工具名，每回合自动发给模型。发行版给哪些，简报就出哪些节。
- **内置工具**：`player_state` / `player_rules` / `player_events` / `memory_search` 由引擎提供，任何发行版都有。
- **回合小结**：`end_turn` 必须收 `summary`，并在回执数据里回 `text`。
  模型客户端会直接读 `receipt['data']['text']`，缺了就抛异常——这是接模型最常踩的坑。
- **内容键值**：模型看到短键值（`gold`）与显示名（`黄金`）；注册成内容才有短键，
  `register_aliases` 才能让中文名直接提交。

完整清单见 `docs/site/content/reference/模型面向契约.md`（由 `scripts/api_doc.py` 生成）。

## 四、minigame 补齐的模型面

- 发行版清单里声明 `llm` 客户端工厂（`clients.llm:LLMClient` + `clients.config:normalize`）。
- `end_turn` 收 `summary`、回 `text`。
- 新增三个只读事实：`stock`（资源存量）、`view`（地图逐格）、`catalog`（建筑/兵种/地形图鉴）。
- 全部工具写中文描述（原来全是英文占位符，模型无从判断该传什么）。
- 地形、建筑、兵种注册成内容；再注册中文同义词，模型照抄面板里的「兵营」也能直接提交。
- 宣战时记录宣战方，使交战事实里的进攻方/防守方有真实含义。

## 五、兼容性与影响

| 面 | 影响 |
| --- | --- |
| native 的系统提示 | **原文保留**（那段专属文案只是从基础语言包搬到了发行版工具层语言包），行为不变 |
| native 的存档 | 不变（未改存档格式与依赖清单） |
| 正在跑的对局 | 进程在启动时加载代码，改动**不影响**已开的那局（2026-10-20 八国局仍跑在旧代码上） |
| 简报内容 | 发行版没有的概念不再出现——对 native 无变化（native 该有的都有） |
| 规则正文 | `RuleSection` 新增 `system` 字段，默认 `False`，native 的「匈奴政体」显式标 `True` |

## 六、验证

- 新增 `tests/test_model_view_contract.py`（8 项）：守住「提示按工具表生成」「简报只出现有事实的节」
  「minigame 能被模型客户端跑完整回合」「三种交战形状都读得动」。
- 全量离线回归 **805 项通过**。
- minigame 离线对局照常跑完；`mods/examples/tour.py` 修好并锁成冒烟测试。

## 七、遗留

- 简报分节仍以**事实名**为约定（`econ` / `stock` / `view` / `army` / `government.plan` …）。
  换发行版若要用同一套简报模板，按这套名字给事实即可；将来若要更通用的分节机制，
  应当由发行版声明「我有哪些节」，而不是继续往 `briefing.py` 里加条件。
- `ruleai/v11plus` 仍硬编码 native 的资源与建筑 ID，规则 AI 还不能直接用在别的发行版上。
- 文档站（`docs/site/`）的 API 参考页是**生成**的：接口变了要跑 `python3 scripts/api_doc.py`，
  CI 会用 `--check` 卡住不同步的提交。
