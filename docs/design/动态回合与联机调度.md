# 动态回合与联机调度

2026-10-28 用户要求：参考文明的动态回合，和平时允许同时行动，战争时强制有序行动；`stock` 分支已有并行回合实现，应先参考复用。**动态／并行回合是未来联机的必做能力。** 本次记录设计与源码入口，尚未改造调度或实现联机；当前版本仍为单机一位真人。

## 目标与结算边界

| 状态 | 目标行为 |
| --- | --- |
| 和平行动期 | 各玩家可以同时规划、输入和行动；LLM等待可重叠，不必按国家逐个等待 |
| 战争行动期 | 受战争约束的行动按明确顺序开放，避免战斗先后由网络速度或点击速度决定 |
| 所有应行动玩家完成 | 进入统一结算，保留原18阶段及其顺序，每期只执行一次 |

动态切换首先作用于**行动调度与权限**。用户此前保留的回合末生产、补给、战斗等原阶段顺序继续有效，不改成各国轮流完成全部结算。

目标是让未受战争约束的玩家继续并行；交战参与方怎样分组、多个独立战争能否并行、每组的具体顺序，下阶段结合战争图和共享资源冲突确定。不能未经设计就把全世界永久锁成同一条队列。

## 已核对的 stock 参考实现

本次已执行 `git fetch origin stock`，查阅快照 `0fa86f63bcf8165ae92d77ce14ca9250b31108f8`，未切换或合并分支，也未操作真实股票局。

- [StockSession源码](https://github.com/northwindlight/zhanguo/blob/0fa86f63bcf8165ae92d77ce14ca9250b31108f8/mods/stock/session.py)：`_plan_one` 跑各玩家规划，`_cycle_parallel` 用线程池重叠等待；正式玩家接口通过会话锁提交世界变化。全部工作结束后只调用一次 `world.resolve_turn()`。
- `_guard` 将观战回调串行输出，回执按 `turn_order()` 顺序归并；`planning_workers=1` 可回退串行，未设置时按人数并发。
- [分支说明](https://github.com/northwindlight/zhanguo/blob/0fa86f63bcf8165ae92d77ce14ca9250b31108f8/mods/stock/README.md#并发规划)区分并发规划与市场执行；股票发行版没有战国地图和战争调度。
- [已有离线测试](https://github.com/northwindlight/zhanguo/blob/0fa86f63bcf8165ae92d77ce14ca9250b31108f8/tests/test_stock_game.py)：`test_concurrent_planning_overlaps_client_waiting`、`test_concurrent_planning_keeps_world_deterministic`、`test_planning_workers_one_restores_serial_cycle`，另有工作线程看门狗检查。本轮只读这些测试，没有运行stock测试或真实模型。

可借鉴的是“规划并发、规则提交受控、结束后统一结算”的结构。固定顺序归并回执不等于共享操作本身已按固定顺序执行；会话锁保证单次操作互斥，也不自动定义战国的争夺规则。stock的独立规划测试不能直接当作native并发语义已验证。

## 引擎与发行版职责

- 先查通用 `Session / PlayerSession`、发行版Session、正式行动权限和战争API，再决定抽取哪些已有并行机制。调度留在引擎／发行版层，GUI显示开放状态和提交结果。
- 保持绑定玩家API为唯一动作通路，读写遵循既有锁与身份权限。等待真人输入、网络模型回复或客户端演出确认时，不长期持有世界写锁。
- stock的并行方法当前处理模型／规则规划回调；接入native时还要保留真人 `on_human`、演出 `on_batch`、控制代次切换、场景胜利和地图知识采样，按真实契约适配。
- 并发上限与串行对照使用明确配置；与发行版选择、实验功能开关分别表述，不把它们暗含成同一个选项。

## 战争切换与共享冲突

- 以引擎已生效的战争关系决定调度。当前宣战、停战在外交结算生效；正常情况下由结算后状态生成下一期的行动安排，不把尚未生效的提议当成战争。
- 明确保障／联盟连锁参战、灭国、玩家加入离开与控制权切换后的调度更新点。开放权限须带期数／阶段／代次，过期指令不进入新行动窗口。
- 和平行动仍会共享市场库存、争夺无主地或同时打野。逐项确定由现有规则支持的仲裁方式，并记录真实受理／执行顺序；不能遗漏这些冲突，也不能在GUI另定义胜负或成交规则。
- 阶段推进以服务器／宿主确认的参与者集合和结束状态为准；结算只触发一次，晚到请求、重发和掉线不能导致重复结算。

## GUI与未来联机

- 显示“和平并行／战争顺序／统一结算”、本国当前权限、正在行动或已经结束的国家。并行时不能继续只有一个含糊的“当前行动国”。
- 演出队列与确认按客户端／国家隔离，单个客户端播放动画不阻塞所有其他玩家；镜头聚焦和横幅应能表达多个国家的并行活动。
- 联机使用宿主／服务器权威状态；复用既有玩家身份、请求编号幂等、控制代次和快照权限。未来多连接的令牌归属与可恢复状态需单独核对，当前单真人协议不能直接声称已支持多真人。
- 保存各玩家就绪状态、调度阶段及战争顺序所需的恢复语义；与当前“完整边界保存”契约核对。断线重连、超时或异常中断后的处理规则在实现前明确。

## 实施与验收

先完成引擎API复用和调度契约设计，使用离线模拟客户端验证等待并发、正式动作校验与统一结算；再接GUI状态和未来网络传输。当前单人GUI改进可继续推进，联机交付前必须完成动态回合，不能以仅套线程池作为完成依据。

验收至少覆盖：和平多方同时行动；单场与多场战争；未参战方继续行动；宣战／停战边界与连锁参战；共享库存和无主地争夺；各方结束后一次性按原阶段结算；晚到／重复请求；灭国、控制代次变化、超时和重连；串行对照及按已定义执行顺序审计重放；真人、规则AI与模拟LLM混合，均不调用付费模型。
