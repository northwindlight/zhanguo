# 消费指标误注入与周国策偏差事故报告

日期：2026-10-19（Asia/Shanghai）。本文记录实际对局事故、源码来源、已知影响和修复证据。用户明确要求保留当前对局、仅对周做记忆手术，并要求形成报告。

## 1. 事故结论

开发过程把研究与离线结算使用的消费评测口径写进了 AI 可读的游戏规则和说明书。周在第18期读取该段后，将“累计总消费排名”理解为直接优化目标，形成“增产—尽耗”的国策，并推导出放弃自产补给、追求市购开支等错误安排。议会随后读取同一段规则审核该国策，进一步将这套叙述带入审核对话、历史快照和双方记忆。

这是一条有实际输入、模型发言、国策草案和审核记录相互印证的目标提示污染链。不能归结为模型凭空编造，也不能通过删除当前文档就宣称旧局恢复正常。

另一个同时发现的问题是财政报告的自动呈现：正式报表查询正常，回合简报却使用上一回合流量摘要，缺少已发布报表的覆盖期、跨期投资和增长率，并同样标为“经济报表”。这削弱了模型自动取得财政信息的完整性。

## 2. 消费指标的经济学依据与本次误解

本文依据[指标论文](../research/消费总量评测指标论证.md)第二至六节理解事故。

论文中的生产是社会再生产整体：生产、交换、资源取得、配置和实际使用相互接通。出售使私人生产获得交换承认，消费使社会产品进入已经履行的用途，并继续形成再生产条件。国家消费还反映其通过贸易、联盟、贡赋和军事控制取得社会产品的能力，不能只拿本国产量衡量这一能力。

因此，长期维持更大实际消费，要求更大规模的社会生产及其取得、配置和实现。这与维持军队、建设设施和组织国家行动的能力直接相关，也与取得胜利的现实能力相联系。把消费解释成与胜利能力无关的装饰性成绩，同样割裂了论文的论证。

但“最大化现金支付”“故意采购更贵的物资”“因自产减少采购开支而放弃自产”并不是上述论证。论文明确要求同类实际使用对自产、购买、援助保持来源中立；付款与融资本身不能代替用途。周的推导将支付金额与实际实现混淆，反而可能削弱持续生产和活动能力。

论文也不允许把高开支、借贷或战争一概判为低效：实际建设、训练和维持已履行的活动可以形成真实实现，其战略代价须看后续结果。本次修复不改变消费账、估值规则或既有实际消费记录。

现行动态估值字段的可靠性是论文另外讨论的问题，当前稿第10.1节已有价格通道反例；它不能代替或否定前述经济学依据。本事故处理不向模型补发计分公式、研究论证或操纵方法。

## 5. 财政报告问题与修复

实际载入第21期存档后，用正式玩家入口执行 `query(panel=report)`，正确返回第10—19期报表，包含GDP、窗口建设额、资产负债、进出口与增长率。模型回执渲染也正常。

同一观察的自动简报则读取 `econ.latest_turn`，将第20期单回合摘要标为“经济报表”。完整正式报表没有自动接入；没有证据支持“报告数据已丢失”或“模型完全无法查询”的说法。

修复将最新已发布本国报表作为只读 `econ.latest_report` 提供，回合简报直接复用正式 report 渲染器；首份发布前明确显示尚无报表。上一回合生产流量继续在国力节呈现。财政信息不再由两个不同口径的摘要冒充同一报告。

## 7. 验收边界与防止复发

新增回归核对两个直接要求：回合简报确实包含与 report 查询相同的完整正式报表；玩家公开规则与手册不再包含目标消费排名段或离线结算命令。它们验证接口行为，不证明模型心理状态恢复。

对真实局的修复还必须分别核对公开入口、滚动回放、长期记忆、检索索引、当前国策和议会证据。只删除文档、只发一条纠正通知，或只检查当前国策，都不足以证明旧叙述不会再次回灌。

以后将研究指标、外部评测协议或宿主命令加入运行时规则和模型可读手册时，必须先确认这是用户明确要求的玩家任务信息。手册迁移不得把原有正文自动视为已经获准公开的目标定义。涉及这些入口的验收须检查内容意义与传播对象，而不只检查文件存在、API可调或保存往返一致。
