# 八国局第23期上下文超限恢复

2026-10-19，用户要求修复 `context_length_exceeded` 并续跑当前八国局。

## 现象与定位

第23期魏的首个模型请求返回HTTP 400，错误明确要求减少消息或压缩上下文。完整存档停在第23期开局，周和秦在失败前的本期行动尚未进入存档。

该局DeepSeek四国（秦、魏、燕、周）仍设置 `ctx_window=700000`、`ctx_fill=0.8`。魏的完整回放本地估算为315155 token，尚未达到配置规定的压缩水位。其他三国的完整回放也已超过本地估算的240k。

错误文本没有提供服务端的精确上限，本次按用户观察采用200k作为保守工作窗口；这里不将其写成已证实的模型官方规格。本地估算也不能替代提供方的实际计数。

## 恢复方式

- 保留原第23期存档和失败日志，另建恢复分支；不开新局。
- DeepSeek四国改为 `ctx_window=200000`、`ctx_fill=0.70`，首轮输入预算约140k，为32768输出上限、估算误差及回合中工具往返留空间。
- 同模型议长继承新的窗口配置；Qwen四国原窗口和客户端记忆保持。
- 续跑前调用各国原模型执行旧回放压缩，以原有长期记忆、被移出回放的逐期小结和有预算限制的历史前缀形成摘要；近期完整思考与工具往返保留。
- 压缩请求使用现有120k本地估算上限；有效摘要才记为成功，空摘要沿用已有最多10次尝试规则。
- 首轮压缩复核发现摘要在半句处结束：默认1500输出额度不足，而旧逻辑仅检查正文至少20字，未检查终止原因。恢复副本尚未启动，已从原回放重做四国压缩，并将四国 `ctx_compact_tokens` 设置为8192；先前调用的实际用量保留。
- 两种传输协议的非流式压缩现在保留服务端终止原因，`length` / `max_tokens` 截断摘要不得覆盖长期记忆；按原规则重试，耗尽后保留旧长期记忆并退回逐期小结。69项客户端和传输回归通过。
- 不增加游戏行动，不改资源、贷款、国策、议会材料、外交、地图或军队。旧完整对话、检索历史、小结及独立审计继续保留。
