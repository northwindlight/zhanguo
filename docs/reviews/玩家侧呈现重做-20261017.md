# 玩家侧呈现重做：让模型看见中文

日期：2026-10-17。对照 `main@0cf6386`（重做前）与当前工作区。

## 起因与判据

用户拿两份外部产出的文档要求处理（PRD v2.0 与退步对比报告）。两份文档的事实层已逐条核实：
引用的代码行号、`legacy:mp_ai.py` 的 `compact_state` 原文、被引用的对局存档都属实；
但**文档称工具面为 54 个是错的**——native 实际是 60 个模块工具 + 4 个玩家 API = 64 个，
`docs/reviews/toolcall对照.md` 亦记 64/70。工具面收敛另案处理，不在本轮。

用户当轮裁决：**不是 token 问题，是框架丑不丑的问题**；批间刷新**换成自然语言**；
落地顺序**先呈现、后工具面**。本轮只做呈现层。

判据不是「测试全过」，而是**同一时刻模型看到的东西**与旧版真局可比。

## 改了什么

三处、且只有三处决定模型看到的格式，原先全在 `mods/ui/llm.py` 里 `json.dumps`：

| 方法 | 原先 | 现在 |
| --- | --- | --- |
| `receipt()` | 裸 JSON（含 `exact_total`、`carry_before` 这类内部浮点） | 走观察者同一套 `ReceiptPresentation.receipt_body`，中文长句 + 失败教学 |
| `state()` | 一个 8k 字符 JSON 字典 | 按紧迫度分节的战情总纲（威胁／国祚／领土／国力／国策／国土视野／军队／外交／市场／央行／信箱／在途／近讯） |
| `refresh()` | `状态差分（path 指向字段…）：[{…}]` | 一行中文刷新 |

关键前提：**观察者终端的中文渲染器早就齐全**（`mods/ui/receipts.py` 覆盖 30+ 动作、
`mods/ui/queries.py` 覆盖 7 个面板），只是模型侧够不到。缺口不是渲染能力，是接线——
`LLMUI` 一直持有 `ConsoleUI`，却只拿它翻译失败文案；观察者侧由 `mp_run.py` 每回合喂
`remember(observation)`，**模型侧从来没喂过**。补上这一步，专用渲染器才真正生效。

新增 `mods/ui/briefing.py` 承载分节总纲；删除已无人引用的 `mods/ui/deltas.py`。
`engine/deltas.py` 仍被议会取证使用，保留。

## 真实存档对照

同一时刻（第 15 回合·秦）：旧版真局 `research/game-records/eight-nations-158/journal.md`，
现役真局 `archive/games/qwen-8nations-20261016-185839/session.json`
（`clients['scenario:qin'].state.replay`，重做前）。

**重做前的模型侧回执**：
```json
{"api":1,"actor":"scenario:qin","action":"sell","period":15,"ok":true,"status":"effective","code":null,"message":"",
 "data":{"owner":"scenario:qin","resource":"木头","side":"sell","quantity":2,"gold":9,
 "exact_total":9.357372177146708,"price_before":4.925984049960818,"price_after":4.925984049960818,
 "carry_before":0.3282666308135216,"carry_after":0.6856388079602294,"period":15}}
```

**重做后**：
```
卖出 木头×2，实收9金（含价差均价4.68；本期市价4.93）
```

**失败回执**（旧版式教学，现役已有）：
```
❌ 该地没有兵营：步兵与骑兵只能在自有已落成的兵营征召，每兵营每回合 1 支
```

**问路并进军事面板**：`reachable`／`frontier` 原先只是裸坐标数组
（`{"visible_unowned":38,"reachable":[[1,8],…]}`），现在可及格数与可拓荒地直接写进
【军队】节，坐标地图（`player_atlas`，按势力分段、带 `L{n}城`／`厅×n`／番号）常驻——
这正是用户点名的「不如一次性给军事地图」。

## 顺带查到并修掉的三件事

### 1. 长期记忆每回合发两遍

压缩当回合，`clients/llm.py` 把同一段正文既写进 `state.long_memory` 又追加成一个
`blocks` 条目；`render_archive` 再把两者分别渲染成【第N-M回合 · 阶段总结】与
【长期记忆 · 递归累积…】。实测：秦／魏／齐**每回合都是 2 份**，
1.6k 字符的状态前缀里同一段 725 字逐字节重复，末尾仅差一行 `（归档截至第 N 回合）`。
修法是在 `render_archive` 里跳过与 `long_memory` 逐字相同的块——**不动 `blocks` 本身**，
它还参与压缩切点计算。两者确实不同时两块都保留，已加测试钉住。

### 2. 市场空转只在结算才播报

空转检测本来就有（`market.churn`），但只在结算阶段以一条事件播报——模型读到它时本回合
早已结束，这一单改不了。旧版是在买／卖回执里当场警告的。现在 `Market.buy/sell` 返回
`TradeReceipt`（成交 + 本期倒手量），回执当场点名并给出做法；没有重叠时整段不出现。
倒手量属于回执不属于市场状态，仍只把纯 `Trade` 记进 `_trades`，存档格式不变；
也没有新增对象接口，`mod.toml` 未动，依赖清单不变。

### 3. 报错文案宽泛

原先大量错误是英文短语，靠 `receipt.<英文原文>` 的本地化表翻译；表里的中文也常常只有一个
结论（「已达到全国民兵容量上限」），既没有数字也没有做法。这类改动集中在军队、外交、
银行、通信、地块与玩家 API 边界，改为直接抛中文并带上实际值与下一步。
例如：

- `已达到全国民兵容量上限` → `全国民兵编制已满：军屯每座可驻 2 支，上限 8 支，现有 6 支，本次还要再加 2 支。先增建军屯，或裁撤旧民兵`
- `A unit has no action available` → `这支军队本回合不能行动：新兵当回合不能动、每军每回合只能行动一次、交战中的须先撤退。逐军状态见 army 回执`

`Interfaces` 属于依赖清单，因此**没有**为了取空转而新增对象接口——那会让旧档读不进来。

## 验证

| 项 | 结果 |
| --- | --- |
| 全量离线回归 | **610 项通过**（重做前 609；新增长期记忆去重 1 项） |
| 合成续档一致性 `experiments/implementation_audit/smoke.py` | native 40 周期、experimental 6 周期，`continuation_equal` 均为 true |
| 载荷实测 `benchmark.py`（同一合成场景、同一 8 国 224 支军） | `state_tokens` 4496 → **1678**；`update_tokens` 716 → **83**；`system_tokens` 852 → 837；`tools_tokens` 10607 → 10607（未动 schema，符合预期） |
| 语言口径 | zh 用本地化键值（粮食／木材），en 用短键（food／wood），与工具 enum 同一套 |

**边界**：上表的 token 是同一台机器上的本地估算器读数，只作诊断；用户已明确 token 次要，
本轮不以它作验收门槛。载荷**变小**的同时模型看到的内容**变多**（地图、市场、央行、
外交、信箱等面板改为成文常驻），两者不矛盾。

## 残留

- 议会的审核快照仍走世界状态重放，不在本轮范围。
- `receipt.<英文原文>` 本地化表保留：旧存档的日志与审计里存的是那些英文串，翻译仍要能命中。
  新增文案不再走这张表。
- 观察者侧仍有硬编码中文（如 `build` 回执的「动工…本回合在建」），英文界面的叙述模板
  完整国际化仍未补齐——这是既有口径（`mods/ui/README.md` 明示「当前优先完善中文叙述」），
  本轮未扩大范围。
