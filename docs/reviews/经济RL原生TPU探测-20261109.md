# 原生 TorchTPU 探测

用户指出应使用 PyTorch 的原生 TPU 路径。Google 当前文档提供 `torch_tpu`，使用 `torch.device('tpu')`；旧 PyTorch/XLA 页面已指向 TorchTPU。PyPI 的 `torch_tpu==0.2.0` 实际提供 cp313 安装包，因此无需为此寻找 Python 3.11。安装包存在只证明解释器版本有包，实际运行还须验证。

来源：[Google PyTorch on TPU](https://docs.cloud.google.com/tpu/docs/pytorch-on-tpu)、[TorchTPU 官方仓库](https://github.com/google-pytorch/torch_tpu)、[PyPI 0.2.0 文件](https://pypi.org/project/torch-tpu/0.2.0/#files)。

## 已完成与待验证

2026-11-09 实查 Kaggle：TPU 独立额度为 20 小时，已用 0；GPU 剩约 4.14 小时。额度不代表能立即分配设备。22:35 时 GPU 第 15 轮和 TPU 环境探测均为 QUEUED。

已接受的 TPU kernel 为 `northwindlight/zhanguo-economy-tpu-probe/1`，只检查环境。Kaggle 限制最多一个待执行的 batch TPU session，因此完整原生探测要等待它结束。`scripts/econ_tpu_probe_watch.py` 自动衔接下一版本并回收结果；推送必须收到版本号才算成功，不能只看 CLI 退出码。

`scripts/econ_tpu_probe.py` 使用当前解释器建立隔离 venv、安装 `torch_tpu==0.2.0`，随后验证：

1. 原生 TPU 张量运算。
2. SHA 校验后的固定第 14 轮模型与真实玩家观测，CPU / TPU 所选动作 logp 误差不超过 1e-4。
3. 现有 PPO 更新函数完成一个更新，两个决策覆盖率 100%，策略梯度有限且非零。

最后一步用合成奖励检查算子和反向支持，结果固定标为 `promotable=False`，不导出权重，不进入训练链，也不能当成经济收益改善。安装、模型操作、优化器或数值检查失败都写入结果；尚未完成实际 TPU 验证，也未切换生产训练设备。

监控服务：`zhanguo-native-tpu-probe-20261109`；本地状态、日志和后续结果位于 `archive/previews/ppo-continue-20261107/native-tpu-*`。临时 venv / 解包模型在远端 `/tmp`，不作为 Kaggle 输出留存。验证通过后才评估生产接入及速度；当前 GPU 主线和默认关闭的无效动作惩罚保持原设置。
