# 经济 RL 推理与编码性能分析（2026-11-07）

本地长局慢有两处来源：**整局的观测编码与正式查询开销**，以及**大候选集里的候选自注意力**。
不能把 Python 进程满一个核全部解释成神经网络前向。当前 C 求解快路径已启用，回退记录为空。
本轮只做性能分析和进程内原型；正式引擎、观测、模型结构、权重和掩码均未改动。

## 测量范围与限制

- 代码 `7dd4a85`，历史 r3 权重；Pi / ECS 的 model.py、layers.py 和权重 SHA 均一致。
  Pi 为 PyTorch 2.14.1，ECS 为 2.14.0+cpu；硬件与构建均不同，不能把差异全部归因于指令集。
- 微基准输入为真实教师数据的四个单条观测，候选数 96 / 685 / 932 / 2376，context 行数
  30 / 101 / 120 / 245。最大观测来自 S4 world-131 第 1368 条。
- 不截断候选、不按可执行性删候选；模型 eval + inference_mode。4 次预热、15 次计时取中位数。
  这是不同真实观察的对照，context 长度也变了，不是仅改变候选长度的受控因果试验。
- 初次探索与后台验证并行，延迟有明显波动，只作为诊断。最终微基准短暂暂停本任务的长局验证，
  显式限制 OpenBLAS / OpenMP / MKL 环境线程后测量，结束已 SIGCONT 恢复；其他用户服务未停。
- 实局分阶段计时为同种子 8101 / 20 图 / r3 的前 30 回合，**不是完整 150 回合的平均比例**。
  所有计时嵌套关系如下文说明；cProfile 另跑 10 回合，其明显插桩开销不混入分阶段墙钟。

## 1. 前 30 回合，模型前向只占约 5.5%

Pi 实局 116.448 秒，259 次实际前向。阶段计时如下，encode 内子项不能重复相加：

| 阶段 | Pi 秒 | 占实局墙钟 | ECS 秒 |
| --- | ---: | ---: | ---: |
| 全部实局与评测初始化 | 116.448 | 100% | 35.300 |
| 学生经济层合计（包含下列子项） | 78.425 | 67.35% | 22.569 |
| encode：观测及项目候选打包 | 53.516 | 45.96% | 16.642 |
| 其中 observation | 29.937 | 25.71% | 9.297 |
| 神经网络前向 | 6.438 | 5.53% | 0.860 |
| collate + prepare | 0.119 | 0.10% | 0.029 |
| 经济层 finish | 10.330 | 8.87% | 2.844 |

另有 19.930 秒落在 funding 调用中，它嵌套在编码/执行/补货等路径中，不能与父阶段相加。
两端实际 encode、forward、execute、funding、package 调用次数均相同；此对照没有另外保存逐动作
完整审计，不能据此宣称跨平台逐位等价。

cProfile 的热点包括正式 planning、trade_quote、observe、引擎 object_call / derived / read、
对象 bind_state 和 wire 序列化；前 30 回合就调用 funding 17,583 次、package 41,895 次。
因此编码与验资的重复查询值得优先处理。此 30 回合样本里，即使前向耗时完全消失，理论上也只省约 5.5%。
后期候选更大时，这个占比可能不同；本轮没有把 30 回合比例外推成全长局结论。

## 2. 单次前向：大候选自注意力很贵

受控条件下，单线程单次前向中位数：

| 实际候选数 | Pi 毫秒 | ECS 毫秒 |
| --- | ---: | ---: |
| 96 | 7.23 | 1.81 |
| 685 | 38.99 | 12.64 |
| 932 | 57.26 | 18.73 |
| 2376 | 263.98 | 85.52 |

这四个观测的各线程组 argmax 一致。Pi/ECS 的此类输入延迟差约 3–4 倍，但仍包含版本、
构建与机器背景负载差异。

2376 个候选的 PyTorch CPU 算子记录中，**候选自注意力的 CPU flash attention 核占约 60%**；
模块计时 cross2 约 170 毫秒，context→candidate 的 cross 约 27 毫秒。CPU profiler 会扰动耗时，
所以模块/算子表用于定位，不能与未插桩中位数直接拼成总耗时。
候选自注意力的成对比较数量随 N² 增长：2376² 约 565 万对，每个注意力头都参与计算。
算子名称中的 flash 在这里指 CPU 实现，并没有 GPU 参与。

## 3. 加线程不是免费提速

| 候选数 | 1 线程毫秒 | 2 线程毫秒 | 4 线程毫秒 |
| --- | ---: | ---: | ---: |
| 96 | 7.23 | 9.10 | 7.21 |
| 685 | 38.99 | 42.07 | 29.95 |
| 932 | 57.26 | 46.57 | 47.66 |
| 2376 | 263.98 | 165.52 | 183.68 |

最大观测下，2 线程约 1.59 倍前向加速；4 线程没有继续改善，进程 CPU 时间中位数达到约 495 毫秒，
1 线程则约 263 毫秒。当前后台评测服务 CPUQuota=100%，只给一个核的总预算，不能直接套用这张
不受该服务配额限制的多线程延迟表。保持一核预算时，盲目提高线程数会增加争用和节流。

显式设置 BLAS 环境线程后，单线程进程实际只有一个原生线程；默认导入时会产生多个线程。
但本轮同时控制了后台验证负载，没有单独隔离“环境变量”这一因素，不能把前后所有差异都算给它。

## 4. 已测的前向小改动

单线程、四个固定观测；各方案均在独立模型副本上测试，未改正式评测。
方案按顺序执行，以下是诊断中位数，不是随机交错的严格消融，几个百分点的差异应复测。

| 方案 | 96 候选毫秒 | 2376 候选毫秒 | 输出情况 |
| --- | ---: | ---: | --- |
| 当前实现 | 7.01 | 244.68 | 参考 |
| Q/K/V contiguous | 7.37 | 241.54 | 四个观测逐位一致 |
| 全有效 key 时不传空 padding 掩码 | 7.13 | 238.92 | 四个观测逐位一致 |
| 恢复原生 F.linear | 7.87 | 242.99 | logit 最大差约 1e-5，argmax 相同 |
| 项目模式省略无用 quantity 网络 | 6.64 | 242.01 | 四个观测逐位一致，项目 limits 全为零 |
| 强制 math SDPA | 9.11 | 449.17 | 更慢；logit 有约 1e-5 差异 |
| contiguous + 空掩码省略 + quantity 省略 | 6.60 | 228.68 | 四个观测逐位一致 |

组合方案只有约 6% 的最大观测前向改善，本轮没有证明整局收益。
当前版本的 F.linear 对照也没有复现旧注释所称固定 6.6 倍差距，历史数字不能继续当作此版本结论。

## 5. 报价缓存原型：编码减少约 23%，194 个状态逐项一致

同一 20 回合真实轨迹上的每次决策，都执行原编码与缓存编码，并交替两者先后顺序。
缓存严格限于一次不执行动作的 encode：正式 planning、trade_quote、unit_catalog；返回后销毁。
没有跨交易、跨决策或跨回合复用报价，也不改变规则、候选与可执行性。

- 194 次编码的 context/candidates/limits/legal 数组及 actions/packages 全部逐项一致，数组类型/形状也检查。
- 原编码累计 16.801 秒，缓存原型 12.886 秒，减少 **23.30%**，编码阶段约 **1.30 倍**提速。
- 31,251 次 trade_quote 请求中，28,750 次命中，命中率约 92%。
- 原有 planning 缓存本来已存在；本轮原型的收益主要来自增加报价和单位目录的复用。

这是编码阶段对照，整段 20 回合为了对账把编码跑了两遍，52.79 秒的墙钟不是“优化后实局耗时”。
尚未完成完整 150 回合的缓存版轨迹/终档对账，因此未部署，也未注册新的特征契约或使旧数据失效。

## 6. 架构检查补充

现有 `--cand-ffn` 实际把 `Block` 放在候选侧，Block 内同时有自注意力与 FFN。
所以打开此开关会额外增加两层候选自注意力，并非只增加两段逐候选 FFN。
当前 r3 以及本轮 14 世界 T4 BC 都关闭此开关，故它不是本次 r3 的现有热点来源；
后续研究 FFN 收益时，需要分清 FFN 与额外注意力这两个变量，不能只按名称解释性能或能力变化。

## 建议顺序与产物

1. 优先把只读报价/目录缓存补成可审计的优化，先完整 150 回合逐项/轨迹对账，再用于正式筛选。
   还要处理纯实现优化与当前契约哈希的关系，不能为了性能把现有示范数据全部判旧。
2. 保留单线程一核的验证预算；大候选的两线程加速只能在明确增加 CPU 配额后再评估整局收益。
3. 对大候选注意力，真正改变复杂度需要结构调整与重新训练，不能把裁候选/硬合法掩码当作透明优化。
4. 现有前向小改动收益有限，不能据此许诺长局大幅提速。
