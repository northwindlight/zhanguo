# 架构复核：纵向已切开，横向仍耦合

日期：2026-10-17。基线：`main@8fd429a`。范围：`engine/`、`mods/`、`clients/`、`ruleai/` 的声明、呈现、注册与内容契约。本文只做复核与方案，不改规则、不跑全量测试。

## 一、结论

「按事分模块」在**领域层**已经基本成立；未成立的是「改一处只动一处」。

现在改一个地方，仍要穿过四张没收口的网：

1. **声明面**：同一事实在 TOML 和 Python 各写一份，引擎各读一半；
2. **呈现面**：所有模块的回执、面板、简报、决策提示集中在 `mods/ui`，按动作名硬编码；
3. **注册面**：工具、玩家事实、查询面板、政体禁用各自维护一张手工名单；
4. **语义面**：首都、兵营、城堡、货币、地形靠内容 ID 与中文字面量跨模块传播。

一句话：**纵向按事切开了，横向的四张网没有收口。** 模块能独立存在，但它的「说法」和「登记」仍散在全局。

## 二、已经成立的（本轮不重做）

- `engine/` 里搜不到 `nativemod`，也搜不到补给、战斗、建筑、外交等游戏词；引擎只有装载、依赖排序、挂点、状态所有权、工具与权限。
- 状态所有权唯一：`Runtime.__init__` 注册 `state_owners`，重复即报错；跨域写入要走 `Requests`，当前各模块均为 `Requests=[]`，没有越权写。
- 跨域协作基本走 `object_call` + `[Interfaces]`；装配期能报「能力无提供者 / 状态无主 / 挂点条件无人提供」。
- 市场计价（`market:pricing`）、地图生成（`map:generation`）是真正的可替换契约。
- 配置层、存档严格校验、客户端权限门（`PlayerSession`）都在正确的层上。

问题不在领域对象内部，而在它们与外部的四个接缝上。

## 三、四张没收回来的网

### 3.1 声明面：同一事实两份，且有一份不生效

证据：

- `[State] Owns` 与代码 `state_keys()` 各一份；运行时以代码为准（`engine/runtime.py:323`），TOML 只在 `Runtime.load` 预检 `RequiredState` 时被读（`engine/runtime.py:464`）。
- `[Capabilities] Needs/Provides` 运行时零读取；真正生效的是 `mod.needs()/provides()`（`engine/runtime.py:344`）。全仓只有 `tests/test_army_resources.py:33` 在读这份 TOML。
- 阶段两种写法并存：buildings / market / economy / bank 在 TOML 写 `[[Stages]]`；army / diplomacy / intelligence / succession / government 在 Python 写 `Stage(...)`。同一个概念，作者要先猜该写哪边。
- 已经漂移：`mods/native/buildings/mod.toml:13` 的 `Needs` 含 `map:generation`，`mods/native/buildings/mod.py:13` 的 `needs()` 不含它。因为 TOML 那份没人读，漂移没有报错。

后果：改一个状态键、能力或阶段，要先判断「这次该改哪份」；改错那份不报错。这是典型的「工具骗人」——声明看起来是契约，实际有一半是注释。

### 3.2 呈现面：UI 是第二个规则实现

- `mods/ui/receipts.py` 有 69 处按动作名分叉；`queries.py` 7 处；`console.py` 1 处；`briefing.py`、`llm.py` 另有按事实形状的分支。
- UI Mod 声明零依赖（`mods/ui/mod.toml` 只有 `Provides = ["ui:presentation"]`），却读取每个模块的事实字段。模块改字段，UI 不会在装配期失败，只会静默走通用格式或 `try/except` 兜底。
- `mods/ui/llm.py:124-176` 的 `dashboard()` 重算了补给需求、军屯免供、装备回血、电力缺口——这些规则的所有者是 army 与 buildings。
- `briefing.py` 自己数市政厅、军队、能源；`economy_queries/objects.py:104-148` 自己重算建筑 ROI（含市政厅另加 3 个建筑位、工程院摊销）。
- 同一内容有两套语言目录：`mods/native/locales/*.json`（37 条 resource/unit/building 键）与 `mods/ui/locales/*.json`（另有 39 个 `content.*` 键），外加 `receipts.py:90` 的硬编码资源短名。UI 目录里还留着没有对应内容的 `archer`、`lumber` 旧键。

后果：改一条补给、电力或建筑收益规则，要改领域模块 + UI 里的第二份实现；加一个动作，要改回执、面板、简报、两份语言目录。模块没有带走自己的「说法」。

这正是 `模块化口径.md` 第三节与 `PLAN.md` 3、4 条尚未完成的部分：文案、面板格式、别名与参数口径应随模块走，UI 只负责编排。

### 3.3 注册面：几张手工名单，漏登记是静默的

同一时刻：注册 61 个规范工具名，其中只读 28 个、引擎明文工具 34 个（模型侧再加 4 个内置 API）；发行版 `PlayerState` 列 22 个（`mods/native/mod.toml:9`）；查询面板 `PANELS` 列 26 个（`mods/native/query/mod.py:9`）。这些名单各自维护：

- 加一个只读事实：模块工具 + `PlayerState` + `PANELS` + `PROPERTIES/TYPES` + `DESCRIPTION` + UI 渲染 + 两份语言目录 + 测试计数，合计 8~10 个文件。
- 漏了 `PlayerState`：`observe()` 不扇出这个工具，事实静默消失，没有报错（`engine/player.py:109` 只遍历名单）。
- 漏了 `PANELS`：工具被 `ReadOnlyPanel` 收成 hidden，模型既看不到也查不到，只剩脚本和规则 AI 能按名调用。
- `RequiredState`、`ReadOnlyPanelKeep`、experimental 的整套 `Members/Hooks` 也是手工复制；native 加一个模块，experimental 要再抄一遍清单。
- 登场字段有三份：`config.py` 的 `ACTOR` schema（`start_gold/start_supply/start_cavalry`）、`observer.py:91` 的 `excluded` 集合、`NativeSession.spawn` 的 `start_*` 映射。加一个开局字段要三处同步。
- `NativeObserver.observer_snapshot` 逐域硬取 `buildings/economy/market/bank/military/diplomacy`；新加一个要进地图或观测面板的模块，还要改观测器。

后果：加一个只读面板要动 6~10 个文件；漏一处不是报错，而是「模型看不到」这类软失败。

### 3.4 语义面：内容 ID 和中文地形名当跨模块契约

- `native:town-hall` 出现在 13 个代码文件，`native:castle` 10 个，`native:gold` 17 个（含 examples 与 ruleai）。
- 地形映射存在 6 处：`territory/mod.py:7`（ID 定义）、`map_generation/mod.py:7`（中文→ID）、`army/mod.py:12`（中文→ID）、`ui/maps.py:10`、`ui/views.py:5,41`（ID→字形）、`session.py:60`（默认平原）。
- 建筑物没有声明角色。succession 用 `native:town-hall` 判断首都；vision 用 `castle/town-hall` 决定对外公开；army 用 `barracks/militia-camp` 判断征兵；economy_queries 用 `academy/town-hall` 算收益。加一个「也算首都」或「也能征兵」的建筑，要改这些模块。
- 政体禁用是工具名单：`polities/huns/mod.toml:19` 的 `Disable` 写了 31 条（tool/action/communication）。默认放行；新加一个联盟动作而忘了登记，匈奴就能用，且没有测试会响。
- `observer.py:103` 仍硬编码 `'匈奴','huns','hun' → native:huns`，违反「政体字面量只许在政体模块内」。

后果：加地形、建筑或外交动作，改的不是一个模块，而是「所有认识这个 ID 的地方」；漏改时往往不报错（例如 `unit_move_cost` 对未知地形默认 1）。

### 3.5 附带：跨模块实现 import 与数值 import

- `mods/native/bank/objects.py:10,269` 直接 import 并调用 `Economy._report`（私有方法）。
- `mods/native/economy_queries/objects.py:5,132` import `NativeBuilding` 与 `government.parameters.ACADEMY_AMORT_TURNS`，绕过能力接口。
- `mods/experimental/combat_research/mod.py:4` import `army.parameters.COMBAT_DIE_MOD`；`client.py:2` import `ruleai`，使 `grep -rn "ruleai" mods/` 不为空。
- 「换实现」的验收样例 `fixed_credit_bank` 是继承 `BankMod/Bank`，不是独立实现；换建筑实现会直接打断 economy_queries。

这些不是风格问题：它们让「替换一个模块」从声明级退化成源码级。

### 3.6 附带：文档与数值重复

- `handbooks/basics.md:33`、`handbooks/war.md:24-26` 写死 35HP / 30HP / 1 装备；`army/parameters.py:21,25,42` 是同一组数。改参数不会改手册。
- army 的 `rule_sections()` 用 f-string 注入参数，手册用静态数字；`docs/generate_manual --check` 只保证 rule_sections 与生成物一致，不检查 handbooks 里的数字。
- `mods/native/README.md` 的工具数、模块数已与当前实际（61 个规范工具、34 个明文工具、17 个阶段）不一致。

## 五、根因

1. **没有单一声明源。** 引擎既读 TOML 又读 Python，两边都能写同一事实；没有任何时候要求两者一致。
2. **模块只交数据，不交说法。** 呈现所有权没有随模块下沉；`mods/ui` 成了所有模块的上帝对象。上一轮把 JSON 换成了中文，但中文的**所有权**仍在 UI。
3. **注册靠人肉枚举。** 发行版、查询面板、策略禁用都是全局名单；模块新增能力不会自动出现，漏登记走默认。
4. **语义寄居在字面量。** 内容 ID、中文地形名、工具名承担了「角色 / 类别」的职责；没有声明式的角色层。
5. **软失败没有闸门。** 漏登记、漏映射、漏禁用都走默认值或兜底，装配期不响，测试也不响。

这五条的共同点是：它们都能靠代码审查「发现」，但无法靠代码审查「保证」。所以修复方向不是再写一遍规范，而是把事实变成派生或装载期校验。

## 六、目标形态：四个收口

原则：仍然显式声明，不引入 DI 容器、事件总线、反射扫描或任何「魔法」。下面每条都能用现有 `GameMod` 接口做，不需要新框架。

### 收口 1：声明单一来源

建议以 **TOML 为声明源**（`Mod` / `State.Owns` / `Capabilities.Needs,Optional,Provides` / `Interfaces` / `[[Stages]]`），Python 只交对象、工具、面板、呈现。

- 引擎直接读 TOML，删除各模块对 `state_keys/needs/optional/provides/stages` 的重复覆盖。
- 内容派生的能力（resources 的每资源一个 capability）从 TOML 的 `ResourceTypes` 派生，不再手写第二份。
- `[[Stages]]` 的 `Handler` 统一为模块上的公开方法名；army 等现在写在 Python 的阶段迁到 TOML。
- 装载期加不变量：每个 `Provides` 有主、每个 `Needs` 有供、`Interfaces` 的能力必须在 `Needs/Optional` 里、每个 `Handler` 可解析、每个 state 只有一个所有者。
- 如果保留动态声明，也只允许「从 TOML 声明的列表派生」，不允许代码与 TOML 各写一份。

**验收**：改一个状态键/能力/阶段只改一个文件；故意删掉一条 `Needs` 或改错 `Handler`，`Runtime.load` 必须报错；当前 `buildings` 的漂移应被新校验直接抓出。

### 收口 2：呈现归模块

在引擎定义最小呈现协议（普通函数与数据，无反射）：

- 模块可提供 `action` 的抬头与回执、`panel` 的成文、`briefing` 的分节、`cues` 的决策提示。
- 模块拿到 UI 传入的渲染上下文（`text/num/pos/name/resources`）写自己的句子；模块不 import `mods/ui`，UI 也不 import 模块实现。
- UI 只保留：分节顺序、越界裁剪、语言选择、地图渲染、未知动作的通用兜底。
- 语言目录按模块命名空间装配；现有 `Translator` 的占位符校验继续用。`mods/native/locales` 与 `mods/ui/locales` 合并为一套内容键，由内容属主提供。
- `cues` 由属主给：army 给补给/兵力/可及，buildings 给电力/建筑位，economy 给现金流；UI 的 `dashboard()` 不再重算规则。

**验收**：先选 **army 或 market 一个模块**做样板，迁移后从 `receipts.py/queries.py/briefing.py` 删掉它的分支，UI 其余部分不动；同一存档、同一 observation 的渲染结果与迁移前逐句对比（允许措辞调整，不允许事实变化）；未知动作仍能走通用格式。

### 收口 3：注册表派生

给 `Tool` 增加元数据：`fact`（进入玩家事实）、`panel`（可查询只读面板）、`groups`（策略类别）。

- `PlayerState` 从 `fact=True` 派生；发行版只声明 include/exclude 或模块集合，不再列工具名。
- `query` 的面板表从只读工具派生；`PROPERTIES/TYPES/DESCRIPTION` 由工具 schema 与描述生成，删除手写的四张表。
- `RequiredState` 从模块 `State.Owns` 派生；`ReadOnlyPanelKeep` 从 `panel/hidden` 元数据派生。
- 测试从「断言 61/34/17」改为「结构不变量」：每个 fact 只读且唯一、每个工具所有者存在、每个 panel 有渲染器或兜底、每个 state 有主。

**验收**：加一个只读面板只改模块声明；发行版 diff 为 0；删一个工具，查询表与玩家事实自动少一项；漏登记变成装载期错误而不是静默缺失。

### 收口 4：语义用角色，不用 ID

- 内容定义带角色/标签：建筑 `ROLES=('capital','recruiter','militia','castle','vision')`；资源带 `ROLE='currency'/'supply'`；地形带 `name_key/glyph`。
- 消费方通过属主能力问角色（如 `native:buildings.has_role(site, 'capital')`、`native:resources.role(id)`），不写内容 ID 字面量。
- 地形单一登记：算法内部的中文键只保留在 `map_generation` 边界，其它模块只用 `Terrain` 定义；删除 army 的 `TERRAIN_IDS`（单位 `move_cost` 改用 ID）。
- 政体按能力组禁用：工具声明 `groups`，`Policy.Disable` 写组名（如 `diplomacy.alliance`、`communication.gift`）；新动作继承组，自动被禁。
- 删除 `observer.add` 的政体名字面量，改由政体模块声明别名匹配。
- 跨模块数值走 `runtime.number(key)`（`numbers()` 已登记所有权），禁止 import 别人的 `parameters`。

**验收**：加地形/建筑/资源/外交动作，只改属主模块与内容/语言；huns、UI、army 不动；删掉政体模块标准局照开；匈奴的禁用名单从 31 条降到 3~4 个组。

### 收口 5（顺带）：契约与文档

- `bank` 的 `Economy._report` 改走 `native:economy` 的公开方法；跨域私有调用清零。
- 手册用 `{{number:army.starvation}}` 之类的显式占位，由 `runtime.number` 在 `rule_sections` 时替换；或者手册不写具体数字，只指路目录。
- `generate_manual --check` 覆盖 handbook 正文；README 的数量改为生成或删除。
- **待裁决**：是否把 `dependency_manifest` 拆成「规则契约」与「呈现/只读接口」两部分，让加只读面板不再废档。当前严格清单把呈现变化也算进存档契约，是「加一个面板就旧档作废」的直接原因。

## 八、推进顺序

不在一个批次里做全部。每个批次单独审阅、单独验收。

| 阶段 | 内容 | 风险 | 停点 |
|---|---|---|---|
| P0 | 声明单一来源 + 装载期不变量 | 低 | 漂移用例被装载期抓住 |
| P1 | 呈现协议 + **一个模块**（army 或 market）迁移 | 中 | 同一存档渲染对比；UI 删掉该模块分支 |
| P2 | 注册表派生（PlayerState / query / RequiredState） | 中 | 加面板只改模块；结构不变量测试 |
| P3 | 其余模块按同一呈现协议迁移 | 中高 | 每迁一个模块，UI 分支减一 |
| P4 | 内容角色 + 策略组 + `runtime.number` + 跨模块契约 | 中 | 加地形/建筑/动作的改动面收敛；huns 名单缩短 |
| P5 | 文档数值同源、README 生成、存档清单拆分（若采纳） | 低 | `--check` 覆盖手册 |

理由：P0 是地基，先让声明不能骗人；P1 先用一个模块验证呈现协议，避免一次迁 20 个模块；P2 消除最高频的多文件编辑；P3 铺开呈现；P4 是语义层，放在协议稳定之后。

## 九、明确不做

- 不把所有 UI 塞进模块。模块只带自己的说法；通用编排、裁剪、地图渲染仍在 UI。
- 不让引擎认识游戏词、内容 ID 或 `native:` 前缀。
- 不引入 DI 容器、事件总线、自动扫描、装饰器注册等「魔法」。本项目的口径是显式声明。
- 不借重构改规则。呈现迁移只允许措辞调整，不允许事实变化。
- 不为旧档做兼容层；是否拆分存档清单由用户裁决。

## 十一、待用户裁决

1. **声明源选 TOML 还是 Python。** 本文建议 TOML：发行版清单、说明书、存档清单已经围绕声明组织；Python 只保留实现。
2. **呈现下沉的边界。** 本文建议模块带走动作回执、面板成文、简报分节与 cues；地图渲染与裁剪顺序留在 UI。
3. **存档清单是否拆分。** 本文建议把呈现/只读接口移出规则契约，但这会改变「旧档作废」的现行口径，需明确裁决。
4. **experimental 的 ruleai import。** 本文建议把 research 客户端移出 `mods/`，或改为只依赖 `ruleai` 的公开入口。
