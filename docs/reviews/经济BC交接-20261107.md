## 一、目标与验收口径

- 用户 2026-11-06 定：**验收 = 总 S 达到教师的 150%**（“超 50% 就是 150%”）。
  已实现为 `rl/economy/acceptance.TARGET_RATIO=1.5`，CLI 有 `--target-ratio`。
- 主指标 S = 征召+军需+行政（当期价累计实际消费）；建造是固定资本形成，不计入 S。
- 奖励 `ΔS/1000`，`γ=λ=1` 完整回报；PPO 一轮的有效批 128（8 条微批累积）、KL 采用窗口估计 + 自适应 β。
- **选模只能用多环境实局 S**，不能用验证损失或分类准确率（见第三节的反例）。

- 基线（codex 的 8 世界族头模型之外）另测：40 回合旧 BC 87.8%、分桶版 89.0%、FFN 版 **70.9%**
  （验证损失最好 1.43，实局最差——**验证损失与 S 无单调关系**，这也是不能按 loss 选模的直接证据）。
- 结论：PPO 确实在动行为，且多环境都在涨，但**单轮方差极大**（2 世界两路曾从 99.5% 掉到 82%）；
  4 世界那轮最差环境 82.3%，是当前最好。离 150% 仍有明显差距。

## 六、坑（都踩过，别再踩）

1. `colab exec` 30 分钟超时；长任务在 VM 内 `start_new_session=True` 后台跑，轮询文件。
2. 用 base64 分块经 exec 拉权重时，`cat part*` 会按字典序排成 part0/part1/part10/part2…
   导致权重损坏；必须按数字序拼接并核对字节数。
3. `colab ssh` 的会话注册会残留，之后连接一律 429「another colab ssh is connected」。
4. 单环境高分是假象：PPO 第 1 轮 8101 99.5%，换到 8102 只有 75.2%（而 BC 在 8102 是 65.3%）。
   **任何结论至少要在 8101 不换位 + 8102 换位两个环境上同时看。**
5. 验证损失低 ≠ 实局好：FFN 版验证损失 1.43（最好），实局 70.9%（最差），且 buffer 席位尾段直接 0。
6. PPO 单轮样本太少会剧烈震荡：2 世界一轮的两路分别 99.5/75.2 与 82/60.4；4 世界一轮最差环境 82.3。
7. 数据契约：改 `rl/economy` 下的 `.py` 只影响 implementation hash，feature contract 未变时旧世界仍可用
   （`provenance.py` + `legacy_contracts.json`）；不要去动 `adapter.py`/`projects.py` 的观测语义，否则数据全废。

## 七、下一步建议（按优先级）

1. **把每轮样本量做上去**：`ppo_round --worlds 8` 并混地图/换位；ECS 上 rollout 便宜（2 秒/回合），
   真正的成本在 CPU 更新（约 40 分钟/万条）。目标是让最差环境稳定上升而不是抽签。
2. **多环境判据固化成脚本**：现在靠手工在 8101/8102 上跑 `scripts/econ_eval_env.py`，
   建议扩到 4–6 个环境（含 150/200/250 回合）并按最差环境选模。
3. **BC 起点太低（95.7%/65.3%）**：14 世界数据已备好但没在 GPU 上训过（Colab 挂了）。
   拿到 GPU（Kaggle/租机）后先训 14 世界 + 族头（FFN 可选，注意第 5 条反例），用双环境 S 判。
4. **不要去追单环境 150%**：当前 150% 只在个别席位出现过（buffer 席 158.9%），
   总 S 到 150% 需要每一档环境都抬起来，这仍是一条长路。
