## 权重身份纠正

Kaggle version 3/4 重复跑了第 3 轮，version 6/7 重复跑了第 5 轮；每对作业的
输入恢复包 SHA 相同，输出策略 SHA 不同。旧调度只根据轮次目录判断“已有评测”，
因此后一次权重覆盖原轮次后，其评测被错误跳过。上表第 3、5 轮只对应首次作业；
不能把这些数值贴到后一次权重上。

最新第 5 轮权重 `1e1356b0353d…` 已启动独立补测，第 3 轮后一次权重
`2f804e266bea…` 随后补测。旧摘要保留。现在按策略 SHA 判断评测是否匹配，
并复制不可变评测权重到 `models/<policy-sha>.pt`；不同权重使用不同评测目录。
GPU 运行期间也持续检查评测队列，不必等下一轮结束才补测。

已登记摘要见忽略目录 `archive/previews/ppo-continue-20261107/round5-results-review.json`；
原始结果在其 `evaluations/`，训练指标在 `live/round-*/candidate.json`。

## 实际训练结构

当前权重配置：160 维、2 层上下文编码、4 个注意力头、projects 动作模式、
动作族辅助头与共享编码器 critic，总参数 1,037,607。候选侧额外 FFN 未开启，
族头和 critic 使用首个 context token；不能把旧交接中的候选 FFN/池化候选说成
当前已使用。候选评分、动作族先验与可执行性软先验共同生成项目分布，仅屏蔽
padding，建设/征兵由网络选择，v11plus 军事负责实际扩张。

每轮 8 个新世界、150 回合、1 epoch；逻辑 batch128、micro8、lr3e-5、
自适应 KL。Actor 与 critic 共用编码器，价值梯度默认不 detach。AdamW 优化器
状态每轮重建，KL beta 每轮从 0.1 开始；critic 权重沿轮次保留。上述是源码事实，
尚未做同样本对照证明哪项导致泛化退步。

五轮平均 KL 依次 0.0374 / 0.0191 / 0.0207 / 0.0249 / 0.0204；clip 比例
22.2% / 18.2% / 15.8% / 17.7% / 17.8%。训练回报来自不同世界，不能把其变化
直接当成公平评测增益。
