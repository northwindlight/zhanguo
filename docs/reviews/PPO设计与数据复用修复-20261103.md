# PPO设计与数据复用修复（2026-11-03）

用户指出的五项问题成立。前一轮参数测量揭示了局部 KL 早停和数据兼容性设计缺陷；
仅测 batch32、或者再跑一夜，不足以解决这些问题。本轮先修实现、验证完整流程，
再做执行辅助权重对照。保持原奖励、无合法硬掩码、逐环境逐席位验收门槛及原始 BC 保护权重。

## 更新与 KL

原路径在固定 11248 条决策中仅处理 16 条，第 3 个 8 行批次触发整轮停止。
正常路径现在以微批 8 累积成有效批 128，再裁剪梯度和更新参数。
策略、价值、熵和 KL 按实际行数归一化；执行辅助按真实候选数归一化，
开局 BC 约束按符合开局条件的行数归一化，避免候选长短和尾批大小改变损失比例。

不再按微批 KL 硬停。用非负采样估计 `(ratio-1)-logratio` 加 KL 惩罚，初始系数 0.1；
每 8 个有效批累计约 1024 行的加权统计，与目标 0.03 比较后将系数加倍或减半。
最后不足窗口的部分也记录；系数限制在 0.0001–10，显式系数 0 则关闭该项。
这是跨更新窗口的自适应估计，不冒称每次更新后精确计算全数据 KL。
显式预算、截止时间和非有限损失/梯度仍会停止；日志区分这些情况与正常完成。
保留 `kl_mode='legacy'` 复现旧报告，不以新默认冒充旧默认等价。

测试覆盖高局部 KL 仍用完全部行，以及不同微批大小在同一有效批上的更新一致性。
更充分地更新仍可能让模型退步，不能拿覆盖率代替实际长局 S。

总 S 为 38154.266325，总 S / 成功项目数为 38.345996。
另记录成功项目所在期的 S 与无成功项目期的 S，避免将一整期消费归因于某次建造。
成功项目所在期的 S / 成功项目数为 26.572584；无成功项目期仍产生 11714.545356 的 S，

也不意味着其 gamma=1 的完整未来回报为零。实测 9096 条无效决策的完整未来回报全部非零，
其中 43 条因动作预算末尾承接结算，连即时 reward 也非零；证据 invalid-credit-audit.json。

新增 execution_coef=0.3、1.0 对照原 0.1；同起点、同 11248 条决策、同随机顺序，

此短预算仅作同剂量比较，生产路径不设置该上限。
另跑原默认辅助权重的完整一遍，实测全部长局数据是否被处理。

150 回合、不换位及换位。旧验证路径只做推理，没有克隆后训练的缓存碰撞。
这仍是两个选模环境，不能替代六环境加独立种子确认，任何候选均不自动晋级。

三组短预算更新已实际完成：每组 1024/11248 行、8 次有效批更新，均为显式预算停止，
没有 KL 停止。固定采样状态探针 128 行上的合法概率质量分别为 20.82%、21.47%、23.45%，
