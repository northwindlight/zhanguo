# 统一结算后的观战回归修复

原生终端局在完整结算造成国家灭亡后，会因刷新该国延迟回执而报错。此次修复同时补齐统一队列执行后缺失的观战呈现，并保证完整回合先落盘。

## 原因

旧观察器假定刷新回执时国家仍能建立玩家视图。建设、征兵和结束行动收尾改在所有国家行动后的统一边界执行后，回执可能一直排队到国祚结算之后；这时灭亡国家已不能调用 `player().observe()`。这是旧观察器假设被新的回执生命周期打破，不是模型额度或动态回合开关引起的错误。

同一处衔接还造成三个可见问题：自动回执触发国家“行动开始”标题，看起来像又轮到该国；实际开工回执和生成的军队列表被套用入队回执格式，最终退回原始字段；统一 `query` 的正文已按面板渲染，抬头却仍显示 `query panel=...`。

此外，宿主原来在刷新显示之后才保存完整回合。因此游戏结算已完成、仅显示失败时，磁盘仍停在上一个边界。

## 当前行为

- 国家灭亡后照常输出它已产生的回执，使用已有的展示标签，不再查询失效的玩家视图。
- 回合末队列、自动交易、外交收尾明确显示为“结算”，不启动第二次国家行动标题。行动开始时的持续军令仍归行动阶段。
- 入队回执保留“预付、等待执行”；实际开工、实际出兵分别显示“已开工”“已生成”，注明使用预付材料、本次不重复扣款。
- 查询抬头沿用被选面板的中文描述；手册显示具体标题。
- 只有 `host.cycle()` 完整成功后保存，保存先于观战刷新；行动或结算中途失败仍保留上一完整边界。

没有调整经济、军事、队列执行或胜负规则，也没有更改存档依赖契约。

## 验证

新增五项回归，覆盖真实领域灭国后的待刷新回执及读档、自动回执不重开行动标题、显示失败前完整回合已落盘、查询与手册中文抬头、实际开工与实际出兵成文。独立存档副本进一步验证灭国、显示、落盘与恢复，原始输入哈希不变。

固定回合常规离线检查共1105项，零失败、零错误，2项可选跳过；按本次范围排除并发行动、桌面并发及无关stock测试。API参考同步，29页站点构建和站内链接自检通过。新旧显示对照使用相同回执数据，显示操作前后游戏状态一致。
