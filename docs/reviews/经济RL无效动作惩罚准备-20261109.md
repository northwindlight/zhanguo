# 无效动作惩罚准备：默认关闭

用户要求给失败尝试负反馈，随后明确“现在不急，先加着，20回合之后再考虑上马”。
已实现选项，默认 0，不更新当前 Kaggle 运行时、不改当前基线奖励；20 轮检查后
只准备评审参数，不自动启用。

## 语义

- 入口 `ppo_cycle --invalid-action-penalty`，直接调用 `ppo_update` 同样支持。
- 训练回报 = 原始 ΔS/1000 − 系数 × 该步实际失败的项目次数；每个动作是一条
  决策，因此重复失败逐次扣，正常结束和成功项目不扣。
- 依据是 rollout 的 `executed=False`，不是合法性布尔值或预测；保持只屏蔽
  padding，不引入硬合法掩码，不扣游戏资源或修改实际消费账本。
- 在训练更新阶段浅拷贝 step、共用未改动的观测数组和行为 logp，再计算惩罚。
  原始轨迹保持 raw ΔS，便于对照、恢复和重算。启用时缺少动作/执行标签直接拒绝。
- 系数单位是归一化奖励；例如 0.001 对应每次失败扣相当于 1 个原始 S 单位的
  训练奖励。候选 0.001/0.003/0.01 仅为第 20 轮之后的待评审配置。
- checkpoint 另存 training_objective，更新指标另存原始奖励总和、惩罚总额、
  调整后总和、无效动作次数。原 reward 字段仍描述原始环境 S。
- 默认 0 不改原有 run settings；非零会加入不可变实验配置，禁止直接恢复到
  原零惩罚目录，须建立独立实验。正式验收始终是原始实际 S、教师 150%、逐席
  与尾段保护，不拿调整后的奖励分数替代经济成绩。

50 项相关测试通过，含正惩罚确实进入 PPO 回报、重复尝试逐次扣、结束不扣、
原始轨迹/观测/logp不变、默认与显式 0 优化结果逐位相同、负数/NaN/Inf 拒绝。
feature/teacher 契约与推理签名均仍为原 fc7f507e…/e8e612dc…/565098b3…；
原环境奖励和观测没有变化，历史数据与评测缓存不作废。

## 用户同时询问信息查询能力

当前经济网络没有查询动作。执行器在每次经济决策前固定调用玩家权限内的观察、
市场、建设/征兵规划和目录，提取为 96 维 token；成功项目后再次编码，未变局面
的重复失败可复用等价快照。并非一回合只看一次，也不是全图或全部原始资料。

输入主要包括资源/市场、电力与军需、已有及在建建筑、可建地点、项目公开成本
与条件、国家存续/威胁数量等摘要。网络动作是 finish/build/recruit；没有购报、
谍报或“继续查询”动作。军事仍由 v11plus 处理，所以它尚未学习自主信息获取策略。
