以下为已经核对 CLI 参数和开局合法性的入口模板，**尚未执行采集或训练**。GPU 机器上使用 CUDA；
CPU 环境应改 `--device cpu`，不要在未确认资源时照搬并发数。训练和验证按世界种子隔离，8101／8102
留作已知选模环境，不能当成新的未见确认集。

```bash

python3 -m rl.economy.collect --projects \
  --seeds 121 122 123 124 125 126 221 222 --sizes 20 24 28 \
  --turns 150 --out archive/previews/econ-v4/data

# 从新模型做 BC；逐 epoch 留档，按长局而不是分类 loss 单独选起点。
python3 -m rl.economy.train --projects --family-aux \
  --data archive/previews/econ-v4/data --valid-seeds 221 222 \
  --epochs 20 --save-every 1 --batch 8 --threads 2 --device cuda \
```

--invalid-action-penalty 0 --exec-prior-weight 0.5`，不加 `--legal-mask`。其中 0.5 是旧 PPO CLI

## 已有因果证据，避免重走的误判

完整报告：[建筑偏向因果实验](经济RL建筑偏向因果实验-20261113.md)，代码及报告提交 `2fc655c`。
这些结果对应 v3，不是 v4 的效果评估。

- R6 在 8102／24／换位的 n0 持续投资耗电设施，缺电后征兵受阻；固定第 80 期状态到 150 期，
  尾段均 S 原策略 5.19、单次补电 44.61、持续补电并保留资金 187.32、教师 97.78。
  世界有恢复路径；单次补电及换回 BC 都没有稳定解决后续失衡。补电控制仅为诊断，不可当作模型晋级。
- 原 v3 已有原始电力字段；本次是让供需关系显式化，不是首次让模型看到耗电量。新特征效果尚未测量。
- 实际旧链为 turn／MC／gamma=1；远期回报已经覆盖几十期后的消费，R9 奖励与正式 S 账平。
  不能将问题定为“finish 记账导致前面动作没奖励”。因果信用估计、critic 干扰、恢复状态覆盖与容量仍未定因。
- 固定后期状态及第 80 期仅改 n0 的去软先验消融均不改变决策，不能声称辅助头直接压制电厂。
  全局从开局去先验的收益变化来自不同演化路径，不能等同于单国直接修复。
- 正式项目可执行不等于经济合理。对合法但破坏配套的建设，无效动作惩罚没有直接作用。
  早期征兵也可能因完整项目融资不足而不可行，不能全部解释为模型拒绝征兵。
- 不能沿用旧二十轮链的“74% 废动作”解释新链；新链的剩余执行率主要是 finish，没有对应比例的失败动作。
