# 经济 RL 显式电力观测（2026-11-13）

用户要求：选择耗电建筑时明确电力缺口，缺电和供电足够各有标志，补电装置也明确标记。
本次只修改公开观测编码与相关验证，不改变游戏规则、奖励、正式可执行性、教师排序或模型架构。

## 字段与口径

使用原有 96 维中的空位 87—95。下表字段存在于全国状态行和每个候选动作中；全国状态行
等同于“不新增建筑”时的供需信息。建筑目录行单独补充耗电／发电两个标志。

| 列 | 字段 | 含义 |
| --- | --- | --- |
| 87 | `current_short` | 正式生产预估的缺电量大于 0 |
| 88 | `current_sufficient` | 正式生产预估的缺电量为 0，与上一项互补 |
| 89 | `consumes_power` | 此建设候选的 `energy_use > 0` |
| 90 | `provides_power` | 此建设候选的 `energy_output > 0` |
| 91 | `current_shortfall` | 正式预估缺电量，含燃料不足的影响 |
| 92 | `committed_capacity_gap` | 本国所有已完工及在建建筑的额定需求减额定发电容量 |
| 93 | `post_build_capacity_gap` | 上一项加上此建设的耗电量、减去此建设的发电容量 |
| 94 | `post_build_short` | 建成后的额定缺口大于 0 |
| 95 | `post_build_sufficient` | 建成后的额定缺口小于等于 0，与上一项互补 |

标志直接编码为 0/1，和正式可执行 token 相同，不使用对数缩放；三个数值字段仍使用
既有 `sign(x) * log1p(abs(x)) / 5`。数值缺口为正表示容量不足，为负表示有余量。
`finish`、征兵与原子交易候选不新增电力容量或建筑用电，所以其建成后缺口等于已有项目缺口，
耗电／发电标志均为 0；交易对燃料库存的影响不冒充建筑额定容量预测。

例如，已有和在建的额定需求为 13、容量为 8，缺口为 5：再建一座耗电 1 的兵营，
候选直接显示缺口 6、耗电标志 1、建成后容量不足标志 1；木电厂提供 2，显示缺口 3、
发电标志 1、仍然容量不足；油电厂提供 8，显示余量 3、发电标志 1、建成后容量足够。

## 当前供电与建成容量分开

当前供电标志使用正式 `econ.preview.energy.shortfall`，由引擎按已完工建筑、库存、采集、
发电顺序和燃料计算。当前没有用电需求也属于供电满足需求，不表示一定存在电厂。

建成后的字段是额定容量比较，假设本国现有在建项目及所选建筑都完成，且发电装置有燃料；
不是本期已经发出的电，也不是长期运营保证。在建实例包含在 `building_sites.instances`
中，只加一次，不重复叠加施工回执，不读取外国私有状态。

因此，可能同时出现“当前缺电=1”和“建成后容量足够=1”：电厂还在建，或已有电厂缺燃料。
模型可以据此区分装机不足与当前实际预估供电不足，已有原始发电量、需求和配方信息保留。

这些都是公开事实及其算术派生，不包含教师选择或收益评分。候选保持原样，不新增硬屏蔽、
自动补电规则或电力奖励；“不可执行”和“耗电但可开工”仍是两个不同概念。

## 兼容性与验证

观测版本升为 `economy-bc-4`，特征和项目指纹随之更新，完整 feature/teacher 契约也变化。
原 v3 和更早的 checkpoint、示范及 PPO 轨迹不能直接混用；即使张量仍为 96 维，也没有把
新列伪装成旧输入。未修改历史等价登记表，未迁移或覆盖旧权重与原始数据。

针对旧契约的测试同步改成：历史数据与其原契约仍兼容，与新契约必须拒绝；不再要求新观测

验证覆盖本国真实 API 观测的缺电、供电充足、恰好平衡、在建耗电设施、实际开工后的重新编码、

旧数据及权重拒绝、观测纯读取，以及既有教师／学习执行链。
