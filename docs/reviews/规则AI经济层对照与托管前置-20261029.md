# v13 / v11plus经济层对照与托管前置

2026-10-29，核对游戏源码`1d582e7`。用户反馈是“感觉v13稍低效、未严格测”，本次做源码审查、独立合成局复现和现有回归脚本对照，不修改AI策略或正式规则，不读取真实局，也不接入GUI托管。

## 主要判断

v13重写了经济决策，军事仍继承v11plus。它从当前报价下的回本排序，变成带市场压力场景、库存与现金缓冲的边际投资评分。投资更谨慎和整体效率更低不是同一个结论；应分别看扩产、产出、流动性、停电缺料和战局。

源码确认存在值得修正的地方：v13没有把工程院放入经济投资候选，v11plus的最终回本排序会丢掉木材资本估值；两版共享的旧合法性筛选没有对齐撤销后施工额度和预付队列。不能原样拿其中一版充当真人经济托管。

## 实际区别

| 决策 | v11plus | v13 | 对体验的影响／限制 |
| --- | --- | --- | --- |
| 投资排序 | 查询`building_economics`，按回本期为每格预选项目，再按预算建设 | 从公开配方计算投资前后净产出，预估未来价格，以压力场景下的边际收益／资本成本排序，每建一项重新评分 | v13考虑新增出口对原有投资的影响；其分数属于策略预估，不是正式收益保证 |
| 价格与竞争 | 主要依据当期买卖单价；装备厂出口收益打0.85折 | 公开市场库存与基准、整单试算、扣本国成交后的他人订单估计；观察衰减，并假设其他参与者跟随增产 | v13考虑集体压价风险，但压力假设也可能压低有价值项目的评分 |
| 偏好 | 固定参数 | balanced / integrated / merchant / buffer / liquid，开局选定后保存 | 前视24—48期，原料储备2—6期、现金缓冲20金加1—4期运营成本，不同偏好不能混成一种激进程度 |
| 采购 | 用单价×数量估预算；不够整套时可能先买部分材料；不先核市场库存 | `trade_quote`核整单库存和账户实际成本，优先保证完整配方；当期卖过的材料不买回 | v11plus可能浪费交易尝试或留下不能开工的半套材料；v13也不是原子批量采购，行动预算截断等情况仍需另行处理 |
| 运营与储备 | 已有当期工厂原料、木／油电厂燃料、建设和征兵材料预留 | 连同在建产能预留燃料；分批补库、运营现金留存、缺料时降为一期整套再降军需 | 不能说当前v11plus完全不管燃料；v13的更大储备会占用可投资资金 |
| 电厂 | 缺装机时优先木电，计划中的耗电项目也可能换成木电 | 比较木电／油电装机与持续燃料；装机恰好满用且还有合法用电候选时可先扩容 | v13更主动留供电空间，也可能提前花资本；两版仍以策略模型预测运行条件 |
| 工程院 | 建市政厅前有明确优先补工程院的分支，也会将其纳入经济估算 | `candidates()`只留资源输出、电力输出或厅金建筑，工程院被排除 | v13忽略长期建造折扣投资；发现结构缺口不等于证明工程院在每个地块都该先建 |
| 征兵 | 属于经济流程，按收入／补给门槛招步兵，独立安排兵营 | `operations → recruit → invest`，同样会招步兵并建兵营 | “只托管经济”不能直接调用任一整段经济回合，否则会替真人扩军 |

## 当前引擎的最小复现

使用新的native单国合成局，12×12、种子73，明确配置充足金币与木材。需要的建筑只在测试初始化中显式播种；决策比较走绑定玩家的公开目录和规划。生成脚本为[inspect_current.py](../../experiments/rule_market/inspect_current.py)。

1. **撤销施工后仍误判可建。** 正式开工再撤销，`space.order_remaining=0`，正式规划拒绝“每地每期一次”；两版共用`_legal`只检查当前施工回执，该回执已移出，结果仍为True。原引擎正确保留已用额度。
2. **待建预占容量未计入旧筛选。** 合成格18座已落成、2项待建，总占20/20；正式队列规划判满，`_legal`只看实例仍判断有位置。这是复用到人类手工队列场景时的真实适配缺口；两版正常自主经济当前不使用该预付队列，不能拿此例直接解释所有AI对局差异。
3. **工程院可建但未进入v13经济候选。** 正式规划和共享旧筛选均允许，`Planner.candidates()`却不包含它，确认排除发生在策略层。
4. **单价采购预算偏低。** 同一新账户依次只读试算买木材10／100／500单位，v11式预算21／210／1050金，正式整单报价22／216／1200金。报价读取不成交、不扣款。
5. **v11plus回本排序口径缺木材。** 平原农场实际20金15木，公开目录资本估值50金、净收益估值约1.425金／期，目录回本约35.09期；最终排序再乘`建造金币 / 目录资本`，变成约14.04期。公式中木材资本被约掉，会使含较多木材的项目看起来回本更快。这是排序数值，不是实际少扣材料，也不是一次实际投资回报测量。

两个版本的`_cost / _legal`都属于客户端复制的公开规则，最终执行仍由正式引擎裁决。迁移优先接现有`buildings.planning / sites / orders`及`army.planning`，不要再为托管重抄一层。价格预测可以是策略自己的，施工资格与实际扣款必须以正式API为准。

## 当前版本八国对照

方法与原[市场回归](../../experiments/rule_market/README.md)一致：native、24×24、八国，同种子分别全体v11plus／全体v13，种子73、20261023、42，各100期。屏蔽军事移动与攻击，保留正常经济、征兵、兵营、补给和完整正式结算，固定双方土地禀赋。v13抽签沿用脚本的`seed+i`；未强制所有偏好都出现。

三局平均期末建筑265 → 195.67，军队42.33 → 19.33，现金8284.33 → 23462.67。v11plus共2998次失败，均为买入：2991次市场库存不足、7次资源不足。v13无失败动作；累计停电1490 → 24，直接缺配方材料310 → 0。各局v13均只有8次初始市政厅无电厂的停电，之后没有新增停电记录。

这组支持“v13期末扩产与扩军规模更小、运营更少受阻、现金留存更多”，不支持直接宣称其总体经济效率更差或更好。v13三局都没有工程院，符合候选过滤的源码发现；工程院缺失是否造成净收益损失，还需保持其他决策不变的消融实验。

不能从这组实验外推普遍胜率或完整经济效率：它没有领土扩张，不是混合策略市场，也没有统一库存的终局清算、固定价格GDP／实际净产出回报测量。建筑数量不是资本回报，现金更多也可能来自少投资；累计停电／缺料是“建筑×期”，受建筑数量和种类影响。前视／储备偏好的单独贡献需要后续消融对照，不把全部差异归给市场预测或工程院一个因素。

2026-10-23的[历史结果](../../experiments/rule_market/results/README.md)用于说明设计动机，不能冒充本轮新引擎复测；历史固定土地中v13同样更少建筑、更多现金，而一个完整战斗种子中v13建筑更多，说明不能只用一类场景归纳强弱。

## 经济托管与编组的前置

- 经济托管先复用正式规划、整单报价与经济策略中的运营／投资部分，提供可解释建议、预算与保留资源，再接明确开启的自动执行。范围可以按国家并排除指定地块；不要把完整`RuleClient.play()`交给玩家席位。
- 自动建设尊重当前已用施工次数、预付材料与预占位、手工排程、全国电网和玩家观察。每次实际提交后刷新计划；不因演出等待阻断后续手工输入，也不重发同一个项目。
- 需要自动补料或出售时明确权限，与已有自动交易核对保留量和预算；不默认借款，不替玩家征兵、移动、外交或结束回合。
- 优先比较统一规划后的当前价ROI、带工程院折扣的多步投资及v13市场压力评分；保留运营偿付约束，不能靠重新允许无库存采购来提高“建设速度”。
- 军队编组先保存本国单位编号和名称，恢复选择与现有批量军令相连；不合并实体／HP／行动额度。现有AI自动目标分组和地图小人编队并不等于人类持久自定义编组。

这两项的界面与迭代范围已记入[UX计划](../plans/GUI体验打磨-20261029.md)，本轮未实现托管或编组功能。
