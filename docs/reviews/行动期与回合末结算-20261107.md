# 行动期与回合末结算（2026-11-07）

改动性质：回合结构与规则口径，不是界面改动。为未来动态回合打基础：**行动期只做提交与预付，世界清算集中在回合末**。已通过 1100 项离线回归（17 项跳过）。

## 口径

| 阶段 | 内容 |
| --- | --- |
| 行动期（玩家行动时） | 移动、进攻、撤退、拆建、市场买卖、外交提交等玩家动作即时执行；资源消费随动作即时扣除或预付（queue_build/queue_recruit 入队预付、市场金币与商品即时到账）。直接 `build`／`recruit` 保留旧的即时开工、出兵，不与队列混用 |
| 回合末（所有玩家结束行动后） | 自动交易与外交拒签按既有轮换次序统一执行；预付的**建设队列**统一开工、**征兵队列**统一出兵（每地块同时只开工一项，其余排到以后各期末）；市场按本期净成交清算库存（可为负）；随后按原 18 阶段统一结算（生产、补给、战斗、占领、外交、报表等） |

明确**没有**改动：军队移动/进攻仍按原逻辑在行动期即时生效；战斗仍在结算阶段裁决；18 阶段顺序、存档格式与依赖校验不变。

## 具体改动

- 市场：成交当场转移双方账户资源，但市场自己的库存在结算阶段才按本期净成交变更，允许为负；报价与自动交易不再受当期库存限制（自动交易只受资金/限价约束），负库存可存档、可定价，缺口由后续回补与价格反映。
- 建设：`queue_build` 只预付并占位，开工统一在回合末（每地块同时只开一项，其余排到以后各期末）；取消未开工条目仍全额退回。直接 `build` 保留原行为，提交即开工、结算后落成（本批未改）。
- 征兵：`queue_recruit` 只预付并占位，出兵统一在回合末，按设施额度分期生成；待征民兵仍预占全国编制，取消只退未生成部分。直接 `recruit` 同样保留原行为。
- 引擎：新增 `Session.before_settlement()` 扩展点（行动期全部结束、`resolve_turn()` 之前调用），native 在此推进预付队列；不新增、不重排结算阶段。
- 规则正文、游戏说明书、市场 README、API 参考页同步；生产/征兵队列与地图读模型测试按新口径更新。

## 未做（留待后续）

- 动态回合的调度层（和平并行行动、战争有序行动、并行等待）仍按[动态回合实现研究](../design/动态回合实现研究-20261107.md)分阶段推进，本轮只落语义边界。
- 拆除（demolish）仍是行动期即时生效；若后续要求"所有世界效果都在期末"，需要单独一轮评估（会影响当期生产与战果时序）。
- 自动交易与外交拒签已从 `end_turn` 提交触发改为回合末按轮换次序统一执行（与谁先结束行动无关）；GUI 侧的自动交易演出提示尚未重接。
