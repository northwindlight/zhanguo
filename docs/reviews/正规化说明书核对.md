# 正规化规则册核对

基准：`正规化@b4b9b8d`；裁决输入：《正规化口径定稿》。本文件为工程跟踪，不规定游戏规则。规则正文为《游戏说明书》；已定规则不因当前实现缺失而降为建议。

## 已定规则与实现差异

| 条款 | 规则要求 | 实现工作 |
|---|---|---|
| 第四、三十五、六十六条 | 国家间外交提交后，回合末按阶段生效；请求编号稳定且不得重复执行 | 建立持久化外交队列；统一正式入口与兼容别名；同步回执、查询、恢复逻辑 |
| 第六条 | 至第N回合的休战包含N | `mp.py.active_truce` 等现用 `turn >= until` 过期；`mp_ai.py` 展示同样为排除端点。统一判断及创建截止值，保证参数表的持续回合数 |
| 第十八、二十一条 | 新兵本轮不能主动进攻；原地进攻免跨格额度 | 当前新兵只设置 `moved_turn`，原地进攻跳过该字段检查。分别保存出生回合及行动额度 |
| 第二十三、二十五条 | 多军整批校验，失败不发生部分移动；盲探处罚结果明确 | 核验所有错误路径；回执分别给出位置变化、额度变化与结果状态 |
| 第十七、二十四、六十五条 | 位置、归属、交战、额度和待撤离分开；事实与记忆分开 | 重写 LLM 面板及回执；以后 GUI 复用同一状态接口 |
| 第五十三、五十四条 | 发起后下一回合投票，世界结算首阶段统一计票，再按议案内容分阶段执行；无提前通过、无盟主否决 | 修改 `_new_vote`、`cast_vote`、`_expire_votes`；去除即时结束与即时否决；同步工具 schema 及面板 |
| 第五十八条 | 同初价、无插入交易的同方向拆单与整单总额一致 | `market_walk` 在限幅后取首尾均价；跨越地板/天花板时不满足分段价格积分。零头累积不能单独保证此不变量 |
| 第四十八条 | 馈赠送达失败须留结果并通知，双方亡国也不得静默 | 保存可供终局读取的失败记录；完成下列物资处置裁决后实现 |

实体条约、个人和约冻结与恢复、无损伤兵输出、撤退减伤例外、报表仅公告本国、亡国者终局入席等已纳入正文；后续改变须修改条文。

计票位置已按用户补充定案：结算最前计票，按议案内容决定执行位置。现有宣战、议和、缔约、入盟在本轮外交阶段执行；通过与生效为不同状态。

## 定稿仍未提供完整裁决的事项

以下事项不得从现代码擅自反推为最终规则。补齐后直接修订对应条文，并增加相应语义验收。

| 缺口 | 必须裁决的问题 |
|---|---|
| 同阶段外交冲突 | 多个请求按何键排序？同对象入盟/宣战/议和冲突如何处理？提交时和生效时分别验证什么？费用及付款是否预留，取消是否退费？ |
| R16 投料与电网 | 原料不足时工厂按何顺序分配？行动阶段征召核验本轮计算的电网还是上一轮缓存？ |
| R20 双方亡国的馈赠 | 原主也亡国时，退回物资如何记账，或是否销毁；手续费是否退回？原定稿要求择一，未指定选项 |
| 撤退及遣返并列路径 | 多个合法替代邻格、多个等距归国路径的稳定排序键是什么？ |
| 战线合并 | 第四十条的匹配条件、主导者继承、多个既有战线同时匹配及同盟两侧冲突的处理，需要形成完整判定表 |
| 中断与恢复 | 稳定存档已规定结算后写入；外交阶段中断重试的原子边界、部分效果与费用回滚规则仍需确定 |
| 空转与测评 | 正文规定空转的统计口径；检测后的警告、惩罚或仅记录是否为测评规则，需单独定案 |
