## 工程验证

C# `dotnet build`：零警告、零错误。
`tests/desktop-layout/Checks.csproj` 直接编译实际布局类，已检查：

- 同输入同种子重现，输入数组重排后相同，改变视觉种子后有差异。
- 所有样板设施/人物数量与输入一致，设施不压山、不碰撞树木或其他设施。
- 固定同一坐标的木资源 0→25→55→100 时，树数增加，已有树不被重新随机移动。
- 只有含金地区生成露金岩；跨地块的高度场在水平和垂直边缘连续。

已将布局检查加入现有桌面 CI。项目虚拟环境 `.venv/bin/python -m unittest discover -s tests -q`
运行 853 项离线回归，全部通过（约 127 秒）。

## 性能记录的边界

环境：树莓派 Linux ARM64，Godot 4.7.2 .NET，Compatibility，
Mesa llvmpipe 软件渲染，窗口 1440×900，Xvfb。
首批自动截图过程仅采到约 1.17 秒、17 帧，帧间隔中位数约 54.2 ms，P95 约 144.8 ms，
进程工作集从约 363 MiB 到 438 MiB。包含首帧、字体与纹理准备及截图，不作为稳定帧率或内存泄漏结论。
原始短时记录见 [gui-stage-a-first-metrics.json](gui-stage-a-first-metrics.json)。

样板目前在输入变化时绘制，尚未进行持续镜头运动、30–60 秒录屏、长时间内存及实际 GPU 对照。
Windows/macOS 本批未验收。上述缺口保留在阶段 A 后续工作中。
