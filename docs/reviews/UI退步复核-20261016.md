# UI 退步复核：旧版设计与当前呈现

日期：2026-10-16。对照 `legacy` 的 `2e0160dfdcc72309d692c3af20bfb566bc4bfe20` 与当前未提交工作区。首次复核只读源码并运行合成验证；后续用户授权全部修复、停局并续档，修复验收见文末。

旧版注释包含用户逐步设计的依据，复核不能只检查工具是否存在。必须同时检查：信息供谁使用、何时展示、如何排序、哪些条件才触发、为什么曾否决其他做法。坐标统一 0-based、隐藏 LLM 的 player_state、按需查询和回合间播报等最新要求优先，不按旧版机械回滚。

本轮覆盖当前发行版的 27 个只读领域工具，核对专用回执覆盖情况；重点对照地图、军事、领土、外交、银行、国策和历史信息。带参数及非空场景用临时合成世界或按公开契约构造的回执检查；不是全部业务状态的穷举验收。以下保留 14 项问题的修复前证据，现已完成本地修复；之前 logistics 与 reachable 的显示修复不计入。

## 应优先处理的信息错误或丢失

### U1：国祚警报的触发语义改变

- 旧版依据：`legacy:mp_ai.py:_fmt_hall_alert`（2127 行起）的长注释明确记录，必须是市政厅无人守卫，且可见敌军按引擎真实路径本回合能抵达；不是简单要求每座厅驻军。
- 当前入口：[LLMUI.dashboard](../../mods/ui/llm.py)，`capital_warning` 使用棋盘距离与兵种速度比较，没有核对敌军新兵/已行动、真实阻挡，也不排除有驻军的市政厅。
- 合成复现：给公开观察加入一支 `born_turn=0, moved_turn=0` 的邻近敌国步兵，第 0 回合仍进入 `capital_warning`。该军当期不能异地出征。
- 影响：提示的紧迫程度失真。修复需要发行版提供过滤过的真实威胁事实，不能让 UI 穿透世界，也不宜再复制一套移动裁决。

### U2：城堡等级被折叠成座数

- 旧版依据：`_fmt_tile`、`_fmt_land` 分别显示 `L等级`、防御收益和国土城堡等级。
- 当前入口：[ReceiptPresentation.receipt_body / land](../../mods/ui/receipts.py)：按建筑实例的 kind 计数，忽略该实例的 `level`。
- 合成复现：公开单格回执中一个 `level=3` 的已落成城堡，输出 `建筑：城堡×1`。
- 进一步核实：正常建造是每级一个实例，完整三级城堡通常会显示“城堡×3”，不能把单个 level=3 的构造例当成正常三级档的存储方式。修复用真实 seed 三级城堡验收，统一显示为“城堡 L3”，实际防御仍按原领域规则。
- 影响：看不出一级与三级要塞的差别。单格详情和建筑站点都应保留等级；不是要求修改实际防御计算。

### U3：银行展示吞掉已购买的报表

- 旧版依据：`_fmt_report`、`_report_of` 与银行面板提供有日期的报表访问路径。
- 当前入口：[ReceiptPresentation.receipt_body](../../mods/ui/receipts.py) 的 bank 分支只显示现金、额度和欠款，完全忽略公开回执中的 `purchases`。LLM system 却指示“已购报表用 bank”。
- 合成复现：在 bank 的公开数据中放入一份含 GDP 数值的购买记录，终端输出与未购报表完全相同。
- 边界：LLM 工具回执仍是结构化数据，能拿到 purchases；这里确认的是观察者显示丢失，不能说底层报表或模型权限丢失。

### U4：军队行动状态在观察者列表中丢失

- 旧版依据：`_fmt_armies` 显示可行动、已移动、交战中，并附移动力、可及格数。
- 当前入口：[ReceiptPresentation.army_line](../../mods/ui/receipts.py) 只展示交战和待撤退，没有使用 `born_turn/moved_turn` 表达新兵、已行动或可行动。
- 合成复现：实际新兵公开数据含 `born_turn=0,moved_turn=0`，军队查询只显示兵种、位置、兵力，看起来与能出征的军队一样。
- 边界：模型的自动 dashboard 有行动状态；不是所有客户端都缺状态。

## 阅读和检索能力退步

### U5：单国文字地图只剩地形，图形失败时回退也同样贫乏

- 旧版依据：`_fmt_map/_fmt_mil_map/_fmt_atlas` 提供坐标轴、归属、城堡、市政厅、军队、图例与重叠说明。
- 当前入口：[player_map](../../mods/ui/views.py) 只画 `. f ^ M ~` 地形字符；`map 秦` 和 LLM 图片失败后的 fallback 都调用它。
- 合成复现：文字地图只有五行类似 `.ffff` 的字符，无坐标轴、国名、军队和建筑。无法直接把格子对应到行动坐标。
- 另有未接线问题：[player_atlas](../../mods/ui/views.py) 已实现按势力分段的逐格语义地图，但 `LLMUI.atlas_text` 没有实际调用方，`view` 也没用它。不能把“有这个函数”当作已恢复。
- 边界：PNG/SVG 仍有归属、建筑和兵种图标，不应笼统说全部地图坏了。

### U6：七个只读查询仍走通用字段打印

- 当前入口：[ReceiptPresentation.receipt_body](../../mods/ui/receipts.py) 的最终 fallback、[ConsoleUI.format](../../mods/ui/console.py)。七项为 `view/nations/nation/government/terrain_catalog/frontier/dispatches`。
- 合成例：`view` 的 21 格视野展开成 126 行；`frontier` 输出 `visible_unowned/reachable/frontier`；地形目录输出 `defense/build_penalty/cavalry_cost`；在途信件输出 `fee/submitted/arrive`。
- 旧版对应 `_fmt_atlas/_fmt_countries/_fmt_plan/_fmt_intel_hint` 等专用展示，先交代含义再列内容，而不是把公共数据结构翻一半直接展开。
- `government` 观察者回执仍可展开全部 summaries；模型专用回执已有剔除，不应混淆二者。

### U7：军队列表没有稳定的本国优先和分类

- 旧版依据：`_fmt_armies` 主体是本国逐军列表；`_fmt_threats` 另列他国，明确过滤不主动进攻的野人。
- 当前 army 将所有可见军队混排，不做本国优先；终端统一只显示前 10 行。
- 合成复现：先生成 13 支可见外军，再生成本国军，army 的完整回执含本国军，但终端 preview 中本国军完全不出现。
- 准确边界：初始虚拟野人附加在实体军队之后，不是每次都先列野人。问题是没有优先与分组保证，以及对静态野人逐支重复展开。

### U8：国土列表丢掉核心、建设资格和驻军线索

- 旧版依据：`_fmt_land` 每格同时列核心标记、资源、建筑与在建、剩余位置、本回合可建/已下单、驻军。
- 当前 land 主要显示地名地形和资源；building_sites 补了建筑，但两处都不表达核心与本期已下单状态。
- 当前 land 的公开数据仍有 `tile.core`；建筑公开状态已有施工/下单相关信息，展示没有利用。不是要求 UI 访问世界对象。
- 影响：玩家要在几个查询间拼接原来一行就能看明白的事实，也容易重复尝试在同格下单。

### U9：分页结果冒充国土总数

- 旧版依据：`_fmt_land` 明示筛选命中总数、原国土、本页范围、offset 和续页入口。
- 合成复现：实际有 5 块地，调用 `land(offset=1,limit=1)`，标题却是 `国土 1 块`。
- 当前 land 返回切片数组，UI 也没有区分“本次列出”与“国土总数”；至少应改为准确的本页描述。如需完整分页统计，由查询契约提供总数，不能凭截断数组猜。

### U10：兵种目录丢掉已返回的地形移动代价

- 旧版依据：`_fmt_armies` 的 `_move_brief` 与地图提示直接解释不同地形的行军限制。
- 当前 unit_catalog 的公共数据含 `move_cost`，专用回执却只显示移动力，不显示代价表。
- 合成复现：骑兵原始目录明确含森林/山地代价 2，观察者目录只写 `移动2`。
- 影响：目录查到了仍难解释为何平原能走两格、树林走不了两格。地形目录单独查询又落入 U6 的原始字段打印。

### U11：外交对象列表失去条约方向信息

- 旧版依据：`_fmt_countries` 显示同盟实体、共同防御、本实体保障它、它保障本实体、接壤、信件数量与可见军队。
- 当前 countries 主要显示中立/同盟/交战、接壤、有信、求和代表，缺少保障方向与共同防御标签；其回执也忽略已有 `entity/chief`。
- 根因横跨公开事实与 UI：当前 countries 事实本身就没有直接带条约标签，不能只增加几个翻译键就算恢复。可基于公开 diplomacy 整合，仍须服从玩家权限。

### U12：历史情报主动查询缺少“最新优先”的阅读顺序

- 旧版依据：`_fmt_mail` 对信件倒序展示，新信优先；常驻只展开最新几封，旧信摘要与全文入口明确。
- 当前 intel 按 messages 原到达顺序拼接全部内容，再统一截断前 10 行。只要早期长情报占满屏幕，最新信件就在截断部分。
- 边界：新消息自动播报已按到达集合去重修好；本项只指主动查询历史的排序、分类和摘要。不能恢复跨回合重复自动播报。

### U13：历史报表失去专用趋势表

- 旧版依据：`_fmt_report_trend` 对 `all=true` 一行一期、对齐指标，并与单份明细区分。
- 当前 reports 对所有结果使用同一种每期三行的平铺，缺少趋势表；多期历史同样从最早项开始被终端截断。
- 本项是阅读能力退步，不主张恢复旧版“GDP−军费=财政收入”的口径，也不改现行经济核算与自动注入策略。

### U14：领土得失警报未继承旧版的结构化摘要与优先级

- 旧版依据：`_fmt_alerts` 注释记录用户要求“领土变更、被侵略是大事”；只汇总自上次行动以来的真实得失，标地名、核心和市政厅，不重复播报泛泛“敌军站在我地上”。
- 当前占领事件只有普通 `occupation` 文本与 position，缺少旧归属、新归属、核心及市政厅等结构化摘要；LLM 重大事件优先集合也没有包含 occupation。
- 影响：失地可能与普通动作一起被近讯十条/预算窗口挤掉，且难明确突出“丢的是国祚”。最新修好的联盟重大事件保留不能覆盖这个缺口。
- 恢复方向：在现有回合间事件与模型当期近讯中保留重要领土变更事实及摘要，服从当前只播报新增动态的要求；不要重新把上回合历史塞进中途表格。

## 本轮结论与验证边界

根因集中在三处：旧版专用展示未接回；公共事实存在但专用展示主动省掉；原来以真实裁决为依据的提示被 UI 内近似计算替换。前两类通常能局部修复，后一类要先补清公开事实接口，避免 UI 再复制规则。

此次实际运行的合成验证包括：只读工具覆盖与输出规模、单国文字地图、新兵状态、外军挤掉本国军、三级城堡、银行购买记录隐藏、新兵敌军误触国祚警报、国土分页标题、骑兵地形代价。其余顺序/字段/优先级结论由当前调用链和旧版注释确认，没有声称已在真实长局逐项复现。

建议先处理 U1/U2/U3/U4/U14，再统一地图与土地展示，最后补齐其余查询的专用格式。旧注释中的设计约束应转成可审阅的说明与行为验收，不能只以工具返回成功或测试总数判断 UI 迁移完成。

## 议会收尾

保持原两步设计：先审上版国策及其后轨迹，再提供新版；否决保留本次审核对话，通过清空，下一次不回灌更早国策。审核输入的快照与差分剔除残留旧国策、小结和前次审核正文，区间内实际行动、否决后解释与独立原始档案保留。行为验收覆盖连续否决后通过、下一次第一步仅有最新上版且看不到新草案、否决上下文及解释续接、存取一致性。

从第一次请求提示 [x/10] 轮，第 6 轮起每轮催办；完整输入、思考、正文、工具往返、用量与裁决增量写 journal，终端保留进度。提示词要求沿用已确认事实、定点查询、及时提交按钮。未调整实际模型、思考强度或输出上限，未另做付费性能对照；不以离线通过宣称实际耗时已经下降。
