# 玩家侧 UX 对比：旧版真上下文 vs 模块版真上下文

日期：2026-10-17。

## 方法

两边都**从存档里直接抽原文**，不重新渲染：

| | 来源 | 抽取路径 |
|---|---|---|
| 旧版 | `research/game-records/eight-nations-158/state.json` | `turn_memory['秦']` 第 158 回合 |
| 模块版 | `archive/games/qwen-8nations-20261016-185839/session.json` | `clients['scenario:qin'].state.replay` 第 26 回合 |

存档保存的是**当时真正发给模型的消息**，所以这比任何重渲染都可信。

## 量化对比

| 指标 | 旧版 | 模块版（重做前） | 重做后 |
|---|---|---|---|
| 一回合消息数 | **9** | **21** | 约 9–12（批间消息已删） |
| 开局载荷 | 13,635 字符 | 12,663 字符 | — |
| 批间消息 | 1 条 / 116 字符 | **3 条** / 434・979・483 字符 | **0 条** |
| 单条工具回执 | 41–43 字符 | 180–1,056 字符 | 17–40 字符 |

## 逐项判断

### 1. 开局：体量相当，可读性不是一个物种

旧版每行都是「事实 + 后果」，模型不需要自带规则知识：

```
电网: 产8/需5 正常（不足则补给厂/装备厂/兵营/市政厅全部停摆）
国祚: 市政厅 2 座（★失去全部即亡国，余土沦为无主之地）
```

模块版是嵌套 JSON：数字在，**后果不在**。这不是长度问题，是把判断写没写出来的问题。

### 2. 回执：模块版每条都在付「信封税」

旧版一条 41 字符说完：

```
售出 木头×18（中间价 2.09→2.07，含价差均价 1.97，实收 36），余4
```

模块版连失败都包在信封里，成功的还漏内部浮点：

```json
{"api":1,"actor":"scenario:qin","action":"attack","period":26,"ok":false,
 "status":"rejected","code":"domain_rejected","message":"超出本回合移动范围…","data":null}
```

`api/actor/period/ok/status/code` 六个字段对模型零信息量，每条都要付。

### 3. 批间：模块版每回合塞 3 条 JSON Patch

旧版 116 字符答完「我现在还剩多少」；模块版要模型在没有解释器的前提下脑内合并补丁。
**重做后已整条删除**（模型本来就带着对话历史与回执）。

### 4. 回合轮次是前三项的结果

同样的一个回合，模块版用掉 2.3 倍消息 → 压缩触发频率翻倍 → 状态丢失也翻倍。

### 5. 错误信息：内容追平，形式仍贵

旧版：`赵·民一军 本回合已移动过（每军每回合只动一次），不能再冲；换一支「可行动」的军，或等结算`
模块版内容接近，但被 `code:"domain_rejected"` 与 `data:null` 包着——读得懂，多花五倍字。

### 6. 地图：旧版给了逐军可及

```
秦·民九军(#9) | 80HP | (4,12) 丽坡 | 可行动 | 动1格/回合（任何地形）｜本回合可及 8 格
```

模块版只有聚合的「本期军队可及 8 格」，**没有逐军的**。

## 旧版赢在哪（三条）

1. **每条事实都带后果**：停摆、亡国、不返还、不能遣散——判断写在数据旁边。
2. **一回合只发 9 条消息**：同样的信息量，模块版用了 21 条。
3. **回执是句子，不是信封**。

## 重做后已补回的

- 回执改中文散文；失败回执带做法与实测值。
- 取消批间消息与结构化差分。
- 外交 16 个动作从「已提交，等待外交结算」改为逐个说明对象、金额与下一步。
- 移动 / 遣散 / 出击 / 间谍 / 信件恢复旧版信息量（未占地、不退料、每回合结算可撤退、能拿回哪些情报、字数）。
- 总纲补【上一回合结算】【经济报表】【信箱与情报的来源条数】。

## 仍缺的（事实层，UI 补不了）

| 缺口 | 原因 |
|---|---|
| 逐军「本回合可及 N 格」 | `PlayerState` 里没有逐军可达，只有聚合 `frontier` |
| 「上一回合结算」的逐资源产出（`粮食+17 木头+22`） | `econ.latest_turn` 只给折金总额 |
| 市场均衡价与大单试算 | 快照只有现价/买/卖/基准库存 |
| 央行授信口径（GDP×5、利率） | 快照只有余额，没有 GDP 与利率 |

以上都需要改事实接口，而 `PlayerState` 与 `Interfaces` 都在 `dependency_manifest` 里——
**动它们就会让旧档读不进来**，属于阶段二（工具面/事实层）的活，动手前要先停局。

# 第二轮抽样：八国 46 回合、432 次工具调用

第一轮只看一国一回合。第二轮把两边存档的所有回合都拆开量：

- 模块版：`archive/games/qwen-8nations-20261016-185839/session.json`（8 国，各 4–7 回合，共 46 回合）
- 旧版：`research/game-records/eight-nations-158/state.json`（秦 7 回合 + 魏韩燕齐楚各 4 回合，共 27 回合）

## 1. 记忆层：模块版的归档在重播同一份长期记忆

| | 旧版 | 模块版 |
|---|---|---|
| 每回合小结长度 | 平均 **406–1,021 字**（秦 406 / 魏 1,021） | 平均 **81–134 字**（赵 81 / 魏 134） |
| 开局带的历史 | 最近 **10 条逐回合小结**（秦第 158 回合 = 7,130 字） | **全部压缩块**（每块都是当时那份长期记忆的全文） |
| 压缩块数量 | 19–75 块，只喂给压缩调用，不进状态 | 1–13 块，**全部进状态** |

模块版的块是「压缩当时的 long_memory 快照」，下一次压缩会整体取代它，但归档把
**每一块都重播**。楚是极端样本：

```
12 块，合计 27,491 字；其中只有 long_memory + 未被覆盖的小结是新增内容
去重后 = 3,391 字 ⇒ 24,100 字（88%）是同一份长期记忆的旧副本
```

楚第 26 回合的开局状态因此是 **35,357 字**（魏 20,462、秦 12,663）。还有两个直接证据：
楚有两块**逐字相同**，四块开头相同；齐三块开头相同，魏两块开头相同。

**本轮已修**（`clients/context.py` + `clients/llm.py`）：成功压缩写下的块标记
`memory=true`，归档只保留当前 `long_memory`；压缩失败写下的逐期小结块标 `memory=false`，
照常重播；旧档没有标记的块按快照处理（现网存档里没有一块是失败形态，已逐块扫过）。
8 国归档合计 **58,298 → 19,417 字（−67%）**。

## 2. 工具回执：两类查询吃掉 45% 的工具字数

432 次调用，用户侧 711,397 字，工具侧 336,892 字（每回合工具 7,323 字、用户侧 15,465 字；
旧版每回合工具 2,431 字）。

| 动作 | 次数 | 平均字数 | 最大 | 合计 |
|---|---:|---:|---:|---:|
| building_economics | 30 | 2,676 | 13,610 | 80,280 |
| news | 4 | **17,941** | 22,913 | 71,766 |
| sell | 105 | 376 | 383 | 39,567 |
| buy | 58 | 372 | 379 | 21,631 |
| tile | 57 | 361 | 685 | 20,612 |
| end_turn | 46 | 302 | 419 | 13,905 |
| player_rules | 11 | 1,216 | 1,944 | 13,378 |
| building_sites | 4 | 2,765 | 2,956 | 11,061 |

`building_economics` + `news` 34 次调用（7.9%）占工具字数 45%。

- **news**：工具描述是「最近 10 周期」，一次返回 **75–85 条**事件、1.4–2.3 万字。
  旧版 `_fmt_news` 是 `events_for(limit=10)`——**十条**，1,874 字。
  **本轮已修**：回执只展开最新 12 条，其余收成一行「另有 N 条更早近讯（第a—b回合）」
  并指路 `player_events(cursor)` 与存档旁归档；16,777 字 → 约 2,600 字。
- **building_economics**：模型逐个建筑问（补给厂/装备厂/石油厂），单条 1,048 字里
  全是 `209.9389330294519`、`17.17881324734057` 这种内部浮点。旧版韩 t156 是
  **一张 1,169 字的对照表**：所有建筑一行一个，带「回本≈N 回合」，末尾还有一行为
  该国军队规模定制的「**你的口径**：8 支军队每回合吃 8 补给……别只盯外销价」。
  重做后的散文渲染已经去掉浮点和 `{known,unpriced,total,complete}` 信封，但
  「一次给全 + 按你的口径算」还没有。

## 3. 轮次：模块版每回合多 1.3 轮

| | 旧版 | 模块版 |
|---|---|---|
| 每回合模型轮次（带工具调用的 assistant 消息） | 3.5（最多 6） | **4.8**（最多 15） |
| 每回合工具消息 | 8.6 | 9.4（最多 35） |

燕第 25 回合 53 条消息、赵第 24 回合 44 条，都是查询/试错堆出来的。
赵 t24 的 6 次 `script_*` 最典型：模型想读 `building_sites`，写了 3 版脚本、
`script_check` 一次、`script_run` 两次，第一次报 `inputs must be a JSON object`，
第二次 `Computation budget exceeded`（12,001 步，卡在 `rows.sort`），
还把本回合唯一的脚本额度烧掉了。它的思考原文：

> "each country has only one script execution budget per turn, and a failed run
> consumed it."

这不是模型笨，是工具面让它以为需要写脚本。

## 4. 失败回执：11/432（2.5%），内容参差

```
attack  → 部队是新兵、已行动或正在交战；请核对 army 状态，交战守军用 retreat。   ← 带做法，好
attack  → 超出本回合移动范围，或沿途有阻挡；请查询 reachable 并分回合行军          ← 带做法，好
sell    → 资源不足  data{required:2, available:1}                              ← 可算，但没说下一步
borrow  → 现有金币不足支付借款手续费；须先筹措手续费。                            ← 可以
script_run → "inputs must be a JSON object"                                    ← 英文，没给正确形状
script_run → "Computation budget exceeded"（含 line/column/source）             ← 英文
```

重做后的专用渲染器已经覆盖前四条；`script_run` 的英文错误仍直出（脚本是实验模块）。

## 5. 压缩输入在抄工具调用

赵的第一个归档块，正文开头是：

```
Tool calls:
[{"id": "call_5a558933a5e945ebbbfe6402", "type": "function", "function": {"name": "tile", ...
```

`clients/llm.py::_compact` 把**真实请求前缀**（含 assistant 的 `tool_calls` 与 tool 的
JSON 回执）直接喂给压缩模型，于是它偶尔照着抄成「Tool calls: …」。旧版
`_compact_input` 喂的是「逐回合小结 + 行动记录（剥思考）」，不喂工具信封。
8 国里出现 1 次，属于会污染长期记忆的偶发缺陷；本轮只记录，未改压缩输入。

## 6. 逐项对照（同一种决策，两边的原话）

| 场景 | 旧版 | 模块版（存档原文） |
|---|---|---|
| 卖出 | `售出 木头×18（中间价 2.09→2.07，含价差均价 1.97，实收 36），余4` | 377 字 JSON，含 `exact_total`、`carry_before` 内部浮点 |
| 出击成功 | `秦·民二十二军… 冲入 (3,2) 与野人交战，之后每回合结算一轮；可 retreat 撤出` | 184 字 JSON，`"message":"Occupied"`（英文）+ 7 个布尔字段 |
| 遣散 | `已遣散 2 支：…——**不返还**任何粮/装备/黄金；本回合起即不再吃补给…番号不回收` | 305 字 JSON，`"message":"Disbanded without refund"`（英文） |
| 地块 | `(10,8) 沙漠｜无主（有野人守军，atk 打赢才能占）｜地形：防御 -10%、建设惩罚 +40%｜…｜本回合有军队够得着：是` | 361 字 JSON，含 `born_turn:null`、`moved_turn:-1`、`retreat_to:null` |
| 近讯 | 10 条，1,874 字 | 75 条，16,777 字 |
| 建筑收益 | 一张 1,169 字对照表 + 你的口径 | 单建筑 1,048 字 JSON，30 次调用 |

注：旧版也不是没有冗余——它的【近讯】会把工具参数重播一遍
（`秦 ◇ sell good=木头 qty=18 → 售出 木头×18（…）`）。但它把「参数」和「结果」
压在一行里，模块版是整包 JSON。

## 7. 记忆质量：小结变薄是上游

旧版小结平均 406–1,021 字，模块版 81–134 字。两边提示词都写「一句话」（旧版
`SUMMARY_MIN_CHARS`，模块版 `SummaryMin = 4`），差别在模型：旧局是 deepseek 系，
模块局是 Qwen。压缩的原料就是这些小结——**小结薄，长期记忆必然薄**。
这一条不是 UI 能修的，属于「用什么模型跑长局」的选择。
