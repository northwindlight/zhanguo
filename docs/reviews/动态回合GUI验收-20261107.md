# 动态回合 GUI 验收（2026-11-07）

性质：GUI 侧的离线验收脚本更新与**手动验收清单**。规则口径见[行动期与回合末结算](行动期与回合末结算-20261107.md)与[并发行动期](并发行动期-20261107.md)；本篇只记录"玩家在窗口里能看到什么、脚本怎样核对"。

## 本轮改动

1. **嵌入确认框的合成点击在窗口未前台时失效**：`ConfirmationDialog` 等嵌入子窗口的按钮，合成鼠标事件只会到达控件的 `GuiInput`，不触发 `BaseButton` 的按下/单击（Godot 4.7.2 / Windows）。真机手动点击不受影响，但离线脚本会卡在第一个确认框。`PointerClick` 现在先 `GrabFocus` + `WindowMoveToForeground` 再对嵌入窗口注入点击。
2. **验收脚本按旧口径断言**：`--human-review-output` 仍假设"入队即开工"，把队列占用本期施工额度、待建 1 条、空间显示 1 项施工中当成预期。已改为新口径：队列入队只预付、不占当期额度、待建可多条、空间显示 0 施工 + N 待建。
3. **新增两条 GUI 覆盖**：
   - 队列征兵：提交后行动期**不出兵**，回执说明"待生成"，取消未生成部分全额退回；随后切回直接征兵继续原流程。
   - 队列开工：两条待建城堡在回合末只开工一条并在本期结算落成，后一条继续排队；本格本期施工状态同步更新。
4. **减少偶发点击丢失**：在选择地块、点征兵前先等 `HumanIdle`，避免演出未结束时的点击被忽略（此前复跑曾因此误报"未产生两处实际驻军"）。

口径澄清：**直接 `build`／`recruit` 仍保留旧的即时开工、出兵**（旧路径，规则 AI 与兼容调用都在用）；只有 `queue_build`／`queue_recruit` 走"入队预付、回合末统一开工/出兵"。手动验收时先确认面板处于"生产队列"模式（默认开启）。

## 自动验收

```bash
# 仓库根目录（Windows：python 换成 .venv\Scripts\python.exe）
python desktop.py --human-review-output archive/previews/human-dynamic-turn-20261107 --log-file archive/previews/human-dynamic-turn-20261107.log
```

脚本用真实指针事件走完：主菜单两步建局 → 八国自由局真人席位 → 地图工具/指南 → 市场买卖与排队 → 外交写信 → 建设与地形报价 → 结束回合与生产演出 → 拆除撤销 → 队列建设/征兵 → 银行 → 军令与野人战斗 → 总览筛选 → 四种窗口尺寸 → 保存排队与退出选择。

结果判定：日志出现 `HUMAN_GUI_OK <path>`，并生成 `<path>.json`；`queue_turn_end_start`、`queue_recruit_prepay_only`、`pending_full_refund`、`production_queue` 等标记为 `true`。截图与 JSON 在 `archive/previews/`（不进版本库）。

本机 Windows 11 / Intel Iris Xe / OpenGL Compatibility 实跑结果（全程约 14 分钟）：

- `HUMAN_GUI_OK`，无异常日志；第 4 回合结束，31 次真人动作、35 个行动批次、4 个结算批次。
- `queue_turn_end_start`、`queue_recruit_prepay_only`、`production_queue`、`pending_full_refund`、`garrison_visible_without_scroll` 全部 `true`。
- 新增截图：`*-recruit*.png`（队列征兵回执）、`*-production-cancel.png`（未开工全退）、`*-queue-started.png`（回合末只开工一条）。

注：队列开工放在四种窗口尺寸的布局验收**之后**再结束回合——新开工会改变地块建筑与驻军，提前结束会让后续布局截图对不上当时的局面。

## 手动验收清单

先 `python desktop.py` 启动（默认 Compatibility 渲染），在"玩家模式"里选自由列国、1 位真人 + 至少 1 个规则 AI，地图取小一些以便两三回合看全流程。

| 操作 | 预期 |
| --- | --- |
| 建设面板（生产队列开启）点建筑 | 回执"已排入待建队列 · 预付材料"；地块**不出现**施工中；本格本期施工额度仍在（其他建筑图标不变暗）；全国生产面板出现该条目、显示排队位置 |
| 全国生产面板取消未开工条目 | 全额退回预付材料（金币/木材数值复原），条目消失；已开工条目只能按 50% 拆除 |
| 关闭生产队列后直接点建筑 | 回执"已动工"、立即出现施工中（旧路径，属预期） |
| 征兵面板（生产队列开启）点兵种 | 回执"待生成 N 支"；**不出兵**、军队总览数量不变；取消后全额退回、数量仍不变 |
| 结束回合（待建条目 ≥1） | 结算阶段该条目开工并落成（本格出现建筑），同格后续条目仍排在队列；下一期本格"本期已施工"为真 |
| 市场买入/卖出 | 点下立即扣/加金币与商品（左上资源行即时变化）；市场自己的库存**不在成交瞬间变**，回合末按净成交结算，可为负 |
| 市场自动交易 | 结束行动时**不**立即成交；回合末按既有轮换次序成交，市场面板/回执显示成交结果；"结束回合"回执只说等待统一结算 |
| 外交未处理提议 | 结束行动时按轮换次序在回合末统一拒绝；结束行动只标记本国行动结束 |
| 移动/进攻/撤退 | 仍是行动期即时执行，与改动前一致；战斗在结算阶段裁决 |
| 默认配置 | `planning_workers` 不填或为 1：AI 仍按轮换次序串行行动，窗口表现与之前一致 |

负库存只影响市场报价与后续回补，不改变玩家库存下限；GUI 的"期望库存/参考库存"读的是正式市场数据，不应拿玩家库存顶替。
