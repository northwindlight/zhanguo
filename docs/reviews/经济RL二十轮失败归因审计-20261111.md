# 经济 RL 二十轮失败归因审计

对象：[经济RL二十轮综合报告-20261111](经济RL二十轮综合报告-20261111.md)。本审计只读现有权重、报告、优化日志与保留轨迹，**没有启动任何训练，也没有改动奖励、网络、验收或远端实验**。所有数字都可以在 Pi 上用 `scripts/econ_failure_audit.py` 复算（见第 12 节）。

结论先行：**这二十轮不是"学了但没学会"，而是"几乎没有产生有方向的参数更新"**。20 轮、8,237 次 AdamW 更新、1,053,116 条样本之后，策略相对 BC 起点的位移与"同样大小的随机步"完全无法区分（观测 5.14，随机游走期望 4.81）；同时链上唯一真正卡住成绩的机制——贪心时选中不可执行项目、把整个回合打空——从第 1 轮到第 20 轮**没有改善，反而略有恶化**。

## 3. A：参数根本没有朝某个方向走

### 3.1 位移与随机游走无法区分

以去掉 critic 的 1,011,686 个参数为向量：

| 量 | 值 |
| --- | ---: |
| ‖BC15‖（参数向量 L2） | 54.6 |
| ‖R20−BC15‖ | **5.14**（相对 9.4%） |
| 20 步各自 ‖Δ‖² 求和再开方（随机游走期望） | **4.81** |
| 观测 / 期望 | **1.07** |

也就是说：**20 轮累积的参数位移，正好等于把 20 个互不相关的随机步叠加起来会长成的距离**。如果 PPO 在朝一个方向学，这个比值会显著大于 1；现在它几乎是 1。

相邻两步位移的余弦：R1→R2 与 BC15→R1 为 +0.166，此后稳定在 −0.05 至 −0.23（19 个中 **16 个为负**），中位数 **−0.14**。这不是"收敛"（收敛应当步长趋于 0），而是**每一步都在部分抵消上一步**的有界随机游走。

到 BC15 的距离本身也在饱和：R1 2.91 → R8 4.38 → R20 5.14，最后 12 轮只增加 0.76，每轮约 0.04。

### 3.2 行为确实变了 13%，但方向是错的

把第 20 轮每个回合的**首个决策状态**抽成 192 个固定状态（8 世界 × 4 国 × 每 5 回合），逐个 checkpoint 做前向：

| checkpoint | argmax 合法率 | argmax 族（finish/build/recruit） | 策略熵 | 合法候选概率质量 | 与 BC15 同解 |
| --- | ---: | --- | ---: | ---: | ---: |
| BC15（起点） | **66.7%** | 34 / 39 / 119 | 1.58 | 0.651 | 100% |
| R1 | 66.7% | 33 / 37 / 122 | 1.59 | 0.649 | 94.8% |
| R4 | 64.6% | 26 / 38 / 128 | 1.86 | 0.613 | 88.5% |
| R8 | **60.4%** | 17 / 37 / 138 | 1.89 | 0.599 | 87.0% |
| R10 | 61.5% | 18 / 35 / 139 | 1.81 | 0.610 | 85.9% |
| R13 | 62.0% | 20 / 36 / 136 | 1.93 | 0.615 | 87.0% |
| R20 | **60.9%** | **17 / 35 / 140** | 1.88 | 0.620 | **85.9%** |

21 份权重全算过（192 状态 × 21 次前向）。注意族分布的变化方向：**建设从 39 次降到 35 次（−10%），征兵从 119 次升到 140 次（+18%），finish 从 34 次掉到 17 次**。argmax 合法率的最高点是第 2 轮（68.2%），之后单调下滑到 60%—62% 的平台。

三点：

1. 贪心 argmax 与 BC15 的一致率从 100% 掉到 ~87% 后**不再变化**（R5 之后始终 86%—88%）——策略在 4 轮内走到某个点就停住了。
2. 停住的方向是**更不合法**：合法率 66.7% → 60.9%（第 8—9 轮最低 60.4%），合法候选上的概率质量 0.651 → 0.620。
3. 策略熵在上升（1.58 → 1.88，第 14 轮峰值 1.98），argmax 变得更不可靠。这与"熵系数 0.001 与策略项 0.004—0.010 同量级"一致：熵奖励在噪声梯度里持续生效，策略被推平。

**这一条直接解释了为什么贪心部署会把一半回合打空，而且越训越糟。**

## 4. B：策略梯度项是零均值噪声

对 20 轮 8,237 次更新逐条统计 `updates.jsonl`：

| 量 | 第 1 轮 | 第 10 轮 | 第 20 轮 | 全链范围 |
| --- | ---: | ---: | ---: | ---: |
| 更新次数 | 728 | 471 | 288 | 249—728 |
| `policy` 项均值 | +0.0062 | +0.0080 | +0.0039 | +0.0039—+0.0106 |
| `policy` 项标准差 | 0.145 | 0.101 | 0.093 | 0.083—0.145 |
| `policy` < 0 的比例 | 49% | 49% | 49% | **43%—51%** |
| 梯度范数中位数 | 3.31 | 3.37 | 3.46 | 3.00—4.23 |
| 触发裁剪（>0.5）比例 | 100% | 100% | 100% | **100%** |
| `value` 项均值 | 0.585 | 0.123 | 0.081 | 0.067—0.585 |
| KL β 触底（1e-4）窗口比例 | 33% | 83% | 75% | 68%—85% |

**`policy` < 0 的比例是 43%—51%**：这个东西的符号在掷硬币。它是 `-A·ρ` 的批次均值，符号 50/50 说明**这批样本里优势的加权平均几乎为 0**——即"这批动作比平均水平好还是差"没有稳定答案。

按单轮算：288 次更新的均值标准误 = 0.093/√288 = **0.0055**，大于均值 **0.0039**。也就是说，**一轮 PPO 的"改进方向"在统计上不可与零区分**。8,237 次更新堆起来也仍然是这个结构，因为每一轮都换了新世界、新行为策略。

补充两条与"裁剪"有关的事实，避免误读：

- 100% 的更新梯度范数都超过 `max_grad_norm=0.5`（中位数是它的 6—8 倍），个别批次达到 151（第 1 轮）、70（第 10 轮）、55.6（第 8 轮）——batch 间的原始梯度尺度跨了两个数量级。在 AdamW 下，梯度被全局等比缩放**不改变步长**（一阶矩与二阶矩同比例缩放），所以这条裁剪既不限制也不保护；它只是说明梯度本身的尺度极不稳定。裁剪真正的效果只是"名义上安全"，不是任何一个问题的原因。
- 真正限制总位移的是 `lr=3e-5` 与"每轮只有 249—728 次更新"。BC 用的是 3e-4、17.7k 次更新（21,239 行 × 20 epoch / batch24）。**PPO 的更新次数只有 BC 的 47%，学习率只有 BC 的 1/10，而这 9.4% 的位移里还没有方向。**

## 5. C：信用分配在回合内断裂

### 5.1 同一回合的所有决策共享同一个 return

`rollout` 只在每个回合末把这一回合的 ΔS 加到该国家**当回合最后一条决策**上（`online.py:198`），`monte_carlo` 再从后往前累加。因此对同一 (国家, 回合) 内的所有决策：

```
return(第 i 条决策) = Σ_{t' ≥ 当前回合} ΔS_{t'}
```

**与 i 无关**。实测：把所有步骤按 (stream, period) 分组，组内 return 方差为 0，用组均值预测 return 的 R² = **1.000**。

后果是：一个回合里"选错导致失败"的决策和"选对成功建设"的决策拿到**完全相同的信用**。第 20 轮 4,800 个国家-回合里，平均每个回合 7.67 条决策（中位数 3；597 个回合只有 1 条，1,196 个正好 2 条，405 个 ≥20 条）。

### 5.2 74% 的样本是同一观测的重复

对每条决策的 `context+candidates` 做哈希，与同一国家上一条决策比较：

| 量 | 第 20 轮 |
| --- | ---: |
| 与上一步观测完全相同的比例 | **74.29%**（27,364 / 36,832） |
| 这些重复步里动作与上一步不同的比例 | 72.3% |
| 每回合决策数 | 均值 7.67 / 中位 3 |

也就是说：PPO 的 36,832 条样本里只有约 9,500 条是"新观测"，其余是同一个状态被反复采样，每次抽一个不同的动作，**共享同一个 return**。这等价于在同一个状态上做"多臂老虎机"，但老虎机的收益对所有臂都相同。

### 5.3 优势里只有 30% 是决策差异

把归一化优势 `A=(R−V)/std` 做方差分解（第 20 轮）：

| 成分 | 占 Var(A) |
| --- | ---: |
| 国家-局身份（32 条轨迹的常数偏移） | **51.2%** |
| 再加"回合序号线性趋势" | 累计 **69.7%** |
| 剩余（同一局内、去趋势后的差异） | **30.3%** |

另外：`Var(回合均值)` 占 return 总方差的 **71.3%**，`Var(轨迹均值)` 占 **27.8%**。

换句话说：**梯度里一半以上的"好坏"是在说"这一局/这个国家整体富不富"，而不是"这一步选得对不对"**。而一局富不富由地图、席位偏好、其他 AI 席位决定，不是策略能控的。

报告第 7.4 节说"价值头干扰共享表示"。本审计看到的是更前面的问题：**价值头已经很努力了**（R²=0.815；离线可得上限——同时知道局身份与回合号——是 0.887），剩下的 21% 里还有一半是"这一局是谁"这种策略不可控的信息。

### 5.4 优势对"这一回合有没有干成事"几乎不敏感

| 分组 | 平均归一化优势 |
| --- | ---: |
| 执行成功的决策 | +0.081 |
| 执行失败的决策（无效果） | −0.005 |
| finish | −0.051 |
| 回合内有成功 vs 无成功（按回合平均） | 相关系数 **0.041** |

差 0.086σ、相关 0.04——**"干成了"与"没干成"在梯度里的差别基本为零**；而 74% 的决策是"没干成"。

## 6. D：74% 的决策是废动作，而且训练与部署的后果不同

### 6.1 成功与否 = 编码时的 `legal` 标志

第 20 轮：

| 量 | 值 |
| --- | ---: |
| `executed==False` 且 `legal[action]==True` 的步数 | **0** |
| `executed==False` 且 `legal[action]==False` 的步数 | 27,421 |
| 采样时选中合法候选的比例 | **25.6%** |
| 候选里合法的比例（全部步） | 4.62% 均值 / 0.19% 中位 |
| 候选里合法的比例（回合首步） | 12.8%（80.6 / 628） |

**执行结果完全由"这一步选的项目当时能不能被正式资助"决定**——`executed` 和 `legal` 是一一对应的。所以这 74% 的失败不是"运气不好"，是**模型在选一个它自己能算出来的不可行项目**。

### 6.2 贪心部署的后果被放大

`LearnedProjects.run_economy` 里有一条 `collapse_noop_retries`：贪心选中不可执行项目时，**把剩余预算一次性记成失败并结束整个回合**。所以部署语义是：

> 一个回合里，先做若干成功项目，**一旦某次 argmax 指向不可执行项目，这一回合就到此为止**。

教师评测缓存（`archive/previews/econ-handoff-20261107/teachers/`）里，两个筛选环境的 v13plus 席位：

| | 被拒回执（`failures`） | 回合 150 建筑数 |
| --- | ---: | ---: |
| 教师 8101 n1/n3/n5/n7 | **0 / 0 / 0 / 0** | 139 / 131 / 181 / 178 |
| 教师 8102 n0/n2/n4/n6 | **0 / 0 / 0 / 0** | 167 / 98 / 220 / 136 |
| 学生 R20（贪心） | **7,138** | **26.6** |
| 学生 1—20 轮（贪心） | 6,723—8,423 | — |

（教师的 `truncated` 不在教师报告里：`snapshot` 用 `getattr(client,'truncated',0)`，而 v13plus 规则客户端没有这个计数器——所以教师侧**能证明的是"零被拒回执"，不能证明"零触顶"**。学生侧两个数都有：74.4 个回合触顶、每个触顶回合 96 次失败。）

学生每个触顶回合 96 次失败 × 74.4 个回合 ≈ 7,142，与 `evaluation_seats.csv` 的 `failures`（7,138）完全对上——**失败几乎全部发生在"整回合被一次错误选择打空"的那 74 个回合里**。这个比例从第 1 轮（70.1）到第 20 轮（74.4）没有改善，第 9 轮甚至到 87.9。

### 6.3 训练语义与部署语义不一致

`OnlineClient.run_economy`（训练）在失败且世界未变时，**复用缓存分布继续采样下一条决策**（`reuse_noop`）。`LearnedProjects.run_economy`（部署）在同样情况下**直接结束回合**。

> 训练里"选了个不可行的项目"是免费的：换个动作再来一次，最多浪费一条样本。
> 部署里"选了个不可行的项目"是灾难性的：整回合的剩余 96 次预算全部作废。

这就是 `truncated` 在训练里从 19.2 掉到 1—2，而在部署里始终 70—88 的原因——**策略优化的是"失败可以重来"的目标，被验收的却是"失败即结束"的目标**。报告 §6.2 把这个现象描述成"贪心放大了排序问题"，但没有指出两边语义根本不同。

### 6.4 采样策略与贪心策略差距有 3.7 倍

同一套 150 回合、同一套席位：

| 策略 | 回合 150 建筑数 | 回合 150 军队 | 每回合 S |
| --- | ---: | ---: | ---: |
| 教师（v13plus） | 156 | 34 | 51.8 |
| 学生·采样（训练轨迹，R20） | **99** | 16.7 | 37.8 |
| 学生·贪心（评测） | **27** | 10.0 | 45.0 |

学生用采样跑出来的经济是贪心部署的 3.7 倍，但每回合 S 反而更低（37.8 vs 45.0）——这既说明**训练在优化采样分布、验收看的是 argmax，两者不是同一个策略**，也再次说明 S 不随经济规模走（见第 7 节）。

## 7. E：奖励口径 S 对建设几乎不给梯度

### 7.1 S 不含建设

`online.py:79` `S_CATEGORIES=('recruit','military','administration')`；建设属于固定资本形成，单列不计入。所以：

- 成功征兵 → 同回合就体现在 S（相关 **+0.74**）；
- 成功建设 → 同回合对 S 的影响是**负**的（花钱、且不产生 S）。

第 20 轮回合级相关性（去国家均值、去回合趋势后）：

| 动作 | 与 ΔS_t | 与 ΔS_{t+1..t+5} |
| --- | ---: | ---: |
| #成功建设 | **−0.209** | **−0.127** |
| #成功征兵 | **+0.741** | −0.091 |
| #全部成功 | +0.136 | −0.156 |

这是相关性不是因果：建设出现在"有钱、有余力"的回合，本身要花钱，所以同期为负。但**从梯度看，这正是策略收到的东西**：招兵立刻加分，建设立刻扣分。而且建设对未来 5 回合的 S 也没有可测出的正相关。

### 7.2 结果就是"只招兵不建设"

| | 教师演示标签 | BC15 argmax | R20 argmax | 学生 R20 贪心实局 |
| --- | ---: | ---: | ---: | ---: |
| build 占比 | 43.9% | 20.3% | **8.9%** | — |
| 回合 150 建筑数 | 156 | — | — | **26.6** |

报告 §4 已经指出 BC 建设准确率只有 13.59%。本审计补充的是：**S 的口径让这个问题几乎无法通过 PPO 修好**——建设带来的收益（产能→材料→更多兵）要在几十回合后才落到 S 上，而回合级优势的噪声是 1.12（raw），一栋建筑对未来的边际 S 贡献远小于这个尺度。

## 8. F：BC 起点在"建设"上就是坏的

用 14 个 BC 世界的 .npz 直接统计教师的标签分布（28,693 行、每行中位 666 个候选）：

| 族 | 行数 | 占比 |
| --- | ---: | ---: |
| build | 12,583 | **43.85%** |
| finish | 11,400 | 39.73% |
| recruit | 4,710 | 16.42% |

BC 第 15 epoch（PPO 起点）：overall 55.91%、**build 12.19%**、recruit 93.51%、finish 90.54%、族头 79.2%、exec BCE 0.0944。

到了第 20 epoch，build 也只到 13.59%。**这个模型从来没有学会"该建哪个"。**

而在第 20 轮的固定状态集上，BC15 的 argmax 族分布是 finish 17.7% / build 20.3% / **recruit 62.0%**——把 44% 的建设样本压成 20%，把 16% 的征兵样本放大成 62%。

> 起点策略 = "多招兵、少建设、不太结束"。
> PPO 的奖励 = "招兵加分、建设扣分"。
> 两个错误方向一致，于是互相加固。

这就是"经济越训越小、S 却还在 90% 附近"的原因：S 只数军需和行政，不数产能。

## 9. 其余七条机制性问题（次级但真实）

### 9.1 KL 控制器事实上关闭

`kl_beta` 每轮从 0.1 开始，只要窗口 KL < target/1.5 = 0.02 就减半，12 个窗口后就到 1e-4 下限。第 2—20 轮 **68%—85% 的窗口 β=1e-4**（第 1 轮 33%，第 6 轮 0%）。第 20 轮 288 次更新里 β 的中位数是 1e-4，KL 惩罚项对损失的贡献约 3e-5。**"目标 KL 0.03"这个约束在整条链上基本不存在。**

### 9.2 观测里没有回合号

`adapter.observation()` 只读 `facts`；`player.observe()` 返回的 `period` 从未进入特征（`grep` 只在 `profile.cash_periods` 命中）。回合 0 和回合 149 的观测在结构上无法区分，只能靠"军队/建筑/库存"这些代理变量反推。

实测：只用回合号预测 return 的离线 R² = 0.648；知道"局身份+回合号"的上限是 0.887；当前 critic 是 0.815。**虽然没有回合号，critic 仍靠状态代理吃到了大部分时间信息**——所以这不是主因，但它让价值估计多背了 7—10 个百分点的无关方差。

### 9.3 值头主导共享编码器

第 20 轮 60 个探针：值项在共享编码器上的梯度范数是策略项的 **1.2 倍**，其中 27/59 与策略方向夹角余弦 < 0；值损失占总损失 **74.9%**（第 10 轮 80.7%）。共享编码器主要在服务"预测这一局最后能花多少"，而不是"这一步该选哪个"。

### 9.4 AdamW 每轮重建

`ppo_update` 每次调用都 `AdamW(model.parameters())`，一阶/二阶矩清零。每轮只有 249—728 次更新，而 β2=0.999 的有效窗口是 1000 步：**前几十次更新的二阶矩只由少数几个 batch 决定**（偏置校正只消掉尺度偏差，消不掉方差），等价于每轮开头几十步退回 sign-SGD 式的大步。报告 §7.3 提到这个事实，但没有把它和"位移饱和"联系起来。

### 9.5 锚点固定为 BC15，且只覆盖前 12 回合

`anchor.pt` 在 run 开始时从初始 checkpoint 复制一次，之后再没更新；anchor 损失只对 `period<12` 的候选算 KL。第 20 轮锚点 KL 均值 0.0715、最大 0.49，加权后约 0.0036，**与策略项（0.0039）同量级**。开局 12 回合的策略被一根固定的绳子拴着，而 150 回合的其余 138 回合完全自由。

### 9.6 链上没有任何模型选择

`ppo_cycle` 的注释写得很清楚："Rejected candidates may continue the experimental chain"，`save_model(..., accepted=False)`。所以 20 轮就是裸 PPO 轨迹；报告选出的"第 10 轮最好"是 20 次噪声抽样的最大值，不是选择出来的模型。

评测噪声本身也够大：两个环境 S 比值的相关系数只有 **0.289**，单环境标准差 0.09—0.10；S 与"离 BC15 的权重位移"相关系数 0.19，与轮次 0.12。**成绩波动基本由种子决定，与权重变化无关。**

### 9.7 "最差尾段 0.00"不是亡国

7 个席位出现 `tail_ratio=0`。逐个查：它们**都还活着**（land 27—72，多于教师的 41—60），建筑 35—48 栋，金币 983—3,281，**但 army=0**。S 只数军需与行政，军队归零 → 尾段 S 恒为 0。

这件事本身是结论的一部分：**学生丢掉的是"军队"，不是"土地"**（学生平均 land 52.99 > 教师 50.75）。而军队来自征兵 → 兵营 → 建设，又回到第 7、8 节。

## 11. 若要继续：按证据强弱的最小对照

以下都不是本审计执行的，只是按"能不能直接检验上表某一行"排序。每一条都必须先固定验收口径（逐席、尾段、开局），再跑。

1. **把部署语义搬进训练**（对应 §6.3，最高优先）。让训练里的"失败即结束回合"与部署一致，或者反过来让部署在失败后继续尝试。这一步不改奖励、不改网络，只消除同一个策略在两套语义下的错配。
2. **可执行性硬掩码 / 强先验**（对应 §6.1）。候选集合法率中位 0.19%，软先验上限只有 0.5·log(σ) ≈ −3.45；把它做成掩码或把系数放到 2—4，先在固定 192 状态上看 argmax 合法率能不能从 60% 抬到 >90%。这是唯一能在**不做长局**的情况下先验证的开关。
3. **每个回合只保留"状态变化前"的决策做 PPO**（对应 §5.2）。74% 的重复样本不贡献新信息，只是把同一个 return 复制 7 份；去掉它们等价于把有效样本翻 4 倍、把噪声里的重复权重去掉。
4. **优势改成回合内可分的形式**（对应 §5.1/§5.3）。例如按"该决策是否改变了世界/是否成功"给一个可验证的分解项，或者用下一状态的价值做差分（`r_t + V(s_{t+1}) − V(s_t)`），而不是整回合一个常数。
5. **给观测加回合号/剩余回合**（对应 §9.2），成本极低，同时也能让 critic 少背无关方差。
6. **重做 BC 的 build 分类**（对应 §8）。候选集是 96—2000 个 (site, kind)；现在的 12% 说明模型没有学到"该建在哪、建什么"。可以先用分族（先选族、再选候选）或按地块分解，把建设准确率抬到 40% 以上再进 PPO。
7. **选择/晋级机制**（对应 §9.6）。20 轮里没有一次"因为更好才保留"；至少要做到"新候选在固定环境不比现役差才进入下一轮"，否则链上永远是随机游走。

不建议直接做的：加宽/加深网络、打开 `cand_ffn`、把 lr 调大。前两者在"梯度无方向"的前提下测不出东西；后者会让随机游走走得更快。

## 13. 一句话

**这条链没有"训歪"，而是"没训动"：20 轮 8,237 次更新之后，策略相对 BC 起点的位移与随机步无法区分（5.14 vs 4.81），而唯一决定成绩的那个开关——贪心时不要选不可执行的项目——从 66.7% 掉到 60.9%，于是部署时一半回合被一次错误选择打空，学生只建出教师 17% 的建筑。要动的话，先动回合语义与可执行性，再谈惩罚、容量与网络结构。**
