# GUI / UX 体验打磨

2026-10-29，承接v0.7.0后的试玩反馈。状态：**问题梳理与布局原型，交互方案需要试玩验证**。本轮没有修改Godot运行界面或发布新包。

用户最新判断：基础功能已经接近齐全，整体信息过多、不直观，需要时间和更多反馈来打磨。以下意见作为问题线索和候选方案，不能直接当成全部定案。

## 本轮反馈

| 玩家遇到的问题 | 要解决的体验 | 待验证方案 |
| --- | --- | --- |
| 不知道这个地块本回合修过东西没有 | 点选后立即看见状态 | 固定地块摘要显示本期施工额度、已落成、施工中、待建；地图／列表同步状态标记 |
| 所有东西都写“加入队列”，队列被滥用 | 分清立即做、安排以后做、正在等界面提交 | 普通建造／征募有明确主操作，生产排程有显式独立入口与列表；不再用“入队”概括所有动作 |
| 连续路径改目的地不顺，得先手动取消 | 改主意只需重新指定目标 | 普通目的地操作替换剩余路线，Shift明确追加；不要求先点停止或重画。具体鼠标映射要在原型中对比 |
| 建筑没有清楚地作为地块属性展示 | 看地块就知道有什么、在做什么 | 建筑图标、数量、落成／施工状态进入地块属性，不埋在驻军和说明文字后面 |
| 军队页找不到兵营／军屯所在格 | 军队管理与征募地点连在一起 | 军队工作区提供“部队／征募地点”，列本国兵营与军屯格子，点后定位并进入正式征募 |
| 按钮应该缩成图标 | 减少大片等权重文字按钮 | 导航与工具图标化，配中文悬浮、状态角标和清楚的选中反馈；付款、停止、结束回合等关键含义仍清晰可读 |

## 已核对的现状

基于源码`f210878`及v0.7.0 Windows验收工件，未读取真实对局。

- `Desktop.Human.cs`把建设、军队、市场、银行、外交、联盟、邮箱、国家、结束回合共9项同级铺在底栏。
- 左侧完整资源账目、回合大横幅、右侧总览、操作抽屉分别占位。相同国家／回合信息在多个区域重复出现。
- `RenderHumanTile`先展示驻军，再展示建筑大卡和容量，“在这里建设”入口在后面；建筑与本期施工状态没有组成固定摘要。
- `_productionQueueMode=true`使建造／征募默认显示“加入队列”。界面同时存在尚未扣款的输入等待、已预付的生产队列和跨期军令，玩家需要自行区分。
- 建造页在候选格之前放置地块切换、四个标签、地形说明、队列开关、施工项和队列入口；长悬停又展开整套费用步骤与规则。信息虽然齐全，优先级不清楚。
- 军队总览当前按部队列驻地；没有独立的全国征募地点视图。已有的“有征兵设施”地块筛选不能替代从军队页直接办事。
- `HumanMapOrder`中Shift默认追加，替换持续路线需要先使用“重画已选路线”。当期普通动作成功时会清旧路线，但远目标重新指定仍需要更直接的交互。

**证据边界：**验收初始截图主动调用了`Fit()`，不能据此认定正常开局镜头就是那么小；代码已有`FocusNation`。`human-march-outliner`截图发生在关抽屉的动画过程中，不能据一帧认定稳定态存在永久遮挡。后续要同时检查稳定状态和切换过程，而不是把所有截图都当作默认玩家画面。

## 整体方向

### 地图、对象、动作相连

地图继续铺满窗口。固定资源区先给库存与必要预警；完整收支、来源和报表按需展开。换国／换期横幅短暂播报，回到操作时收起，当前回合和操控国家保留在紧凑状态区。

右侧组织成**一个工作区**：地块、军队、征募地点、生产排程在同一区域切换，返回入口固定。避免列表和详情各自弹出一列互相遮挡。跨驻地选军摘要与清空／查看完整名单始终可达；换页不丢勾选。

导航用有含义的图标和角标，第一次使用、悬浮或键盘聚焦时给中文提示。不能仅把现有大按钮等比例缩小，或要求玩家猜九个抽象符号。经济区整合市场／银行／报表，外交区整合条约／联盟／信件，原能力都应能找到。

### 地块属性先于操作说明

固定摘要依次回答：这是哪里、归谁、本期施工额度还剩多少、有哪些建筑、是否有施工／待建、是否有驻军。

已有建筑用紧凑图标＋数量／状态。当前选中的地块、建造候选、付款信息和处理结果始终对应；不从视野外或历史快照推断当前施工情况。

建造图标默认给名称、真实费用和主要缺项；作用与预计收益保留短／长悬浮或固定详情入口。把长公式和完整条件放在可控的说明区，避免鼠标经过后出现一大块遮挡地图的文字。

### 队列有明确用途和状态

| 状态 | 玩家应看到什么 | 既有规则 |
| --- | --- | --- |
| 请求尚未提交 | 简短“正在处理／待处理”，需要时可取消尚未提交项 | 不扣款，不能冒充生产已开始 |
| 本期直接建造／征募 | 明确的“建造／征募”动作及实际结果 | 由直接`planning`与原动作决定，不自动偷换成排程 |
| 安排后续生产 | 明确“安排生产”入口，显示项目、地点、顺序、已支付、等待原因和取消 | 入队预付、锁价、容量预占保持；未开工取消全退 |
| 已经施工 | 地块属性与生产列表同时显示施工状态 | 取消按原规则返50%，不恢复本期施工额度 |
| 完工 | 成为地块已有建筑 | 拆除0返还，不标成可无损撤销 |

候选交互：普通操作以本期实际动工／征募为主；安排多期生产作为明确的第二动作。先用同一地块的两个原型比较，再决定按钮位置与默认方式。队列不能靠改名字隐藏，取消价格、扣款时刻和当前施工额度必须让人看见。

### 路线可以直接重设

将“新目的地”和“追加节点”作为两种清楚的意图；候选是普通右键设新目标、Shift右键追加，Ctrl对应攻击。远目标是否直接生成持续军令，需结合原有Shift长距离约定验证，不能无提示改变操作含义。

已有`queue_orders(append=False)`可替换剩余路线，`append=True`可追加，正式`cancel_orders`可停止。优先连接这些语义。新指令被正式规则拒绝时保留原路线并明确原因；已受理但暂时阻塞／等待的路线则显示真实状态，不能冒充拒绝或暗中回滚。已经发生的位移、战斗、补给不撤销；回血锁定和行动额度仍由规则处理。

路线重设后立即更新地图线、目标标记与右侧状态；停止是独立图标，不应成为换目的地的必经步骤。多选时明确受影响编号，部分可执行与未参与原因保持可查。

### 军队页直接找到征募地点

“部队”与“征募地点”分开阅读。征募地点显示格名、兵营／军屯图标、落成／施工状态与可查看的征募信息。没有军队时也能找到这些地点。

点地点后定位并进入该格征募。设施存在来自本国建筑事实和正式角色；额度、材料、电力与民兵编制来自正式征募规划，不能在UI另算。无法征募时说明原因，不用一片空白代替反馈。

## 按体验小步落地

1. **本轮：梳理问题与三张布局原型。** 展示地块属性／施工排程、选军／改路线、征募地点。图为示意，数值不代表真实对局，尚未进入游戏。
2. **第一条完整流程：看地 → 识别本期状态 → 建造 → 查看结果／排程。** 做一个可以连续玩的小版本，验证信息层级与状态，不同时翻新全部功能。
3. **第二条完整流程：找到部队／征募地点 → 选军 → 指定目标 → 换目的地／追加／停止。** 重点验证重新下令、跨格勾选与名单可见。
4. **回收反馈后再扩展经济、外交和通知。** 十档即时交易、自动买卖、银行和邮箱能力保持，调整入口、密度和反馈的一致性。

优先序可随试玩反馈调整；不预先把所有意见固化为一次大改，也不以加更多设置页消化问题。

## 验收看什么

- 不悬停、不滚动，能说出选中地块“本期能不能施工、现在有什么、有什么在建／待建”。
- 点图标前知道是立即执行还是安排后续、何时扣钱；执行后能看到真实结果，连续操作不被演出打断。
- 不先手动取消，就能给持续行军部队指定新的目的地；Shift追加保持可预期。
- 从军队工作区直接找到兵营／军屯格子，并能进入该地块的征募。
- 图标可以凭图意或悬浮中文识别；关键价格、失败原因、选中编号不被省略号或滚动区藏掉。
- 覆盖1024×768、1280×720与1920×1080；检查面板互斥、弹窗遮挡、键盘焦点、动画过程中点击是否误落到地图，而不只检查控件有没有出窗口。
- 记录完成任务的耗时、返回／滚动／误点次数和玩家口头困惑，与v0.7实际基线比较。尚未收集首玩者样本，不把自动测试通过当成“容易上手”。

建议让没参与开发的试玩者独立完成“建一座建筑、重新分配一次行军目标、在另一个地点征兵”，先观察操作，再解释规则；每轮保留问题、改动和复测结果。不要代替用户联系其他人或安排测试。

## 方案边界与入口

- 只支持当前单机一位真人，保留原18阶段、现有价格／退款／额度／视野。联机和新玩法不进入这一轮。
- 界面增删先查现有`site_options / planning / building_sites / production_queue / army_orders / queue_orders`及实际回执；新缺口单独记录，再决定是否补正式派生信息。
- 本轮原型是静态SVG，不连接规则、不扣款，也不证明鼠标操作已经改好。既有v0.7发布包与存档不变。
