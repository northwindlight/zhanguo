# GUI / UX 体验打磨

2026-10-29，承接v0.7.0后的试玩反馈。状态：**问题梳理与布局原型，交互方案需要试玩验证**。本轮没有修改Godot运行界面或发布新包。

用户最新判断：基础功能已经接近齐全，整体信息过多、不直观，需要时间和更多反馈来打磨。随后明确了地块管理方向：**建筑不单列为全局功能，选中地块后打开独立的大面板，在里面查看该地块的产值、工期、建筑、地形防御，并完成建造和管理，参考群星的星球面板组织方式。** 这是本轮地块原型的依据；具体分区、图标、尺寸和操作细节仍需试玩验证。

军队面板随后补充为**4个可独立折叠／展开的子面板**：正规军、民兵、兵营、要塞和市政厅。按用户说的4组，当前将“要塞和市政厅”合为第四组；兵营组保留此前要求的军屯地点。下文及两张军队草图按此组织，替代先前“部队／征募地点”双页草案。

## 已核对的现状

基于源码`f210878`及v0.7.0 Windows验收工件，未读取真实对局。

- `Desktop.Human.cs`把建设、军队、市场、银行、外交、联盟、邮箱、国家、结束回合共9项同级铺在底栏。
- 左侧完整资源账目、回合大横幅、右侧总览、操作抽屉分别占位。相同国家／回合信息在多个区域重复出现。
- `RenderHumanTile`先展示驻军，再展示建筑大卡和容量，“在这里建设”入口在后面；建筑与本期施工状态没有组成固定摘要。
- `_productionQueueMode=true`使建造／征募默认显示“加入队列”。界面同时存在尚未扣款的输入等待、已预付的生产队列和跨期军令，玩家需要自行区分。
- 建造页在候选格之前放置地块切换、四个标签、地形说明、队列开关、施工项和队列入口；长悬停又展开整套费用步骤与规则。信息虽然齐全，优先级不清楚。
- 军队总览当前按部队列驻地；没有独立的全国征募地点视图。已有的“有征兵设施”地块筛选不能替代从军队页直接办事。
- `HumanMapOrder`中Shift默认追加，替换持续路线需要先使用“重画已选路线”。当期普通动作成功时会清旧路线，但远目标重新指定仍需要更直接的交互。

**证据边界：**验收初始截图主动调用了`Fit()`，不能据此认定正常开局镜头就是那么小；代码已有`FocusNation`。`human-march-outliner`截图发生在关抽屉的动画过程中，不能据一帧认定稳定态存在永久遮挡。后续要同时检查稳定状态和切换过程，而不是把所有截图都当作默认玩家画面。

## 整体方向

### 地图、对象、动作相连

地图继续铺满窗口。固定资源区先给库存与必要预警；完整收支、来源和报表按需展开。换国／换期横幅短暂播报，回到操作时收起，当前回合和操控国家保留在紧凑状态区。

地块与军队按管理对象组织。**地块使用独立大面板**，容纳该格的完整经营；右侧总览主要用于找地块、找军队与征募地点，点击后进入对应对象。地块面板打开时，其他总览／详情合理收起，不能把大面板继续塞进原来狭窄的建筑抽屉，也不能叠出数列互相遮挡。关闭后回到原来的地图／列表上下文，返回入口固定；跨驻地选军摘要与清空／查看完整名单仍可达，换页不丢勾选。

导航用有含义的图标和角标，第一次使用、悬浮或键盘聚焦时给中文提示。不能仅把现有大按钮等比例缩小，或要求玩家猜九个抽象符号。经济区整合市场／银行／报表，外交区整合条约／联盟／信件，原能力都应能找到。

### 独立地块面板：查看与管理在同一处

管理主线是：**地图或地块列表选中一格 → 地块面板 → 看懂状态 → 在面板内建造／拆除／征募 → 原处看到结果**。军队页的征募地点也进入同一地块面板，不再复制另一套建设或征募页。

| 面板部分 | 需要回答的问题 | 呈现方向 |
| --- | --- | --- |
| 固定地块概览 | 这是哪里、归谁、是什么地形、本期动过工没有？ | 地名、坐标、领主、地形与本期施工状态始终可见；提供前后地块切换、地图定位与关闭 |
| 产值与运转 | 这里产什么、消耗什么、是否缺料／缺电？ | 资源图标＋带正负号的数量；实际已结算与预计／满负荷值明确标注口径，按需展开来源与条件 |
| 地形与防御 | 建设受什么加价、守军受什么保护？ | 显示正式地形加价／折扣和地形、城堡防御来源；合成减伤与适用对象读取共享规则，不直接相加 |
| 本地建筑与空位 | 有什么、哪些正在建、还有没有位置？ | 已落成、施工中、待建用不同状态；建筑图标为地块属性，点建筑查看作用与管理，点空位或建造图标展开本地候选 |
| 施工与待建 | 谁在施工、何时完成、后面排了什么？ | 明确的本地列表显示工期／完工时点、顺序、等待原因、已付款与取消退款；概览保留摘要，不因换页消失 |
| 驻军与征募 | 这里有哪些军队、能征什么？ | 放在面板内部的军事分区，联通既有跨驻地选军与正式征募；不把长驻军列表放到建筑概览之前 |

建筑不另设与地块、军队并列的全局主入口。候选“建筑与建设／产出明细／驻军与征募”可以作为面板内分区，但不应让玩家来回切页才能知道本期施工状态或找到正在建的东西。全国生产汇总可作为批量查看工具保留，具体操作回到该格，不替代地块的管理主体。

参考的是围绕单个经营对象组织信息与操作的方式；空位图标只表示现有规则的抽象建筑位，不引入建筑摆放坐标、人口或区划等新机制。

已有建筑用图标＋必要的数量／状态，普通建筑不加无意义的Lv1；只有城堡显示实际等级。当前选中的地块、建造候选、付款信息和处理结果始终对应；不从视野外或历史快照推断当前施工情况。工期用回合表达：当前规则下普通施工本回合末落成、下回合参与生产；待建标顺序与等待原因，不能虚构现实秒数或保证缺条件项目必在某回合完成。

建造图标默认给名称、真实费用和主要缺项；作用与预计收益保留短／长悬浮或固定详情入口。把长公式和完整条件放在可控的说明区，避免鼠标经过后出现一大块遮挡地图的文字。

### 产值与数据来源：先复用，再补真实缺口

地块产值以具体资源产出和投入为主，不把折金币估值、GDP、金币现金流当成同一个数。全国库存与全国电网仍是全国事实，不伪造一套地块库存或独立供电。示意中的满负荷数字不代表已经结算或保证获得；在建与待建不能计入当前已落成产出。

本轮只读核对了现有正式API与投影，尚未新增接口：

| 数据 | 已有来源／实际限制 | 实施时的处理 |
| --- | --- | --- |
| 已有建筑、空位、施工次数、预占资源位 | `building_sites`、`planning.space`、`site_options` | 直接呈现，不在GUI另写施工资格与容量计算 |
| 在建剩余工期、待建顺序、取消金额 | 建筑实例的`remaining`、`planning.construction / orders / demolitions` | 沿用正式状态与报价；显示本期已施工，取消不恢复额度 |
| 建筑费用、地形修正、作用与候选收益 | `site_options`内的正式规划、`cost_breakdown`、目录与`building_economics`估算 | 价格和条件使用原结果；建筑候选收益含满负荷／密度等假设，不能直接加总成该地块已实际实现的产值 |
| 地形、城堡及守方合成防御 | `terrain_catalog`、本国建筑事实、共享`army.defense`及已有防御投影 | 由规则层／授权投影提供，说明只适用于对应守方；无驻军时也应能查看地块的防御条件 |
| 本地上期实际产出／本地当前预估 | 正式`ProductionRecord`已有`site / id / status / inputs / outputs / energy`；当前玩家`production-detail`按全国建筑类型汇总，没有保留地块明细 | **这是待接通的信息缺口。** 若展示本地实际值，应在规则／玩家只读接口保留或投影本国记录，不能按全国总量平摊，也不能用现有建筑倒推过去；地块预估同样应复用正式生产算法和口径 |

地块明细需要明确采样回合和当时归属；没有记录时显示“暂无该期地块明细”，不写0。外国／历史地块继续只读授权可知内容，不暴露私有产出或施工队列。若后续保留逐地块历史记录涉及状态与依赖契约，实施前评估存档兼容；本轮原型不改数据结构。

### 队列有明确用途和状态

| 状态 | 玩家应看到什么 | 既有规则 |
| --- | --- | --- |
| 请求尚未提交 | 简短“正在处理／待处理”，需要时可取消尚未提交项 | 不扣款，不能冒充生产已开始 |
| 本期直接建造／征募 | 明确的“建造／征募”动作及实际结果 | 由直接`planning`与原动作决定，不自动偷换成排程 |
| 安排后续生产 | 明确“安排生产”入口，显示项目、地点、顺序、已支付、等待原因和取消 | 入队预付、锁价、容量预占保持；未开工取消全退 |
| 已经施工 | 地块属性与生产列表同时显示施工状态 | 取消按原规则返50%，不恢复本期施工额度 |
| 完工 | 成为地块已有建筑 | 拆除0返还，不标成可无损撤销 |

候选交互：普通操作以本期实际动工／征募为主；安排多期生产作为明确的第二动作。先用同一地块的两个原型比较，再决定按钮位置与默认方式。队列不能靠改名字隐藏，取消价格、扣款时刻和当前施工额度必须让人看见。

### 路线可以直接重设

将“新目的地”和“追加节点”作为两种清楚的意图；候选是普通右键设新目标、Shift右键追加，Ctrl对应攻击。远目标是否直接生成持续军令，需结合原有Shift长距离约定验证，不能无提示改变操作含义。

已有`queue_orders(append=False)`可替换剩余路线，`append=True`可追加，正式`cancel_orders`可停止。优先连接这些语义。新指令被正式规则拒绝时保留原路线并明确原因；已受理但暂时阻塞／等待的路线则显示真实状态，不能冒充拒绝或暗中回滚。已经发生的位移、战斗、补给不撤销；回血锁定和行动额度仍由规则处理。

路线重设后立即更新地图线、目标标记与右侧状态；停止是独立图标，不应成为换目的地的必经步骤。多选时明确受影响编号，部分可执行与未参与原因保持可查。

### 军队面板：4组独立折叠，连通部队和据点

| 子面板 | 展示对象 | 主要操作 |
| --- | --- | --- |
| 正规军 | 本国步兵、骑兵等正规部队，显示编号、兵种图标、驻地、生命和行动／路线状态 | 跨驻地勾选、定位、查看军令；与地图脚下光环同步 |
| 民兵 | 本国民兵，按相同方式显示真实编号与状态 | 与正规军允许混合选择；全国编制等信息仍读正式规则 |
| 兵营 | 本国兵营及军屯所在格，显示设施图标、名称、落成／施工／待建状态 | 定位并进入同一地块面板的征募分区；没有部队也能找到征募地点 |
| 要塞和市政厅 | 本国城堡／要塞与市政厅所在格，显示设施、城堡实际等级与施工状态 | 定位并打开地块面板，查看防御、驻军、施工和管理 |

每组标题带展开箭头与数量，部队用“支”，设施地点用“处”。同格有多座兵营，或同时有城堡和市政厅，地点合并显示各自图标，不把建筑数量混成地点数量；按真实状态区分在建／待建，不能冒充可用设施。用户称呼的“要塞”在当前规则中对应`castle`角色，不新增另一种建筑规则。

折叠／展开只改变显示，不清空已选军队、不取消路径，也不提交行动。保留各组的折叠状态；允许多组同时展开，不强制只能开一组。部队组折叠后，标题仍显示已选数量；面板外层固定保留总已选数、查看全部编号／清空入口。展开内容过长时留出其他组标题与固定选军摘要，不让长名单把其余入口挤没。

组标题用于展开收起，单位勾选与定位是独立操作，避免点标题意外全选／发令。筛选可以减少条目，但不能静默取消已选对象；无匹配时给空状态。默认展开哪些组和各组高度仍待体验验证，草图展示“部队展开”和“兵营展开”两个状态，不增加另一套全屏征募列表。

数据优先复用本国`facts.army / unit_catalog`、`building_sites`实例与正式建筑角色`recruiter / militia / castle / capital`，以及`production_queue`的待建事实和`army_orders`。当前规则民兵类型为`native:militia`，与正式征募分类保持一致，不按小人外观猜兵种。设施存在与施工状态不等于本期能征兵：额度、材料、电力与民兵编制来自`site_options`内的正式征募规划。无法征募时说明原因；不读取外国或迷雾私有状态。

### 军队编组：先保存选择，再考虑更多指挥能力

用户希望允许编组，先以**保存一组本国军队编号**为方向：跨驻地选中后命名编组，下次点击恢复这一批选择，显示成员、驻地分布、生命与路线状态；正规军和民兵可混编。编组入口放在军队面板内，不另加常驻大面板。快捷键保存／调用、双击定位作为候选细节，待实际操作验证。

编组是选择与指挥便利，不合并军队实体、生命、移动力或本期额度；恢复编组本身不发军令。批量发令继续交给已有正式候选与整批动作，各单位的实际结果独立显示。成员死亡／消失时移除失效编号并更新数量；跨存档不串组。先核对现有桌面选择、编队分组和规则AI分组的职责，避免把AI自动重分配目标当成人类保存的编组。保存位置与兼容性待实施时确定，当前未实现人类自定义持久编组。

### 经济托管：复用经济策略，先对齐正式规划

用户希望增加经济托管，自动按ROI选择建设，参考v13经济层；同时提出v13可能比v11plus低效，但未严格测试。该判断作为待核实问题，源码与当前引擎的离线对照见[经济层对照](../reviews/规则AI经济层对照与托管前置-20261029.md)。先修正共享规划适配与投资评价口径，再决定托管默认策略，不直接把现有v13整段接到玩家按钮上。

托管方向：国家经济入口提供开关和简洁预算／保留库存，地块面板能看本格是否参与托管、准备建设什么及原因。按期选择正式可行项目，并在预付队列、手工建设和当前施工额度基础上重新规划；尊重玩家已有排程，不擅自取消／拆除或把每格自动填成长队列。决定受理后显示项目、真实花费、预计收益口径与结果，缺钱／缺料时给原因，允许随时暂停后续托管。

职责先限定自动建设及其必要燃料、原料与交易预算；盈余出售等权限应在启用说明中明确。**不调用整个规则AI回合，不自动征兵、调兵、宣战、写信、借款或结束玩家回合。** 当前`v13.run_economy`含`recruit()`，需将投资／运营决策与军事采购拆开；托管不能借此越过玩家的军事选择。自动交易已有独立规则，托管应核对其保留量和预计支出，避免两个控制器互相买卖。

实现优先级：先利用现有正式`planning / sites / orders / trade_quote`构造共用的经济计划与解释，使用正式提交回执刷新；缺失信息先核对领域API，GUI不再抄价格、施工或配方公式。v13的市场预测与偏好属于策略假设，应显示为预计而非规则承诺；工程院等长期投资也需纳入可解释的评价，不能只按瞬时售价选建筑。首轮适合先验证“本期建议”与手工执行结果，再接明确启用的自动执行。

用户进一步强调复利目标：当存在合法、能持续运营、边际净收益为正的项目时，应尽早有效再投资，不把囤现金本身当作经营成绩。保留必要周转金与玩家军费预算，同时区分“没有合适项目”和“模型／筛选误拒绝”：托管须能解释未投资原因。当前v13是逐项评分策略，没有跨期再投资与多步建设的全局优化，不能称为已实现最大复利；投资评估还需考虑工程院折扣、前置建设与市场增产影响。

现金追踪已确认v13的具体冲突：先出售本期盈余，后选中新投资所需材料时，被“本期卖过不可买回”拦截，投资直接终止。托管前需先协调投资／新增运营材料预留与出售，并让候选和实际资金准备遵守一致条件；不把几千金闲置一概解释为安全储备，也不直接删除防反复交易保护。详见经济层复核的现金追踪。

## 按体验小步落地

1. **本轮：梳理问题与三张布局原型。** 地块原型按用户补充改为独立大面板；另外两图按4个可折叠军队子面板，分别展示部队展开／选军与兵营展开／征募入口。图为示意，数值不代表真实对局，尚未进入游戏。
2. **第一条完整流程：选地 → 地块面板识别产出／本期状态 → 就地建造或管理 → 原处查看结果／排程。** 先接已有正式数据，补清地块产值口径和缺口，做一个可以连续玩的小版本；不同时翻新全部功能。
3. **第二条完整流程：找到部队／征募地点 → 选军 → 指定目标 → 换目的地／追加／停止。** 重点验证重新下令、跨格勾选与名单可见。
4. **回收反馈后再扩展经济、外交和通知。** 十档即时交易、自动买卖、银行和邮箱能力保持，调整入口、密度和反馈的一致性。
5. **编组与经济托管列为后续增量。** 先做保存选军的最小编组；托管先完成经济层对照及规划适配，再接建议／预算与自动执行。当前新增的是设计与离线核验，没有接入运行界面。

优先序可随试玩反馈调整；不预先把所有意见固化为一次大改，也不以加更多设置页消化问题。

## 验收看什么

- 不悬停、不滚动，能说出选中地块“本期能不能施工、现在有什么、有什么在建／待建”。
- 地块大面板中可以看产值／工期／建筑／地形防御并进入建造与管理，不被跳转到另一套全局建筑页；产值明确实际或预计、回合与成立条件。
- 点图标前知道是立即执行还是安排后续、何时扣钱；执行后能看到真实结果，连续操作不被演出打断。
- 不先手动取消，就能给持续行军部队指定新的目的地；Shift追加保持可预期。
- 从军队工作区直接找到兵营／军屯格子，并能进入该地块的征募。
- 军队面板4组可分别折叠与展开，数量单位清楚；折叠／筛选不改变选军或军令，已选摘要始终可达，长名单不挤没其他组入口；要塞／市政厅能定位并进入同一地块管理。
- 编组恢复只改变选择，不改变单位属性／额度或偷偷下令；托管仅在用户启用的职责与预算内行动，尊重手工项目、预付队列、真实施工额度及玩家视野，暂停后不再新增自动项目。
- 图标可以凭图意或悬浮中文识别；关键价格、失败原因、选中编号不被省略号或滚动区藏掉。
- 覆盖1024×768、1280×720与1920×1080；检查面板互斥、弹窗遮挡、键盘焦点、动画过程中点击是否误落到地图，而不只检查控件有没有出窗口。
- 记录完成任务的耗时、返回／滚动／误点次数和玩家口头困惑，与v0.7实际基线比较。尚未收集首玩者样本，不把自动测试通过当成“容易上手”。

建议让没参与开发的试玩者独立完成“建一座建筑、重新分配一次行军目标、在另一个地点征兵”，先观察操作，再解释规则；每轮保留问题、改动和复测结果。不要代替用户联系其他人或安排测试。

## 方案边界与入口

- 只支持当前单机一位真人，保留原18阶段、现有价格／退款／额度／视野。联机和新玩法不进入这一轮。
- 界面增删先查现有`site_options / planning / building_sites / production_queue / army_orders / queue_orders`及实际回执；新缺口单独记录，再决定是否补正式派生信息。
- 本轮原型是静态SVG，不连接规则、不扣款，也不证明鼠标操作已经改好。既有v0.7发布包与存档不变。
