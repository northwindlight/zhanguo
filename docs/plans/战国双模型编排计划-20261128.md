# 战国双模型编排计划

实现已接入原生版和实验版的「君主与首辅」开关。当前配置、求助和国策规则见[游戏说明书](../../mods/native/docs/游戏说明书.md#实验功能君主与首辅)。首辅主动触发，每席滚动十回合三次，每次二十轮君主工具往返。国策缺失或到期时继续走原结束校验。两角色支持现有四种模型协议，君主负责总路线、四方面定调和十回合 GDP 目标。后文保留最初方案供复盘。真实模型的同档对照留待试玩。

模拟对局验证了第 20 轮颁布、中断续局后的求助扣次、国策到期拒绝结束和计划作者权限。使用官方 SDK 的模拟端点跑通 OpenAI 首辅与原生 Gemini 君主的交接及签名回放。Godot 实际窗口验证了实验选项、君主档案和配置体检。

编排支持首辅同意后由君主直接执政五回合。模拟对局验证了请求与明确同意、下回合开始执政、任期中读档、期满交还，以及首辅接手时收到任内回执。

为单个 LLM 席位增加规划模型和执行模型。规划模型负责跨回合的经济、军事和外交决策，执行模型负责每回合落实国策。两者在同一个国家的行动期内交接。日常回合由执行模型推进，强模型额度留给建立国策和局势变化。首轮用一个席位试验，规划模型可配任一有额度的强 Gemini，执行模型先用 Gemini 4 Hydrogen，以便和现有单模型打法做对照。

Antigravity 的 Orchestrator 提供了可借鉴的交接方式。规划模型先只读调查，执行模型负责操作，预期落空时把现场交回规划模型。战国内由客户端向各自的原生 Gemini API 发请求，并根据游戏事实决定交接。 [Antigravity 编排说明](https://antigravity.google/docs/models#orchestrator)

## 按国策推进每个回合

1. **第一次规划。** 轮到该国时，汇总当前可见局势、上一轮国策及兑现情况。规划模型给出跨回合路线，并排定本期就能做的第一步。使用现有 `plan` API 登记国策，正式回执成功后交给执行模型。
2. **日常执行。** 执行模型读新事件和国策进度，查当前报价、合法地点与行动资格，依次处理本期动作。它可以在国策允许的预算与条件内调整采购量、站点或调兵顺序。每一步以正式回执更新进度，区分下单、交战、落成和占领。回合结束使用 `end_turn`，由宿主统一结算。
3. **同回合重新规划。** 如果执行到一半发现关键前提不成立，把当前事实、已生效动作和剩余选项交回规划模型。新的国策从当前局面继续，已经成交、动工或提交的外交动作照实计入。轻微价格波动和一次可纠正的参数错误由执行模型直接处理。
4. **到期复盘。** 按现有国策有效期更新，通常每十回合一次。用实际产出、费用、战果和外交回应核对旧国策。逐项决定继续、改顺序或放弃，并给出下一阶段具体动作。

## 国策写到能执行的程度

| 决策内容 | 规划模型交付的内容 |
| --- | --- |
| 局势判断 | 本国面临的主要威胁、能改变态势的机会、哪些情报过旧或未知。写明证据的周期和适用范围。 |
| 经济与军需 | 给项目排序，写明地点候选、材料、供电、预期开工回合和投产后的用途。并列预计产量、军队净维护、原料净耗与债务到期现金。扩军时同时说明长期多养几支、从哪里补供。 |
| 战争与外交 | 指定作战目的、能在几回合内集结的兵力、留守和增援、开打和退出条件。外交动作写预期改变哪条战线或哪一方参战条件。 |
| 等待与备选 | 写清等待能换来什么、最晚何时重查、错过当前窗口的代价。给出条件变化时可执行的备选，以及由执行模型直接调整的范围。 |

首版用结构化国策和进度记录关联既有 `plan` 文本。由受信的编排客户端使用绑定玩家 API 提交规划结果，执行模型接收同一份计划和精简事实。计划有优先级、准备条件和可选路径，执行仍逐步查价和验资。正在备料的项目标出要留多少木、粮或矿，执行模型用这份清单设定可以出售的余量。每次重新规划只需给出修改理由、新的首步和被替代的项目。

例如，一个国家两座补给厂实产 4，本期养兵耗 6，其中两支民兵回军屯后可免供。规划时就要选清楚，是回屯让日常需求回到 4，还是保留机动兵并建第三座厂。若新厂是为了外销，就按外销价格、原料、电力和投产期单独算。决定借款时，要把到账、一次性开支、每期现金流和正式到期扣款放进同一份预算。希望打下森林来缓解木材短缺，就把预期林场、开工时间和战后守备接到同一个目标上。

## 触发条件与强模型用量

| 信号 | 默认处理 |
| --- | --- |
| 席位启动、国策到期 | 规划模型做一次完整规划或复盘。 |
| 市政厅受威胁、正式开战或停战、盟约改变、关键阵地得失 | 核对本国可见事件。影响当前国策时，同回合重新规划。 |
| 预计到期现金不足、持续缺料停产、预计产出和军需连续偏离 | 执行模型先用正式面板确认，超出国策给的调整范围时交回规划。 |
| 限时机会出现、关键动作反复失败、当轮已无法完成首选计划 | 有明确备选就执行。没有合适备选且下一步会改变战略时申请重新规划，附最近回执。 |

首轮预算建议为**单席每十个游戏回合最多三次强模型请求**。一次用于定期规划，一次在需要时核实关键事实，保留一次给突发事件。失败和实际发出的重试一起记账。相同事件在关键事实发生新变化时才可再次触发，多个变动合并成一次交接。按接入账号统一限额，以便以后增加席位时仍能控制总用量。常规上下文用本国简报、当前国策和发生变化的证据，旧回执按需查询。规划与执行分别保留模型自己的会话和协议签名，交接只传事实、国策、证据编号和执行进度。

收到 429、超时或预算用尽时，继续沿用有效国策中的可行部分，反映局势变化的待决事项保留到下一次可规划的时点。国策到期而强模型不可用时，执行模型通过普通 `plan` 提交临时国策，并在下一次规划时复核。失效报价和过期计划在实际动作之前复查，交易与建造依旧以游戏回执为准。记账区分真实请求与成功规划，重启或从上个结算边界续跑时仍计入已发出的请求，防止故障反复消耗额度。

## 接入位置与验证步骤

1. **先做一个离线客户端原型。** 从 native 串行行动局开始，在可选 LLM 客户端配置里按席位启用。复用 `clients/llm.py` 的工具循环、`clients/gemini.py` 的原生模型接入与绑定玩家 API。规划只调用 `observe`、`events`、`rules` 和正式只读查询。沿用已有的建设报价、经济与军需预演、还款计划、可达和外交推演，按当前身份读取外国情报。交接前检查回合与控制权代次。编排状态随客户端保存，包含国策版本、证据游标、待复盘事项和用量。通过正常观测回调在看海日志显示规划触发原因、计划改动与实际回执。 [玩家接口](../接口/客户端接线.md) · [Session 契约](../接口/发行版Session.md)
2. **用回执验证交接。** 用合成局和模拟模型检查开局规划、日常回合零强模型调用、同回合重规划后继续行动，以及国策到期、429、预算耗尽和重启。检查已执行动作只入账一次，模型能区分下单与落成，规划查询只能看本国权限内的事实。覆盖借贷后到期现金、征兵后军需、作战所得地块的建设，以及工具报错后依据回执继续或转交的场景。
3. **先做离线对照，再开单席实验局。** 用相同起点、对手、座次和执行模型比较三组。第一组是现有单模型，第二组给同一个执行模型提供相同的精简事实和进度，第三组再加入强模型规划。重点比较国策首个有效动作兑现所需的回合数、攻占资源地后形成产能的比例、补给与到期现金预测偏差、战局突变后多久调整，以及每十回合强模型请求数、Token 和耗时。用回执逐条复核典型决策，胜负作为长局结果一并记录。

首轮验收以两个现场结果为准。局势稳定时，执行席能连续落实国策并省下强模型调用。实际回执推翻国策前提时，能在额度内重新规划并完成下一步。通过这两个条件后，再根据实测用量决定扩到几个席位。
