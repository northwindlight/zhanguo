## 2. 建筑与军队生产队列

- [ ] 建筑建设、军队征募有正式生产队列，显示条目、顺序、所在地点、进度和当前状态，方便连续安排。
- [ ] **加入生产队列时直接扣除所需资源**，包含实际金币与材料成本；展示已支付费用，开始执行时避免重复扣款。余额不足时给出明确原因。
- [ ] 队列进入规则侧并随存档保存，读档后继续；每地块每回合施工限制、耕地容量与征兵设施等条件统一核算，排队占用也要体现在可用容量中。
- [ ] 下次设计时明确跨回合推进、容量变化或失去地块后的处理，以及未开始条目的取消／退款规则。既有在建拆除返还50%、完工拆除返还0%的规则保持，新增队列退款另行定案。

当前 v0.6.2 已有动画期间接受买卖／建设／征兵输入的界面待执行队列，费用在实际执行时扣除；下一轮需要实现上述正式生产队列与入队扣款。

## 3. 连续军令与低血量恢复

- [ ] 按住 Shift 可以依次安排连续移动，也可以安排连续攻击；显示路线、目标顺序和当前执行到哪一步。
- [ ] 军队按合法军令逐步执行，保留跨回合尚未完成的路径／目标；行动额度、不可通行地形、目标变化和战斗状态仍由规则核算。
- [ ] 增加可切换按钮：**生命低于30时自动停止**。这里按用户原话记录为绝对生命值30，未指定为30%。
- [ ] 开启后，低血量暂停后续军令，等待正常补给／回血，恢复后继续原队列；明确标出“等待回血”及暂停原因。
- [ ] 恢复到多少生命后续行、混编或多选军队怎样判断低血量、无法回血时如何提示，留到实施时确定；遵循现有回血与补给规则。

### 2026-10-28 补充：寻路与动画一致性

用户反馈 GUI 寻路不正常，询问是否使用游戏引擎的 `reachable`。本次只读查源码，未根据具体对局复现，先追加优先修复项。

当前分为三条链路：真人候选圈经 `HumanAPI.targets()` 调用 `army/candidates.py`，根据玩家事实另做可达搜索；实际移动／攻击由军队规则 `_batch()` 调用 `reachable()` 校验；真人行军演出 `PlayerCapture` 只发送起点、终点两个点并标记 `schematic`，Godot按点插值，未采用规则的逐格绕行路线。看海模式则通过 `observer_route()` 使用 `reachable()` 的前驱记录生成合法演出路线。真人动画因此可能显示穿过障碍物，不能据此判断实际规则允许穿山；候选范围是否也有错误需要复现核实。

- [ ] 优先复现并区分候选范围错误、实际移动失败与动画穿障碍，记录出发格、目标格、兵种、所选军队及视野状态。
- [ ] 已知地形的候选与路线共享规则侧公开可达性／路径计算，核对地形代价、移动力、对角夹角、领土通行和进攻终点规则；迷雾中的尝试继续明确标为不确定。
- [ ] 真人行军动画接入按权限提供的合法逐格路线，绕开高山、海洋和受阻夹角；连续移动／攻击预览与实际执行、演出使用一致的路径依据。
- [ ] 统一时保留玩家信息边界，不向真人调用全图观察者路线接口；逐支行动状态和多选军队的目标适用范围仍要明确。
- [ ] 加入需绕行的高山／海洋、对角障碍、地形耗费、混合移动力、迷雾和原地攻击等验证案例，核对候选、执行及动画各自的结果。

## 实施顺序与验收依据

下次开工先理清生产队列、扣款和连续军令的规则及存档，再接 GUI；地图／列表与银行／指南／报表可按界面批次推进。CI 自动发布随下一次版本交付接通。本次不修改游戏代码、工作流或发布现有版本。

验收重点：入队扣款与取消对账；施工／征募跨回合及存读档；Shift 多段移动和攻击、低血停下回血续行；地形加价与实际扣款一致；耕地空位组合筛选；小图标列表；右键开关与取消操作；银行入口；到期报表进邮箱并只提醒对应新报表。通过后由 CI 直接公开预发布供试玩。
