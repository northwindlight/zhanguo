# GUI 下一轮试玩改进

记录日期：2026-10-27。承接 [v0.6.2 试玩版](https://github.com/northwindlight/zhanguo/releases/tag/v0.6.2)反馈；用户要求本次先保存计划，下次实施。本文件各项均未实现，不代表已经进入当前版本。

继续保持单机一位真人、本国信息权限和原18阶段结算顺序。上一批已完成内容见[军队总览、地块筛选与资源明细](军队总览与地块筛选-20261027.md)。

2026-10-28 用户明确开发原则：**任何增删先查引擎已有 API；语义足够就复用，GUI 负责展示和交互。** 先盘点 API／规划／报价／目录／回执，再确认真正缺口，避免在界面层另定义可达性、行动资格、生产条件或攻防公式。

## 2. 建筑与军队生产队列

- [ ] 建筑建设、军队征募有正式生产队列，显示条目、顺序、所在地点、进度和当前状态，方便连续安排。
- [ ] **加入生产队列时直接扣除所需资源**，包含实际金币与材料成本；展示已支付费用，开始执行时避免重复扣款。余额不足时给出明确原因。
- [ ] 队列进入规则侧并随存档保存，读档后继续；每地块每回合施工限制、耕地容量与征兵设施等条件统一核算，排队占用也要体现在可用容量中。
- [ ] 下次设计时明确跨回合推进、容量变化或失去地块后的处理，以及未开始条目的取消／退款规则。既有在建拆除返还50%、完工拆除返还0%的规则保持，新增队列退款另行定案。

当前 v0.6.2 已有动画期间接受买卖／建设／征兵输入的界面待执行队列，费用在实际执行时扣除；下一轮需要实现上述正式生产队列与入队扣款。

## 3. 连续军令与低血量恢复

- [ ] 取消同驻地选择限制，支持跨地块勾选；固定显示已选总数、驻地和编号清单入口，不因面板过长或滚动而隐藏选中状态。候选目标标明可执行部队与未执行原因。
- [ ] 被选中军队脚底显示选中光环，与右侧勾选及实际军队编号一致；混编或合并绘制时区分部分选择，同格未选军队不一起高亮。
- [ ] Shift＋右键长距离移动，Shift＋Ctrl＋右键长距离攻击；重复标记多个节点，显示节点顺序、路径线和当前执行进度。
- [ ] 军队按合法军令逐步执行，保留跨回合尚未完成的路径／目标；行动额度、不可通行地形、目标变化和战斗状态仍由规则核算。
- [ ] 增加可切换按钮：**生命低于30时自动停止**。这里按用户原话记录为绝对生命值30，未指定为30%。
- [ ] 开启后，低血量暂停后续军令，等待正常补给／回血，恢复后继续原队列；明确标出“等待回血”及暂停原因。
- [ ] 恢复到多少生命后续行、混编或多选军队怎样判断低血量、无法回血时如何提示，留到实施时确定；遵循现有回血与补给规则。

### 2026-10-28 补充：寻路与动画一致性

用户反馈 GUI 寻路不正常，询问是否使用游戏引擎的 `reachable`。本次只读查源码，未根据具体对局复现，先追加优先修复项。

后续澄清：问题包括“引擎可达却在 GUI 不可达”，不限于穿山动画。[规则复用审计](../reviews/GUI规则复用审计-20261028.md)已找到4类至少6处独立规则片段，并用合成局证实真人候选误排合法攻击、按钮误禁用原地攻击。尚未取得用户具体对局；两个反例只证明误拦截存在，不涵盖全部反馈。

当前分为三条链路：真人候选圈经 `HumanAPI.targets()` 调用 `army/candidates.py`，根据玩家事实另做可达搜索；实际移动／攻击由军队规则 `_batch()` 调用 `reachable()` 校验；真人行军演出 `PlayerCapture` 只发送起点、终点两个点并标记 `schematic`，Godot按点插值，未采用规则的逐格绕行路线。看海模式则通过 `observer_route()` 使用 `reachable()` 的前驱记录生成合法演出路线。真人动画因此可能显示穿过障碍物，不能据此判断实际规则允许穿山；候选范围是否也有错误需要复现核实。

- [ ] 优先复现并区分候选范围错误、实际移动失败与动画穿障碍，记录出发格、目标格、兵种、所选军队及视野状态。
- [ ] 优先消除真人候选／提交前置与按钮置灰对引擎合法操作的误拦截；复用现有 API 的规则结果，单支／批量状态、撤退、原地攻击和迷雾尝试按其真实契约处理。
- [ ] 按审计清单逐项复查军令资格、自动交易校验、防御显示及设施入口，先查引擎再确定增删；建设征兵继续使用现有 `planning`，交易继续使用正式整单报价。
- [ ] 已知地形的候选与路线共享规则侧公开可达性／路径计算，核对地形代价、移动力、对角夹角、领土通行和进攻终点规则；迷雾中的尝试继续明确标为不确定。
- [ ] 真人行军动画接入按权限提供的合法逐格路线，绕开高山、海洋和受阻夹角；连续移动／攻击预览与实际执行、演出使用一致的路径依据。
- [ ] 统一时保留玩家信息边界，不向真人调用全图观察者路线接口；逐支行动状态和多选军队的目标适用范围仍要明确。
- [ ] 加入需绕行的高山／海洋、对角障碍、地形耗费、混合移动力、迷雾和原地攻击等验证案例，核对候选、执行及动画各自的结果。

## 9. 瞭望塔同格限建，由引擎统一执行

2026-10-28 用户要求：瞭望塔不应堆叠，修改位置应在引擎。源码核对：`Watchtower` 当前继承 `MAX_PER_SITE=None`，允许同格重复建造；`vision_radius` 已按非累加效果处理，多座塔不会扩大同格视野。

- [ ] 瞭望塔每地块最多1座，已有与在建一并计数；正式生产队列也须在安排时核算占用。该限制是同格限制，不是全国只能有一座。
- [ ] 优先复用引擎已有的建筑类型 `MAX_PER_SITE` 及共享 `_check_slots / planning / build` 校验链，实现规则侧统一限制。真人、LLM、规则AI和其他正式调用都遵守同一规则，GUI读取规划结果置灰并说明原因。
- [ ] 保留现有视野不按同格塔数累加的语义。拆除／取消后的再次安排遵守原施工额度与队列规则。
- [ ] 对建成、在建、重复安排和不同地块分别验证；实施前核对旧档中已经存在的同格多塔与存档依赖检查，明确处理办法，不擅自删除旧建筑。

## 10. 启动前选择发行版与实验功能开关

2026-10-28 用户反馈发行版混用，要求启动前明确选择发行版，并通过开关决定实验发行版功能是否启用。源码核对：GUI建局没有独立发行版选择控件，`mods` 只可在看海模式的全局附加JSON中填写；native与experimental各有正式装配清单，实验服务当前随发行版装配，尚未证实用户具体对局的运行时混载原因。

- [ ] 新建对局时先明确选择发行版，至少区分 native 与 experimental；发行版、剧本、玩家／看海模式分别显示。保留玩家定制本国、再配置对手的两步流程。
- [ ] 根据所选发行版的真实声明显示可用剧本、客户端及功能；界面说明与最终启动配置保持一致。切换发行版时校验并处理不适用的配置，避免附加JSON或上次选择无提示覆盖实际发行版。
- [ ] experimental提供实验功能启用开关，按实际支持的可选项展示，例如议会审核、脚本／沙盒和规则AI研究能力；逐项明确适用对象、当前开关状态及需要的配置。哪些项目可以独立启停、默认值和依赖，实施时先核对正式装配与配置入口。
- [ ] 开关影响真实服务、工具和客户端调用链；关闭的功能应真正停用，并按依赖关系处理相应配置与存档组件。需要模型接入的功能只在启用且适用时准备，不以隐藏按钮代替停用。
- [ ] 开始前给出“发行版＋版本＋实验功能启用清单”摘要，对局菜单与存档列表也显示，便于确认玩的是哪套规则。读档使用该档记录的发行版、功能组合和依赖，保持原有一致性校验。
- [ ] 共享的native基础模块按正式发行版清单正常复用；启动和能力装配先查引擎已有API／配置语义，实际不支持的组合明确说明，不在GUI自造一套装配规则。
- [ ] 验证native、experimental及其支持的功能组合，覆盖玩家／看海建局、切换后配置、开始摘要与保存读回；确认未选功能没有进入实际执行链。

## 实施顺序与验收依据

下次开工先查引擎API和发行版装配，处理规则重复误拦截、瞭望塔限建、发行版选择与实验开关，再理清生产队列、扣款和连续军令的规则及存档，随后接 GUI；地图／列表与银行／指南／报表可按界面批次推进。CI 自动发布随下一次版本交付接通。本次不修改游戏代码、工作流或发布现有版本。

动态／并行回合纳入未来联机的必做设计；当前GUI批次与联机实施范围分别说明，不能将单机版本的完成视为联机调度已实现。

验收重点：入队扣款与取消对账；施工／征募跨回合及存读档；跨驻地选择的持续反馈与选中光环；右键／Ctrl／Shift军令和范围切换、多节点路径线、低血停下回血续行；地形加价与实际扣款一致；耕地空位组合筛选；小图标列表；右键开关与取消操作；银行入口；到期报表进邮箱并只提醒对应新报表；灭国后归属快照与国色及时更新；瞭望塔引擎同格限建；发行版与实验开关的显示、配置、实际执行及读档一致。通过后由 CI 直接公开预发布供试玩。
