### 2026-10-28 补充：寻路与动画一致性

v0.6.3已共用领域导航与资格判定，修复三种已复现差异，并接入已知逐格路线。以下审计描述保留为修复前证据；当前状态见[本版记录](../reviews/GUI军令规则与自动预发布-20261028.md)。

用户反馈 GUI 寻路不正常，询问是否使用游戏引擎的 `reachable`。本次只读查源码，未根据具体对局复现，先追加优先修复项。

后续澄清：问题包括“引擎可达却在 GUI 不可达”，不限于穿山动画。[规则复用审计](../reviews/GUI规则复用审计-20261028.md)已找到4类至少6处独立规则片段，并用合成局证实真人候选误排合法攻击、按钮误禁用原地攻击。尚未取得用户具体对局；两个反例只证明误拦截存在，不涵盖全部反馈。

审计时分为三条链路：真人候选圈经 `HumanAPI.targets()` 调用 `army/candidates.py`，根据玩家事实另做可达搜索；实际移动／攻击由军队规则 `_batch()` 调用 `reachable()` 校验；真人行军演出 `PlayerCapture` 只发送起点、终点两个点并标记 `schematic`，Godot按点插值，未采用规则的逐格绕行路线。看海模式则通过 `observer_route()` 使用 `reachable()` 的前驱记录生成合法演出路线。真人动画因此可能显示穿过障碍物，不能据此判断实际规则允许穿山；候选范围是否也有错误需要复现核实。

- [ ] 优先复现并区分候选范围错误、实际移动失败与动画穿障碍，记录出发格、目标格、兵种、所选军队及视野状态。
- [ ] 优先消除真人候选／提交前置与按钮置灰对引擎合法操作的误拦截；复用现有 API 的规则结果，单支／批量状态、撤退、原地攻击和迷雾尝试按其真实契约处理。
- [ ] 按审计清单逐项复查军令资格、自动交易校验、防御显示及设施入口，先查引擎再确定增删；建设征兵继续使用现有 `planning`，交易继续使用正式整单报价。
- [x] 已知地形的候选与路线共享规则侧公开可达性／路径计算，核对地形代价、移动力、对角夹角、领土通行和进攻终点规则；迷雾中的尝试继续明确标为不确定。
- [x] 真人行军动画接入按权限提供的合法逐格路线，绕开高山、海洋和受阻夹角；连续移动／攻击预览与实际执行、演出使用一致的路径依据。
- [x] 统一时保留玩家信息边界，不向真人调用全图观察者路线接口；逐支行动状态和多选军队的目标适用范围仍要明确。
- [ ] 加入需绕行的高山／海洋、对角障碍、地形耗费、混合移动力、迷雾和原地攻击等验证案例，核对候选、执行及动画各自的结果。
