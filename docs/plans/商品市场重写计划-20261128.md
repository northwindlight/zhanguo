# 六种商品的市场重写计划

2026-11-28 设计提案，规则基线为 `main@26c5311`。适用粮、木、矿、油、装备和补给。首要目标是让国家为实际消耗买货、靠出口换金，也能因预判他国需求而获利。四个国家把同一批货来回倒一遍，不能仅靠跨过回合边界从市场赚金。

## 为什么四国学出了同一个开局

目前行动期立即收付金币、交割商品。各国从同一期公开价起步，各自独立走完整条市场深度；到回合末，四国净买量合计决定下期报价。这样做让并行玩家不会因网速吃亏，却让四国都能按同一段低价买货。GDP 按市价计产出，高木价还可能提高伐木业的名义增加值。[市场实现](../../mods/native/market/objects.py) · [定价实现](../../mods/native/market_pricing/pricing.py)

第 453–456 局用相同策略控制四国。16 席开局共买 8,444 木，花 20,442 金。用 C++ 引擎在第二回合把相同数量全部卖回，同局四席都可以成交，合计赚 21,547 金。逐席只保留自己的木市订单，同样操作合计亏 942 金。真实对局里主要用途是建设，按混仓比例追踪，约 62% 用来建造，31% 卖出。

另做了一席偏离的检验。保持本席首回合已成交的其他订单和建设支出，以及三名对手的木材订单，比较“跟买”和“留现金”。两种情况下都在第二回合卖清该席手中余木，使最终持木相同。16 席的跟买方案分别多得 777–1,567 金。例如地图 640452 的第 4 席，跟买后清仓有 3,219 金，留钱只卖原有的 110 木有 1,806 金。这是固定其他订单的两回合现金比较。它说明老规则会奖励跟买，还不足以说明相同权重必然导致趋同，也不能据此判定哪种开局的百回合 GDP 更高。

## 建议采用的成交规则

**全世界同种商品共用一份深度，在回合开始时把这份深度按存活国家平分。** 四国各占四分之一，八国各占八分之一。深度决定买卖多少会让自己的下一单变贵或变便宜。各国依然能看价、卖矿拿钱、用钱买木、当回合开工。各自成交后立即更新本国的下一笔报价，其他国家的成交在下期开盘价中体现。行动快慢不会影响别国本期的成交价。

| 项目 | 第一版规则 |
| --- | --- |

## 定价与可验证的边界

每种商品有固定深度 `D`。设 `x = D − 世界库存`，买货使 `x` 增大。开盘稀缺程度为 `x₀`，中间价取 `p(x) = clamp(基价 × exp(弹性 × x / D), 最低价, 最高价)`。定义 `F(b) − F(a)` 为从 `a` 到 `b` 的中间价曲线面积。指数段用闭式积分，越过价格上下界的部分按常价计。

本国深度份额为 `s`，本期此前累计净买 `q`，新单数量 `d` 买入为正、卖出为负。新单未加价差的有符号成本是

```text
s × [ F(x₀ + (q + d) / s) − F(x₀ + q / s) ]
```

买入按正成本乘 1.05 扣款，卖出按负成本的绝对值乘 0.95 付款。用未舍入值计算，最后才按各国现有的金币零头账户收付。买和卖沿同一条曲线折返。世界在回合末进入 `x₁ = x₀ + 各国净买量之和`。各国下一期重新从 `x₁` 出发。

这个口径给出了一条可验收的性质。因为价格随稀缺程度单调上升，`F` 是凸函数。各国本期走过的终点按份额加权，正好是世界终点 `x₁`。所以各国支付的合计中间价成本至少为 `F(x₁) − F(x₀)`。跨回合相加，若没有外部流动且世界库存回到起点，所有参与国合计的金币加零头只能持平或减少。某国提前备货，之后别国确有需求，该国依然可以赚钱。

**可手算的验收局。** 木材基价 2、深度 1,920。四国各买 200 木，下一回合各卖 200，期间无其他订单。旧规则每席付 443 金、收 581 金，净赚 138 金。提案公式每席付 522 金、收 472 金，净亏 50 金。另一例中，一席先买 100 木，下一期三名对手各买 250 木（各付 726 金），再下一期该席卖出 100 木，实际现金净赚 33 金。两种情形应同时通过。

## 实施和验收

1. **先做独立账本和固定订单回放。** 六商品、2／4／8 国都测。验收跨回合闭环、同一国拆单与整单、同回合买后反卖、互换国别编号、打乱不同国家请求到达顺序、跨价格边界和不足额拒单。比较逐席金币、零头、库存、下一笔报价。上面的四国算例可作首个固定样例。四个真实种子 `640452 / 640457 / 640462 / 640467` 另跑一遍，允许新价格使旧订单买不起，须分别报告成交与拒单。
2. **在 main 的 Python 规则层落地并校验玩家体验。** 沿用市场对象、报价接口、自动交易、钱包和生产报表。公开汇总给世界开盘价，绑定身份的报价给本国实付金额。GUI、规则 AI、LLM 和自动交易都读同一份正式报价。验收“卖矿后立即买燃料，本回合生产用得上”，以及多人并行时同一国家重复提交的原子性。旧档缺少市场版本时按旧公式恢复，新规则由新局显式选择。对局中途保存时记录开盘状态、各国份额、净量、金币零头和交易流水，恢复后逐单一致。
3. **Python 契约稳定后再移植 C++ 采样器。** 用相同初始存档和动作流逐笔对齐。特别核对现有 C++ 候选使用市场库存检查、Python 正式成交允许缓冲库存为负的差异。让策略看到公开开盘价、本国当前净头寸、各档候选整单成本和本国库存，不提供对手私单。轨迹、数据集和模型评估记录市场版本。
4. **检验策略趋同和经济收益。** 用相同地图、相同权重和轮换席位分别跑四席同策略以及三席同策略加一席偏离。偏离席分别试留现金、优先建设、照常跟买。再用历史模型混桌，验证换对手后能否调整。按地图配对比较第 2 回合等持仓现金、第 20／100 回合现金、名义与固定价 GDP、产量、断电率、首购木材的建造和转售比例。用同一套实物产量和投入分别按当期价、开局价计值，列出名义 GDP 增量中来自价格重估的部分。以一张地图为一个配对样本估计误差。若四席仍偏爱木材，且木材主要用于高产建设，这个结果本身可以接受。

**取舍。** 一国独自大量进口时，占用自己较浅的一份深度；同回合一国买、一国卖，也不能立刻享受对方带来的流动性。正式启用前要专门测试缺油国短期进口维持供电、专业出口国卖货筹军费两类局面。若必需品难以进口，先用这些场景校准商品深度，再评估增加一次所有国家均可参与的清算窗口。上线依据是闭环账目、行动顺序公平和正常生产贸易都能成立。
