# 未占领地块的地名：可以有，不向玩家暴露

## 口径

- 地名是**地图的属性**，不是地块的状态：由 `(seed, size, x, y)` 纯函数决定，未物化的格子也有一份，不进存档。这一点保留。
- **未占领的地块不向玩家暴露名字**：玩家侧的 `view` / `tile` / 状态地图 / 回执渲染，只在**已有主**的地块上给地名；无主（含未物化）一律只给坐标。名字可以存在，但不出现在玩家拿到的任何字段里。
- **名字不是句柄**：解析地名时按同一条口径收（见"要改的地方"），未占领之地只能用坐标指。

## 现在是什么情况

### 1. 名字表（保留）

`mods/native/map_generation/names.py`：`name_grid(seed, size)` 按规范扫描序给**每一格**一个唯一名字，前缀 98 × 后缀 82 = 8036 组合，撞名加序号。名字是 `(seed, size, x, y)` 的纯函数，同 seed 同 size 逐格相同，不受 `PYTHONHASHSEED` 影响。

### 2. 没有默认铺地

`Territory.initialize_world`（`mods/native/territory/mod.py:16`）只建 `Territory` 对象，不生成任何地块。未占领的格子由 `Territory.cell(x, y)`（`mods/native/territory/objects.py:74`）**临时合成**：`Tile('', x, y, terrain, None, cell.name)`——**id 为空串**，查完即弃。只有 `create` / `create_claim` / `transfer`（占领、易主）才真的落一块进 `_tiles` 与存档。所以"野地有名字"与"野地被铺地"是两件事，后者不存在。

### 3. 名字不进存档（保留）

`territory/objects.py` 的 `Tile` 带 `name`，但 `to_save()` 只写 `id / position / terrain / core`；读档时用 `map:generation cell` 从地图读回。名字不随存档往返变化。

### 4. 暴露面：视野内**每一格**都给名字，与是否占领无关

| 位置 | 现在 |
| --- | --- |
| `mods/native/vision/mod.py:41` | `VisibleTile((x,y), fact.tile.name, …)`——视野里每一格（本国、他国、无主、野人）都带名字 |
| `mods/native/army/mod.py:148` | `tile` 工具载荷 `{'position', 'name', 'terrain', 'owner', …}`，工具说明写的是"返回可见单格详情（**含地名**）" |
| `mods/ui/views.py:66` | 模型状态里的地图行 `if row.get('name'): out.append(row['name'])`，无主地归入【野人】段照样打名字 |
| `mods/ui/receipts.py` | 回执渲染经 `remember(observe)` 拿到同一批名字，`pos()` 打「名(x, y)」 |
| `mods/native/observer.py:35` | 观察者地图也带名字——旁观面，玩家提交不到（`observer_snapshot` 不是玩家动作），不算暴露 |

### 5. 同一个结构里两套口径

这两处的**资源与建筑明细都按归属门控**，唯独名字没有门控：

```python
# mods/native/vision/mod.py:41
VisibleTile((x,y), fact.tile.name, fact.tile.terrain, fact.owner, tuple(kinds.items()),
            fact.resources if fact.owner==actor or fact.owner is None and fact.tile.id else ())
#                          ↑ 无条件                       ↑ 资源：本国，或无主且已物化
```

```python
# mods/native/army/mod.py:145（tile 工具）
full=fact.owner==actor or fact.owner is None and bool(fact.tile.id)
result={'position':(x,y),'name':fact.tile.name,'terrain':…,'owner':…}   # ← name 无条件
if full: result.update(resources=…, capacity=…)                          # ← 明细才门控
```

工具文案也按这个口径写过：「他国仅公开建筑和归属，不泄露迷雾或资源」（`view`）、「本国及物化无主遗址显示资源、容量、施工与建筑」（`tile`）——**资源被点名保护，名字没被提到过**。

### 6. 名字是全局句柄，解析不看视野

`territory.resolve(text)`（`mods/native/territory/objects.py:65`）对非坐标串直接调 `map:generation where(seed, size, text)`——纯地图函数，**不查视野、不查归属**。同一段里坐标串只认「`x y`」与「`x,y`」两种写法。

## 0.1 是什么样

`git show v0.1:game.py`（第 187 行附近）：`"""随机生成一个不与现有地名重复的地块名。"""`——名字是**地块的属性**，**实例化时才起**，随地块进存档。未占领的野地没有名字，名字是"占下来的地方才有"的东西。

## 变更点

`8247946`（2026-10-14「恢复地名表，并修正征召报错与造价口径」）把名字改成地图属性并铺到未物化格子，同时把这件事写进了三处文档：

- `names.py` 模块注释：「未物化的格子同样有名字——"有名字没守军"这才是可读的侦查信号。」
- 该提交的信息：「地名回到地图上……未物化的格子也有名字，所以"有名字没守军"这类侦查信号重新可读。」
- CHANGELOG 同款措辞。

即：一个实现副作用被写成了设计意图。本文件记录的就是这一条——**要读的侦查信号应该是"占领了才有名字"，而不是"未物化也有名字"**；后者让野地在玩家面前变成有名有姓的实体，且与同结构里资源/建筑的门控口径自相矛盾。

## 影响

1. **语义**：地名在本作里是经营结果的一部分（0.1 语义：占下来才有名）。全图预先命名后，未占领之地也带着名字进来，玩家能直接引用自己没占的地。
2. **泄漏路径**：名字是全局唯一句柄，解析不看视野。名字一旦经任何渠道（信件、共享地图、报表、他国回执）落到玩家手上，就能被用来指一块自己没看见的地；`tile` 会以迷雾拒答，但渲染形态「名(x, y)」本身就会把坐标带出来。
3. **一致性**：`resources` / 建筑明细门控、`name` 无门控，同一个结构两套标准；工具文案声称保护了资源，却漏说了名字。

## 要改的地方（尚未改）

| 位置 | 现在 | 按口径 |
| --- | --- | --- |
| `vision/mod.py:41` | 视野内每格都给 name | 只在 `fact.owner is not None` 时给名字，否则给空 |
| `army/mod.py:148`（`tile`） | `name` 无条件 | 同上（`tile` 的说明同步去掉"含地名"） |
| `mods/ui/views.py:66` | 无主段照样打名字 | 名字为空时只打坐标 |
| `mods/ui/receipts.py:pos()` | 经 `_tiles` 打名字 | 只记已占领地块的名字；其余回落坐标 |
| `territory.resolve` | 地名 → 坐标不看视野/归属 | 待定：是否限制成"只有已占领（或本国）的格子能用名字引用"，未占领只能坐标 |

## 不动的部分

- 名字表本身、名字不进存档、观察者地图带名字（旁观面）。
- 已占领的地块继续带名字——0.1 语义就是"占下来才有名"。
- `native:tile/{x}-{y}` 这种 id（占领来的格子，id 不随归属变）**不额外处理**：回执渲染认不出就照原样回显。
- 本次已修的显示问题（`pos()` 认坐标串，见 `0aab9a0`）与本文口径一致：未占领之地只剩坐标可显示，缺了它日志里那块地就空着。
