# 配置提供层

组件负责字段语义，发行版负责组合，CLI 负责文件和显式覆盖，host 消费准备后的结果。`engine/config.py` 不定义国家、地图规则或模型字段；JSON 保持平面结构，不提供旧配置或旧档迁移。

## 使用示例

程序调用和终端走同一条配置路径：

```python
from engine.config import read_config
from host import GameHost

prepared = GameHost.prepare(read_config('my_config.json'),
                            overrides={'language': 'en-US', 'ctx_window': 262144})
host = GameHost.new(prepared)
# 续局：GameHost.load('my_session.json', prepared)
```

显式覆盖 > 玩家局部值 > 顶层默认。只有组件声明的字段会继承，其他扩展字段保留原样。准备过程复制输入，不修改调用者的配置；Session 再复制准备结果。准备对象关联已经装配的 Runtime，避免 CLI 和 host 重复装配、重复规范化。

CLI 的 `--save`、`--turns` 对应 runner 字段，`--language` 交给 UI，`--small-ctx` 等价于 `--ctx-window 262144`。同时指定后两者时显式窗口优先。发行版未声明可消费的覆盖会报错；例如只有 mini 客户端的发行版不接受上下文窗口覆盖。JSON、范围、客户端和服务配置在创建世界、恢复存档或写入新档之前验证。

## 发行版接口

发行版可声明可选的 `Distribution.Assembly.Entry`：在成员加载前接收声明与原始配置副本，返回实际成员／服务／客户端声明。通用引擎不解释实验功能名。`Distribution.Configuration.Preflight` 在开始前接收规范化配置与runtime，核对接入准备状态，不创建Session或调用模型；离线开发可只用 `GameHost.prepare`。当前experimental三个独立开关及兼容边界见[发行版说明](../mods/experimental/README.md#开局选择实验功能)。

```toml
[Distribution.Configuration]
Entry = "my_game.config:normalize"

[Distribution.ClientFactories.my_client]
Entry = "my_game.client:Client"
Configuration = "my_game.client:normalize_config"

[Distribution.Session.Services.advisor]
Entry = "my_game.advisor:Service"
Configuration = "my_game.advisor:normalize_config"
```

发行版入口签名：

```python
def normalize(cfg: dict, *, runtime, overrides: dict) -> dict:
    ...
```

发行版解释自己的场景结构，选择玩家条目，并可调用 `configure_components(cfg, entries, runtime=runtime, overrides=overrides, path='config.seats', fields=SCENARIO.fields)` 组合所选客户端、服务和 UI 的配置。该辅助函数由 UI 网关提供（`ui.configure_components`，选择 UI Mod 并组合其呈现字段），引擎不导入 UI。玩家条目不必位于 `nations`；示例验收使用 `seats`，没有国家或地图字段。`fields` 是发行版自己消费的场景字段，用于检查显式覆盖。该辅助函数原位规范化传入的配置副本与条目列表。

未声明发行版配置入口时，只校验 runner 字段并复制配置；此时不接受组件覆盖。需要组件继承、校验与覆盖的发行版应声明入口。

## 组件接口

客户端 / 服务配置入口签名：

```python
def normalize_config(cfg: dict, *, defaults=None, overrides=None,
                     path='config', runtime=None) -> dict:
    ...

normalize_config.fields = ('my_option',)
```

`fields` 声明可消费的字段，供组合器检查显式覆盖。入口负责局部字段校验、默认继承和显式覆盖；返回配置对象。没有 `Configuration` 声明的自定义客户端 / 服务接收配置副本，组合器不猜测其字段。入口不能执行游戏动作或调用模型。

通用 `Schema(fields).normalize(...)` 提供复制、继承和覆盖；`Field(types, minimum=None, maximum=None, choices=None, nullable=False)` 提供严格类型和范围验证，整数不接受布尔值，浮点数不接受 NaN / 无穷。配置错误使用 `ConfigError`，报告字段路径，不附带配置值。声明错误使用 `ModError`。

UI Mod 可通过 `presentations()` 提供 `ui:configure`；签名与组件入口相同（无需 `runtime` 参数），并声明 `fields`。组合器使用所选 UI Mod 的入口，不绑定标准 UI 的字段。只提供 `ui:create` 的 UI 不自动继承或消费界面覆盖。标准 UI 同时在 UI 实例提供 `configure`，供议长等客户端编排独立配置。

## 当前所有权

| 提供者 | 所有配置 |
| --- | --- |
| runner | mods、save、journal、max_turns |
| native 配置入口 | nations、身份与登场、初始资源、map_size、seed |
| mini 配置入口 | mini 身份、登场与自己的地图场景 |
| LLM 客户端 | 模型接入、重试 / 超时、上下文、max_steps |
| v11plus 客户端 | rule_ai、max_actions |
| experimental 议会服务 | parliament、reviewer、审核要求；审核模型复用 LLM 配置契约 |
| UI 装配入口 | ui_mods（先选择模块，再校验该模块的字段） |
| 所选 UI Mod | 语言、目录、视觉与地图呈现 |

规则数值、模块清单及沙盒额度仍归模块 / 发行版 TOML，不移到玩家运行配置。凭据仍只留在配置和内存中，不写入整局存档。离线测试不要求真实模型凭据；接入必需字段由实际传输后端在调用时检查。
