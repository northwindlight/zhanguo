# 单机真人玩家接口

状态：宿主接口与 Godot 真人操作均已实现。当前只支持**一位本机真人与规则 AI／LLM 混合对局**，不支持多真人交接或联网。设计与现成素材见[真人 GUI 计划](../plan.md)。

## 席位与调度

国家配置使用 `client: "human"`，可填 `nickname`，无需模型、API 或上下文设置。native 和 experimental 均支持，真人必须开局登场；第二个启用的真人席位会在配置阶段报错。

`HumanClient.play(player, request=...)` 由交互宿主提供输入回调。没有回调、或回调没有真正结束本国行动时，拒绝推进结算。`Session.cycle(on_human=...)` 保留原先手轮换和全部 18 个结算阶段，输入等待期间不持有 Session 锁。

政府从受信任的国家配置绑定真人身份，写入政府存档；前端参数不能自行申请豁免。真人 `end_turn` 不需要国策或小结，也不生成占位文本。experimental 不为真人装配议会及脚本服务；AI 仍按原要求执行。结束成功后照常自动拒绝未回应的外交提议、对本期开放而未表态的联盟投票投反对票。

## 玩家应用接口

实现：[HumanAPI](../mods/native/human.py)。构造时传入 `GameHost`，所有操作绑定已配置的真人身份。

| 方法 | 返回与约束 |
| --- | --- |
| `state(actor)` | 本国公开事实、实际装配的操作表及参数结构、地图、购图目录、生产队列、已发布本国报表、结束回合的外交待办 |
| `operations(actor)` | 按模块实际装配与政体权限筛选的操作，带中文标签、所属入口及参数结构 |
| `submit(actor, operation, arguments)` | 经绑定玩家 API 提交一次真实领域命令，保留审计、回执和原有批量预验 |
| `targets(actor, ids, mode)` | 从玩家当前事实计算逐格候选；`mode` 明确为 `move/attack/retreat` |
| `tile(actor, x, y)` | 当前合法观察或已保存历史，以及依法可见的驻军；暗区不调用实时单格查询 |
| `panel(actor, arguments)` | 只读面板，沿用 `query(panel=...)`；近讯额外去除外国操作回执 |
| `site_options(actor, x, y, count=1, queued=False)` | 只读本国地块：建设与征兵价格、要求、余额、施工／征兵额度、队列和公开估算；`queued=True` 按正式队列的预占容量与分期语义规划。读取不扣款，不接受他国或未知地块 |
| `market_options(actor, resource)` | 本国市场操作视图：五档数量双向共十笔整单试算、持有量、市场库存、可成交状态，以及本国自动交易设置和最近结果；不扣款、不成交 |

建设、拆除、征兵、移动、攻击、撤退、遣散、手动买卖、自动交易设置／删除、贷款、经济报表、信件、馈赠、外交、联盟、投票、派谍、共享图和购图均通过同一入口。GUI 可以按操作表制作按钮和列表；这些内部参数无需让玩家手填。

`queue_build / cancel_build_order` 对应 `native:buildings.enqueue / cancel_order`；`queue_recruit / cancel_recruit_order` 对应 `native:army.enqueue_recruit / cancel_recruit_order`。入队立即锁价并预付，当前可执行部分立即开始，其余在后续行动期按设施额度推进，不再次扣款。`state.production_queue` 提供本国全国进度；模型使用 `query(panel=construction_queue/recruitment_queue)`，不增加按地块查询。失地／亡国取消待生产部分，退原付款国。

未开工取消全额退回；`demolish(id)` 对应 `native:buildings.demolish`，施工中返还实际材料的一半，完工后零返还，不恢复本格本期施工额度；城堡按最高级向下拆。部分征兵只退尚未生成单位的预付费用。预付材料单列 `econ.prepaid_stocks/prepaid`，不属于可用库存，仍计入资产；实际开工／生成才计一次消费。两种队列状态与锁价随存档保存，读取不推进。

`auto_trade / remove_auto_trade` 对应 `economy:queries` 的同名 API，设置本身不成交，本国成功 `end_turn` 后执行一次，先卖后买。这些 API 同样供 LLM 和规则／脚本客户端使用；不增加或重排18个结算阶段。

`queue_orders(ids,nodes,append=True,auto_heal=True)` 对应军队域正式持续军令；`nodes`为`{mode:move/attack,position:[x,y]}`数组，每军最多64项。追加可立即开始当前合法部分，后续在所属国家行动前推进；`append=False`重设剩余路线。低于30生命时独立暂停，通过原补给恢复满血后续行；空节点可修改已有路线的回血开关。`cancel_orders(ids,node=可选的1起始序号)`删除指定节点或全部后续路线。原手动移动／攻击／撤退执行后替换该批军队路线；已执行动作不会撤销。

`state.army_orders`与`query(panel=march_orders)`返回本国路线、原因和公开路径。规划复用已有导航及候选规则，只使用玩家当前事实；未确认段没有隐藏格路径，GUI仅画虚线示意。被选军队集合可跨驻地，提交直接军令仍只执行该目标合法的子集，并保留其他勾选。路线查询与状态读取不推进。

`submit()` 是受信任宿主内的应用方法；外部输入必须经过下节的请求校验。`can_act` 本身不代表当前轮到该国。

## 桌面宿主协议

入口仍是 `python -m ui.desktop --output <全新目录>`，读取标准输入 NDJSON，输出 `zhanguo.desktop/1` 消息。通过 `ZHANGUO_DESKTOP_CONFIG` 提供独立配置。Godot 玩家模式先定制唯一真人国家与地图，再配置其他 AI 国家；看海模式全部 AI。真人席位不要求 API 档案。

- 到真人行动时发出 `human_turn`：`actor / period / control_generation / seat_token / nickname`。每次真人回合生成新令牌。
- `human_query`：`actor / request_id / query / arguments`；`query` 可选 `state / tile / targets / panel / site_options / market_options`。允许在暂停或演出确认等待时查看。`site_options` 使用绑定玩家的规划 API，经 UI 投影补中文描述与公开收益估算，读取不生成建设或征兵指令；`market_options` 只用绑定玩家的行情、余额和整单报价。
- `human_submit`：携带上述席位、期数、控制代次、令牌，以及 `request_id / operation / arguments`。身份过期、暂停或演出未完成时拒绝新写操作。
- 返回 `human_result`。外层 `ok` 表示请求处理成功；`data` 是领域回执，实际操作结果仍须检查其中的 `ok / status / message`。相同请求编号及内容重发只返回缓存回执，标记 `duplicate: true`；相同编号换内容会拒绝。
- 单次提交执行完后发 `timeline`，再发同一事实边界的 `snapshot`。客户端确认 `playback_ack(generation, sequence)` 后才允许下条写操作。
- 真人局的快照明确标记 `scope: "player"`，`actor` 始终是本机玩家。AI 思考、私信、国策、账户和后台操作回执不进入此通道。呈现采集失败只退回玩家快照，不能转观察者全图。

示例写请求（供界面接线，实际令牌取 `human_turn`）：

```json
{
  "command": "human_submit",
  "actor": "scenario:qin",
  "period": 0,
  "control_generation": 0,
  "seat_token": "从 human_turn 读取",
  "request_id": "本次点击的唯一编号",
  "operation": "end_turn",
  "arguments": {}
}
```

`pause / resume / save` 保持现有协议；回合中保存排队到完整边界。真人局中途 `stop` 返回 `exit-choice`，暂停并提示继续或放弃，绝不自动代结束真人行动。确认放弃时发 `discard_progress` 和 `confirm: true`；最近完整存档保留。标准输入断开相当于丢弃未保存部分并退出。真人亡国后停止推进，保留最后合法观察，不转为全图观察者。

## 地图知识与军令候选

`state.map.tiles` 包含全图坐标，分三种状态：

- `live`：`current` 只有玩家观察接口当前允许的字段。外国建筑继续受原有公开范围限制。
- `memory`：只有历史 `fields`。每字段含 `value / sampled / order / source / acquired`；建筑按类型分别合并，部分观察缺失的类型不会被当作拆除。
- `unknown`：只有 `position / visibility`。不发送秘密地形、建筑、资源或真实地图种子。

地图知识由情报模块持有，在合法行动和完整边界采样，随存档保存。清理收件箱不会清除知识；新观察只更新有权看到的地块及字段，旧报告不能覆盖新观察，同一期按持久观察顺序判新旧。历史地图没有敌军位置；己方军队仍来自本国公开军队列表，可处在未照亮的格子。

军令候选计算不访问世界，只消费玩家事实。多选取范围并集，每格返回可执行的 `ids`、排除原因和 `uncertain`。提交时重新筛选该目标的军队子集，仍只调用一次原有整批裁决。已行动、新兵和交战限制保留，原地攻击按规则例外处理；未知通路按可能可行计算，不用后台障碍或旧快照提前排除，不给出秘密地形的精确行军路线。实际失败及额度消耗以领域回执为准。

## 正式购图接口

`native:intelligence` 新增 `knowledge / map_offers / buy_map`；工具入口为 `query(panel=map_knowledge/map_offers)`、`intelligence(action=buy_map, target=...)`，真人与 AI 共用。

供图来源为各国地图商公开的定期全国测绘。开局和每个完整回合边界发布一次，覆盖该国土地及邻接无主地，包含当时的地形、归属、资源、建筑与在建数量，不含军队分布、建筑等级或实例位置。它不是购买时临时读取对方现状。目录只显示来源、采样期、覆盖数、价格和是否购买。

价格由 `mods/native/intelligence/mod.toml` 声明：基础 20 金加每格 2 金，作为测绘服务费扣除并记入行政消费。单个买方每个版本只能买一次；等待下一完整边界才有新版本。成功后立即取得历史地图并合入知识，不扩大实时视野。经济报表购买仍是独立动作。原有共享图、间谍图按实际送达时点合并。

## 存档与验证

整局格式升为 `zhanguo.session/5`；native `4.19.0`、experimental `0.20.0`，政府与情报模块版本同步更新。真人 GUI 的 `ui:standard` 为 `1.9.0`，不改变结算或整局格式。严格拒绝旧依赖混载，不自动迁移、覆盖真实存档；旧发布包和旧局继续使用原版本。

离线验收：

```bash
python -m unittest tests.test_human -v
python scripts/review_human_interface.py --output archive/previews/human-interface-new
```

第二条启动真实独立宿主进程和正常八国 v13 对局，以协议操作真人三期；核对重复提交、批次确认、存档读回、玩家视野及无国策小结，输出 `report.json / protocol.ndjson / stderr.log`。不读取私人配置、真实对局或模型凭据，不调用外部模型。窗口验收使用 `python desktop.py --human-review-output <绝对输出路径.png>`；用独立目录创建正常开局，从菜单、按钮到三期结算实际运行，包含费用预览、双击去重、建设、征兵、移动／攻击区分、买图、静态暗区、四种尺寸和保存退出。Windows 便携构建也执行这一检查。

## 窗口操作

新建对局先选剧本，再为一个国家选“真人”。底部提供建设、军队、市场、外交、联盟、情报、国家和结束回合；左上角固定本国库存及已结算收支。建设／征兵选地块和类型，费用按钮调用真实报价；交易可查看整单报价。

点地块打开驻军面板，以复选框选本国军队，分别点移动、攻击或撤退，再点逐格目标圈。蓝色空心圈与红色准星区分军令，虚线表示通路未确认；悬停显示可执行子集与排除原因。Esc 先取消选目标，否则打开自动暂停菜单；空格只控制演出。

买图后直接合入世界地图。未知格没有底图对象，历史地块压暗、去饱和并停止居民、水面、树木、施工和烟气；未公开等级的建筑标“示意”与采样期。外国额外历史建筑在局部实时视野中仍保留日期。己方迷雾军团在遮罩上方以同格汇总标记出现，点该格选择；不会显示敌军实时追踪。

每条命令收到真实回执后播放本批，演出完再解锁写操作；只读地图与面板仍可使用。保存排队到完整边界，回合中退出提供继续或明确放弃未保存进度，保留最近完整档。默认看海局仍使用观察者；真人局始终固定本国权限。

### v0.6.3军令投影

`HumanAPI.state`为本国军队补充`commands`，按`move / attack / retreat / disband`提供`available / reason`；界面直接读取，不自行推断资格。`targets`的逐格目标保留参与编号与排除原因，并为逐支部队提供`routes`；已探明路线包含逐格`points`，不确定路线的`points`为空。预览与正式执行共用军队域导航规则，事实来源仍限绑定玩家。

### 第二版开发：旧图归属失效

真人`visual.tiles`对旧地图中的已灭亡领主增加`ownership_status="outdated"`与`historical_owner`，绘图用的`owner=null`，不再铺该国国色；界面显示现归属待确认。依据来自既有公开`native:nations.snapshot`存续事实，不查询视野外新领主。`knowledge`内的原始归属、地形、建筑及日期仍保留，当前实时视野优先；不改变存档结构。
