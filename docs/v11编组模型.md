# v11 军队编组运筹模型（设计底稿）

> **状态：已实现**（`ruleai/` 包，见 §六之二、§九）。定案日期 2026-09-15（用户口径逐条见下）。
> 本文记的是**模型与推导**：为什么不是榜单、三个指标怎么来、约束与求解、以及踩过的坑；
> 效果数字见 §九（锚定提交）。

## 一、为什么不是榜单

原来的做法是"**先把候选格排成一张榜，再按榜序给每个目标凑兵**"。这个形状从根上不对：

1. **它是静态排序，而问题是序贯的** —— 占了这块地，才会出现下一批可占的地（边境生长）。
   一块地的名次取决于它邻居的名次，榜单装不下这种依赖。
2. **兵是抢的** —— 每一格的最优成员都是"离它最近的 `n` 支"，而同一支军常常是好几个目标的
   最近几支。按榜序逐格从池子里取（先到的先抢、后到的拿残渣）⇒ 总行程显著劣化。
3. **人数被写死** —— `MIN_SQUAD = 2` 是教条，而"打这一格要几支"本来是**算得出来的**
   （空地 1 支、满血野人 2 支、山地 + 城堡 L5 可能 4~5 支）。
4. **"待命"是个没定义的状态** —— 富余兵力在原设计里无处安放，只能靠"每军各自挑最近"
   糊过去，于是全军被吸到同一个最近目标上，别的方向边境空着。

正确的形状：**以军队为决策变量的编组问题**。军队是主体，目标是军队的**属性**，
不是一张给军队打分的榜。

## 二、三个度量（用户口径，2026-09-15）

用户原话：「只有三个指标，编组内成员的距离必须最小，找到这个编组全体距离最近且没被锁定的
目标，这个目标又反过来决定成员数量，这是运筹学。」

| # | 度量 | 形式 | 为什么是这个形式 |
|---|---|---|---|
| 1 | **组内距离** | `spread(S) = Σ_{i<i'∈S} d(i,i')` | 组要抱团。**这是跨回合约束**：打完这块，这一组还要**一起**去下一块；一盘散沙的组下次分配必被拆散，等于每回合重组、白走里程 |
| 2 | **全体到目标** | `reach(S,j) = max_{i∈S} d(i,j)` | ★用 `max` 而不是 min/avg：引擎的 `atk` 是**原子**的（`mp.py:1032`，`aids` 里任一支自己到不了就**整通调用全废**）⇒ 组的到达时刻就是**最慢那支**的时刻 |
| 3 | **目标定人数** | `n_j` 是**这一格能不能打的门槛** | `n_j` 由判定式算：`ruleai/combat.py` 逐轮模拟引擎的伤害公式（骰子取期望），给出"最少几支能赢"。写死成 2 就是 `MIN_SQUAD` 那种拍脑袋 |

`d(·,·)` 一律是**行程**（移动力代价，`MOVE_COST` 逐格、`max(出发格,目标格)`，`mp.py:339`），
不是格数 —— 否则"绕山三格"与"平地三格"会被当成一样远。

## 三、编组 = 状态机（生命周期）

用户口径（2026-09-15）：

> 「重新编组只发生在这个编组的目标消失，于是全体没有目标的军队重新编组，
> 有目标的编组直到目标被拿下才会重新编组。」
> 「任何军队一定会找到目标，因为是全局编组。」

### 唯一的状态
```
target: 军 → 格        每支军当前认领的目标
```
**"组"不是独立实体 —— 组 = `target` 的等价类**（target 相同的那些军就是一组）。
所以状态就是一张 `id → 格` 的表，不存别的（组名、组长、编成历史一概不存）。

### 转移

| 触发 | 动作 |
|---|---|
| 目标**被拿下**（自己拿的 / 别人拿的 / 目标不再是可攻格） | 该组成员全部变成"无目标" |
| 目标**消失**（变成身不可攻：中立化、被盟友占、野地上有非敌非盟在打野） | 同上 |
| 出现**无目标的军**（新征的兵、刚打完仗的兵、上面两种触发） | 与**所有**无目标的军一起做一次**全局编组** |

- **有目标的组不参与重算** ⇒ 每回合的编组计算只覆盖"无目标的那些军"，不是全军。
- 新征的兵**天然无目标** ⇒ 下一回合落进重新编组，不需要特殊照顾
  （经济段产兵、出生在兵营格，位置由经济段决定，见 §六）。

### "任何军队一定有目标"
因为候选池是**全局**的：视野内**全部可攻**的格，不是"军队旁边那一圈"。
- 边境永远非空（有一块地就有一圈无主邻格）；
- 池子远大于当前需要（近处不够还有更外一圈、野人驻守格、交战敌国格）；
- ★ **池子不排除"已经有编组在打的格"**：新征的兵、刚打完仗的兵要能**并进**那一组
  （那格要 2 支、现在只到了 1 支，第 3 支就该往那儿走）。排除掉它 = 逼每支新兵各自
  认领一个**新**目标 ⇒ 一支军站一块要 2 支的野地、谁也不动手（**真发生过**：
  300 回合 11 次移动、0 次进攻、领土停在 5 格）。"认领互斥"只体现为
  **一格里已有的兵力** `c_j`（见 §四），不是"这格不许别人来"。
- ⇒ "无目标"只是**当回合内的瞬时状态**，不是长期归宿。**"待命"从模型里消失**，
  不必再为富余兵力发明"预备队"之类的东西。

（这里原来写过一条"宇宙边缘的兜底：允许把未来目标编进组" —— **定稿后不需要了**：
§四 把模型写成**指派**（每支军认领一个目标、`n_j` 只是门槛），"覆盖全体"是结构性成立的，
不必再为边角情形加规则。）

## 四、单次全局编组问题（形式化 · 定稿）

> **2026-09-15 修正**（用户：「全体无解是求解器的问题，而不是应该兜底」）：
> 第一版把约束写成"**每组恰好 `n_j` 人**"。那个写法**经常平凡无解**
> （目标都要 2 支而军队数是奇数；或"每格只认它最近那 `n_j` 支"时凑不出互斥覆盖），
> 于是代码只能靠兜底糊过去，反而给每支军各发一个目标 ⇒ 一支军站一块要 2 支的野地、
> 谁也不动手。实测：**300 回合 11 次移动、0 次进攻、领土停在 5 格**。
> **正确写法是"指派"**：`n_j` 不是每组的**人数**，而是**这一格能不能打的门槛**。

触发时已知：**无目标的军集合 `U`**、可攻格集合 `J`、判定式给出的 `n_j`、
以及每格**已经在打的兵力** `c_j`（状态里查得到 —— 新兵要能**并进**已有编组）。

**变量**：`σ(i) ∈ J` —— 每支军的**认领**（一支军恰好认领一个目标）。
同一目标下的那些军就是一组：`S_j = {i ∈ U : σ(i) = j}`。

```
min   Σ_{j ∈ J} [ spread(S_j) + reach(S_j, j) + λ · max(0, n_j − |S_j| − c_j) ]
s.t.  σ 覆盖 U（每支军都有认领）
```

- **第 3 项 `λ·缺员`** 是**目标函数的一部分，不是兜底**：派给这一格的人不够 `n_j`
  ——加上已经在往那儿走的 `c_j` 仍不够——这一仗就打不下来，那几支只是朝那儿走
  （下回合人齐了判定式自然放行）。`λ` 取得比任何路程都大
  （`balance.V11_SHORTFALL_PENALTY`=500）⇒ **"能打下来"永远优先于"省点路"**。
- **结构性有解**：只要还有一支军没认领，就给它一个目标（最坏情况是单独朝最近的格走）。
  **无解不存在，也就没有兜底这回事。**
- "目标反过来决定成员数量"仍然成立：`n_j` 决定**这一格要凑几支才动手**；
  多于 `n_j` 只是打得更快（多出来的是"跟队的"，不改这一组的名额）。

### 不动点（"目标反过来决定成员数量"）

```
给定已认领的军 → 目标 j 的成组 S_j = {i : σ(i) = j}
给定目标 j     → n_j（判定式）+ 谁去（离它近的、以及补足 c_j 的那几支）
```
人数与目标是**同时**定的：`n_j` 决定这一格要几个人，而"这格要几个人"又决定
新兵该并进哪一格、谁该另开一块。所以不能"先圈人再找目标"，也不能"先找目标再圈人"。

### 一个漂亮的副产品
"每支军都必须有认领"会自动产生"暂存"行为：够不着好目标的那些军，只能认领
**对它最便宜的那个格** —— 那就是"朝最近的方向推进"。
⇒ **不需要单独的"预备队/暂存"规则**。这是把"待命"禁掉之后模型自己长出来的东西。

## 五、可解性（为什么说"能拿全局最优"）

- 规模：`M ≤ ~20` 支军、`J ≤ ~40` 格。
- **状态 = 还没认领的军**（记忆化 DP）：固定取**最小的未认领军** `i`，
  枚举"给 `i` 认领哪个目标"（只考虑离 `i` 最近的 `V11_NEAR_TARGETS`=4 个候选格 ——
  更远的目标在目标函数里本来就不会赢，限制它只为省算力），并顺手带上
  `0 … V11_MAX_GROUP-1` 个离那个目标最近的同伴。每一步都**必然覆盖 `i`**
  ⇒ 递归必然到底 ⇒ **无解不存在**。
- 子问题最优值 `f(未认领集合)` 可缓存 ⇒ 搜索塌到多项式级（早先"每格只一个候选组"
  的写法每回合撞 2 万节点上限、退化成"当前最好"；现在 20 支军也是一次到底、`exact=True`）。
- 顺序与并列比较都是**全整数 + 显式排序**（坐标兜底）：同一局面永远同一张编组。
- 每回合只对"无目标的军"重解（§三），所以典型规模远小于全军。

## 六、与其它子系统的接口

| | 谁说了算 | 说明 |
|---|---|---|
| **产兵**（几支、何时、出生在哪格） | **经济段**（用户 2026-09-15：「产兵由经济引擎决定」） | 编组模型**不碰**产兵。新兵出生在兵营格（位置已知），下一回合作为"无目标的军"进池子。产兵权不在它手上 ⇒ 不建"军事需求 → 产兵"的反馈回路 |
| **军队数 `M`** | 外生（经济段的产物） | 本轮模型不建经济复利（用户：只扩张速率、军队数当外生） |
| **交战中的军** | 引擎锁定 | 它不能动、也不能改攻（`mp.py:1032` 的直接拒绝）⇒ **它的目标钉在它脚下那格**、不参与重新编组，等战斗结束再放回池子，这样"任何军都有目标"不因交战而破例 |
| **判定式 `n_j`** | `ruleai/combat.py` | 只看**胜败**（用户 2026-09-15：「只看胜败，不管滴血」）。但 `rounds` **要留着** —— 它不是战损、是**工时**（打几轮 = 那几支军几回合不能动），进的是时间账 |

## 六之二、代码怎么分层（用户 2026-09-15：「单独弄个目录装 ruleai」）

v11 是一个**经济层与军事层分离**的规则 AI，整体住在 `ruleai/` 包里：

    ruleai/__init__.py   共享的**动作账本**（两层唯一的公共接口：world + Ledger + 额度）
    ruleai/v11/entry.py  入口：`expand_rule_turn_v11` = 经济层 + 军事层（四行胶水）
    ruleai/economy.py    经济层：钱/料/建造/征兵（**产兵权在这里**）
    ruleai/military.py   军事层：编组 → 判定式 → 寻路 → 出手
    ruleai/grouping.py   军事层部件：编组状态机 + 全局求解器
    ruleai/combat.py     军事层部件：难度判定式
    ruleai/pathfind.py   军事层部件：视野掩码 + 代价场 + 落点
    ruleai/targeting.py  军事层部件：候选池

**两层不许互相 import** —— 这是分层的唯一纪律，由 `tests/test_ruleai_layers.py` 钉住
（这类越界是渐进的：先"就一行"读一下国库，再"顺手"调一次征兵，两次之后就分不开了）。

## 七、状态放哪（已定）

用户 2026-09-15 定：**放规则 AI 模块内存**（现在就是 `ruleai/grouping.py` 里的 `_STATE`）。

- ✅ 不动引擎、不碰存档格式（`SAVE_VERSION` / `SAVE_KEYS` 一律不动）。
- ⚠️ **已知代价，必须写清楚而不是假装没有**：读档续局会**丢掉编组** ⇒
  "续局 == 一口气跑"这条底线**对 v11 不成立**（`tests/test_save_version.py` 那条现在跑的是 v10）。
  表现是：续局后的第一个回合，全军无目标 ⇒ 做一次全局编组（结果与"本来该在跑的半途编组"
  一般不同）。**结果仍是确定的、可复现的，只是与不中断的那次不同。**
- ️ RL 侧：每一局开始必须**清空**这份内存，否则上一局的编组会漏进来
  （这是"模块级状态"的固有负担，交接时务必写上）。

## 八、相对现有代码的结构改动

1. 旧 `formation.allocate`（排榜 → 逐个领兵）**整个删掉**：换成 §四 的全局指派 + §三 的状态机。
   `ruleai/targeting.py` 不再产"榜"，只剩**候选池**。
2. **`V11_MIN_SQUAD` / `V11_MIN_SQUAD_EMPTY` 两个常数删掉** —— 人数由 `n_j` 门槛决定。
3. **`V11_MAX_GROUP` 的意义变了**：不再是"一队最多带几支"，而是"给一支军配几个同伴"的枚举上界。
4. 编组状态机与求解器住在 `ruleai/grouping.py`；模块内存里的状态**只在这里读写**，别处不许碰。
5. 整个 v11 搬进 `ruleai/` 包，经济层与军事层分成两个模块（§六之二）。

## 九、验证（已实现的部分 + 效果）

已落地（`ruleai/grouping.py` / `ruleai/v11.py`，测试见 `tests/test_grouping.py`）：

1. **全局最优**：与手算/穷举对拍（3 支军两个目标，三种划分手算得出来，必须挑中最优）；
2. **永远有解**：军队数为奇数、目标都要 2 支这种"恰好 n_j 人"必然无解的局面，
   断言每支军都拿到目标（`test_always_covers_every_army`）；
3. **三指标**：人数由判定式定（空目标 1 / 满血野人 2）、`reach` 取最慢那支、
   `spread` 进代价、缺员吃罚；
4. **状态机**：目标被拿下/变成不可攻 ⇒ 那一组解散；**有目标的军不被改派**；
   交战中的军钉在脚下那格。

### 实测效果（锚定提交 `0f7cc3c`）

`experiments/march_probe.py`，40×40 · 300 回合 · 6 种子 · 单国（秦），中位：

| 指标 | v10 | v11 |
|---|---|---|
| **领土** | 279 | **400.5（6/6 种子全胜，+43%）** |
| 到 10 / 20 / 30 格 | 62 / 73.5 / 84.5 | 60.5 / 70 / 78.5（都更快） |
| **倒退次数（抖动）** | 198 | **0（6/6 归零）** |
| 行军 / 进攻 | 1223 / 347 | 406（−67%）/ 402（+16%） |
| 消费 | 29.9k | 28.7k（−4%） |
| 停滞军队·回合 | 55.5 | 86 |

停滞那项略高是**设计使然**：军队到了目标旁会**等队友到齐**（组不够 `n_j` 就不动手），
不是卡住 —— 与"倒退次数归零"合起来看，它换来的是"少走冤枉路、一次打下来"。
